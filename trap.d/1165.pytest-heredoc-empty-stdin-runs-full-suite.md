`python3 -m pytest ... <<'PYEOF'\nPYEOF` with nothing between the markers ran the FULL
suite (2026-09-07, issue #1165 lane, worktree <worktree-1165>).

I was trying to (a) run a pytest invocation with an empty heredoc as a throwaway no-op sanity
check, chained via `&&`/newline before a *separate* `python3 - <<'EOF' ... EOF` block that did
the actual manual repro I wanted. The empty-heredoc `pytest` command had no `-k`, no path argument,
no `--collect-only` -- nothing scoping it -- so it silently collected and ran every test in
`tests/`, which this repo's own CLAUDE.md explicitly says never to do locally ("Do not run the full
suite locally... it is red here before you touch anything, and it rewrites the index of the
checkout it runs in").

Cost: ~1m42s wall clock, 1927 passed / 1 failed / 2 skipped, and the one failure
(`test_classify_live_2046.py::test_an_ordinary_safe_message_comes_back_safe`) was pre-existing and
unrelated to my diff -- it needs an authenticated `claude` binary this environment does not have
("Not logged in - Please run /login"), exactly the kind of environment-only red the brief warns
against writing into a PR body as a fact about the branch. No lasting damage (no files were
mutated by the run itself, `write-guard(#1998)` confirmed installed and armed), but it burned real
wall time and briefly risked reporting the unrelated failure as caused by this change.

What would have caught it before running: treat ANY bare `python3 -m pytest` invocation with no
explicit scoping argument as a red flag regardless of whether the intent was "run nothing" -- an
empty heredoc is not the same thing as "no command runs". If the intent is a genuine no-op /
placeholder step, skip the pytest invocation entirely rather than writing one with nothing piped
into it.
