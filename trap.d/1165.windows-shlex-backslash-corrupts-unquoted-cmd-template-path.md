A raw path spliced unquoted into a preset-op cmd TEMPLATE string is corrupted on Windows
CI by `_resolve_custom_op`'s own `shlex.split(cmd)` (2026-09-08, issue #1165 lane, PR #2403,
windows-latest/3.9 and /3.12).

`tests/test_preset_op_payload_route_1165.py::_register_argv_echo` built a synthetic preset op's
`cmd` as `f"{{python}} {script} {{args}}"` where `script` is a `pathlib.Path` from pytest's
`tmp_path` fixture, inserted directly as template TEXT rather than through a `{file}`/`{arg}`
placeholder `_resolve_custom_op` quotes on the caller's behalf. `shlex.split()` implements POSIX
shell tokenization rules unconditionally, regardless of the host OS it runs on -- so on Windows,
where `tmp_path` renders with a drive letter and backslashes (`C:\Users\runneradmin\...\argv.py`),
every unquoted backslash was consumed as an escape character and the following letter kept
literally: `C:\Users\...\argv.py` became `C:Users...argv.py`, a path nothing can open. All 12
tests in the file failed identically on both Windows legs; the same fixture passed 12/12 on the
macOS runner the lane developed on, because macOS/Linux temp paths never contain a backslash to
trigger the bug -- so this went completely invisible until Windows CI actually ran it, days after
a clean local self-review.

This exact trap and its fix are ALREADY documented in this repo's own test suite --
`tests/test_custom_ops.py::TestPlaceholderInjection._script`'s docstring says almost word for word
"Forward slashes + shlex.quote: a raw Windows path would lose its backslashes to the shlex.split
the cmd template goes through" -- and I did not find or reuse it before writing a fresh, naive
version of the same helper. Cost: a full CI round-trip (a pushed branch, an opened PR, ~10 minutes
of Windows CI wall clock across two Python versions) to discover a class of bug this repo had
already paid for and written down once.

What would have caught it before writing the fixture: grep the test suite for `shlex.quote` +
`as_posix` BEFORE writing any new helper that builds a preset op's `cmd` string with an
interpolated path, since this is evidently a recurring shape (a test helper registering a
synthetic op via `supertool._CONFIG = {"ops": {...}}`) and not a one-off.
