Self-review finding on #2705 (ported release-branch machinery), ranked `misreports`
(non-blocking, can ship behind this fragment) rather than fixed in the PR itself --
the maintainer can decide whether it is worth a follow-up issue.

`.github/scripts/smoke_release_tree.py`'s `run_smoke()`/`SmokeResult.ok` cannot tell
"every hook ran and passed" from "there were zero hooks to run" when `hooks/hooks.json`
exists but parses to a structurally empty hook set (e.g. `{"hooks": {}}`): `hook_commands()`
returns `[]`, the hook-running loop never executes, `result.hooks` stays `[]`, and
`all(h.returncode == 0 for h in self.hooks)` is vacuously `True` over an empty list.
`report()` then prints only the unconditional `after` lines and ends with `smoke: OK`,
with no line anywhere saying zero hooks were actually exercised. The absent-file case
is announced ("hooks: no hooks/hooks.json in the tree, nothing to run"); the
present-but-empty case is not. Observed by the `oss:auditor` self-review spawn on this
issue's own commit (fcf3dc33), 2026-10-02; not fixed in #2705's diff because it widens
blast radius into a file this issue only needed to adapt, not harden further, and it is
a real but very specific gap (the shipped `hooks/hooks.json` in this repo is never
structurally empty).

A smaller instance in the same ported family, same root cause (a status line that is
silent in two different states): `build_release_tree.py`'s `main()` only prints
"rewrote N link(s) in path" when `n` is nonzero, and never states whether
`rewrite_links` was enabled or disabled in the config -- "rewriting was on and found
nothing to rewrite" and "rewriting was off" print identically (nothing).

This is the repo's own named defect class ("an absence produced by the tool, read as
an absence in the world" -- see CLAUDE.md) landing inside code this same issue just
wrote. The fix, if someone picks it up: have `run_smoke()` append an explicit
`result.notes` line stating the hook count it is about to run (including zero) before
the loop, the same way `check_release_tree.py`'s own `REVIEW`/`FAIL` lines never let a
clean pass and a declined check look identical.
