Self-review of #227's OAuth error-receipt fix (fix/227, commit 0a7bff04):
the auditor spawn (oss:auditor) noted the inline comment above
`presets/youtube/comment.py`'s could-not-verify fix slightly overstates what changed.

The fix is `return "could-not-verify", repr(safe_short(str(e), 300))`, with a comment saying
this is "Escaped the same way the MISMATCH arm below does". `safe_short()`
(`presets/youtube/_sanitize.py:108-120`) already strips newlines (replaces with a space) before
truncating -- so the newline-flattening this fix's changelog/commit message credits to the fix
is actually mostly already handled by `safe_short` alone, one call earlier. What `repr()` adds
on top is escaping of a carriage return, quotes, backslashes and other control bytes `safe_short`
does not touch on its own -- confirmed: `repr(safe_short("a\rb", 300))` shows `repr()` escaping
the carriage return that `safe_short` alone would pass through unescaped. So the actual defense
here is the `repr()` wrap, not (only) `safe_short`, and the inline comment's "the same way
MISMATCH does" framing is accurate for the *mechanism* (both call `safe_short` then apply
repr-equivalent escaping via `!r` / `repr()`) but understates that `repr()` is doing real,
distinct work here beyond what the comment's phrasing suggests to a reader who has not looked
at `safe_short`'s own code.

Caller-visible behavior is correct either way -- this is a comment-accuracy nit, not a runtime
defect. Non-blocking; logged rather than fixed because it is a one-line comment wording
question with no clear single best rewrite, better left to a later pass with more context on
this repo's own comment style conventions.
