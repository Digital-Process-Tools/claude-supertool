# #2436 review — test fixture omits `no_run_streak`, understating the streak gap

**What was observed:** reviewing #2436's grace-window fix to
`presets/watch/sources/gh-branch/poller.py`, the Explore reviewer found that
`tests/test_watch_gh_branch_no_run_regression_2333.py::test_the_uncertain_state_survives_a_second_no_run_poll_without_reflaring`
constructs its starting state as `{"branch_state": UNKNOWN, "sha": ..., "lookup": OK}`,
omitting `no_run_streak`. `poller.py`'s `prev_no_run_streak = int(state.get("no_run_streak")
or 0) ...` then defaults it to 0, so the test's "second empty read" computes
`confirmed_streak = 1` rather than the `3` a real, persisted post-guard state would carry
(the poller always writes `no_run_streak` into `new_state` every poll).

**Where:** `presets/watch/sources/gh-branch/poller.py` (`raw_is_no_run`/`confirmed_streak`
logic, ~lines 250-321); the stale fixture is
`tests/test_watch_gh_branch_no_run_regression_2333.py:128-142`.

**What it cost:** nothing yet in production — reproduced only by hand-feeding `poll()` the
real persisted state shape (`no_run_streak: 2`, `branch_state: UNKNOWN`) plus one more
empty read, which yields `confirmed_streak = 3 > UNKNOWN_CONFIRM_STREAK` and fires `no_run`
immediately, one poll earlier than the "silent, unknown, no_run" narrative claims. The gap
is pre-existing (the same fixture omission existed against the old single-shot guard on
master) but #2436 widens it from off-by-one to off-by-two polls, and no new test in #2436's
diff catches it.

**Who would hit it:** only a caller that reconstructs an `UNKNOWN` state without its
accompanying `no_run_streak` — a stale/hand-rolled state file, or a dispatcher merge that
drops the field. The poller's own normal operation always round-trips `no_run_streak`
through persisted state, so this is not reachable via ordinary polling.

**How it was confirmed:** Explore agent review of #2436's committed diff (worktree
`/Users/floriandavid/Documents/st-wt/2436`, commit `b2cef52c`), by manual trace and direct
reproduction against `poll()` with the real persisted-state shape. `oss:auditor`'s
independent pass over the same diff found no Class A/B/C findings and did not flag this
(its trace used the test-suite fixtures, not a hand-rolled persisted state).

**Left as a trap, not filed as a blocking issue:** unreachable via normal operation, and
fixing the fixture (adding `no_run_streak` to the stale test's starting state, and possibly
a positive-control test for the persisted-state boundary) is a small, well-scoped follow-up
rather than a release blocker.
