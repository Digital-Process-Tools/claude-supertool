Issue #2571's fix routed `op_between_pattern`'s `start`/`end` through `_pattern_gate` wholesale, which bundles four independent checks: length cap, ReDoS backtracking guard, BRE-alternation rewrite, and a "saturating pattern" refusal (`_saturating_pattern_refusal`, `_supertool.py:6692`). The last one does not transfer cleanly to `between`.

`_saturating_pattern_refusal` exists for `grep`/`around` because a pattern that matches every line makes the *result count* meaningless -- you cannot tell "found a lot" from "matched everything trivially". `between` has no result count: it just wants the first line matching `start`. A pattern like `foo|.*` (an alternation branch that matches the empty string) is a perfectly legitimate, previously-working `start` spec for `between` -- e.g. "match the very first line" -- and now gets refused with:

```
ERROR: pattern `foo|.*` has an alternation branch `.*` that matches the empty string, so the whole pattern matches every line of every file scanned. That is a saturated pattern, not a search, and its result count is indistinguishable from a search that genuinely found a lot.
```

Two problems in one: (1) a functional regression -- a non-adversarial, previously-working `between` call now errors; (2) the error text itself talks about "result count", a grep-specific concept `between` does not have, so the message is actively confusing for this op.

Found by the self-review's `Explore` reviewer on PR for #2571, confirmed live: `_supertool._pattern_gate('foo|.*')` returns that refusal.

Not fixed in #2571 itself: whether `between` should get a carve-out from the saturation check (and if so, what the message should say for a non-`grep` caller) is a design decision -- `_pattern_gate`'s docstring frames single-sourcing all four checks as the fix for #1344's route-by-route drift, so un-sharing one check for one call site reopens exactly that hazard, and doing it safely needs its own look at whether `read`'s `grep_filter` or any other route has the same mismatch. Ranked non-blocking (functional regression on a narrow, likely-rare pattern shape, not a security or data-loss issue) -- logged here rather than filed, per the ranking table's "can ship behind a trap.d fragment" row.
