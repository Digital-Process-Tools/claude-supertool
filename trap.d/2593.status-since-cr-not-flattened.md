`presets/youtube/status_since.py:118`, `:125`, `:126`, `:181` flatten `\n`
only (`.replace("\n", " ")`) on `authorDisplayName`, `textDisplay` and the
video `title` before rendering them inline.

In the same delta, issue #2636 (`45e2c081`) established
`.replace("\r", " ").replace("\n", " ")` at eight other sanitizer/read sites
(`presets/youtube/_sanitize.py:102`, `read.py:91`, plus the bluesky/devto/
hashnode copies) for exactly this reason -- `str.splitlines()` also splits on
a bare `\r`, so an unflattened CR from a stranger's display name or comment
text reaches column 0 of the receipt. `status_since.py` is a new file in this
same delta (issue #2593) and missed that pattern.

Ranked `misreports` (non-blocking), following the repo's own prior handling
of this exact class (issue #2636). Settling fact before folding into a fix:
whether YouTube Data API v3 can actually deliver a bare CR in `textDisplay`
(it is HTML-formatted) or `authorDisplayName` -- if unreachable in practice
this may not be worth its own patch, only a note.
