`~/.config/bluesky/session.json` is shared by every Bluesky-touching preset and the
`bluesky-engagement` watch source alike (`presets/bluesky/_atproto.py::SESSION_FILE` and
`presets/watch/sources/bluesky-engagement/poller.py::SESSION_FILE` both resolve to the same
path). #2484's fix made the *permission* narrowing atomic (`os.open(..., 0o600)` instead of
write-then-chmod), but the *write itself* is still not atomic with respect to other processes:
`os.open(O_TRUNC)` truncates in place, so a concurrent reader (another poller tick, another CLI
invocation refreshing its own session) can observe a half-written or truncated-then-partially-
rewritten file mid-write, not just a permission race. A crash between truncate and the write
completing would also leave a corrupt (but zero-byte or partial) session file rather than either
the old or the new content.

Named out of scope for #2484 by that issue's own body ("non-atomic shared write ... is
deliberately out of scope here"). The standard fix is write-to-tempfile-then-`os.replace()` in
the same directory (same filesystem, so the rename is atomic), created with the same `0o600`
mode this issue just pinned. Two independent call sites would need it -- the same duplication
question this issue already flagged: no shared helper exists between the two files today. Logged,
not decided
whether it is worth a dedicated issue or is low-severity enough to fold into some other pass over
this module.
