# The fallback TOML parser silently merges a repeated single [table] header instead of erroring

Found by `oss:auditor` reviewing #2473's own fix (single `[table]` header support added to
`_mini_toml_loads`). `_supertool.py`'s new `[table]` branch does `table = result.setdefault(name, {})`
-- reopening an already-declared single-`[table]` header in place and silently merging its keys
rather than raising.

```
raw = "[a]\nx = 1\n[a]\ny = 2\n"
supertool._mini_toml_loads(raw)   -> {'a': {'x': 1, 'y': 2}}   # no error
tomllib.loads(raw)                -> TOMLDecodeError: Cannot declare ('a',) twice (at line 3, column 3)
```

That is a real divergence between stdlib `tomllib` (Python 3.11+) and this fallback (3.9/3.10,
two of CI's own legs) on the *same input text* -- the exact class of bug #684 already fixed one
level up (the parsers now agree on escaping). A caller cannot tell "my payload had a genuine
duplicate-header typo" from "it merged silently and produced a partially-wrong document," and
which one happens depends on which Python interpreter the op happens to run under.

Neither changed test file in #2473 (`tests/test_toml_ops_detect_357.py`,
`tests/test_toml_single_table_header_2473.py`) exercises a repeated single `[table]` header --
only `[[table]]` positive-control and dotted-name-refused cases are covered.

Ranked `misreports` per `skills/manager/phases/findings.md`'s table -- non-blocking, ships behind
this fragment. `/oss:curate` decides later whether this becomes a permanent rule or a follow-up
issue (e.g. raise `ValueError` on a repeated single `[table]` header, matching `[[table]]`'s own
repeat-name collision guard, which already errors).
