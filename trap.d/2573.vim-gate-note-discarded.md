Issue #2573's fix routes op_vim's 9 raw-pattern entry points through `_pattern_gate`, which returns `(effective, refusal, note)`. All 9 sites bind the third element as `_gate_note` and never read it again -- confirmed by grep, `_gate_note` appears only in the 9 assignment tuples and nowhere else in `_op_vim_impl`.

`note` is `_bre_rewrite_note`'s output: the disclosure that fires whenever `_bre_alternation_rewrite` silently turns a caller's bash-grep-style `\|` into Python's plain `|` alternation operator (`_supertool.py:6734-6745`, `_BRE_ALT = "\|"`). Every other existing caller of `_pattern_gate` prints this note when non-empty -- `op_grep` (~6952-6957), `op_around` (~7523), and `op_between_pattern`'s `start`/`end` (~7745-7748, added by #2571). op_vim computes the identical note at all 9 of its new sites and silently discards it every time.

Concretely: a caller typing `/foo\|bar` in an op_vim script gets `\|` rewritten to alternation (which happens to match real vim's own `\|`-is-alternation semantics, so the rewrite itself is arguably correct) with zero indication in the op's output that anything was rewritten -- unlike the identical rewrite surfaced everywhere else `_pattern_gate` is used.

Found by the self-review's `oss:auditor` reviewer on the PR for #2573 (Class B: "a guard that did not run" -- more precisely here, a disclosure that did not run). Not reproduced beyond reading the source: the auditor noted no existing test in `tests/test_pattern_gate_vim_2573.py` or elsewhere exercises a `\|`-containing pattern through op_vim, so whether the note is ever actually non-empty on this path (as opposed to always empty because `_bre_alternation_rewrite` never fires for op_vim's typical inputs) is `reasoned`, not `observed`.

Not fixed in #2573 itself: surfacing the note would mean touching all 9 log.append call sites (each with a different message shape -- some append immediately after the gate call, some several lines later after a retry ladder that may have further mutated `pat`), which is more invasive than the security fix itself and risks widening the diff's blast radius past what a focused ReDoS-guard PR should carry. Ranked non-blocking (a missing disclosure, not a missing guard -- the length cap and backtracking guard still fire regardless of whether the rewrite note is shown) -- logged here rather than filed, per the ranking table's "can ship behind a trap.d fragment" row.
