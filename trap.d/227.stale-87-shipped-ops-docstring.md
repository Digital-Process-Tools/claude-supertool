While sweeping this repo's test suite for census/inventory-style guards that
enumerate shipped ops by name or count (#227, prompted by two CI failures on
PR #2527 that were exactly this shape -- tests/test_custom_op_dropped_tokens_873.py
and tests/test_replaces_census_1384.py, both fixed), one more stale count
turned up that does NOT fail CI, so it was left alone rather than fixed in
that commit:

`tests/test_cmd_placeholder_path_detector_1350.py`'s
`test_a_path_naming_syntax_still_fires_with_no_cmd_placeholder` docstring says
"the cmd detector currently matches zero of the 87 shipped ops" -- this is
prose, not an assertion, so it does not fail when the true shipped-op count
moves (it is 98 as of #227, having been 87 at some point before #873/#1384
bumped it further). Nothing in this file asserts the total shipped-op count
itself; the numbers it does assert (25 syntax-gated ops, per
`test_the_arg_lint_would_reach_no_op...`-style counts elsewhere) are unrelated
and unaffected.

Worth a housekeeping pass to either derive this number rather than hardcode
it in prose, or accept that a docstring reference to a total population will
always drift and stop citing an exact figure there. Not urgent since it
never causes a red build; logged so it does not have to be rediscovered by
the next person sweeping this same class of test.
