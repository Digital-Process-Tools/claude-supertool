While updating a developer report JSON in place (a `files` array, one entry
per touched file), needed to append a new entry to that array. `json-set`
only sets scalar/object leaf values at a dotted path -- it has no append
verb, and there is no existing index to set a new array element's path at
in advance (the array's current length has to be known first, which is a
second read-then-write round trip `json-set`'s one-shot design does not
offer). Ended up writing the append with a raw `python3 -c 'json.load /
list.append / json.dump'` inline script instead of going through a
supertool op -- exactly the "raw, unvalidated python3 -c transform" #1822's
own motivation section calls out as the failure mode json-set exists to
replace, just for the append case rather than the field-set case.

Not deciding here whether json-set should grow an append verb, or whether
this is a `paste`-the-whole-file case instead (report JSON files are small
enough that whole-file re-send is proportional) -- just logging that the
report-update workflow this repo's developer brief describes (update the
same report JSON across several follow-up passes, appending to its `files`
array each time) has no op-covered path today for the array-append shape,
only for the field-set shape.
