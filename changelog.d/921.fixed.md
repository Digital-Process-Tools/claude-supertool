- **`grep` handed a comma-separated path list no longer blames the CWD** ([#921](https://github.com/Digital-Process-Tools/claude-supertool/issues/921)). `grep:mark.slow:tests/a.py,tests/b.py,tests/c.py` joined the list into one filename, failed, and offered `wrong CWD? Prefix the call with cwd:PATH` — the one remedy that provably could not apply, since all three files resolved from the current directory. Following it produces the same error a second time, and the working fallback is to grep the parent directory instead: 391 files scanned to answer a question about three.

  The list is still refused — `git-resolve` accepts `PATH[,PATH...]` and `grep` does not, and quietly making it work here would be a second spelling to remember rather than one fewer. What changed is that the refusal names the cause and states what it checked: `a comma-separated list is not accepted here — grep takes ONE path, and the whole list was read as a single filename (all 3 of its entries exist, so the cwd is not the problem)`. When only some entries resolve it says `2 of 3` rather than implying all; when none of them do it stays silent and the ordinary CWD advice stands, because a path with a literal comma that is simply absent is a typo, and inventing a list there would trade one misreport for another.
