- **`append` hardcoded an LF terminator on the content it appended, regardless of the target file's own newline convention, and never disclosed a mix it created.** Appending an unterminated block to an all-CRLF file silently produced a mixed-newline file with a receipt saying nothing about it -- one step earlier than the sibling defect #1075 already fixed for `replace_lines`, since `append` never went through the newline-convention machinery at all. It now adopts the file's own convention (scanned backwards from EOF, the same `_local_newline` helper `replace_lines` uses) for the terminator it has to invent, and discloses through `_newline_note` -- computed from the file as written, not as it was found -- when the result is genuinely mixed. The caller's own text is never rewritten, only the ending invented when `content` carries none. [#1085](https://github.com/Digital-Process-Tools/claude-supertool/issues/1085)
