- **The two radar tiers no longer assert `killed by signal N` on a returncode nobody has observed on Windows** ([#1871](https://github.com/Digital-Process-Tools/claude-supertool/issues/1871)). `gh_prs.py` and `gl_mrs.py` both fire on `result.returncode < 0`; on POSIX `subprocess` documents `-N` for a signal, so the old wording was exact there. On Windows the same field is the process exit status, and `_winapi.GetExitCodeProcess` is declared `unsigned long`, so a negative value is unexpected — but the negative spelling of the same DWORD circulates widely enough (shells, Python 2) that the premise is worth distrusting without a runner to check it on. Reasoned, not observed, in either direction.

  Both tiers now state the returncode, which is true on every platform, and hedge the mechanism rather than asserting it: `"...did not finish before it answered (returncode -9, consistent with a killing signal on POSIX — not established on Windows, see #1871): ..."`. The classification — the process did not finish, retry — is unchanged; only the vocabulary moved. One change to both tiers, matching the wording drift PR [#1869](https://github.com/Digital-Process-Tools/claude-supertool/issues/1869) had already removed once between them.
