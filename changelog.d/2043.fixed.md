- **The `slack` watch source no longer gets stuck forever on its first tick** ([#2043](https://github.com/Digital-Process-Tools/claude-supertool/issues/2043)). A watcher with no stored cursor used to ask for the whole channel history; on any channel with more than ~1000 messages that exhausted `MAX_PAGES` and the burst guard refused, correctly — but the refusal left the cursor unset, so every later tick repeated the identical request and refused identically, forever. A cold start now anchors on the channel's single latest message (`limit=1`) instead of replaying history, stores its `ts` as the cursor, and emits nothing; delivery begins with the next message posted, the documented semantic for a stream source. `presets/watch/sources/slack/poller.py`, `docs/presets/watch.md`.
