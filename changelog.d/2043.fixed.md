- **The `slack` watch source no longer gets stuck forever on its first tick** ([#2043](https://github.com/Digital-Process-Tools/claude-supertool/issues/2043)). A watcher with no stored cursor used to ask for the whole channel history; on any channel with more than ~1000 messages that exhausted `MAX_PAGES` and the burst guard refused, correctly — but the refusal left the cursor unset, so every later tick repeated the identical request and refused identically, forever. A cold start now anchors on the latest message instead of replaying history, stores its `ts` as the cursor, and emits nothing; delivery begins with the next message posted, the documented semantic for a stream source. A bare channel does this with one `limit=1` call (`conversations.history` is newest-first); a thread's `conversations.replies` is oldest-first, so a thread anchor instead pages through the thread (same `MAX_PAGES` budget as a catch-up tick) to find its newest reply rather than mistaking the thread's root message for "latest". `presets/watch/sources/slack/poller.py`, `docs/presets/watch.md`.
