- **The front page taught an idiom the payload route does not implement** ([#1134](https://github.com/Digital-Process-Tools/claude-supertool/issues/1134)). `.supertool.json`'s `introduction` — the first text every session reads — said to write `chr(10)`/`chr(27)` instead of a newline or an ESC in payload content. A payload is parsed, never evaluated: measured on the real edit route, `chr(10)` puts the seven characters `c h r ( 1 0 )` into the file and the receipt still says `edited` — a corrupted file behind a green write receipt, arriving through the documentation rather than through the validator. The same sentence shipped in `.supertool.example.json`, which every downstream project copies, and `docs/operations/edits.md` repeated it while attributing it to the ops listing, which never said it. All three now name the working idiom instead: a real newline inside the literal block, or a basic block where TOML escapes are processed (`\u001b` for an ESC; `\x1b` is not TOML and is refused at parse time). A test measures the route and then scans every guidance surface for the idiom that measurement disproves, so prose and behaviour cannot drift apart silently again.
