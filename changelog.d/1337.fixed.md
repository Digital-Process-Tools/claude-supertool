- **`session_path()` now discloses when a session UUID resolved from a store that is not the caller's own** ([#1337](https://github.com/Digital-Process-Tools/claude-supertool/issues/1337)). Given a bare UUID it has always scanned every project store under `~/.claude/projects` and returned the first match — deliberate, and still correct, since a session id is globally unique. #1317 fixed the sibling substitution class for `resolve_project_dir()` (the store-resolution path used when no UUID is given) by walking upward only and declining sideways, and left `session_path()` unchanged on purpose: unlike that path, a cross-store scan hit here genuinely answers the caller's question, it just did not say which store answered. `session_path()` now returns `(path, note)`: `note` is `""` for a direct hit or no hit at all, the same ancestor-substitution text `source_note()` already prints elsewhere in this family when the caller's own resolved store is itself an ancestor's, and a new cross-project note — worded against the caller's own resolved `kind` rather than assuming a direct hit — when the UUID was found in a genuinely unrelated store. `tail.py`, `summary.py` and `cost.py` all print the note when it is non-empty.

  Self-review caught two defects before this shipped: `cost.py`'s no-UUID default path (list recent sessions, no arguments) shadowed the module-level `source_note` import with a same-named local inside `session_path()`'s tuple unpack, raising `UnboundLocalError` on every invocation that reached an existing project store — its own default, most-used code path, missed by this change's new tests because they all pass a UUID and caught only by an unrelated pre-existing test file the diff had not been run against. And the new cross-store note's em dash is now guarded by `use_utf8_stdout()` in `tail.py`/`summary.py`, the same guard `cost.py` already carried (#1388) — unguarded, it would raise on a Windows console using a codepage that cannot represent the glyph.
