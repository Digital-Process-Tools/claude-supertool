- `read`'s inline `grep=` filter now goes through the same pattern gate as `grep`, `grep_around` and `around` (#1344). It had been wired to neither half of it: `read:probe.txt:::grep=^|x` returned every line of the file under an ordinary `(2 lines, 8 bytes)` header — nothing looks impossible, and what the caller takes away is that every one of those lines matched the pattern they typed. A saturating filter is now refused on this route too, rather than disclosed: the whole file already has a spelling (`read:PATH`), so the refusal removes no call anyone meant. bash-grep BRE alternation is rewritten here as well, so `read:PATH:::grep=alpha\|gamma` filters on either branch instead of searching for a literal `alpha|gamma` — and the rewrite is disclosed, never silent, which is the trap #1344 was filed to avoid. Both decisions live in one function (`_pattern_gate`), pinned by a test, so a fifth route cannot inherit a third behaviour.
