- `git-worktrees` takes the publication count against the remote the branch
  actually tracks, and the row names that ref (#1525). The ref used to be
  chosen by preferring `origin` unconditionally whenever two remotes carried
  the same branch name, and the sentence reporting the count named no remote at
  all — so on a fork layout (upstream `fork/X`, an `origin/X` at a different
  commit) the row answered a question nobody asked and the reader could not
  check it. Measured on a two-remote sandbox before the fix: a branch one
  commit ahead of its `fork` upstream read *in sync with its remote ref … the
  work is published but unproposed*.
- A branch with **no upstream** is a third state, not a zero. The same-named
  ref is still measured — the commits really are on it — but the row says it
  was `picked by name: this branch has no upstream configured` (#1525).
- A branch whose upstream is **not in this clone** — deleted on the remote, or
  never fetched — is not measured at all, rather than counted against whichever
  other remote carries the name. The row reads `sync not measured, no open PR`
  and names the ref it was looking for. That token is new and is the point:
  *not measured* used to render as `no open PR`, identical to *measured,
  nothing missing* (#1525).
