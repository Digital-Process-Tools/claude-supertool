- **`bin/supertool-workspace` is gone; the `oss` plugin's `bin/oss-workspace` replaces it** ([#1729](https://github.com/Digital-Process-Tools/claude-supertool/issues/1729)). Every behaviour the local launcher had is in the plugin's — the clone resolved from the script's own location, `SUPERTOOL_WATCH_NAME` derived from the CWD's `.supertool.json` op blocks with a refusal when they disagree, an already-exported name winning and both values named, the consumer registered at local scope with an absolute path, and the development-channel flag passed only when that registration held. Two things it did not have are there: `CDPATH` is cleared before any `cd`, and a `.supertool.json` declaring no radar tiers is reported rather than launching a board that is armed and delivers nothing. Keeping a 197-line subset here meant every fix landed twice or once, and the copy that was not this repo's problem was the one that shipped to everybody. `tests/test_workspace_launcher_1541.py` and `tests/test_workspace_channel_name_1538.py` go with it — they test a launcher this repository no longer owns, and belong against `bin/oss-workspace` in `claude-oss`.
