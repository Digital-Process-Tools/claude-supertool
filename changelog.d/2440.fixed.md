- **The trap.d local-path guard's own reach was narrower than the leak class it names, and two live username leaks sat outside it** ([#2440](https://github.com/Digital-Process-Tools/claude-supertool/issues/2440)). `test_trap_d_no_local_paths_2426.py`'s docstring frames the defect as a property of anything this repo ships, but its sweep was `trap.d/*.md` alone -- so `presets/claude-log/_common.py` and `CHANGELOG.md` each shipped the maintainer's own dash-flattened home-directory path, unredacted, since the v0.34.0 release (`ef0d4e3e`), with nothing checking either file. Both are now redacted to a generic `<maintainer>` placeholder, the shared regex the trap.d guard used is factored out into `tests/_local_path_scan.py` so it is not reimplemented a second time, and a new guard (`tests/test_shipped_artifact_no_username_leak_2440.py`) sweeps the whole tracked tree outside `tests/` and `trap.d/` for this repo's own known-real leaked identities -- narrower than a fully generic username scan, deliberately, since this repo's docs and presets use single-word placeholder paths (`/Users/x`, `/home/dev`, ...) throughout that a generic scan would drown the real signal in.
