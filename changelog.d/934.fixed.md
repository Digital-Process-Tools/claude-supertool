- **The changelog fragment guard is a whitelist now, after a blacklist lost twice in one release** ([#934](https://github.com/Digital-Process-Tools/claude-supertool/issues/934)). [#927](https://github.com/Digital-Process-Tools/claude-supertool/pull/927) refused fragment lines matching heading and link-reference patterns anchored at column 0, and [#930](https://github.com/Digital-Process-Tools/claude-supertool/issues/930) found three bypasses. [#932](https://github.com/Digital-Process-Tools/claude-supertool/pull/932) widened them to `0-3` spaces and made labels case-insensitive, and the very next audit found **six more** — a link label split across two lines, the same lowercase, label and destination both split, a `>` prefix, a four-space indent inside the list item, and a tab — plus a heading class the patterns never modelled at all (setext underlines and raw HTML), plus a false refusal, plus documentation whose prescribed remedy was itself an injection. Each one produced `ok` on both disclosure surfaces while the released `CHANGELOG.md` carried the injected line.

  **The finding was the approach, not the patterns.** Enumerating what CommonMark can do is unbounded; what a fragment is allowed to *be* is small and was already written down. So the rule is now stated positively and everything else is refused: **a fragment is one or more `- ` bullets at column 0, every other line blank or indented at least two spaces under one, and — fenced code blocks excepted — no line opens anything but a list item, a table row or ordinary prose.** All nine vectors are out by construction rather than by being named, and a tenth nobody has thought of is out on the same terms.

  **The prescribed remedy was the worst part, and it was wrong by a container.** Both the refusal message and `changelog.d/README.md` told authors to indent a quoted heading by four spaces. CommonMark's four-column code-block threshold is relative to the containing block's content column, and every fragment is a `- ` bullet whose content column is 2 — so four spaces is *two* relative columns: an ordinary paragraph, in which a heading is a live heading and a link-reference definition resolves. Following the guard's own advice produced the injection it had just refused. The remedy is a fenced code block at the bullet's own indent, which is what every fenced example in the shipped `CHANGELOG.md` already does.

  **Fences are parsed now, reversing a decision taken twice.** #927 and #932 each declined fence-awareness because nothing downstream understands fences, so a fence bought no safety. That was an argument about the assembler's own column-scoped scanners, and it does not survive the inversion: the whitelist keeps those safe by position instead, since no body line ever reaches column 0 except a `- ` bullet. That leaves the fence free to do what it measurably does for a reader's parser — make its contents inert — so the `# comment` inside a ```bash block that #932 refused is an ordinary entry again.

  **Measured against the shipped file rather than against the docs.** Every entry body in `CHANGELOG.md` uses exactly two indents, 0 and 2; every column-0 line is a `- ` bullet; all eight fenced blocks open at indent 2; there are no blockquotes, no raw HTML, no headings and no definitions outside fences, and zero tabs in 2,737 lines. A pin feeds all 360-odd shipped entries back through the guard, so a rule that would refuse this repo's own published work fails the suite. A `>` quote is stripped and its contents checked rather than refused outright, because refusing the marker would have cost an author a legitimate construct for no safety.

  **Verified with a real CommonMark parser, not by reasoning about the spec**, which is how two confident guards shipped wrong. `markdown-it-py` is a dev dependency and `tests/test_changelog_fragment_whitelist_934.py` renders every refused vector and asserts it really produces an `<h1>` or really resolves a label to the attacker's URL, and renders every accepted entry and asserts it does neither. That is also how a pin in the previous round turned out to be pinning a live heading as safe: `test_a_leading_tab_is_already_the_remedy` asserted that a tab-indented `## [0.26.0]` is inert, and it is not — a tab reaches column 4, which inside a bullet is the second relative column. That test is inverted rather than deleted, because a test that blessed an injection is the record of how this was missed.

  **The receipt states the shape.** `--check` no longer mentions a column at all: naming where a pattern is anchored is what stayed literally true through three bypasses and then six more, while the released file carried the lines. It now reports that every body is `- ` bullets plus lines indented under them, and that none can open a heading or a link ref of `CHANGELOG.md` at any indent or nesting.
