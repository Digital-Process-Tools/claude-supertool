- **The test suite no longer leaks `git fsmonitor--daemon` processes through its temp repos** ([#1892](https://github.com/Digital-Process-Tools/claude-supertool/issues/1892)). Three independent measurements on one machine on 2026-08-21 found 965-979 orphaned daemons at `ppid 1`; with them present, a full suite run hung at 98% for over an hour and a plain `git add` in a fresh temp repo timed out at 30 seconds. `git fsmonitor--daemon run --detach` is by design started once per repository and never torn down by the repository closing — and the suite creates thousands of them, each inheriting whatever `core.fsmonitor` an operator has set globally, an ordinary preference rather than a defect.

  `tests/conftest.py` now sets `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=core.fsmonitor`, `GIT_CONFIG_VALUE_0=false` once, in `pytest_configure`, before any fixture runs. Every `git init` in the suite is a bare `subprocess.run(["git", ...])` with no `env=`, so it inherits the pytest process's environment and the suppression reaches all of them without touching the 27+ files that create one — there is no single shared repo-creation helper to patch instead. A test that deliberately wants the daemon can still force it with `-c core.fsmonitor=true` on the individual invocation, which outranks the environment.
