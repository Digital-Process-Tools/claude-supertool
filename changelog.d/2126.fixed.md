- **`help:gh-pr-create` no longer claims the pull request "opens either way" when a body carries no working `Closes #N`** ([#2126](https://github.com/Digital-Process-Tools/claude-supertool/issues/2126)). `presets/github.json`'s own description still said "Reported, NOT refused: the pull request is opened either way and the exit code is 0" -- the behaviour [#1970](https://github.com/Digital-Process-Tools/claude-supertool/issues/1970) replaced with a refusal (nothing created, non-zero exit, escaped with `no_close = true` for a deliberate `Part of #N` pull request). `docs/presets/github.md` carried the same stale claim and is corrected with it. The help text is the contract other projects document against, and one already had.

  The same description also still said a **malformed** `Closes` line is "reported at creation" -- true before #1970, false since: a malformed reference hits the identical empty-refs refusal as no reference at all, which `pr_create.py`'s own module docstring already called "caught" and `docs/presets/github.md` already said too. Corrected to `caught` for consistency, and the #1835 test that pinned the old "reported" wording (`test_gh_pr_create_does_not_claim_to_catch_a_malformed_closing_line`) is updated with it.
