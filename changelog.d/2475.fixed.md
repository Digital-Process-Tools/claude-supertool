- **`.mcp.json`'s `claude-channel` entry no longer warns `Missing environment variables: CLAUDE_PLUGIN_ROOT` when read as project config** ([#2475](https://github.com/Digital-Process-Tools/claude-supertool/issues/2475)). The same tracked file is read at two scopes — as the plugin's own MCP config, where `${CLAUDE_PLUGIN_ROOT}` is set by the harness, and as *project*-scope config for anyone with this checkout open, where it is not — so every contributor opening a session here got `claude mcp list` reporting a server that could never start. The declaration itself could not simply be dropped: `.mcp.json` is the only registration path for a plugin-installed user who never runs `oss-workspace`, so removing it would be a feature regression for them. The script path now reads `${CLAUDE_PLUGIN_ROOT:-.}/notifiers/claude-channel/start.mjs` — Claude Code's own `${VAR:-default}` expansion syntax — which suppresses the warning and happens to resolve correctly too, since a project-scope MCP server is spawned with cwd set to the active project, which at project scope *is* this repo's own root. That does not reopen the #2051 two-consumer socket collision: `.claude/settings.json`'s `disabledMcpjsonServers` (#2221) still stops the entry from actually starting at project scope, so the fallback only removes a spurious warning about a substitution that was never going to matter.
