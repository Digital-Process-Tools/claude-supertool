- **A `youtube` preset adds discovery ops for the YouTube Data API v3** ([#227](https://github.com/Digital-Process-Tools/claude-supertool/issues/227)): `youtube_search:QUERY[|N]`, `youtube_read:VIDEO_ID_OR_URL` (video metadata + top inline comments), and `youtube_list:CHANNEL[|N]` (a channel's uploads). API-key auth only, following this repo's existing credential-resolution convention (env var, then `~/.config/youtube/api_key`, then a cwd dotfile) rather than the bare single-path convention the issue itself proposed. All three go through `presets/_http.py`'s shared redirect-refusal and size/deadline-capped opener, so no new raw `urllib.request.urlopen(` call site is introduced. The OAuth2 write ops the issue also describes (`youtube_comment`, `youtube_reply`, `youtube_like`, `youtube_status_since`) are out of scope for this slice -- the issue itself proposes splitting them into a second pull request behind an explicit OAuth setup, and this one implements only the low-blast-radius read half.
