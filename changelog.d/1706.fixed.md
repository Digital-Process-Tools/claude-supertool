- **A guard refusal no longer closes by naming a harness write tool as the route past it** ([#1706](https://github.com/Digital-Process-Tools/claude-supertool/issues/1706)). Every `deny` ended "a harness Edit/Write reaches this same path with no op, no validator and no rollback" — a working bypass spelled out in the one sentence a blocked agent is guaranteed to read, and an agent that takes it loses the validator chain and the write rollback the refusal exists to route it into. Inert in this repository, where the `harness-tools-blocked` rule denies those tools; live for every plugin user, which is who the plugin ships to. **Not a revert of [#1671](https://github.com/Digital-Process-Tools/claude-supertool/issues/1671):** the refusal still says the gate hooks Bash only, that the denial is about the route and not the path, and that any other route to the file gets no op, no validator and no rollback. Only the tool name is gone. The names stay on the surfaces where a reader is deciding rather than being denied — the SessionStart roster, `docs/configuration.md`'s `raw_command_guard` section and the README deny-list recipe — and all three are asserted, so this is a move rather than a deletion.
