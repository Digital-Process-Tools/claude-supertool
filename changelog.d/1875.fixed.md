- **`.githooks/pre-push` now runs the suite under `-X utf8`, the flag CI has carried deliberately since #546** ([#1875](https://github.com/Digital-Process-Tools/claude-supertool/issues/1875)). The hook and `.github/workflows/tests.yml` disagreed about the one flag that decides how a non-ASCII failure message is rendered, and the hook was the exposed half: CI's Windows leg had the flag, a local `git push` did not. pytest writes failure lines on a stream whose codec is the console codepage, so on a codepage that cannot carry the character the local run and the CI run describe the same failure differently.

  **The issue's stated symptom was wrong, and correcting it is what settled the design question.** #1875 said the missing flag makes pytest raise `UnicodeEncodeError` while reporting. It does not — `TerminalWriter.write_raw` catches exactly that and re-emits the line unicode-escaped, so the strict-stream outcome is a diagnostic degraded to a backslash-u escape, not a destroyed one. The genuinely destroyed outcome is the U+FFFD that #546 measured on `windows-latest`, where the stream substitutes instead of raising and pytest's fallback never fires. Observed here on darwin under a latin-1 stdio codec: without the flag a failure message carrying U+0662 comes out escaped, with it the character survives. That the same holds for a Windows console codepage is reasoned, not observed, and whether any Windows user runs this hook is still unmeasured.

  **The alternative the issue offered — `ascii()` at each assertion site — was rejected rather than deferred.** It cannot reach pytest's rendering of compared values, where `assert DIGITS.match(probe)` prints the probe with no message for a source edit to touch; and the ten sites the issue estimated are 430 assert messages across 184 test files once counted, excluding the runtime-valued ones that are the actual shape and cannot be found statically. A flag on the emitter covers all of it in one line. A repo-wide convention against non-ASCII in assertion messages would be a house-style change against prose that uses em dashes on purpose, and belongs in its own issue if it is ever wanted.

  Pinned behaviourally rather than by substring: `tests/test_prepush_utf8_mode_1875.py` runs the hook against the #572 stub interpreters and asserts on the argv it really issued, reads the flag off both the hook and the workflow so dropping it from either goes red, and reproduces the rendering difference with a positive control that fails loudly if the locale stops reproducing anything. Where no non-UTF-8 locale exists the reproduction skips saying what went untested.
