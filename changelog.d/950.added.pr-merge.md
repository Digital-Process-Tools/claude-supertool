- **`gh-pr-merge:NUMBER` — merge a PR, then prove it landed** ([#950](https://github.com/Digital-Process-Tools/claude-supertool/issues/950)). Replaces four hand-rolled calls, one of which was a hand-written `jq` expression sitting in the middle of the maintainer's merge path — and a hand-rolled `jq` over check states is what produced [#454](https://github.com/Digital-Process-Tools/claude-supertool/issues/454), where a `CANCELLED` leg counted as neither a pass nor a pending and very nearly merged a run that had already concluded `failure`.

  **This is the first op in the family that writes, so the refusal surface is the design.** It refuses a PR that is not `OPEN`, a draft, one GitHub reports `CONFLICTING`, one whose `mergeable` is `UNKNOWN`, one whose merge state is not `CLEAN`, one with `CHANGES_REQUESTED`, one with zero check runs, one whose rollup could not be read, and one whose legs are not all green — where green is #454's arithmetic and `CANCELLED`, `SKIPPED`, `TIMED_OUT`, `NEUTRAL` and `ACTION_REQUIRED` are each named and none is permission. A tally it could not reconcile against what the runs declare is a refusal too: every leg *read* passing is not the claim that every leg passed, which is the call `gh-branch`'s own verdict already makes. Pending legs are named here even though the shared disclosure helper drops them — that exclusion is right for a status board and wrong for a gate, where which legs you are waiting on is the entire question. There is no green-bypass; a refusal names the raw command instead. Without `|force` the op prints the gate and merges nothing, through the same confirmation gate the publish ops use.

  **Nothing is inferred from an exit code.** `gh pr merge` can print nothing at all on success, so `state`, `mergedAt` and `mergeCommit.oid` are read back off the remote and all three must arrive before the merge is called verified.

  **Then every linked issue, named individually, with its verified state.** The body's own closing references are reconciled against GitHub's `closingIssuesReferences`, and the disagreement between them is the finding: read against the API on 2026-08-07, eleven of the last twelve merged PRs here had their declared reference bound and PR #908 did not — its body said `Closes #899`, GitHub bound nothing, and no error was raised anywhere. Every issue that did not close carries the exact command to close it by hand; a lookup that failed renders as `unknown` with its reason, never as closed and never omitted. A merge that lands while an issue stays open is rendered as both facts at once, implies no rollback, and does not exit 0.

  The default branch's state after the squash is reported separately via `gh-branch`, because a green PR is a statement about its merge-base and that gap has left `master` red for hours with the board reading clean. Branch cleanup is named and never run — chaining a delete onto a merge once deleted the branch and auto-closed the PR when the merge had failed on a conflict.
