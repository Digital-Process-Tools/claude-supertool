- **The printed cleanup command had no "default branch could not be read" state, so it handed over the DELETE the cleanup arm would have refused** ([#1292](https://github.com/Digital-Process-Tools/claude-supertool/issues/1292)). `run_cleanup` refuses all three items when this repository's default branch is unestablished — one of the four facts #1281 established a delete needs. The **command-printing** path, which is the default one and the one a human actually pastes, tested only whether the head was cross-repository or equal to the default branch. An **empty** default branch satisfies neither: `""` is not the head. So it fell straight through and printed a ready-to-paste `gh api -X DELETE .../refs/heads/<head>` having never established that the head is not the branch it was about to delete.

  Empty is a reachable answer rather than an impossible one. `_repo_identity` returns it whenever the API reply lacks `defaultBranchRef.name`, `main()` bails only on the repository half, and the section header three lines above already renders `default_branch or '?'` — the file elsewhere knows the value can be missing.

  The printed arm now tests the same three conditions as `run_cleanup`, **in the same order**, and picks its stated reason in that order too, so the two arms cannot report different grounds for one refusal. The file's own comment already called a printed delete "the same decision made by the reader"; it is now the same decision in code as well. Quoting makes a wrong command safe to paste — it does not make it right.
