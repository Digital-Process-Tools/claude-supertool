- The guard can now read an exclusion flag standing behind another flag on the git subcommands it gates, so
  `git commit --no-verify --amend` is un-claimed silently instead of allowed with "the guard did not run"
  ([#1816](https://github.com/Digital-Process-Tools/claude-supertool/issues/1816)). `_GUARD_VALUELESS_FLAGS` carries
  which flags consume no separate value for `git commit`, `git push`, `git status` and `git worktree list`, measured
  from `git <sub> -h` on git 2.46.2. Only that half is tabled: a flag absent from it stays ambiguous, allowed and
  disclosed, and both ways the table can age land on allowing more rather than on manufacturing a block. gh is
  deliberately not in it. The allow decision is unchanged for every command.
- When the guard still cannot read a flag, the note now names **which op's claim went unevaluated** and what a
  readable re-issue would be, rather than reporting only that a check was skipped
  ([#1816](https://github.com/Digital-Process-Tools/claude-supertool/issues/1816)).
