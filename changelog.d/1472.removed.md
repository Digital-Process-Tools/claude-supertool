- **`oss_train` is gone** ([#1472](https://github.com/Digital-Process-Tools/claude-supertool/issues/1472)). It batch-rebased and force-pushed every branch under `~/Documents/st-wt` in one call, and it automated a problem that [#906](https://github.com/Digital-Process-Tools/claude-supertool/issues/906) removed: per-issue `changelog.d/` fragments mean two open PRs share no file. Measured 2026-08-12 — eight PRs merged in one afternoon, zero rebases, not one call to it. What it did, `git-push` now does per branch on demand, at the moment the branch needs it. Against that it carried three containment-class repairs in four days — [#1246](https://github.com/Digital-Process-Tools/claude-supertool/issues/1246) (it force-pushed any repository the caller named), [#1247](https://github.com/Digital-Process-Tools/claude-supertool/issues/1247), [#1298](https://github.com/Digital-Process-Tools/claude-supertool/issues/1298) (a pre-rebase guard reading a `git status` configured not to look; it went on to force-push a worktree an agent was working in) — on a tool with no caller.

  Nothing else batch-rebases N branches. That is deliberate, and bringing it back is a decision to make deliberately rather than by improvising a force-push loop: `docs/contributing.md` records the contract those three issues cost.

- **The path-declaration detector's `cmd` arm keeps a live instance.** `_entry_names_a_path` reads two signals OR'd — a `PATH`/`FILE` component in `syntax`, or `{file}`/`{dir}` in the `cmd` template. `oss_train` was the **only** shipped op the second arm found, so deleting it would have left that half with zero instances: the guard still compiles, every test around the first arm still passes, and nothing reports that half stopped being exercised. A check with no instance is indistinguishable from a check that passes, which is this repo's signature defect landing inside the guard built to prevent it. The arm now has a fixture — a real `.supertool.json` written to disk, read by `_load_config()` and driven through `dispatch()`, so it reaches the detector by the route a shipped project op takes rather than by being handed the entry as a literal. Its reach is asserted rather than assumed: the same fixture, declared, runs its command end to end, which is the control saying the refusal came from the detector and not from something earlier declining the op. Verified red by disabling the arm — the undeclared fixture then returned `PASS` on `cmd_arm_probe:/etc/passwd`.

- **A swept directory that no longer exists is declared, not counted as zero.** `tests/test_git_status_display_config_gates_1295.py` sweeps `presets/git`, `presets/github` and `scripts` for `git status` call sites. `scripts/` held only `oss_train.py`, so it is now empty — and an absent directory contributes zero sites, which renders identically to a directory with nothing to find. It stays in the swept set so a script written there next month is swept on the day it lands, and its absence is recorded in `ABSENT_TREES` with the reason; the register reds both if an undeclared tree goes missing and if a declared one comes back.
