- **`paste` on a new file reported a ruff baseline it never measured, and printed a `-1` improvement against a file that did not exist** ([#1466](https://github.com/Digital-Process-Tools/claude-supertool/issues/1466)). The baseline pass ran the whole validator fan-out *before* the write, against a path that was not there. Most of the 36 adapters answer that with `code: "adapter"`, which the core already routes to `? → N (baseline not measured)` — which is why `py-syntax` was right. Three answer instead, because a missing file is a finding in their own vocabulary rather than an adapter fault: ruff calls it `E902`, `tsc-check` `TS6053`, `prettier-check` `formatting`. Those fabricated counts were accepted as measurements, so one call printed `ruff : 1 → 0 (-1) ✓` and `py-syntax : ? → 0` in the same block, disagreeing about whether the file had a past.

  Fixed above the adapter layer rather than in the three: `_pre_existed` is already sampled before the op for the rollback arms, and a file that did not exist has no pre-op state for *any* adapter to measure, so the baseline pass is skipped and every row takes the `?` road. Patching the adapters would have been one adapter's memory at a time — the shape #1202 had to undo across sixteen of them — and it also spares a full validator fan-out on every file `paste` creates.

  The `1` was arithmetic and not only prose. `_validator_regressed` subtracts the baseline, so an invented `1` against a real post-write finding of `1` is equal counts and equal `ok`: a finding the create had just introduced was excused as `(pre-existing — not from this edit)`. The sign only ever ran that way — a fabricated baseline is higher than the true zero, so it suppresses regressions and cannot manufacture one — so this misreported rather than reverting an edit.
