- **`$SUPERTOOL_REQUIRE_VALIDATORS` exited 0 on five ways a required validator did not run.** [#967](https://github.com/Digital-Process-Tools/claude-supertool/pull/967) fixed the one case an adapter can report about itself — it ran, `refusal.required()` found the binary missing, and it emitted an `adapter` error. Every way the adapter is too broken to reach that code went elsewhere: an adapter that prints nothing, prints non-JSON, crashes, or replies without a verdict key all land in `_validator_unusable_reply` and become a `skipped`, and one that hangs lands in the core's own `TimeoutExpired` arm and rendered `1 err (timeout)`. `_note_not_checked` recorded none of them, so `supertool 'edit:...' && git commit` proceeded past an ungated edit in all five — the entire failure mode the variable exists to prevent, guarding a secret scanner among others. The row text was already honest in every case; only the exit code lied, and the exit code is the half a `&&` reads.
- **The core now answers the question instead of asking the adapter.** `_validator_gate_did_not_run` keys on the two things the core constructed itself — the `no_verdict` marker on a `_validator_unusable_reply`, and `timeout` — and consults `$SUPERTOOL_REQUIRE_VALIDATORS` through the core's own `_validator_required`. The core watched each of these five happen; it does not need the cooperation of the process that failed in order to know that it did. The row reads `NOT CHECKED  (no verdict about this file)` with an `adapter` or `orchestrator` reason line, the validator is named on the `[result]` line, and the call exits 1.
- **Scope is the breakdowns the core observed, not every skip.** `warm_unsafe` ([#345](https://github.com/Digital-Process-Tools/claude-supertool/issues/345)), an out-of-scope path ([#263](https://github.com/Digital-Process-Tools/claude-supertool/issues/263)) and a resolver that maps a file to nothing are a healthy adapter declining on its own terms, and nothing in the reason string distinguishes them from a broken one — hence the core-internal `no_verdict` key rather than prose matching. Escalating those under `'*'` would fire on ordinary edits nobody meant to gate, which is a gate that cries wolf: the quiet bug traded for a louder one rather than fixed. An adapter that is genuinely absent still escalates through `refusal.required()`, as before.
- **Still an exit code, still not a refusal, still not a rollback.** The write lands, and an edit is never reverted by a checker that formed no opinion about it — [#967](https://github.com/Digital-Process-Tools/claude-supertool/pull/967)'s judgment call and [#969](https://github.com/Digital-Process-Tools/claude-supertool/issues/969)'s, unchanged. Unset the variable and none of this is reachable: every one of the five is the honest `skipped` it always was and exit stays 0.
- **The core's reader of the variable is a deliberate second implementation of `refusal.required()`**, because that twin lives in the package adapters import inside their own subprocess, and a gate that stops working when a `sys.path` resolution does is not a gate. `tests/test_require_validators_core_975.py` executes `validators/common/refusal.py` and pins the two to the same answers across thirteen env-var shapes plus the `os.pathsep` form, so the copy cannot drift into a second rule.
