- **`grep_around` refused a colon-bearing pattern with the interpreter's own sentence about it** ([#1826](https://github.com/Digital-Process-Tools/claude-supertool/issues/1826)). `grep_around:Class::CONST:PATH` puts `CONST` in the numeric N slot, and `int()` raised through dispatch as `ERROR: argument parsing: invalid literal for int() with base 10: 'CONST'` — no cause, no escape, and the caller's search term quoted back as if it were a number. It is now a refusal that states how the call was read (`pattern=` / `path=`) and gives the payload spelling. The parse is deliberately **not** changed to `grep`'s right-to-left rejoin: three shipped guards read `grep_around`'s slots by position — the containment gate takes the path from slot 2 statically, the `all`-in-N-slot refusal reads slot 3, and #1345's fifth-token refusal counts them — and a rejoin that peels trailing integers would take `all` for the PATH and delete the first two. #1065's `pattern read as` disclosure, extended to `around` in #1821, can never fire for this op at all, because it needs a `:` in slot 1 and slot 1 cannot hold one; the refusal carries the disclosure itself.
