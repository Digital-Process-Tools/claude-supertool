- **`radar`'s delivery banner printed a socket path straight out of a `/tmp` state file** ([#1423](https://github.com/Digital-Process-Tools/claude-supertool/issues/1423)). `_destination_lines` joined the `sock_path` values `transport.emit_destinations()` reads out of the watcher state files into radar's own text, and `SUPERTOOL_WATCH_STATE_DIR` defaults to `/tmp`. A planted state file whose `sock_path` carried a newline printed a whole extra line at column 0 — a fabricated `radar: delivery — all N watcher state file(s) had their last emit accepted by a listener`, which is precisely the false all-clear the banner exists to prevent, authored by anyone who can write to the state directory. `radar.py` imported no `_untrusted` at all, while `dispatcher.list_watchers` and `channel.stranded_watchers` already read the same directory through it.

  Paths are now flattened with `_untrusted.flat` — not `repr`'d, because this line's job is to tell an operator which socket to go and look at — and flattened **before** the de-duplicating set, so two recorded values that render identically are printed once rather than twice. `SOCK_PATH` is flattened at the render too; it is printed by both arms and arrives from the environment. The comparison that decides which watchers disagree still runs on the raw value.

  Radar cannot verify a path it did not write, so flattening alone would have left it asserting one. The arm that prints somebody else's text now carries `_untrusted.flat_note` above it, once, naming the watchers' own state files as the source — and only that arm: a note over a line radar wrote itself would be a claim about the render rather than about the source.
