- **Three remote fields reached `gh-branch`'s own lines unflattened, one of them the verdict sentence** ([#1408](https://github.com/Digital-Process-Tools/claude-supertool/issues/1408)). `presets/github/branch.py` imports `_untrusted` for the #851 convention — a value GitHub returned occupies exactly one line of our render, because a newline in it emits at column 0 and column 0 reads as the tool talking — and applied it to workflow and job names while three neighbours on the same lines went in raw.

  `orphan_lines()` backticked `conclusion` twice in the f-string whose sibling field was already `_untrusted.flat(name)`, inside a two-space-indented block. `_row()` dropped the same field into the fixed-width workflow table, whose own docstring says one extra line is one extra workflow a reader will count as having run. `_names()` rendered the workflow names in the verdict sentence itself — the line `pr_merge` republishes on the merge gate, and the highest-authority line the op writes.

  Flattened at the seam rather than at each call site, so `_names()`'s fifth caller is right too. `conclusion` is an enum in practice and renaming a workflow needs write access to the base repo, so none of the three was a live exploit; the convention is not conditioned on that, because #851 and #981 were both filed after somebody reasoned that way about the field next door.
