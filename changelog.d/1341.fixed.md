- **The preset transport seam is now enforced by the socket rather than by a convention** ([#1341](https://github.com/Digital-Process-Tools/claude-supertool/issues/1341)). `presets/_http.py` binds `_OPEN` at import and every preset calls through it, so a test that stubs `MODULE.urllib.request.urlopen` replaces a name nothing consults: the request goes out to the real host and the test passes on whatever comes back. Two tests in `tests/test_security_error_echo_691.py` were in that state for months, one of them a credential-redaction regression test whose injected payload had never once been delivered ([#1312](https://github.com/Digital-Process-Tools/claude-supertool/issues/1312) repointed them).

  Repointing the stubs was not the fix. `monkeypatch.setattr` and `mock.patch` already raise on a name that does not exist, so *renaming* `_OPEN` would redden its stubs; the defect was the opposite shape and no rename check reaches it, because the stubbed name existed and was live — it just was not the one the product calls. `tests/_netblock.py::block_outbound` is now armed by an autouse fixture in `tests/conftest.py` for every test in the suite, instead of being a per-file fixture each author had to remember.

  The fixture builds its own `pytest.MonkeyPatch.context()` rather than requesting the shared `monkeypatch` fixture, and that is load-bearing. It is autouse and defined early in `conftest.py`, so it is set up first and torn down last; asking it for `monkeypatch` instantiates that fixture there and moves `undo()` past `_guard_repo_git_state`'s teardown. `test_git_resolve.py` and `test_git_resolve_validate_scope_876.py` patch `os.path.isfile` to `lambda p: True`, CPython 3.13+ routes `Path.is_file()` through `os.path.isfile`, and the git guard's after-snapshot then read every *directory* under `refs/heads/` as an unreadable ref — 18 teardown errors across those two files, blaming tests that had changed nothing, plus a nineteenth in a concurrent worker via the shared-repo fan-out #433 documents.

  **Named blind spot, because a green here must not be read as "nothing reached the network":** it binds `socket` in the pytest process only, so a test that shells out to `supertool.py` or a preset gets an unpatched child. The static `tests/`-side grep the issue proposed is deliberately not shipped alongside it — #1312 measured a grep for transport tokens at 2 of 3 live leaks against the socket recorder's 3 of 3, and a second guard whose green means strictly less than the first one's is how a green stops meaning anything.
