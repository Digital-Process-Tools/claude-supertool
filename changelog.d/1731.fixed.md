- **`claude-log-cost`'s selection tests pin the number the report attributes, not a digit substring of the whole report** ([#1731](https://github.com/Digital-Process-Tools/claude-supertool/issues/1731)). `test_single_uuid_argument_measures_only_that_session` asserted `"500" not in r.stdout` to mean "session `bbbb`'s 500-byte result was not counted". What it actually said is that three characters appear nowhere in a report that prints byte totals, percentiles, shares and a filesystem path — so it failed under the full suite and passed in isolation on the same commit, order the only difference (`13457 + 1 = 13458`, identical selection). The assertion could not tell its finding from a coincidence, which made a pass no evidence the selection worked and a failure no evidence it did not.

  A `measured()` helper now reads `(sessions, results, bytes)` off the report's own `Measured:` line and raises when that line is absent, so a report that printed nothing reddens instead of satisfying a negative assertion for free. `== (1, 1, 10)` carries both halves at once: the selected session was measured, and the other one's 500 bytes are not in the total. A new sibling test measures the whole project and requires `(2, 2, 510)` from the same fixture — without it the first test would still pass against a `cost.py` that had simply stopped seeing `bbbb`, which is a selection test whose evidence is indistinguishable from a broken reader. Two adjacent assertions of the same shape went with them: `"500" in r.stdout` in the limit test, and `"2000" not in r.stdout` / `"15" in r.stdout` in the non-text disclosure test, where `15` occurs in almost any report.
