- **A mixed-tree decline for a write-class builtin or a config-declared custom op now runs before the `@file`/`@-` payload is read, not after** ([#1878](https://github.com/Digital-Process-Tools/claude-supertool/issues/1878)). The #1942 check (a write-class builtin, `paste`/`edit`/...) and the #678 check `_resolve_custom_op` runs for a config-declared custom op (`git-commit` and every other op this project's `.supertool.json` defines under `"ops"`) both used to sit downstream of the shared `@file`/`@-` payload route in `_dispatch_impl`, so `edit:@-` or `git-commit:@-` under a mixed core/tree pair still drained `sys.stdin` before declining — a single stream, so the caller had to re-send the whole payload to retry from the matched tree. Moved to right after the op name is parsed, before either payload route can touch stdin; scoped identically to the two decline sites it replaces (`_OP_SAFETY_BUILTIN[op] == "writes"`, or `op` present in the project's own `ops` config) so an unrecognized op name still falls through to "unknown operation" rather than a mixed-tree decline it was never going to earn. `tests/test_mixed_tree_stdin_early_fail_1878.py` pins both classes with a stdin sentinel that fails loudly if anything reads it, and a positive control proving the sentinel actually detects a read when the tree matches.
