- **A cloned repository's `.supertool.json` could write lines into the guard's system-authored denial** ([#1391](https://github.com/Digital-Process-Tools/claude-supertool/issues/1391)). `guard_command` walks up from the cwd for config, so any op in a repo you cloned could declare `replaces[].argv` — `"git status"` is enough — and the refusal then rendered that op's `use` and `description` verbatim into `permissionDecisionReason`. Both are newline-bearing, the description cap was per match while the number of matches was uncapped, and the whole thing reached the model unsolicited on any `Bash` call. The direction is inbound: untrusted repository bytes acquiring the authority of the tool's own refusal channel.

  The refusal still quotes the op's own description, and that is a decision rather than an omission. It is the feature the guard is built on — the refusal text cannot describe a flag the op no longer has — and replacing it with "run `help:OP`" would charge a second command on every legitimate block, forever, to disarm a case the three measures below already disarm. A gate that makes the common path more expensive is a gate that gets switched off.

  So: registry text is flattened through `presets/_untrusted.flat` before it is interpolated, which is the repo's one implementation of "this value occupies exactly one line" and covers the ten separators `str.splitlines()` folds on rather than the newline alone. The cap is one budget for the whole message plus a limit on how many matches are detailed, not a per-match cap multiplied by an uncapped number of matches. And a refusal that quotes an op defined in the project's own `.supertool.json` now says so, so a stranger's prose is never read as supertool's; a preset-defined op is not attributed to the project, because a disclosure that fires on everything is wallpaper.

  Reproduced against a real file on disk, not in-process: the audit that filed this was read-only and said its file leg was inferred. `tests/test_guard_refusal_injection_1391.py` plants the config and drives `hooks/pre_bash_guard.py` end to end.
