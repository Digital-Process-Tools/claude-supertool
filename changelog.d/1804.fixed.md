- **Three more renders counted a superseded check run as red** ([#1804](https://github.com/Digital-Process-Tools/claude-supertool/issues/1804)). #1792 fixed the merge gate — `gh-pr:N:status`, `gh-pr:N` and both paths of `gh-pr-merge` — so a check run a later run of the same name replaced is no longer a live failure there. `git-status`'s per-PR `Checks:` line, the dashboard board's per-PR verdict (and the `next:` reference it offers for a red leg), and `gh-pr-create`'s post-create summary all called `_checks.github_states()`/`summarize()` directly and kept the old arithmetic — so the same commit could read `clean` through the merge gate and red on the board or on `git-status`. All three now go through `github_live_states()`/`summarize_github()` (and, where a per-leg reference is offered, `github_named_live()`), the same discriminator #1792 gave the merge gate: a leg only leaves the red count when another leg of the same name started strictly after it completed.
