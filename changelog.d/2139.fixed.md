- **`classify`'s parse-failure refusal now names a recognisable scaffolding shape instead of only quoting bytes** ([#2139](https://github.com/Digital-Process-Tools/claude-supertool/issues/2139)). Observed twice live: `could-not-classify (model output did not parse: '<budget:token_budget>200000</budget:token_budget>')`, harness scaffolding arriving where a verdict was expected. When the unparsed output is a single line that opens with a bare `<tag`-shaped fragment -- something the fixed `SAFE`/`SUSPECT: ...` vocabulary can never itself start with -- the refusal now reads `could-not-classify (the output was the caller's own scaffolding, not a verdict)`. Restricted to a single line so a reasoning model's `<thinking>...</thinking>`-style preface, followed by a real verdict on a later line, is never misreported as pure scaffolding; every other parse failure keeps the original bare quote unchanged, both paired in the same test fixture. The timeout shape from the issue's own comment (`spawn timed out after 45s`) is a separate, already-correctly-labelled failure mode this fix does not touch and remains open.
