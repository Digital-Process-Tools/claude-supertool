- **`.oss/statusline.py`'s remaining three `gh api` call sites now validate `repo` before interpolating it, closing the gap #2245's guard left behind** ([#2278](https://github.com/Digital-Process-Tools/claude-supertool/issues/2278)). `_gh_count`, `_gh_external_issue_count` and `_latest_release` built a search query, a listing path and a contents path directly from the same unvalidated `owner/name` value #2245 already found reaching two other call sites with no check in front of it. A new `_malformed_repo` helper — the `repo`-only half of `_malformed_api_ref`, for the call sites here that have no `branch` in scope — refuses a malformed value (returns `None`, the same "could not look" answer each function already gives for an unanswered call) before `gh` is ever invoked.
