- **Every type error `tsc` found arrived as one unlocatable finding carrying a terminal dump** ([#1499](https://github.com/Digital-Process-Tools/claude-supertool/issues/1499)). TypeScript 5.x emits *pretty* output by default whether or not stdout is a tty — ANSI-coloured, four lines per diagnostic, a caret rule under the column, a trailing `Found N errors` tally. `tsc-check`'s parse reads the plain one-line form, so it matched nothing and the adapter published a single error with `code: "syntax"`, `line: null` and the whole coloured dump as `msg`. N type errors rendered as one problem with no location, and a reader acting on it looked in the wrong place.

  Fixed by asking for the plain form — `--pretty false` on the argv. The alternative on the table was stripping ANSI before the regex, and measured against a real `tsc 5.x` dump that fixes nothing: stripped, the pretty form reads `bad.ts:1:7 - error TS2322: …`, which is not the `bad.ts(1,7): error TS2322: …` the pattern requires, and zero lines match. Colour was never the whole problem; the layout was. The strip is applied as well, before the parse and to the excerpt, because it is `--pretty false` that removes the colour today and nothing `tsc` documents keeps the two coupled.

  A parse that still comes back empty is now `code: "adapter"` — the code the core reads on every error as "no verdict was obtained about this file" (`_validator_not_checked`), so it renders as the third state, is never cached and never rolls back. Not `skipped`, which omits `errors` entirely and would drop `tsc`'s own objection with it (`validators/SCHEMA.md` §"A located diagnostic still has to be about *this* file (#754)"). The same arm now also covers a non-zero exit with **no** output, which used to emit `ok: false, count: 0, errors: []` — a verdict of "not clean" carrying nothing to act on, and an absence the core could not recognise either, because it looks for the reason on an error that was not there.

  This was one of the two permanent local reds in [#1333](https://github.com/Digital-Process-Tools/claude-supertool/issues/1333). It inverts how that red should have been read: the machines where `tests/test_tsc_check.py::test_source_context_present_on_error` passed were the ones whose `tsc` happened to emit the plain form, so the green was the accident.
