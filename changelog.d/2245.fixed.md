- **`.oss/statusline.py`'s check-runs and combined-status readings now validate `repo`/`branch` before interpolating them into a GitHub API path** ([#2245](https://github.com/Digital-Process-Tools/claude-supertool/issues/2245)). `_reading_from_check_runs` and `_reading_from_combined_status` built `"repos/{}/commits/{}/...".format(repo, branch)` directly from `.oss.json`'s `repo`/`default_branch`, with no upstream validation — the file already had a validator for exactly this shape, `_REPO_RE`, but only `_expected_watch_name` applied it. A malformed value now refuses (returns `None`, the same "could not look" answer these functions already give for an unanswered call) instead of addressing whatever endpoint the value happened to name.
