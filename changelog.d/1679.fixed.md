- **`gh-check` and `gh-job` printed four `gh api` commands that named no repository, and no test could exercise a `repo:`-targeted `gh-pr-merge`** ([#1679](https://github.com/Digital-Process-Tools/claude-supertool/issues/1679)). Two ways `repo:` targeting was honoured by the argv path and invisible everywhere else in `presets/github`.

  **The printed commands.** `check.py`'s two 404 messages and `job.py`'s missing-log and empty-log blocks each hand a reader a `gh api repos/{owner}/{repo}/…` line to paste. `gh api` resolves those two placeholders from the cwd's remote, which is right for a path this process executes and wrong for one a reader pastes: the same command names a different repository in every checkout and says nothing about having changed meaning — the distinction [#1670](https://github.com/Digital-Process-Tools/claude-supertool/issues/1670) drew in `pr_merge`. The four now go through `_repo_target.api_path_printable`, which fills in the cwd's own slug and declines to the placeholders when `gh repo view` does not answer. `api_path_for_display` from #1670 took a slug the caller "had already read", and outside `pr_merge` no caller had one; `cwd_slug()` is that missing half, put next to it rather than becoming a sixth hand-rolled copy of `gh repo view --json nameWithOwner` — there are five today, returning three different absence sentinels between them.

  **The issue's own claim that these named the wrong repository under a `repo:` target was wrong**, and the fix is not built around it: all four already went through `_repo_target.api_path`, which substitutes a target whenever one is set. The defect was only ever the untargeted case, and a test now pins the targeted one so the claim cannot be re-derived from the code.

  **The blind harness.** `tests/test_gh_pr_merge_main_950.py` routed the PR read on `"statusCheckRollup" in args[-1]`, but `gh_args()` appends `--repo OWNER/NAME` *after* the field list — so under a target the last argument is the slug, the branch never matched, and the read fell through to the post-merge read-back. `main()` then saw `MERGED` and refused a PR it had never read. No test in that file exercised a targeted run, so the refusal read as a legitimate gate outcome: a harness rendering its own blindness as a product verdict. It now matches over every argument, and two tests run a targeted `main()` end to end.
