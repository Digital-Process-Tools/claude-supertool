- **`youtube_reply`, `youtube_like`, `youtube_status_since` — the rest of #227's YouTube write ops** ([#2593](https://github.com/Digital-Process-Tools/claude-supertool/issues/2593)). `youtube_reply:COMMENT_ID|TEXT_OR_file://PATH[|force][|force-dup]` posts a reply via `comments.insert` and reads it back the same three-verdict way (`verified`/`MISMATCH`/`could-not-verify`) `youtube_comment` does, keyed for its duplicate guard on the parent comment id rather than the video so a second reply to a different comment on the same video is not wrongly refused. `youtube_like:VIDEO_ID_OR_URL[|force][|force-dup]` sets this account's rating to "like" via `videos.rate` and confirms it with `videos.getRating`, sharing `youtube_comment`'s plain `VIDEO_ID` duplicate key on purpose (a conservative default, not a claim the two actions are the same). `youtube_status_since[:ISO]` lists new top-level comments on this account's own videos since a cutoff (default 24 hours), needing the same OAuth2 grant as the write ops because "own videos" is only answerable for the authorised account, but never writing, so it carries no sentinel, no rate cap and no confirmation gate. All three reuse `_oauth`, `_yt.authorized`, `_sentinel` and `_publish_safety` unchanged, per #227's own note that they were "argv and an endpoint each" once the write machinery was proved out by `youtube_comment` (#2543).
