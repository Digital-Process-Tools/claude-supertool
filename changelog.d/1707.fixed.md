- **A `NOT COVERED` note no longer claims the op is "the same invocation without" the tokens it declined** ([#1707](https://github.com/Digital-Process-Tools/claude-supertool/issues/1707)). It was false for exactly the argv the branch exists to catch: drop `v0.43.0` from `git push origin v0.43.0` and you push a **branch**, and the third recorded instance was `git push --force-with-lease origin docs/claude-md-git-c`, where the suggested equivalent also discards the safety on the operation while the note enumerated only the operands. The clause now says what the op performs — "`git-push` performs `git push` and nothing more, which is a different command from this one" — which is true of every argv reaching that branch and asks git nothing. Making it conditional on the dropped tokens being inert was the other option and needs the guard to know what a refspec is, per utility, which is the case work `_GUARD_GLOBAL_OPTIONS` refuses to grow. **The clause also leads the note now instead of closing it**, found in this change's own review: `_guard_notes` truncates a note from the end and the echoed command is caller-supplied, so written last the correction was cut mid-word for the reported force push and vanished entirely for a longer branch name — with `… (+N chars)` disclosing that something was cut and never that it was the correction. The `gh run view --help` instance in the issue's first comment does **not** reproduce and needs no `unless_flag`: `_guard_help_state` has un-claimed every entry for a help flag since #1430, now asserted so a regression is visible.
