- **`_publish_safety._supertool_config()` now warns on stderr when `.supertool.json` cannot be read or parsed, instead of silently falling back to `{}`** ([#2306](https://github.com/Digital-Process-Tools/claude-supertool/issues/2306)). Every publish safety reader — `require_confirm`'s `no_publish_confirm`, `_body_allowlist`'s `publish_body_allowlist`, `_disclosure_config`'s `publish_disclosure_text`/`no_publish_disclosure` — goes through this one function, so an operator who wrote a disclosure policy and fat-fingered a comma got the default behaviour with nothing anywhere distinguishing it from a config that legitimately sets none of those keys. The policy chosen is warn-and-fall-back, not refuse: a malformed key unrelated to the one a caller needs must not block an unrelated publish, but the read failure is now named once per process before the default takes over — matching the choice made for the same class of defect in `_merge_presets` (#2308).
