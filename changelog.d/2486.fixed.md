- **The claude-channel consumer now starts on a fresh plugin install** ([#2486](https://github.com/Digital-Process-Tools/claude-supertool/issues/2486)). `.mcp.json` declared the server for every plugin user (#520) and pointed at `channel.ts`, which imports `@modelcontextprotocol/sdk` at module load. `node_modules/` is gitignored, nothing in a plugin install runs `install.sh`, and `package.json` declares no `postinstall`, so the declared server died on `ERR_MODULE_NOT_FOUND` before a line of its own code ran. The only reason it was never felt in development is that `install.sh` had been run by hand on the maintainer's machine. The entry point is now `start.mjs`: it resolves the SDK, installs it once if absent, and refuses with a sentence naming the remedy if it cannot -- three states, and the third never renders as either of the others. Every diagnostic goes to stderr and `npm`'s own stdout is discarded rather than inherited, because stdout is the JSON-RPC stream and one line of install progress on it corrupts the MCP handshake. Verified end to end in a tree with no `node_modules`: the install ran, stdout stayed empty, and `channel.ts` started and hit its own socket-holder guard. `notifiers/claude-channel/bun.lock` is deleted, having outlived the Bun runtime #520 dropped. Found by the v0.59.0 release audit, round 2.
