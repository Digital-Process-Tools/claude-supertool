- **`channel:health` no longer follows a symlink planted at the health-file path** ([#1184](https://github.com/Digital-Process-Tools/claude-supertool/issues/1184)). `read_health` opened `{sock_path}.health.json` by name with a plain `open()`. That name lives in `/tmp` and is derived from a socket path a co-tenant can predict, so a symlink at it got any same-uid JSON file opened and parsed — and, before [#1187](https://github.com/Digital-Process-Tools/claude-supertool/issues/1187), its string fields rendered into the report. `transport.claim_pidfile` has guarded the same directory against the same threat with `O_NOFOLLOW` since [#148](https://github.com/Digital-Process-Tools/claude-supertool/issues/148); this call site did not.

  Now `os.open(..., O_RDONLY | O_NOFOLLOW)`, the same spelling `transport.py` uses rather than a second convention for one directory. A refused symlink is its own answer and says what it found — not folded into "publishes no counters", which means a consumer that predates the field. The existence check is `lexists` rather than `exists`: `exists` follows the link, so a symlink pointing at nothing was reported as no health file at all, a hostile act rendered as an old consumer. `O_NOFOLLOW` is absent on Windows, where the open carries no guard and nothing claims it does.
