- **Validators and formatters now spawn the path `shutil.which()` returned, not the name they handed it** ([#2540](https://github.com/Digital-Process-Tools/claude-supertool/issues/2540)). The two calls disagree on Windows: `which()` consults `PATHEXT` and answers about `eslint.cmd`, while `subprocess` without a shell goes through `CreateProcess`, which appends only `.exe` when it searches `PATH` and cannot find that file. Twenty-one argv sites across twenty adapters gated on the first and spawned the second, so on Windows `eslint`, `stylelint`, `markdownlint`, `tsc`, `pyright`, `prettier` and anything reached through `npx` never ran at all -- five of them declined as `skipped`, which is honest and also indistinguishable from a tool nobody installed, and `prettier-check` reported a finding on every file instead. `argv0()` in `validators/common/spawnable.py` is the one-line repair, applied to every tool rather than to a list of the ones shipped as npm packages, because such a list rots and a new adapter never joins it. `tests/test_spawnable_register_2540.py` is the register that keeps the class closed.
