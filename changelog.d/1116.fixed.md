- **Mutation counters (`_WRITE_COUNT`, `_MUTATION_ATTEMPTS`, `_SKIP_COUNT`, `_ROLLBACK_COUNT`, `_REAPPLY_COUNT`, `_LEFT_ON_DISK_COUNT`) now get the same per-op frame-scoping [#1109](https://github.com/Digital-Process-Tools/claude-supertool/issues/1109) gave the list accumulators** ([#1116](https://github.com/Digital-Process-Tools/claude-supertool/issues/1116)). Each was a `[0]` process-global snapshotted at op entry and subtracted at op exit -- correct only while exactly one mutating op runs at a time, which held only because every mutating op is excluded from `_PARALLEL_SAFE_OPS`, a reachability argument about a membership list kept for an unrelated reason rather than a design one. Two dispatched mutating ops racing that global (reproduced directly against `dispatch()`, bypassing the list, since the list is precisely what made it unreachable through `main`) could misattribute one op's write count to another's footer. Each counter now accumulates on the thread-local dispatch frame `#1109` already installs, and folds up through nested batch sub-ops exactly as the two lists do; `main`'s own whole-call exit-code checks (`$SUPERTOOL_REQUIRE_VALIDATORS`, the skip/rollback deltas) are untouched -- they read the process-global, which every one of their callers genuinely is call-wide about.
