- **A repository that tags releases by date could not name its own tag, and two interpreters disagreed about which values are date-shaped** ([#1526](https://github.com/Digital-Process-Tools/claude-supertool/issues/1526)).

  `gh-prs:merged-since=` routes on whether the value parses as a date, and that question was answered by `datetime.fromisoformat`, whose grammar widened in 3.11. Measured on CPython 3.9.6 against 3.11.11: `20260809` and `2026-W32-1` raise on the first and parse on the second. So the same call was a date boundary at midnight UTC on one interpreter and a tag name hunted in the local clone on another, with nothing disclosed either way. The accepted spelling is now written out in `presets/_filter_tokens.py` — extended ISO-8601, the floor's grammar, on every interpreter.

  `merged-since=refs/tags/2026-08-09` is the spelling a date-tagging repository was missing. A bare date-shaped value is still read as the date, deliberately: `2026-13-45` is a typo in a date, and "no tag by that name" is the wrong sentence to hand whoever typed one. The refusal named a remedy this input had neither of; the full ref path is git's own escape, contains no `:`, and can never parse as a date.
