- **The SessionStart hook no longer spawns the bare name `python3`, and both shipped hooks now resolve one shared ladder** ([#1382](https://github.com/Digital-Process-Tools/claude-supertool/issues/1382)). `hooks/session-start.sh` ran `python3` directly while `hooks/pre-bash-guard.sh`, a few lines away in the same directory, went to some length not to — #572 banned that name from every spawn position because on Windows it can resolve to the App Execution Alias stub and on a stock macOS to the Xcode Command Line Tools stub, and both *block* rather than error. At session start that is not an error anyone can act on; it is Claude Code taking a hook timeout to come up and then saying nothing about supertool.

  The ladder moved to `hooks/python-ladder.sh` and both hooks source it, so the next hook written here inherits the decision instead of making a third one. What each caller does when no rung answers stays its own: the guard declines in words and allows the command, and the session hook now prints one line naming the rungs it tried and exits 0 — keeping the `./supertool` symlink, which never needed an interpreter at all. Not a bare `python3` as a last rung, which would preserve the hang for exactly the hosts with no alternative, and not a loud failure, which is a broken session on every platform in order to report a missing interpreter on one.
