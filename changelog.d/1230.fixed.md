- `radar`'s GitHub tier no longer narrows the board to `author=@me`. It answers over the same population as `gh-prs` — the whole repo — and its scope line reads `scope every author (default) on OWNER/REPO`. #1207 dropped the implicit author filter from `gh-prs` by passing `any_author=True` at the op's own two call sites and leaving `_build_list_cmd`'s parameter default narrow; the tier calls that helper with two positional arguments, so the op a maintainer tick opens with kept excluding every dependabot and outside-contributor PR while rendering as healthy. Two renders of one question, seconds apart, disagreeing about which population answered.
- The implicit `author=@me` is **removed from `_build_list_cmd` itself**, along with the `any_author` parameter, rather than flipped at the tier's call site. A default no caller in the tree wants is not a default; it is the next inheritance of this bug. `anyauthor` stays accepted as a token and still names what the bare op already does.
- The departure snapshot key is deliberately unchanged. #1207 deferred radar's half on the grounds that the key is built from the filter string, which a bare invocation spells identically before and after — but widening a population only **adds** members, so a reused snapshot cannot manufacture a departure, and the PRs it never held print once as new rows, which is the announcement the board owes. Keying in the scope instead would cold-start every board and discard the `_since` stamps every staleness verdict is measured from.
- `gl-mrs` and radar's GitLab tier are unchanged and are **not** the same defect: the tier resolves `defaults.DEFAULT_FILTER` and prints it in full (`scope author=@me,state=opened (default)`), so tier and op describe one population and the scope line is derived from the filter actually applied rather than hardcoded. That `gl-mrs` itself still narrows — with no opt-out at all, so "every open MR on this project" is currently unaskable — is a separate question needing its own argument.
