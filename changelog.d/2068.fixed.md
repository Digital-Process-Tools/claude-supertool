- **The `slack` watch source only ever read `msg["text"]`, so a file upload, image, snippet, Block Kit message or app-posted attachment arrived indistinguishable from an empty message** ([#2068](https://github.com/Digital-Process-Tools/claude-supertool/issues/2068)). A new `content_kind` payload field names where `title` actually came from: `"text"` for the ordinary case, `"files"` / `"blocks"` / `"attachments"` when `text` was empty but the poller found and named one of those instead (a filename, a block count — never reconstructed prose), and `"empty"` as the only kind under which `title` is legitimately `""`. An unreadable message no longer renders the same as one that truly carried nothing.
