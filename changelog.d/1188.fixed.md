- **A guard anchored `^...$` accepts its own value with a newline stuck on the end** ([#1188](https://github.com/Digital-Process-Tools/claude-supertool/issues/1188)). Python's `$` matches at the end of the string *and* immediately before a final newline, so `re.compile(r"^[0-9]+$").match("5\n")` is a match. `presets/_job_argv.py` took a job id that way — the guard [#1145](https://github.com/Digital-Process-Tools/claude-supertool/issues/1145) added whose entire purpose is to refuse before anything is fetched — while `-5`, `5:6` and `5/../6` were all correctly refused. The id then reached `f"actions/jobs/{job_id}"` and a `subprocess.run(["gh", "api", ...])`; that is list-argv, so nothing was injected into a shell. What broke was the module's own stated invariant, and it broke silently, because a trailing newline is invisible in every render of the value that follows.

  **The worse one was `presets/_refname.py`.** `ordinary("main\n")` returned `True`, so `shell_ref()` returned the name **unquoted** and the `To resolve:` block printed a command carrying a live line break — into the shell of the reader who pastes it, which is the one place that module exists to protect. Also rewritten: the daemon's `SERVER_NAME` check, `gh-branch`'s hex-ref test, `gl-issue-create`'s estimate format, dev.to's bare-slug test, `where`'s two symbol shapes, and `_URL_PORT` and `_DRIVE_LETTER` in the op tokenizer. `presets/_checks.py`'s SHA test was already saved by an incidental `.strip()`; it is written `\Z` now anyway, because incidentally-correct is not what the next reader copies.

  **Two the sweep found that the report did not name.** The release assembler's fragment-filename and version patterns: a POSIX filename may end in a newline, and `1188.fixed.md` followed by one parsed as a fragment for issue 1188, was folded into a release and then deleted as consumed. And `_extract_env_prefix`, which is the same character doing the opposite damage — `^([A-Za-z_][A-Za-z0-9_]*)=(.*)$` matched `FOO=bar` plus a newline and captured `bar`, so a value a caller had deliberately quoted a newline into was truncated while the assignment still succeeded, and nothing reported the loss. A value with a newline *inside* it fared worse still: it matched nothing, so the whole `KEY=VALUE` token fell through as `argv[0]` and the variable was never set at all. It is `\Z` with `re.DOTALL` now, and both spellings set what a POSIX shell would set.

  **The pin is the class, not the sites.** `tests/test_anchored_guards_1188.py` walks `_supertool.py`, `presets/` and `.github/scripts/` with `ast` and fails on any fully anchored regex literal that still ends in `$`. A pattern that really is one line out of a larger text carries `# anchored-ok: <why>` on its own call, and a second test refuses a waiver with no reason after the colon. `re.MULTILINE` patterns are skipped by construction — there `$` means the end of a line and `\Z` would be wrong — as are patterns ending in `$` that do not start at `^`, which are suffix tests. Fourteen guards were rewritten and thirteen line-parsers waived. The limit is stated in the test's own docstring: a pattern assembled from a variable, or held in a dict and compiled elsewhere, is not seen, so this narrows the class rather than closing it.
