- **`gl-api`'s dot-segment refusal now decodes the path once before checking it, matching the host check beside it** ([#2244](https://github.com/Digital-Process-Tools/claude-supertool/issues/2244)). `path_refusal` decoded the path once for its host-authority check but handed `dot_segment_reason` the raw, undecoded value — `%` is one of the characters `_PATH_CHARS` lets through unmodified, so `projects/:id/repository/../../../user` was refused while the same traversal spelled `projects/%2e%2e/user` or `projects/%2E%2E/user` was not. `dot_segment_reason` now reuses the same decoded value the host check already computes, one decode, not a second independent one.
