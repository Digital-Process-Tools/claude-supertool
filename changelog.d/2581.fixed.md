- **`phpstan`'s presence gate and four MCP daemon warm-launch resolvers were still resolving a tool via raw `shutil.which()`/`which()`, left open by #2579's own sweep** ([#2581](https://github.com/Digital-Process-Tools/claude-supertool/issues/2581)). #2579 routed every ordinary validator/formatter gate through `spawnable()`, deliberately leaving `validators/phpstan/phpstan.py` off its register: `PHPSTAN_BIN` was never passed through `argv0()`/`spawnable()`/`resolve_bin_cmd()` at all -- it was spliced as a literal script argument to `php`, so the gate had nothing to be inconsistent *with*. Fixed by routing the gate through `spawnable()` and reusing the resolved answer as that argv element instead of the raw, unresolved name: confirmed locally that `php phpstan analyse ...` (the raw bare name, php's own argv resolution is a filesystem path relative to its cwd, not a `PATH` search) fails "Could not open input file: phpstan" from the repository root, while the resolved absolute path runs correctly. A second, structurally distinct instance in the same class, not reachable by #2579's own register (which only flags a gate calling raw `which()` *while also* using the cwd-safe chokepoint elsewhere for its actual spawn): the warm-daemon binary resolvers in `validators/phpstan-mcp/phpstan-mcp.py`, `validators/phpunit-mcp/phpunit-mcp.py`, `validators/phpmd-mcp/phpmd-mcp.py` and `validators/rector-mcp/rector-mcp.py` each called `shutil.which()` directly and reused its answer as the actual daemon spawn path -- there was no separate gate-then-spawn pair to disagree with each other, just one unsafe resolution. Routed through `validators/common/spawnable.py`'s `which_excluding_cwd()` instead. Also fixes a second, narrower bug in that same shared module: its own PATH-walk compared a candidate directory to the current one with a raw `==` while the dedupe two lines above it folded case with `os.path.normcase()` first, so a differently-cased PATH entry spelling the repository directory was not recognised as the current directory on a case-insensitive filesystem (Windows, and macOS by default). `tests/test_mcp_daemon_gate_uses_which_excluding_cwd_2581.py` registers the MCP daemon resolvers as their own instance, since #2579's own register cannot see them by construction; `tests/test_gate_matches_spawn_2579.py`'s `phpstan.py` allowlist entry is now empty, and `tests/test_which_excludes_cwd_2575.py` gained a case-folding regression test for the `spawnable.py` fix.
