- **`phpmd` and `psr`, the two validator adapters #2412's own sweep missed, now contain a flag-shaped target filename the same way `eslint`/`hadolint`/`stylelint`/`terraform-check` already do** ([#2438](https://github.com/Digital-Process-Tools/claude-supertool/issues/2438)). Both were wired identically to the other fifteen #2412 fixed and passed `file` to `subprocess.run` with nothing between the tool's own flags and the target -- a contributor adding a file named `-o=payload` or `--eval=x` to a pull request could change what the validator does rather than what file it lints. Neither `phpmd` nor `phpcs` was available to test against a real binary in this pass, so both route through `contained_target()` (a relative target starting with `-` is prefixed with `os.curdir`) rather than a `--` separator assumed to work: `phpmd`'s own argv shape is positional (`<file> <format> <ruleset>`, file first, not last) rather than GNU-getopt-style, so whether it honours `--` at all was never known either way. `tests/test_validator_dash_filename_2412.py`'s `CASES` table -- the shared, table-driven regression #2412 built -- now carries both, so the earlier "15 of 17" gap cannot reopen unnoticed; `docs/validators.md` corrected from "fifteen" to "seventeen".
