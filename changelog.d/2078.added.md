- **`gh-issue-comment` — comment on a GitHub issue with a read-back that proves what landed** ([#2078](https://github.com/Digital-Process-Tools/claude-supertool/issues/2078)). `gh-issue-create` opens an issue and `gh-pr-edit` corrects a published PR body; a follow-up comment on an issue already filed had no op and fell back to raw `gh issue comment --body-file`, the one write in the family nothing validated and nothing read back. `gh-issue-comment:NUMBER:@FILE` (payload route, same JSON/TOML shape as the other writers) posts through REST and compares the stored body against what was sent in the same call, in the same four states `gh-pr-edit` uses -- EXACT, line endings NORMALISED by the server, MISMATCH naming the first differing line, or UNKNOWN when the response carried no body field. Only EXACT and NORMALISED exit 0. `gh issue comment --body`/`--body-file`/`-b` are now refused by the raw-command guard in favour of it.
