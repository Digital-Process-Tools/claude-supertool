- `oss-tick`'s pending-wait guard (`presets/oss/tick.py::compose`) gated dispatch with `rows["pending_wait"].startswith("holds")`, matched against the installed `oss` plugin's own `oss_state.py --pending-wait` output -- but that script prints a holding or could-not-evaluate wait as a JSON object (`json.dumps(record, indent=2)`), which starts with `{`, never with the literal word `holds`. A real holding wait therefore fell through to `"proceed to dispatch"` instead of the do-not-dispatch `NEXT:` line. `presets/oss/tick.py` now parses the script's real shapes via two new helpers, `_parse_pending_wait` and `_parse_plugin_identity_check` -- the latter for a sibling instance of the identical root cause in the `plugin identity vs last recorded` row, where the script's one-line stderr receipt is merged ahead of its own JSON record on stdout by this shim's `_run`, and used to render raw JSON into that row's line rather than the human-readable sentence the row's own value is supposed to carry. `docs/presets/oss.md`'s vocabulary table gains the `route-mismatch` state this fix now surfaces, and `tests/test_oss_preset_1985.py`'s fixtures, which faked bare-word output the real script never produces, are corrected to its actual shapes ([#2639](https://github.com/Digital-Process-Tools/claude-supertool/issues/2639)).
