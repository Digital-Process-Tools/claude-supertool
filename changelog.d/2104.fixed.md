- **`classify`'s file-backed verdict cache now re-checks a cached entry's `axes` against `model.AXES`, not just its `state`** ([#2104](https://github.com/Digital-Process-Tools/claude-supertool/issues/2104)). `cache.py`'s `get()` already floored a hand-edited or corrupted entry's `state` against the two cacheable states, and left `axes` accepted as any list of strings; a `suspect` entry naming an axis outside `model.AXES` would still be handed back as a verdict and joined, unchecked, into the rendered receipt line. Same-uid only (the cache directory is created at mode 0700), so this closes a gap against the module's own declared threat model rather than a reachable-by-others one — the live model path was already safe, since `model._parse` refuses a non-`AXES` name before a `Verdict` is ever built.
