- **Anchored five adapters' line-parsing regex on the invoked path, tolerant of the spellings a real tool's own platform can introduce** ([#1934](https://github.com/Digital-Process-Tools/claude-supertool/issues/1934)). `actionlint`, `xmllint`, `ruby-check`, `hadolint` and `gofmt-check` located a tool's own `path:line[:col]: message` diagnostic with a non-greedy wildcard standing in for the path, so the regex bound to the *earliest* colon-digit run in the line rather than the one the tool actually wrote. A workflow, XML, Ruby, Dockerfile or Go file whose name embedded its own `:N:M: ` sequence supplied the reported line, column and message of the filename author's choosing, discarding the tool's real diagnostic. Each adapter now anchors on `re.escape()` of the path it actually invoked — `actionlint` additionally relativises against its own working directory first, matching a relativisation actionlint itself performs on the path it prints. An exact-match anchor alone turned out to cost more than it protected: on Windows CI, real ruby's own diagnostic did not echo the exact invoked path byte-for-byte, so the anchor matched nothing and a real, located diagnostic silently lost its line and column. `validators/common/path_anchor.py` widens every adapter's anchor to a small, fixed set of equivalent spellings (separator direction, drive-letter case) rather than one exact string, never a wildcard — a forged filename still cannot use it to impersonate a different path. That widening is gated to Windows specifically: on POSIX, `\` and a leading drive-letter-shaped prefix are ordinary filename content rather than a separator or a drive letter, and the first cut of this module treated them as the latter unconditionally — which let the anchor accept a genuinely different file's diagnostic as this one's, found by this branch's own self-review before it shipped. A second, ungated widening covers a different mismatch found once the Windows-only fix reached CI on Linux: the invoked path can traverse a symlink (a symlinked temp directory is the common case) that a tool's own diagnostic resolves before printing, so the anchor now also accepts `os.path.realpath()` of the invoked path as a candidate — safe on every platform, since two files that are not symlink-equivalent always have different realpaths. When the anchor still matches nothing, the adapter's non-verdict message now names both the invoked path and whatever path-looking prefix the tool's own output appears to use, so a future CI red prints the two strings that differ instead of asking a maintainer to guess the transform from an assertion failure alone.
