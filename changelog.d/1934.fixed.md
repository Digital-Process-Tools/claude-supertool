- **Anchored five adapters' line-parsing regex on the invoked path** ([#1934](https://github.com/Digital-Process-Tools/claude-supertool/issues/1934)). `actionlint`, `xmllint`, `ruby-check`, `hadolint` and `gofmt-check` located a tool's own `path:line[:col]: message` diagnostic with a non-greedy wildcard standing in for the path, so the regex bound to the *earliest* colon-digit run in the line rather than the one the tool actually wrote. A workflow, XML, Ruby, Dockerfile or Go file whose name embedded its own `:N:M: ` sequence supplied the reported line, column and message of the filename author's choosing, discarding the tool's real diagnostic. Each adapter now anchors on `re.escape()` of the path it actually invoked — `actionlint` additionally relativises against its own working directory first, matching a relativisation actionlint itself performs on the path it prints.
