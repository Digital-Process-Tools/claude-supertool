- **`grep` and `around` read the contents of any file on disk when the pattern contained a `:`** ([#1166](https://github.com/Digital-Process-Tools/claude-supertool/issues/1166)). `_PATH_ARG_POSITIONS` gated `parts[2]` for both ops, but `_parse_grep_args`/`_parse_around_args` peel the trailing numbers and take `path = args[-1]` — so a colon anywhere in the PATTERN pushed the real path past the gated slot and the gate inspected a pattern fragment instead. `grep:TOPSECRET|:zz:../outside.py` printed the matching line, and its auto-read the whole file, where `grep:def:../outside.py` — the same file, one slot over — is refused. Same for `around`, which printed the surrounding lines. Both branches now run containment on the path they computed, ahead of `_around_line_delegation` and `_colon_split_hint`, because each stats the path to decide whether to fire and that stat is itself the oracle. `grep` and `around` leave the positional table, which again describes only slots that are always paths; `grep_around` stays, since its trailing slots must parse as integers and a colon in its pattern fails the call rather than moving the path.

- **The mirror: a pattern that looked like a path refused a legitimate local search** ([#1166](https://github.com/Digital-Process-Tools/claude-supertool/issues/1166)). The same table entry from the other side. With a `:` in the pattern, `parts[2]` is a *pattern fragment*, so `grep:path_literal = .:/nope/secret.txt:local.py` — searching a file inside cwd for an absolute-path string — was refused with a containment error naming a file the caller never asked to open. Dropping the positional entry closes it by construction rather than by a second rule.

- **The colon disclosure named the pattern and not the path** ([#1166](https://github.com/Digital-Process-Tools/claude-supertool/issues/1166)). `(pattern read as 'X' — the ':' is part of the regex…)` was honest about how the argument split and silent about the fact that the op then read the last token as the file. A receipt precise about one half and silent about the other reads as complete, which is exactly what stops anyone checking the half that moved. It now names both.
