- **`gh-pr-merge`'s refusal on a not-green PR named a manual route the repo's own raw-command guard then blocked** ([#2588](https://github.com/Digital-Process-Tools/claude-supertool/issues/2588)). The refusal said `the manual route is `gh pr merge N --squash``, and running that from the same session hit the guard's `gh pr merge` mapping, which pointed straight back at the op that had just refused -- two correct refusals citing each other, with no way through for a caller who disagreed with the gate. Every other `gh pr *`/`gh issue *` entry in `presets/github.json` already excludes `--web`/`-w` from its guard mapping (`gh pr view`, `gh pr create`, `gh pr edit`, ...); `gh pr merge` was the one write op in the family missing it. The mapping now carries the same `unless_flag: ["--web", "-w"]` exclusion, and the refusal message names `gh pr merge N --web` -- which opens the merge page in the browser for a human to decide -- as the route that is actually open, alongside merging from outside a hooked session.
