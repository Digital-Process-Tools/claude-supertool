- **The `invariant`-test exclusion step's own comment had its failure direction backwards, and nothing checked its two hardcoded matrix literals against the matrix's own declared axes** ([#2372](https://github.com/Digital-Process-Tools/claude-supertool/issues/2372)). `.github/workflows/tests.yml`'s pytest job deselects `invariant`-marked tests on every leg except `(matrix.os, matrix.python-version) == ("ubuntu-latest", "3.12")`, via `if [ "$MATRIX_OS" != "ubuntu-latest" ] || [ "$MATRIX_PY" != "3.12" ]; then ... fi`. The comment above it claimed the "default arm (no exclusion)" was the safe fallback if those two env vars were ever wrong or unset -- backwards on both halves: an unset `MATRIX_OS`/`MATRIX_PY` compares against the empty string, which makes the `if` true and runs the EXCLUSION branch, not the default one; and if `ubuntu-latest` or `3.12` is ever repinned in the matrix without updating the two literals in the `if`, every leg (including whichever was meant to be the one full run) decides it is not the designated leg and applies the exclusion, so zero of twelve legs ever run the invariant population -- silently, since a deselected test reports nothing. The comment now describes the actual failure mode, and `tests/test_ci_invariant_exclusion_repin_2372.py` (via two new helpers in `tests/_workflow_parse.py`, `matrix_python_versions` alongside the existing `matrix_os`) asserts the `if`'s two literals are still members of the matrix's own `os:` and `python-version:` lists, so a repin of either axis breaks this check loudly instead of leaving the exclusion condition to quietly stop matching correctly on every leg.
