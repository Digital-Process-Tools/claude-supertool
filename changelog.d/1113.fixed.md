- **`assemble_changelog` leaves a blank line above the previous release heading** ([#1113](https://github.com/Digital-Process-Tools/claude-supertool/issues/1113)). `render` ends a section with a blank line and the splice passed it through `str.splitlines()`, which drops the empty field a terminal newline produces — so the new section's last body line landed directly against the `## [x.y.z]` heading below it, on every release since 0.25.0. CommonMark lets an ATX heading interrupt a paragraph, so GitHub rendered it correctly and nothing looked wrong; a stricter parser folds that heading into the paragraph before it, in the one artefact users read to decide whether to upgrade. `_verify_written` now also refuses an assembled file that writes a *new* crowded heading. The four historical instances are left alone deliberately: they shipped inside tags and GitHub release notes, and repairing them would make the file stop matching what was published.
