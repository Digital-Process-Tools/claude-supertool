- **The `github-pr` watch poller no longer votes a superseded check run as a failure**: `_rollup_state` had its own third copy of the FAILURE/PENDING/SUCCESS arithmetic, alongside `gh-pr`'s and `git-branch`'s, and it never got the #1803/#1804 sweep that taught the other two to skip a leg a later same-named run replaced ([#2070](https://github.com/Digital-Process-Tools/claude-supertool/issues/2070)). A cancelled leg a same-named success later fixed still fired an unsolicited `checks_failed` on the watch channel, and it stuck: the next tick only emits on a *change*, so a wrongly-red PR stayed wrongly-red on the board until some unrelated transition moved it. `_rollup_state` now reads through `_checks.github_live_states()`, the same supersession discriminator (timing, not name) `gh-pr`/`git-branch` already use — #1640's two overlapping same-named runs still both count.
