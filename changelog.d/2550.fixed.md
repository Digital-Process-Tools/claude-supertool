- **`_pattern_gate` now caps pattern length at 1000 characters, so `around` and `read:...:grep=` refuse the same way `grep` already does** ([#2550](https://github.com/Digital-Process-Tools/claude-supertool/issues/2550)). The `> 1000 chars` ReDoS length cap was inlined only inside `_op_grep`. `_pattern_gate` -- the single chokepoint `around`'s public wrapper and `read`'s `grep_filter` both route through -- had no equivalent check, so an arbitrary-length pattern from either route reached a live `re.compile`/match against real file content with no size-based backstop at all: the same "guard wired route by route instead of single-sourced" shape #2547 just fixed for the nested-quantifier guard, left unfixed for the length cap. The cap is now single-sourced inside `_pattern_gate`, ahead of the backtracking guard, so every route through it inherits the refusal. `tests/test_pattern_gate_length_cap_2550.py` is the regression coverage.
