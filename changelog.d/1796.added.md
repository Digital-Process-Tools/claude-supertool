- **`gh-job`/`gl-job` list a job's artifacts, and fetch one file out of them**
  ([#1796](https://github.com/Digital-Process-Tools/claude-supertool/issues/1796)).
  `:artifacts` prints what the job (GitHub) or run (GitLab) produced — name, size,
  expiry — and says plainly that neither platform's listing API names the paths
  *inside* an archive, so a specific path still has to be known some other way (a
  log's own printed path, typically). `:artifact:PATH` fetches that one file:
  `gl-job` uses GitLab's single-file endpoint directly, and `gh-job` — which has
  no such endpoint — downloads the one relevant artifact's own zip and reads the
  entry back out, never the whole archive. Printed text only, capped at
  `GH_JOB_ARTIFACT_MAX_BYTES`/`GL_JOB_ARTIFACT_MAX_BYTES` (default 65536 each); a
  binary or oversized file is refused rather than flooding output. `gl-job`
  also names the case that motivated the issue: a token that reads the job's
  metadata fine can still be refused on the artifact-download endpoint, and the
  message says so is a separate scope rather than a bare `Unauthenticated.`.
