- **`registry:OP` now discloses a `builtin-ops` runtime override for a built-in op instead of refusing outright** ([#2079](https://github.com/Digital-Process-Tools/claude-supertool/issues/2079)). `_merge_presets` (#2025) writes a preset manifest's `builtin-ops` entries into the same merged config dict `_get_op_int`, `_get_op_bool` and `_grep_extensions` read for a built-in's runtime behaviour (`read.max_lines`, `grep.extensions`), so a preset — or a project's own top-level `builtin-ops` entry — could silently re-tune a built-in's behaviour project-wide with nothing in the tool disclosing it: `registry:read` refused unconditionally with `'read' is a built-in, not a preset or project op, so it has no registry entry`. `registry:OP` now checks the effective `builtin-ops.<op>` entry first and, when one exists, renders its runtime-affecting keys separately from its documentation-only ones (`syntax`, `description`, `example`, `status`, `hint`, `form` — the shape #1675 already ships for `vim`/`workspace`) and names which preset(s) contributed it. A built-in nobody's config re-tunes keeps the plain refusal unchanged.
