- **A payload quoting the literal-block delimiter twice got a bare TOML column number and no hint** ([#1830](https://github.com/Digital-Process-Tools/claude-supertool/issues/1830)). `_toml_delimiter_hint` fired only on an **odd** count of `'''` runs, on the reasoning that every block opens and closes so a stray one means the content carried its own. The reasoning is sound and the check built from it is not: a run inside a *value* breaks the parse at any count, and even is the ordinary shape for a payload that is about the literal-block syntax — one quoted run in `old`, one in `new`. Hit twice in one agent run while writing #1808/#1814, and again while writing this change. The trigger is now structural and needs no successful parse: each `= '''` opener is walked to the run that closes it, and anything left on that line other than whitespace or a `#` comment means the delimiter closed the value early. The message names the payload line and column of that run. The odd-count trigger is kept behind it, because an unterminated block is odd and has no early close to find.
