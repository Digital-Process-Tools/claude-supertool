- **Containment was verified in a checkout that opts out of it** ([#1353](https://github.com/Digital-Process-Tools/claude-supertool/issues/1353)). This repository's own `.supertool.json` has set `allow_outside_cwd: true` since before v0.33.0, so #1287's boundary is read, resolved, and then declined here. Anyone reproducing a containment fix by running it in this clone gets a pass that is a fact about the config rather than about the guard — this repo's own defect class, arriving through the config instead of through code.

  **The setting stays and the suite stops depending on it.** Removing it would break the cross-worktree reads agents here legitimately make, and a runtime disclosure of which mode a check passed in would print under every call, which is the shape nobody reads. `tests/test_containment_config_independence_1353.py` spawns `supertool.py` from a project directory whose config does *not* opt out, and pins both the core boundary (`read`) and a declared preset boundary (`claims`, `root: repo`).

  **The exposure was narrower than the issue stated, and the scoping is the useful half.** In-process tests were never affected: `tests/conftest.py`'s autouse fixture hands every test `_CONFIG = {}` with `_CONFIG_CHECKED = True`, so `_safe_path`'s config lookup cannot see this checkout's file at all, and deleting the env var is sufficient. It is a *spawned* supertool with a cwd inside this repo that walks up to the real `.supertool.json`. Both halves are now asserted rather than assumed, so if conftest ever stops neutralising the config, one named test says so instead of every in-process containment test quietly becoming a statement about `.supertool.json`.
