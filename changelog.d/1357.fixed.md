- **A containment declaration travelled into the environment of the process it constrains** ([#1357](https://github.com/Digital-Process-Tools/claude-supertool/issues/1357)). `paths` was not in `_RESERVED_KEYS`, so every declaring op exported it to its own subprocess as `SUPERTOOL_PATHS`. Nothing reads it — a tree-wide grep returns zero — and the core has already enforced the declaration by the time the subprocess is spawned. Reserved, on the same terms as `replaces` in #1347, rather than left exported with a note: "our own config, so harmless" is a judgement that would otherwise have to be re-made by every future reader.

  **The `{arg}` lint the same issue proposed is measured and not built.** The proposal was to flag `{arg}` appearing beside a `PATH`-shaped `syntax`. Walked over every shipped manifest: 24 ops carry `{arg}`, 8 of those name a path in `syntax`, and all 8 are already either refused at dispatch by `_entry_names_a_path` unless they declare, or named in `_UNDECLARED_PATH_OPS`. The lint's population is a strict subset of a gate's, and a refusal is strictly stronger than a warning, so it reaches nothing.

  **It is also pointed at the wrong half of the residue.** The op #1357 is about is one that *means* a path and writes `{arg}` behind a `syntax` that does not say `PATH` — and that op is invisible to a lint keyed on the `syntax` saying `PATH`. Closing it would mean promoting `{arg}` to a path signal, which refuses the 16 shipped ops that pass a handle, a ref, a tag, an ID or a repo slug through it and take no path. The residue stays open by decision, pinned by a test that asserts the gate returns `None` for exactly that shape, so the proposal is not re-derived from the issue text alone.
