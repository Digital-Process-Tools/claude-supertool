- **`gh-pr-merge|cleanup` no longer deletes a head branch that an open pull request is stacked on** ([#2225](https://github.com/Digital-Process-Tools/claude-supertool/issues/2225)). GitHub closes a stacked pull request the instant the branch it targets is deleted, and there is no clean way back: reopening a closed PR needs its base branch to exist, retargeting it needs it to be open, and the two refuse each other in a cycle. The op already detected the stacked follow-up and printed a `## Stacked follow-up` section, but only after the delete had already run, so it read as an FYI about what to watch rather than a warning about what the same call was about to close. `run_cleanup` now takes the already-computed stack state and refuses the *remote branch* item -- never the local worktree or local branch, since those are not what GitHub reacts to -- whenever a stacked pull request is known (`STACK_FOUND`) or was never established (`UNKNOWN`), matching the refuse-on-unestablished posture the op already applies to `cross_repo` and the default branch (#1281/#1292). Only an established empty board (`STACK_NONE`) still deletes.
