- **The `SessionStart` hook's behaviour on a native Windows host with no Git for Windows is stated rather than fixed** ([#1401](https://github.com/Digital-Process-Tools/claude-supertool/issues/1401)). That host has no `Bash` tool, so the `PreToolUse` guard never fires there — but `SessionStart` is not tool-gated, and it loses the `./supertool` symlink and the op roster every session. Nothing inside a `.sh` file repairs a host that cannot run a `.sh` file: `args` would switch the entry to exec form and introduce the `PATH` search the issue was originally about, a second PowerShell entry would break every POSIX session to serve one Windows one, and a string valid under both `sh -c` and PowerShell is a polyglot shipped to every plugin user on the strength of a Mac.

  `docs/configuration.md` now carries the gap with its evidence grades — which claims are *observed* and which are *reasoned from Claude Code's documentation* — because nobody on this project has a Windows box and CI's twelve legs cannot settle it either.
