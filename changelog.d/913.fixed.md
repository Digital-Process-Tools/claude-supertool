- **`map`'s three tiers are a per-file chain again — tier 2 was unreachable on any machine where tree-sitter merely imported** ([#913](https://github.com/Digital-Process-Tools/claude-supertool/issues/913)). `use_ctags = not use_ts and _has_ctags()` decided ctags once for the whole run, so the per-file `if not symbols_found and use_ctags` fallback below it was dead code whenever the language pack was installed. The documented cascade 1 → 2 → 3 was really tree-sitter XOR ctags, then regex. `map:notes.rst` — a file no tier-1 grammar claims, which is exactly what ctags exists to cover — went straight to regex and reported `tier: none`, and someone who installed universal-ctags on that advice got nothing back and was told nothing.

  **The fallback is gated on tier 1 being blind to the file, not on it coming back empty.** A file whose extension has no tree-sitter grammar, or whose grammar failed to load, drops to ctags. A file tree-sitter read and found no definitions in does not: the answer is already known. That distinction is the whole cost of the fix and it was measured rather than argued. On this repository at 100 mapped files, 14 produce no tree-sitter symbols and every one of the 14 is the second kind — changelog fragments, an empty `__init__.py`. A ctags call costs ~41ms per file on macOS, ~33ms of it bare process spawn, so falling back on emptiness would have added ~0.6s to `map:.` to reach the same empty lists, and put a per-file subprocess on the shape that has reddened Windows legs four times ([#1296](https://github.com/Digital-Process-Tools/claude-supertool/issues/1296), [#1360](https://github.com/Digital-Process-Tools/claude-supertool/issues/1360), [#1461](https://github.com/Digital-Process-Tools/claude-supertool/issues/1461), [#1501](https://github.com/Digital-Process-Tools/claude-supertool/issues/1501)). Under the gate the added spawn count on both those runs is zero.

  **`; ctags found nothing` now means ctags ran.** The note in the `no symbol parser for .ext` line was appended from ctags being *available*, so it could report an empty result from a tier that was never asked — the absence-produced-by-the-tool shape, inside the render that exists to keep that shape visible ([#887](https://github.com/Digital-Process-Tools/claude-supertool/issues/887)). It is now driven by whether the call was made on that file.

  Behaviour with no tree-sitter installed is unchanged: every file still goes 2 → 3, and that is pinned.
