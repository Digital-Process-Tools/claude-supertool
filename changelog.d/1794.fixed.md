- **Two of #1794's five op-message papercuts fixed: `edit`'s nearest-match hint now names the first byte where a single differing line diverges, and the `literal_backslashes` refusal nudges toward the fix that matches the target's extension** ([#1794](https://github.com/Digital-Process-Tools/claude-supertool/issues/1794)). Filed from a real `oss` loop run: an `edit` whose `old` failed to match reported `nearest match at lines N-M (100%)` for a difference that was invisible at a glance (two backslashes escaping single quotes inside a payload literal) — `_edit_nearest_hint` already named a near miss's KIND (#1855: `differs only in whitespace` / `differs in N of M lines`), and now also names the first character where the ONE differing line diverges when the two blocks are the same height, so a positional pairing can be trusted; a height mismatch or more than one differing line still gets no offset, on the same "declining beats a confidently wrong answer" reasoning as the rest of this hint. Separately, `literal_backslashes`'s doubled-backslash refusal fired correctly every time the reporter hit it but asked the same "half the run, or as written?" question of a payload writing `.json`/`.py` (where a doubled backslash is usually a REAL one — a JSON or Python string-literal escape) and one writing prose (where it usually is not); the refusal now names which of its two listed fixes is the common case for the target's own extension, silent on a mixed or unopinionated extension where a wrong nudge would cost more than none.
