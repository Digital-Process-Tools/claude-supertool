- **`gh-pr-merge`'s cleanup section opened by denying a capability it offers 70 lines later, and printed a delete command carrying `{owner}/{repo}`** ([#1670](https://github.com/Digital-Process-Tools/claude-supertool/issues/1670)). Two halves of one receipt, both in the arm rendered when `cleanup` was not asked for.

  **The header.** It read `## Cleanup — not run by this op`. The op does clean up — `|cleanup` has run it since [#1256](https://github.com/Digital-Process-Tools/claude-supertool/issues/1256), and the line offering it sat 69 lines below. A property of the invocation was stated as a property of the op, and a reader who stops at a header concludes the capability is missing: the shape where a stale absence claim suppresses the call that would disprove it. It now reads `## Cleanup — not run by this invocation (add `|cleanup`)`, and the three refusal arms each say that `|cleanup` refuses on the same ground, so the offer is never left standing where it would not be taken. The test pins the property rather than the wording — whatever token the header offers in backticks has to be one `parse_argv` turns into `cleanup=True`, so deleting the route reddens it and rewording the header does not.

  **The printed path.** `_repo_target.api_path` leaves gh's `{owner}`/`{repo}` in place when no `repo:` target is set, because `gh api` expands them from the cwd's remote and a target has to *replace* rather than accompany them ([#1281](https://github.com/Digital-Process-Tools/claude-supertool/issues/1281)). That is right for a path this process executes and wrong for one pasted by a reader: the command silently changes meaning with the directory it lands in, while the same render prints the concrete slug twice, in its own header and its `URL:` line. Printed paths go through a new `api_path_for_display(suffix, slug)` instead, which fills in the slug the op read back off `gh repo view` and declines to a placeholder path when it did not get a well-formed one — a partial answer is not a path to build. Every executed path still goes through `api_path` unchanged, and under a `repo:` target the two functions return the same string, so the split cannot become a route by which a target is accompanied instead of replacing.
