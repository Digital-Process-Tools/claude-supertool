- **`gl-mrs` had no transport-marker whitelist and no rate-limit arm, so a `glab` DNS failure told a caller to stop where `gh-prs` tells it to retry** ([#1870](https://github.com/Digital-Process-Tools/claude-supertool/issues/1870)). `gh_prs` has classified a transport failure -- DNS, a refused connection, a reset socket, Go's `net`/`net/http` vocabulary -- as `RadarUnreachable` since #1568, so a caller catching it knows to retry; `gl_mrs` classified on structure only (a spawn that never completed, a negative returncode, `_auth_probe`'s answer) and let every transport failure fall into the widest class, `RadarError`, which a caller reads as a verdict about the board rather than a reason to try again. `presets/watch/tiers/gl_mrs.py` now carries its own `TRANSPORT_MARKERS` -- a separate tuple from `gh_prs`'s, mirroring #1846's split for the auth markers, since the two Go CLIs' vocabularies are not guaranteed to stay identical -- plus a rate-limit arm on GitLab's own `429` status rather than a port of `gh`'s `403`. Every marker is prose, never a bare status number, for the reason #1864 names. Reasoned, not observed: no authenticated `glab` was available to drive a real transport failure through, so the marker list is ported from `gh_prs`'s own on the argument that both CLIs are Go binaries surfacing the same standard-library net errors verbatim.
