- **A check run a later run of the same name superseded is a third state, not a red leg** ([#1792](https://github.com/Digital-Process-Tools/claude-supertool/issues/1792)). `gh-pr:N:status` counted every check run on the head SHA, but GitHub decides a required check on the **latest** run carrying that name — so a pull request the forge reports as `mergeable_state: clean` rendered `NOT ALL GREEN`, and `gh-pr-merge` refused it. Permanently: a concluded check run cannot be withdrawn by any trigger a maintainer has, so the pull request could never satisfy the gate by any action available to them. Reported from outside, against `jbkkz/requivo` PR #18 — six check runs named `fragment` on one SHA, five that failed at 22:23 and one that passed eight hours later.

  **The discriminator is timing, not name.** Latest-per-name is not a safe collapse: GitHub's default code-scanning setup emits two concurrent runs per push, and measured against this repository's own `d1bb0837` those two runs emit check runs whose *names collide* — two `Analyze (javascript-typescript)`, two `Analyze (python)`, two check suites, started in the same second. Collapsing on the name would have reported a leg that never ran as green, which is the defect [#1640](https://github.com/Digital-Process-Tools/claude-supertool/issues/1640) fixed one op over. A leg is superseded only when another leg of the same name **started strictly after this one completed** — so the code-scanning pair supersedes nothing, and the five stale `fragment` runs all do.

  It is deliberately **narrower** than GitHub's own rule. Two same-named legs overlapping in time with one failed still read red here even where the forge says clean: a loud false alarm costs a reader one look, a quietly-swallowed failure costs a merge.

  **The superseded failure is never invisible.** It takes its own tally term — so `N total` still accounts for every leg on the commit — and its own named disclosure line carrying the state it concluded in and its job id, on `gh-pr:N`, `gh-pr:N:status` and both paths of `gh-pr-merge`:

  ```
  checks: 6 total: 1 passed, 0 failed, 0 pending, 5 superseded
    superseded failed: fragment (job #95528525867), fragment (job #95528526529), …
  ```

  A leg whose completion cannot be read — an absent stamp, `gh`'s `0001-01-01T00:00:00Z` sentinel, or a legacy commit status, which carries no run timing at all — is never superseded. It stays counted and stays red. The reconciliation against what the runs declare still sees every leg, because that is a coverage question and not a verdict.
