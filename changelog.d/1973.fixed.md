- **Two vim `:r` tests stopped racing the shared platform temp root -- diagnosed, not fixed** ([#1973](https://github.com/Digital-Process-Tools/claude-supertool/issues/1973)). `test_r_success_receipt_carries_no_diagnostic_noise` and `test_log_pattern_Nr_read_file_after_line` built the file `:r` reads via a bare `tempfile.mkstemp()`, landing it directly under `/tmp` or `/var/folders/.../T` -- written and reaped by every xdist worker at once -- rather than under pytest's own per-test `tmp_path`. Both now use `tmp_path`, which removes the tests' own exposure to that shared root; it does **not** establish that the shared root was the mechanism the two CI reds actually hit. One candidate the issue raised is explicitly ruled out by inspection: both tests call `os.close()`, and `mkstemp()`, unlike `NamedTemporaryFile(delete=True)`, does not delete its file on close, so "closes and therefore deletes" does not describe either test. A repo-wide sweep for the same shape (a bare `tempfile.mkstemp()` fed to a vim `:r`/`:w` action) found no third instance -- every other such test already used `tmp_path`.
