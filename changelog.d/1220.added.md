- **`claims:PATH` — does a document's references still hold?** `.claude/skills/opensource-manager/SKILL.md` told the maintainer, under a bullet headed "Two genuine gaps", that no op rendered a commit's run list and nothing tallied label distribution; `gh-branch:COMMIT_SHA` (#1083) and `gh-labels:tally=PREFIX` (#1084) had both shipped, and the second is the cohort burn-down that file orders reported every tick. A doc that is loaded rather than read does not merely risk being wrong, it produces the behaviour it describes. `.claude/jit-context/*.md` is the sharp end — injected at the moment of a tool call — and on the day this shipped it listed five issues under "Open defects" headings, all five closed.
- **It checks references, never reasoning, and the boundary is measured rather than argued.** Flagging `#NNNN` citations by issue state plus an absence-marker word list scored 15 flagged, 2 real — 13% — because past-tense narration of a fixed bug is lexically identical to a present-tense claim that a hole exists. Three narrower lexical anchors were measured against this repo's whole doc corpus and scored 14%, 11% and 20%. None beat the number already rejected, so there is no lexical lens in the op at all and the render says so. Over 22 documents here: 11 contradicted, 11 real; none of the original 15.
- **Three lenses.** Backticked `name:...` tokens against the live registry — `key=` flags only, because a bare segment is a value in a placeholder slot, and a head resolving to nothing is `couldn't check` rather than a finding (19 such tokens here were skill ids and label filters, none a stale op name). Paths, `:LINE` numbers, quoted lines and section headings against the tree — a quotation beside a line number is checked against that line, since a number alone only proves the file is long enough. And issues cited under a heading that *declares* them open defects, which carries a verdict where prose cannot because it reads the document's own annotation instead of guessing at its grammar.
- **Three states, and the third never collapses.** A doc with nothing contradicted but something unchecked prints `NOT A CLEAN DOC`. A sibling repo's path, an ambiguous basename, a placeholder in a naming convention, a citation into another tracker and an unreadable tracker are all `couldn't check` — and the sibling-repo rule refuses to sweep prose for `owner/name` slugs, because doing so read `dependabot/outside-contributor` as a repository and ate two real findings.
