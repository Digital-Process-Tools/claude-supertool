- **`watch`/`radar` no longer push a macOS desktop notification by default** ([#2544](https://github.com/Digital-Process-Tools/claude-supertool/issues/2544)). Every poller fired an undisclosed `osascript` ping on most status changes -- not only on errors, despite `transport.py`'s own module docstring saying otherwise -- undoable only by killing and respawning whatever was already running, and never named in `help:watch`/`help:radar`. The default is now off: `SUPERTOOL_WATCH_DESKTOP=1` (or `watch_desktop: true` under `ops.watch`/`ops.radar`) opts in, read the same way the existing `SUPERTOOL_WATCH_NO_DESKTOP` opt-out is. `SUPERTOOL_WATCH_NO_DESKTOP` keeps working exactly as before and always wins when both are set -- an operator who already silenced this keeps getting silence. `watch`'s and `radar`'s own op descriptions now name both knobs, and the module docstring that used to say "on terminal/error" now says what the call sites actually do.
