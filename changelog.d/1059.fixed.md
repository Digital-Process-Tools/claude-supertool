- **`vim` destroyed every non-UTF-8 byte in the file, including bytes the edit never touched** ([#1059](https://github.com/Digital-Process-Tools/claude-supertool/issues/1059)). `op_vim` read with `errors="replace"`, which turns each such byte into U+FFFD in memory, and `vim` writes the whole buffer back. A single `cc` on line 1 therefore rewrote a stray latin-1 byte on line 40 — unrecoverably, with nothing in the receipt saying anything had happened. `edit`, `replace` and `replace_lines` have read with `surrogateescape` since #1049 and carry a comment saying exactly why; `vim` was the one that did not get it. Now it does.

  **Three reads, not one.** The entry read was the obvious one. `:r FILE` splices a *second* file's text into the buffer that gets written, and `:norm` re-reads the file from disk twice per range. All three had the same `errors="replace"`, so fixing only the entry read would have left two live paths to the same destruction.

  **Refusing to open such files was considered and rejected.** That trades destruction for an outage on files that work today — the loud-for-quiet trade pointed the wrong way.

  **The receipt had to move with it.** A `surrogateescape` buffer holds lone surrogates, and receipts echo the buffer back as context lines and a diff hunk. No UTF-8 stream can encode a lone surrogate, so the fixed op wrote the correct bytes and then died with `UnicodeEncodeError` on the way to saying so: a traceback, no receipt, over a file that had changed. `edit`, `replace` and `replace_lines` have carried that same latent crash since #1049 and nobody had hit it. Sanitised once at `dispatch`, the outermost frame every consumer shares — display only, U+FFFD on screen, exact bytes on disk.

  **Still no `newline=""` on `vim`, deliberately** (#1049's reasoning, unchanged): every motion, `o`/`O` and `dd` assumes `\n`, so adding it underneath converts one whole-file normalisation into scattered mixed endings. That is a separate design job, and the byte destruction was not blocked by it. Shipping half is worth more than waiting for the whole.
