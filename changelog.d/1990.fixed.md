- **`gh-pr-merge` no longer directs a squash-and-delete at a repository nobody named in the call** ([#1990](https://github.com/Digital-Process-Tools/claude-supertool/issues/1990)). It is the one op-mode acting op in the tree, with no payload field to reconcile a `repo:` target against, so #1986's `resolve_or_conflict` chokepoint never reached it — an ambient `SUPERTOOL_REPO` (a caller's shell export, or a value inherited from elsewhere in the same process) still filled `gh_args()`/`api_path()` for every call this op makes, including the merge itself and the branch-delete under `|cleanup`. `presets/_repo_target.py`'s helpers now take an `explicit` flag; `gh-pr-merge` calls every one of them with `explicit=True`, which reads `explicit_target()` — the same guarantee the four payload-mode write ops already had — instead of the bare env var. An ambient value with no `repo:` op in the call reads as absence, exactly as it does for those four; a real `repo:X gh-pr-merge:N` call is unaffected.
