- **Symlink tests asked which platform they were on instead of what it could do** ([#1143](https://github.com/Digital-Process-Tools/claude-supertool/issues/1143)). Nine symlink-dependent tests each decided for themselves whether a symlink was possible, in five spellings across two kinds: `skipif(os.name == "nt")` and its two synonyms, which hardcode "Windows cannot" so a runner that *can* -- Developer Mode, an elevated service account -- still never runs them; and a per-file `try`/`except OSError` whose skip message vanished into a Windows leg's ~680 others. `tests/_symlink.py` now probes once per process by creating a real symlink and checking `os.path.islink` on the result -- an NTFS junction passes `os.symlink` and fails that check, and a junction-based fixture exercises the non-link branch, so it is reported as unavailable rather than as a capability. Where the privilege exists the whole class now executes on Windows, which no platform-name gate could allow. Where it does not, the skips carry one shared reason, and `conftest.py` states the verdict in the report header on every run (green ones included) and counts those skips apart in the terminal summary. `tests/test_coverage_gate_workdir_877.py` was gated on that file's *mode-bits* flag, a second capability behind the same name. `tests/test_read.py::test_read_meta_symlink` stays platform-gated on purpose and now says so out loud: its assertion, not its fixture, is what Windows spells differently.
