- `grep`, `around` and `between` now disclose when an empty result came from `supertool.py`, which since #931 is an entry-point shim — 171 lines, 15 of them executable, almost all comment — with the tool's implementation in `_supertool.py` beside it. `0 results in 0 files, scanned 1 files` was true, and byte-identical to the same zero from the core — so every historical instinct to grep `supertool.py` read as "the symbol does not exist".
- Disclosure, not redirect: the op still scans exactly the file it was named. Silently scanning `_supertool.py` instead would answer a question nobody asked and report it as the answer to the one they did.
- Gated on the pair being on disk together, so a file merely named `supertool.py` in another tree is untouched, and on the result already being empty — a hit is evidence about the shim and needs no disclaimer.
- Every render path that can produce such a zero carries it: `grep` plain, `grep` with context, `grep:...:count`, `around`, and both arms of `between` (symbol and `re:`). The count form matters most — it is the call you make before deciding whether to look at all.
