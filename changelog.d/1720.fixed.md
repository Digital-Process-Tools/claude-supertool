- **`literal_backslashes` set inside more than one `[[ops]]` entry now names every offending index, not just the first** ([#1720](https://github.com/Digital-Process-Tools/claude-supertool/issues/1720)). The issue's own headline case -- a payload write refusal naming only the first offending field -- was already fixed by #1808/#1814/#1819/#1839, which widened `_payload_double_backslash_refusal` to locate every occurrence in every offending field, capped and disclosed rather than silently truncated; this PR pins that with a regression test. The remaining half of the same family, `_payload_literal_backslashes_misplaced` (#1096), had the identical defect one level up: setting `literal_backslashes` inside `ops[0]` and `ops[2]` of the same batch reported only `ops[0]`, sending a caller who fixed it back for a second round-trip to learn about `ops[2]`. It now names every index.
