- **The open-PR board fetch and the default-branch head/run read are now one module, `presets/_pr_board.py`, instead of two implementations that could each fix the same defect and leave the other holding it** ([#958](https://github.com/Digital-Process-Tools/claude-supertool/issues/958)). Radar's GitHub tier (`presets/watch/tiers/gh_prs.py`) and the `dashboard` op (`presets/dashboard/dashboard.py`) each spawned `gh pr list` and parsed the JSON, and each ran `gh-branch`'s `_head_commit`/`_run_list` pair to read the default branch's state -- two copies of the mechanical fetch, not of the judgement: the per-PR leg reconciliation (`pr._reconcile_checks`) was already shared and is untouched. `run_pr_list` gives both callers the same `(data, error, returncode, raw_stderr)` three-state contract -- `data is None` iff there is an error, and `returncode == 0` alongside `data is None` is called out explicitly, since a caller classifying by exit code must not read a bad-JSON payload as "no failure to explain". `head_and_runs` gives both the same two-call sequence for the default branch, with the run list never asked for once the head commit is unresolved. Radar's poller machinery and its own `RadarError`/`RadarUnreachable`/`RadarUnconfigured` classification stay in `gh_prs.py`; the dashboard's `declared_pair` scoping and serial job fetch stay in `dashboard.py` -- both callers currently compose the shared reads differently on purpose, which the new module's docstring says explicitly rather than papering over by force-unifying them.
