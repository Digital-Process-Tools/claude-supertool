- **A `guard_main` crash receipt on the `ci-lint` resolve step could be misread as a resolved file path.** `ci_lint_resolve_root.py` -- the only `resolve` command in the tree -- ends with `guard_main(TOOL, main)`, whose contract is to publish one JSON crash receipt on stdout and exit 0 when `main()` raises. `_validator_resolve` in `_supertool.py` is not an adapter-style reader, though: it takes the resolve command's first stdout line and trusts it as a resolved path outright, without ever checking `returncode`. A crash therefore became the "resolved file", `ci-lint.py` reported "file not found", and a `rollback_on_fail: true` validator could silently revert a correct edit. `_validator_resolve` now recognizes the receipt's shape (a JSON object carrying both `tool` and `ok`) and refuses to hand it back as a target. The adapter-crash-net census (`tests/test_adapter_crash_net_1697.py`) also excluded every file under `validators/common/` by directory, on the stated grounds that it "holds shared helpers with no `main` and no `__main__` block" -- true of every file there except this one, which has both and was therefore invisible to the sweep. The exclusion is now by whether a file actually has a `__main__` block, so the next file shaped like this one is not silently missed the same way.
