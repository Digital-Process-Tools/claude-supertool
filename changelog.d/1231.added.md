- **`ops:roster` — every op name plus a safety class, and nothing else** ([#1231](https://github.com/Digital-Process-Tools/claude-supertool/issues/1231)). No descriptive listing form fits the SessionStart hook's ~7,168-byte cap: `ops` is 47,260 bytes in this checkout and `ops-compact` 9,067, so the startup listing was truncated on **every** session and everything alphabetically after `grep` was hidden — the whole `gh-*` and `git-*` families, `radar`, `watch`, `read`, `paste`, `tree`. `ops-compact` disclosed the truncation honestly and that did not help, because what was hidden was *existence*: in one session a maintainer reached for `worktrees` while `git-worktrees` existed, hand-rolled four `gh pr create` calls past `gh-pr-create` and its closing-reference check, and hand-rolled a cohort tally past `gh-labels:tally=`. Three agents independently reported `write:` is not an op, none having been told `paste:` is. The roster is 1,441 bytes; the whole hook payload is 2,378. It is now what `hooks/session-start.sh` prints.

  **The class is the reason names alone were not enough.** Most ops teach their own signature on contact — `between:FILE:747:820` answers *"'820' was read as the path"* and names the op that does take a range — so roster → call → error is a complete learning loop. It is not available for an op that acts on the world: `oss_train` force-pushes a merge train, `gh-pr-merge` merges, `watch` spawns a poller, `git-push` publishes. Unmarked is a positive **read-only** claim, `*` writes files in this tree, `!` reaches outside it or spawns.

  **Declared, never inferred, and the fallback is the loud one.** Preset and project ops carry a new `"safety"` key beside their `cmd`; built-ins take theirs from `_OP_SAFETY_BUILTIN` in the binary, which a project's `.supertool.json` cannot downgrade — the class is a property of this build and the config may be absent or somebody else's. An op with no class, or an unrecognised one, renders `!`: an `acts` op mis-shown as probe-safe invites someone to probe `oss_train`, while the reverse costs one `help:OP`. Tests fail if any shipped preset op omits the key, so the next op cannot ship unclassed. `_PARALLEL_SAFE_OPS` was rejected as a derivation source despite being documented as the read-only set — it carries `format_staged`, which writes every staged file.

  Flat and alphabetical rather than grouped by family: every miss above was a neighbour miss, and one alphabetical sweep finds `gh-pr-create` beside `gh-pr` where a family grouping asks the reader to already know the family. A test pins the roster under half the cap, so adding ops cannot quietly reintroduce the truncation.

- **`ops` refuses an unrecognised argument instead of discarding it** ([#1231](https://github.com/Digital-Process-Tools/claude-supertool/issues/1231)). `ops:gh-labels` printed the entire 47KB listing and said nothing about the token it dropped — an argument ignored without a word, in the op whose subject is which arguments exist, in a tool whose rule is that an unrecognised token is refused. It now names the alternative: `help:gh-labels` for that op's full entry, which carries more than the listing row ever did, or `ops:roster` for every name. Deliberately *not* made into an `ops:PATTERN` filter: `help:OP` already answers what a filter would and answers it with more, and a filter would rebuild this issue in miniature, since `ops:gh-labl` matching nothing renders identically to an op that does not exist.
