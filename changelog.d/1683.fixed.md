- **An adapter's `duration_ms` on a failure path is measured rather than written down** ([#1683](https://github.com/Digital-Process-Tools/claude-supertool/issues/1683)). Thirteen adapters emitted their own timeout budget as a literal in the `TimeoutExpired` arm — `30000`, `120000`, `TIMEOUT_S * 1000` — and `ruby-check`'s module-level crash handler emitted `0` whenever it fired, because `main`'s `start` was not in its scope. All fourteen now read a clock.

  The number is not decoration. `tests/_adapter_verdict.stalled_at_its_own_wall` declines to assert on a payload whose `duration_ms` reaches the adapter's internal budget, on the stated grounds that an adapter reporting a timeout in 12ms did not time out and its error routing is broken. A literal equal to the budget satisfies that floor whatever actually happened, so the clause could not fail for the thirteen adapters that wrote one: the routing defect it exists to expose would have been declined as a stall instead. #1604 is the same clause working from the other side, where a hardcoded `0` made a real 30-second wall unclassifiable.

  `tests/test_adapter_duration_is_measured_1683.py` keeps it that way. It reads every `duration_ms` inside an `except` handler across every `validators/*/*.py` and requires the value to resolve — through names, and through functions defined in the same file — to a clock read. Argv arms reporting `0` before any clock starts are deliberately out of scope: there is no elapsed there to report, and demanding one would be demanding a fabricated number.

- **The directory-removal register can see `.cleanup()`** ([#1683](https://github.com/Digital-Process-Tools/claude-supertool/issues/1683)). `tests/test_directory_removal_ownership_1635.py` counted `TemporaryDirectory` as an ownership source while its removal side had no matching verb, so `.cleanup()` on any receiver was a directory removal the register did not see — a guard reporting clean because it could not look. The #1656 cache-home teardown added in #1682 was exactly that site, and its own comment had to say so.

  The receiver is now the target, the same shape `rmdir` already resolved, so the ownership question asked of it is the one asked of every other site. Only the no-argument spelling counts: a `cleanup` taking arguments is another object's method. `tests/conftest.py` holds the object in a module list rather than on `config`, because a `getattr` off an attribute is a chain nothing in the file can follow — the site is proved by the register now instead of being invisible to it.
