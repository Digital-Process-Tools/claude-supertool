- **A quoted TOML key on the fallback parser now names its own cause instead of reading `bad key at offset N`** ([#1595](https://github.com/Digital-Process-Tools/claude-supertool/issues/1595)). `_mini_toml_loads` -- the parser every `@payload` runs through on Python <3.11, where stdlib `tomllib` does not exist -- accepts a key character only if it is alnum, `_` or `-`, so a quoted key (`"my key" = 1`, valid TOML and accepted on 3.11+) never starts. The refusal used to read `bad key at offset N`, indistinguishable from a genuine typo on every Python version, including the ones where the input is in fact valid. It now mirrors the message the same function already gives four screens up for a bare `[table]` header: cause, version boundary (`Python <3.11`), and escape hatch (a bare key, or JSON). This is deliberately the second, cheaper half of the issue's own split -- widening the grammar to accept quoted keys is left open, and this PR does not claim to close that half.
