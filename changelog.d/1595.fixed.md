- **The fallback TOML parser now accepts a quoted key, same as stdlib `tomllib`** ([#1595](https://github.com/Digital-Process-Tools/claude-supertool/issues/1595)). `_mini_toml_loads`, the only TOML reader on Python <3.11, scanned a key with `raw[i].isalnum() or raw[i] in "_-"`, so a quoted key (`"my key" = 1`, valid TOML and accepted by stdlib on 3.11+) never started -- a divergence across a third of the supported matrix, with no documented form actually hitting it (measured at zero quoted TOML keys across 28 doc files and 722 test files). #2008 already fixed the SECOND half of this issue -- the refusal names its cause instead of reading as a typo -- so this closes the grammar gap itself: a double-quoted key decodes escapes through `_toml_decode_escape`, the same escape decoder the single-line basic-string VALUE branch already calls (not `_toml_basic_unescape`, which is only for the triple-quoted multi-line value form and has no key applicability -- keys are single-line only), a single-quoted key is used verbatim, both single-line only (TOML has no multi-line key form). Dotted keys (`a.b = 1`) and quoted `[table]`/`[[table]]` names remain out of scope, named as such in the issue.
