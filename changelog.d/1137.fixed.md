- **The commit receipt names a non-ASCII path as itself** ([#1137](https://github.com/Digital-Process-Tools/claude-supertool/issues/1137)). `git diff --cached --name-only` runs paths through `core.quotepath`, so `café.txt` reached the `Files committed:` listing as an octal-escaped, double-quoted `"caf\303\251.txt"` — a rendering that is not the path and does not paste back as one. The read is now `-z`, matching what the refusal path has used since [#1003](https://github.com/Digital-Process-Tools/claude-supertool/issues/1003).

  Long-standing and survivable while the caller had typed the path list and already held it. `--all` is what makes it matter: there the caller typed nothing, and that listing is the only record of what was committed.

- **A staged deletion of a non-ASCII path can be committed by name again** ([#1137](https://github.com/Digital-Process-Tools/claude-supertool/issues/1137)). The same `core.quotepath` defect had a second call site one hop above the receipt, and there it was not cosmetic. A path that is already a staged deletion has to be dropped from the `git add` list, because it is gone from disk and git aborts on it ([#324](https://github.com/Digital-Process-Tools/claude-supertool/issues/324)); the drop-list was read without `-z`, so `café.txt` came back as a quoted, octal-escaped string that never equalled what the caller typed. `git rm café.txt` followed by `git-commit:::MESSAGE:::café.txt` died on `fatal: pathspec did not match any files` — the exact failure #324 exists to prevent, alive for every path git chose to quote, while the identical call with an ASCII name passed.

- **A path made entirely of whitespace is no longer dropped from the receipt** ([#1137](https://github.com/Digital-Process-Tools/claude-supertool/issues/1137)). Three `-z` streams were split and then filtered with `p.strip()`. A NUL-delimited stream's only empty segment is the empty string, so the strip bought nothing and cost every path whose name is whitespace, which git permits and POSIX filesystems hold. Under `--all` that read `Staged: 3 path(s)` above `Files committed: 2`, with no mention anywhere of the third — inside the one flag whose whole contract is that the receipt is the complete, uncapped record of what the caller did not type. All three now go through one `_z_paths` helper that discards `""` and nothing else.
