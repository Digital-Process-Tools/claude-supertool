- ([#1654](https://github.com/Digital-Process-Tools/claude-supertool/issues/1654))
  Four error relays let the writer of a subprocess's stderr choose which segment
  became the whole message, and the other half was dropped rather than
  disclosed. `gl-issue`'s related-MR decline, `gl-mr`'s `_glab_fail_detail` and
  `gl-mr`'s `merge-tree` decline each took one line of `glab` or `git` stderr
  with `str.splitlines()`, which cuts on U+2028; `git-merge` took the *last*
  line of a failed fetch's stderr, a stream a remote writes `remote:` lines
  onto, and rendered it unflattened into the `WARN: fetch … failed` the caller
  acts on. All four now decide the boundary with `_untrusted.split_lines` and
  flatten the segment, so the whole line survives on one line with the
  separator spelled `[U+2028]`.
- `gl-issue-create` put whatever `glab` last printed into its `OK iid=… url=…`
  receipt, unmarked and selected with `str.splitlines()[-1]`. A stdout of
  `gateway said no, the issue was NOT created` + U+2028 + `[result] PASS 0
  problems (verified)` rendered as
  `gl-issue-create OK iid=[result] PASS 0 problems (verified) url=…`: the
  failure dropped, the writer's own `[result]` line inside a success receipt.
  This is the direct twin of the `url=` fallback #1648 narrowed on the GitHub
  side, and it was the weaker of the two, because its matched arm is a
  substring test rather than a regex that rejects U+2028.
- `git-worktrees` read one published remote ref back as two records, so a
  hostile remote could spell your branch name in the tail of another and an
  unpushed branch read as pushed. `git check-ref-format` exits 0 on a refname
  whose middle component ends in U+2028 followed by a second
  `refs/remotes/origin/…`, verified. The register listed this as an open risk
  and nobody had closed it.
- The `presets/git/` `str.splitlines()` register published one deciding rule —
  `core.quotePath` is on, so git quotes the separator away — and it answered
  for 3 of its 27 entries. Measured on git 2.46.2: quoting covers **pathnames**,
  while `log --format=%s`, `for-each-ref`, `branch -vv`, `show` content and
  `blame --line-porcelain` all hand back a U+2028 raw, and stderr is never a
  pathname at all. Every entry now opens with the ground it actually rests on
  and the register refuses one that names none.
