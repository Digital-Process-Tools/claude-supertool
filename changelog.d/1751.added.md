- **`git-worktrees` now answers whether a tree holds uncommitted work, and the exit code says so** ([#1751](https://github.com/Digital-Process-Tools/claude-supertool/issues/1751)). A detached worktree has no branch, so its merge column is structurally `n/a` — leaving `idle` at exit 0 as the entire verdict standing between `git worktree remove` and work that exists nowhere else. Every row now carries `clean`, `dirty: N` or `dirty unknown`, counted on the `[result]` line, and the scan runs `--no-optional-locks` so an op that promises inspection-only does not write the index of a tree somebody is holding.

  **Exit-code change.** `3` joins the declared values and is not `clean`, so `supertool 'git-worktrees:PATH' && <reap>` declines over a dirty tree. Exit `0` is unchanged in spelling and stricter in meaning — `idle` must now also be clean — and a dirty scan that could not answer lands on `2`, never on `0`. A caller testing `== 1` for `occupied` is untouched.
