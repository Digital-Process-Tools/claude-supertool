- **`test_the_environment_switch_turns_it_off` (`tests/test_read_elide_unchanged_1329.py`) is no longer order-dependent under xdist** ([#2619](https://github.com/Digital-Process-Tools/claude-supertool/issues/2619)). It failed once on master (ubuntu-latest/3.11, `popen-gw3`) on the baseline elision check -- content came back on a second, still-unchanged read, before the environment switch was even touched. No sibling-test state leak could be found; instead the test's two `op_read` calls used real `time.time()`, unlike this file's other tests exercising the same "read twice, expect elision" shape, already frozen for the identical class of race in #2354. Reproduced directly: `_read_elide`'s window guard is `0 <= now - prior[1] <= window` -- deliberately conservative, so it declines to elide on a *negative* gap rather than guessing -- and a backward step of the wall clock as small as 50ms between the two calls (an NTP correction or VM clock skew, the same "loaded parallel CI runner" shape #2354 already names) makes the gap negative and the elision is correctly refused. Time is now frozen in this test, matching its siblings, and a new positive control (`test_a_backward_clock_step_still_correctly_declines_to_elide`) pins the `0 <=` half of the guard, which nothing exercised before.
