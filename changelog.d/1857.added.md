- **A `doctor` op reports the environment supertool runs in** ([#1857](https://github.com/Digital-Process-Tools/claude-supertool/issues/1857)). The interpreter's path, version and architecture, with an architecture mismatch (Rosetta 2 on Apple Silicon, or the reverse) flagged loudly rather than left to be discovered as unexplained slowness — measured on the machine that filed this issue, ~3x slower interpreter starts and ~3.4x slower subprocess-spawn CPU time, which matters more for supertool than for most Python programs since spawning subprocesses is most of what it does. Also: CPU performance/efficiency core split where the platform exposes it (supertool does not size worker pools itself, but a caller that does needs this rather than logical core count alone), whether the `supertool` symlink on `PATH` dangles, and the resolved `.supertool.json` and watch fleet name. Every check is a three-state answer — an architecture or topology check that could not run says so, never guessing the clean answer.
