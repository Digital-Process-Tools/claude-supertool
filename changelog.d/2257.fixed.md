- `supertool-no-cut.md`'s `match` regex false-fired when a quoted op argument merely contained a substring like `|header`, `|cutoff`, `|sedan` or `|awkward` — no real shell pipe anywhere in the command — because the `head|tail|sed|cut|awk` alternation had no anchor on its own right edge (#2257). Fixed by requiring a separator, a redirection, or end-of-command after the keyword (a first attempt anchored on whitespace alone and silently stopped catching `|head;rm -rf x` and `|head>out.txt`, caught in self-review before commit). The issue's own cited reproduction (`grep:_is_past|_summary_counts:...`) never actually matched on either side of this fix, and a bar fully inside a quoted argument followed immediately by `|head`/`|tail`/etc. remains unfixed — this dialect (POSIX ERE via awk) has no way to track quote depth, the same limit already documented for `;`/`&&` inside an argument.
