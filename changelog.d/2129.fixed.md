- **`git-commit` gained a worked `Example:` line, so its usage line reads less like a template to paste** ([#2129](https://github.com/Digital-Process-Tools/claude-supertool/issues/2129)). An agent reading `help:git-commit` at speed, just after a refusal, pasted the literal string `MESSAGE` as a commit subject. The live syntax line was already fully uppercase (`git-commit:::MESSAGE[:::PATHS...|:::--all]`, matching the convention every other op in `presets/git.json` already uses — `PATH`, `PATTERN`, `BASE`, `REF`, `BRANCH`, `SIDE`), so introducing a second placeholder spelling such as angle brackets would have been the "third spelling" the issue itself asked not to invent. What was missing is the `example` field `presets/vim.json`, `presets/gitlab.json` and others already carry: `git-commit` now has one too — `git-commit:::fix: correct the off-by-one:::src/foo.py` — rendered as an `Example:` line in `help:git-commit`, a concrete call that cannot be mistaken for a template because `MESSAGE` never appears in it.
