- **radar's GitLab tier refuses a filter token it cannot apply, instead of widening the population it watches** ([#961](https://github.com/Digital-Process-Tools/claude-supertool/issues/961)). [#939](https://github.com/Digital-Process-Tools/claude-supertool/issues/939) rewired `gh-prs`, `gl-mrs` and radar's **GitHub** tier onto the shared tokenizer in `presets/_filter_tokens.py`; the **GitLab** tier still read `mrs._parse_multi(arg)[0]`, discarding the third element — the tokens it could not place. `radar:milestne=v19` therefore fell through to the default filter and rendered every open MR of yours, exit 0, no warning; `radar:author=@me,milestne=v19` dropped the typo and labelled the board `scope author=@me`, which is true about the query and false about the question. Half of radar refused an unrecognised token and half did not, so testing a typo against the GitHub tier concluded the class was closed.
- **Why this is worse than the op-level version:** a board is printed, a scope is _watched_. Radar heals a per-MR watcher onto every iid the scope resolves and names the discovery feed after it, so a silently widened scope starts firing `mr_opened` for strangers' MRs. The mr-feed poller already declined exactly this (#939); the tier is the same shape and did not get it.
- The tier **refuses** rather than declining. `fetch_population` returns `None` because it has no reader — it runs in a loop and its only channel is the events it emits. A tier has a reader, and `tier_reports` already isolates one, so a `RadarError` reaches the operator on stderr with exit 1 while every other registered tier still renders its board. `radar:--state` is the exception: it prints `filter : REFUSED — …` in place, because a read-only view that raises is the view you cannot open.
- The tier's vocabulary is its own, and both directions are pinned by tests. **Narrower than the op:** `iids` and `failed` are board _shapes_ — a radar board silently reduced to a bare id list, or to only the failing rows, is the same lie as a widened one — and `per=` is a page size the tier reads from config, so accepting it in the arg would drop it one level down. **Wider than the GitHub tier:** `glab mr list` has `--milestone`, `--source-branch` and `--target-branch` where `gh pr list` has none of them, and copying `gh_prs.KNOWN_FILTERS` would have refused three filters this tier can actually apply.
- The second defect on the same line: a **known** key whose value maps to nothing. `state=mergd` passes the key check, then `_build_list_cmd` finds no entry in `_STATE_FLAG` and emits no flag, so glab answers with its default `opened` — the merged board renders as the open one and radar heals watchers onto it. Refused, with the accepted values named. A value the backend simply does not match (`milestone=nosuchmilestone`) is still forwarded: an empty board there is the truth.
