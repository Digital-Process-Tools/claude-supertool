- **`gh-issue-create`'s duplicate-filing guard read one page of open issues, so a repository past 100 could still get a duplicate on its oldest titles** ([#2021](https://github.com/Digital-Process-Tools/claude-supertool/issues/2021)). `_find_open_issue_by_title` -- the lookup that stops the `#1790` REST fallback from re-filing an issue whose earlier GraphQL attempt actually landed despite a 503 -- checked a single `per_page=100` REST page and returned `no match` whether the title truly did not exist or was simply pushed off the page. GitHub's REST default order is newest-first, so the titles that fall off are exactly the long-lived ones a stalled maintainer loop is most likely to be re-filing after an outage. This repository itself sat at 88 open issues when the gap was filed, twelve short of the cap.

  The lookup now pages: a page shorter than 100 items is proof there is no next page and ends the loop; a full page is not proof of anything and the loop continues. Past 5,000 open issues (50 pages) it refuses to write rather than paging forever, the same refusal shape the lookup already used when the transport itself errored.
