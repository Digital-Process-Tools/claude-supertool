- **Documented that `.oss/statusline.py` is deliberately unwired, closing the gap where a shipped, tracked file had no tracked pointer to it at all** ([#1964](https://github.com/Digital-Process-Tools/claude-supertool/issues/1964)). The file is tracked because `/oss:scaffold --apply` writes it into every clone (#1956); PR #1956's own body claimed `.claude/settings.json` already pointed a `statusLine` key at it, but that was read out of an uncommitted working copy and was never true at any committed revision — the fix left a tracked file with no pointer at all. `.claude/settings.json` stays free of a `statusLine` key on purpose: it would run a status line in every contributor's session the moment they clone, without an opt-in step, unlike the tracked `PreToolUse` guard already there. `docs/contributing.md` now documents the opt-in `.claude/settings.local.json` snippet, and `tests/test_statusline_wiring_documented_1964.py` pins the decision so the file cannot go silently orphaned again.
