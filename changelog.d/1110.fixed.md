- **Three independently-fixable low findings from the v0.29.0 release audit are closed** ([#1110](https://github.com/Digital-Process-Tools/claude-supertool/issues/1110)). `_validator_meaning_version()` memoised the validator cache's meaning-version for the whole process lifetime with no invalidation, so a schema rewrite under a live/reused daemon process kept serving the previous meaning for that process's remaining life -- exactly what #1048 was built to prevent; it now checks `validators/SCHEMA.md`'s own `stat` identity on every call and only re-hashes when that changes. `gl-job`'s boilerplate discount (`presets/gitlab/job.py::_is_boilerplate`) matched a marker substring anywhere in a line, so a failing test whose own assertion text happened to quote `Cleaning up project directory` or `section_start:...` got discounted as runtime teardown noise and its `error_context` window dropped; the match is now anchored to the whole line (past an optional stream prefix). `gh-labels:tally`'s `repo:` search term was the one interpolated value not checked against `_QUERY_UNSAFE` -- unlike the prefix and every label name -- so a shape like `owner/name is:public` (valid per core's own "one slash, two non-empty halves" check) reached the query as extra search syntax; it is now refused the same way the other two are.
