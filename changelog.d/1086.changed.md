- **`around:PATH:LINE[:N]` now answers as `around_line` and says so**, rather than reporting `file not found: 1160` ([#1086](https://github.com/Digital-Process-Tools/claude-supertool/issues/1086)). `around` takes PATTERN:PATH and its sibling `around_line` takes PATH:LINE — same output, opposite argument order, nothing in either name saying which, and four agents in one session picked wrong. The reinterpretation only ever converts a call that already fails: the numeric argument must not name a real file and the argument before it must resolve, so no working call changes meaning and the `:`-tokenizer is untouched. The receipt names the `around_line` call that ran, including the caller's own `N`. `between:PATH:START:END` keeps refusing and redirecting to `read:PATH:START-END` — its target is a different op, and its error already carries the fully-substituted command.
