- **A per-PR poller forked by `github-pr-feed`'s own discovery now honours `pr_exclude_events`** ([#2536](https://github.com/Digital-Process-Tools/claude-supertool/issues/2536)). `heal()` already resolved `ops.radar.radar_tiers["gh-prs"].pr_exclude_events` into an `only=` filter for every per-PR `github-pr` poller it forked, but `github-pr-feed`'s own `spawn_watcher` -- the *other* forker, called from inside the feed's own process the moment it discovers a PR mid-poll -- hardcoded `only=[]`, unconditionally. Since the loop opens nearly every PR between two `radar` calls, nearly every per-PR poller was feed-forked in practice, so the blacklist filtered almost nothing while `radar:--state` read as though it did. The fix resolves the same list from the same function, `gh_prs.poller_only`, inside the feed's own process -- read from `SUPERTOOL_RADAR_TIERS`, already present in the feed's environment exactly when radar forked it. A feed started by hand carries no such variable and keeps today's unfiltered behaviour, as before.
