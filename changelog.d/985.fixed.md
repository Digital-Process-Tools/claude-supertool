- **The edit-miss diagnostic now names a doubled-backslash mismatch in either direction, not just one** ([#985](https://github.com/Digital-Process-Tools/claude-supertool/issues/985)). #380/#1027 already named the case where a payload's `old` carried two literal backslashes and the file held one -- TOML literal blocks process no escapes, so the two can never match. The reverse direction -- a file holding two literal backslashes (written earlier with `literal_backslashes = true`, or by hand) and an `old` carrying one -- fell through to a bare percentage-and-line nearest-match hint with no mention of backslashes at all, which is the "fails quietly" half #985 was re-scoped to after #1027 shipped the `new`-side warning.

  `_edit_miss_diagnostic`'s doubled-backslash check now runs both directions: `old` doubled against a single-backslash file (existing), and `old` single against a doubled-backslash file (new), each naming which count the file actually holds. A no-match whose only difference is backslash escaping now says so regardless of which side carries the extra pair.
