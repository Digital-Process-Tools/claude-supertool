- **`replace_dry` now discloses a silent line-ending re-termination, the same way `replace` already does** ([#1069](https://github.com/Digital-Process-Tools/claude-supertool/issues/1069)). `replace`'s execute branch has said, per file, when a caller's `old` did not match a file byte for byte and was re-terminated to that file's own line-ending convention to make it match (#1057, #1049) — `replace_dry`'s preview computed the exact same `eff_old`/`eff_new` pair one branch earlier and said nothing about it, so a CRLF-file preview with an LF `old` showed a clean diff for a match that was not the caller's literal text. Fixed the same way, one branch earlier: a `[CRLF]`/`[CR]`/`[LF]` tag on the file's own heading and a trailing note naming how many previewed files it applies to, worded for a preview ("would be re-terminated") rather than a completed write — never a blanket summary line that would be false of a file whose `old` matched literally, the same constraint #1057 already enforced in `replace`'s own execute branch.

  Also closes [#1154](https://github.com/Digital-Process-Tools/claude-supertool/issues/1154), which asked whether `around:PATH:LINE:N` being silently reinterpreted as `around_line`'s argument order should refuse instead of substitute, since the two ops differ only in argument order and the caller's intent looked ambiguous. It is not, by construction: `_around_line_delegation` only ever converts a call into an answer when the literal reading is already impossible (the numeric token must not name a file that actually exists), so delegation never chooses between two real readings — and its disclosure has printed before the reinterpreted answer, not after, since the function was written for #1086. Both are now pinned by tests (`tests/test_around_line_delegation_order_1154.py`) rather than left to reproduce or not on request.
