- **stylelint now recognises an absent stylelint reached through `npx --no-install` as the third state, not a tool fault** ([#1949](https://github.com/Digital-Process-Tools/claude-supertool/issues/1949)). `_resolve_cmd()` falls back to `npx --no-install stylelint` on any machine with `npx` but no global install — the ordinary laptop with node — and until now nothing on that route was checked against npx's own refusal: npx exits 1 with no report on either stream, `_report()` returns `None`, and the adapter published `tool_fault`, "this is a stylelint failure" — which reads as a broken install or bad config, not as "stylelint is not installed; `npm install -g stylelint`", the one sentence this adapter already had and could not reach. Reproduced directly against a real `npx --no-install stylelint` on this machine (npm 10.9.4): `npm error npx canceled due to missing packages and no YES option: [...]`. Fixed the same way eslint already handles its own npx fallback (see #1948): the npx route is checked against the shared marker in `validators/common/npx_absent.py` before falling through to `tool_fault`, so this reads as the same `absent()` third state — with the same install hint — as every other absent-tool path in this adapter. Any other npx failure is unaffected and stays a loud fault.
