- **`glob` answered questions about directories outside the boundary, as counts** ([#1392](https://github.com/Digital-Process-Tools/claude-supertool/issues/1392)). Two mechanisms, one class.

  `_glob_reach` modelled `**` as exactly one component. The expander treats it as zero-or-more, so a `..` written after a `**` climbed one level further than the gate believed and a pattern carrying one `**` per `..` cleared the pattern gate before walking out. The reach is now checked at both ends of that range — every magic component as one level down, and every `**` expanded to zero. Zero is the only other extreme that needs checking: dropping a downward component can only move the cursor up, so the all-zero expansion climbs at least as far as any expansion in between.

  And the exclude-paths filter ran **before** the containment check, so an outside directory whose contents are excluded had every match filtered away and the check then saw an empty list. `glob:**/../.ssh/*` rendered as `(0 files, 6 files hidden by exclude-paths)` while a directory that does not exist rendered as `(0 files)` — a refusal converted into exact cardinality, and two distinguishable answers about a directory the caller may not read. The check now runs over the excluded entries too: being excluded is a reason not to print a file, never a reason not to gate it.

  The refusal itself no longer reports how many matched. The reasoning that shipped with the gate says dropping entries hands back a shorter list under an honest header and printing them discloses the paths; the count is the third form of the same disclosure, and `51 match(es)` next to `2 match(es)` is the whole oracle in one number.

  Not a regression: before the gate landed, inside this same release delta, `glob` had no containment check at all and would have printed the names. This is a narrowing that left a residue.
