- **A worktree whose branch has never committed no longer renders `[merged]`** ([#1750](https://github.com/Digital-Process-Tools/claude-supertool/issues/1750)). "Every commit is already an ancestor of master" is vacuously true of a branch holding nothing, so a brand-new tree and a fully-landed one were the same cell in the column a maintainer reads to decide what is safe to delete — seven of eight live fleet worktrees on `62bc3f0`, each with an agent editing it seconds earlier. The row now reads `no commits yet` and says the work there is uncommitted.

  The issue's own proposed test could not have worked: `git rev-list <base>..<branch>` being empty is the *same predicate* as the ancestry read the op already performs, since a branch is an ancestor of the base iff that range is empty. Measured on git 2.46.2, a branch with three commits merged `--no-ff` and a branch created and never committed to both answer `0`. The branch's reflog is what separates them, it is local, and it costs nothing on the network, so `nopr` still answers. A reflog that cannot be read is the third state and never a silent fall-through to `merged`.
