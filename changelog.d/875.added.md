- **`gh-pr:N:diff` and `gh-pr:N:diff:PATH` — a PR's diff in the shape a reviewer walks it** ([#875](https://github.com/Digital-Process-Tools/claude-supertool/issues/875)). Every read a PR supports was covered — state, tally, mergeability, branch, linked issues, job logs — except the one the merge decision actually rests on, so every review fell back to raw `gh pr diff` piped through a hand-written filter. `gh-pr:N:status` reports that the suite is green, and a green suite is exactly what the review rule says proves nothing: the op surface covered the check you are told not to trust and omitted the check you are told to do yourself.

  **The raw command is also the wrong shape.** An eighty-file mechanical sweep carries four files of judgment, and reading it whole is not a review, it is a context burn. `:diff` returns the file list with per-file line deltas, heaviest first; `:diff:PATH` returns that one file's hunks, fenced as the stranger's text a branch diff is. Same two-step walk `gh-job` already models with `:fail` / `:raw:-N` / `:grep:PATTERN`, in the same preset family.

  **Heaviest first rather than grouped by kind, deliberately.** `git-diff` groups its file list with a path classifier private to its own preset; copying that here would create the second definition that lets the two drift, which is the failure the shared check-tally and board-layout modules exist to prevent. Churn-descending needs no shared vocabulary and is the order a reviewer takes anyway.

  **`[same edit xN]` is a note and never a filter.** A file whose every hunk is byte-identical after stripping whitespace is flagged so attention goes elsewhere; it is never removed from the list and never shortened. The test is exact equality rather than similarity, because under-flagging costs a reviewer nothing and a wrong "mechanical" verdict is an invitation to skim the file that needed reading.

  **Three states, because this renders inside the merge gate.** A diff nobody could fetch prints a named refusal and exits 1, never an empty file list — "this PR changes nothing" is the worst available lie at the moment someone is deciding whether to merge it. A PR that genuinely changes no files gets a different sentence saying the diff was read and is empty. A path not in the diff is a refusal too, naming the paths that are, because "not in this PR" and "in this PR and unchanged" are otherwise the same silence and the first is usually a typo or the wrong number. Both caps disclose what they withheld in the render they truncated, the file cap keeping the real total in the header, the byte cap naming the counts above and below the hunks. The route goes through the shared `gh` wrapper, so it honours `repo:OWNER/NAME` — a raw `gh pr diff` from the wrong directory answers about the wrong repository, silently and well-formedly.
