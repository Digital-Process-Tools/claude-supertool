- **A raw-command guard refusal could render a safe command as though it were two.** The refusal's `` `COMMAND` is replaced by ... `` line rendered `GuardMatch.command` as a plain space-join of tokenised argv, so the caller's own quoting was already gone -- `git commit -m "a; rm -rf /tmp/x"` (one safe command) rendered as `` `git commit -m a; rm -rf /tmp/x` ``, which reads as two shell commands, the second one destructive-looking; a `|` inside a quoted argument rendered the same way. `GuardMatch.command` now reuses the same `origin_texts`/`origin_faithful` pair #2010/#2017/#2023 already thread through `guard_command` for the sibling `discarded` field, so the refusal quotes the caller's actual original text (or, when that text genuinely cannot be recovered faithfully, the same "could not be rendered exactly" marker `discarded` already uses).
