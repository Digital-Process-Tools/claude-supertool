- **The `slack` watch source no longer loses its own message timestamp to a reserved-key collision**: the payload used to carry a key literally named `ts`, one of the channel bridge's own reserved routing names, so every `slack_message` event's `ts` attribute was the consumer's own emit time and never the message's ([#2052](https://github.com/Digital-Process-Tools/claude-supertool/issues/2052)). Renamed to `message_ts`, which now reaches a consumer needing to reply in-thread or build a permalink. A thread reply's parent timestamp is now reachable too, as a new `thread_ts` payload field (`""` on a bare-channel watch) — `parse_id` already split `CHANNEL~THREAD_TS` for the poller's own use, but a consumer only ever saw the composite `id`.
