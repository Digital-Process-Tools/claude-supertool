- `channel:health` reported `FORWARDING` with no session subscribed to the channel, which is the one state it exists to catch: a consumer held the socket, verified as its own socket-holder and published fresh counters, while the session that spawned it had refused the channel tag at startup and every event was read and then discarded. A fifth state, `BOUND, NOT SUBSCRIBED` (exit 5), now carries that finding, and `radar`'s `DELIVERY` banner — the same producer-only view one surface up — says it too (#1543).
- Subscription is only partly observable from outside the target session, and `channel:health` now claims exactly the part that is: which process spawned the socket-holder, and whether the channel tag in its argv names an MCP server the harness has configured (`claude mcp get`, the same question `bin/supertool-workspace` asks before registering the consumer). No tag, an unconfigured tag, or a session that has since exited are definite negatives; anything that could not be asked — no `ps`, no `claude` on PATH, an argv that does not parse — is `CANNOT DETERMINE` with the reason, never `FORWARDING` (#1543).
