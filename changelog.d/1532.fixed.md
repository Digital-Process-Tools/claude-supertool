- **A custom op whose `cmd` template has no argument placeholder at all now refuses a caller token it cannot reach, instead of silently dropping it** ([#1532](https://github.com/Digital-Process-Tools/claude-supertool/issues/1532)). Split out of #873, whose fix only refused an extra token when the template carried a single-token placeholder (`{file}`/`{dir}`/`{arg}`) -- a placeholder-free template dropped every token, exit 0, with no trace in the receipt. `check:PRESET:PATH` always forwards its path to whatever entry was named, so this closes that gap too. Measured population is 4 shipped ops (`git-conflicts`, `mcp_status`, `mcp_stop_all`, `watches`); the actual blast radius on the suite was 29 tests across 6 files (not the 15/6 the original #873 fix priced it at) handing a throwaway token to a placeholder-free `cmd` for unrelated reasons -- each is now fixed to either drop the meaningless token or add the placeholder it always meant to consume. `tests/test_custom_op_dropped_tokens_873.py` and `tests/test_check.py` carry the direct regression coverage.
