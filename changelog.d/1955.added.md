- **`gh-issue` now writes through to an opt-in mirror, and a new `gh-mirror:issue:N` op reads it with no network call** ([#1955](https://github.com/Digital-Process-Tools/claude-supertool/issues/1955)). A maintainer tick that reads the same issue twice paid a fresh `gh` API call each time and threw the rendered text away; a polling cache was the wrong fix (a cached answer that was correct when taken and false a minute later is indistinguishable from a fresh one at render). With a top-level `"gh_mirror_dir"` key set in `.supertool.json`, every `gh-issue` read now stores the FULL, untruncated API reply plus its read timestamp as a side effect, best-effort (a mirror write failure never fails the read it rides on). `gh-mirror:issue:N` answers three states -- `cached (AGE)`, `not-cached`, `mirror-unreadable` -- and the third never renders as either of the other two: a permission-denied mirror directory or a corrupted manifest is a finding about the cache, never silently read as "never fetched" (`Path.is_file()` swallows `PermissionError` and returns `False`, which is exactly the defect this repo's own "absence produced by the tool" class names). Scoped to `gh-issue` only in this pass -- `gh-pr`, `gh-issues` and `gh-prs` are not wired to the mirror yet, so `not-cached` here means "never read via `gh-issue`", not "does not exist on the tracker"; extending the other three ops is tracked as follow-up work, named in the pull request. Never an authority for open/closed state, assignee, labels or linked-PR state, which the issue's own design explicitly rules out and which stay live reads.
