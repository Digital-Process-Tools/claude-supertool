- **`registry` — which ops this project loads, and where each definition came from.** `ops` answers *what can I do*; nothing answered *where did this come from*, and the gap had already cost an audit its subject. A project entry naming an op a preset already defines is a **partial** override — supertool merges it key-by-key, so `{"git-diff": {"red_flags_extra": [...]}}` adds one key and the preset's `cmd`, `syntax` and `timeout` stay in force. Three ops in this repo's own config are that shape (`dashboard`, `radar`, `git-diff`), and every hand-rolled walk over `presets/*.json` plus `.supertool.json` wrote the obvious `ops[name] = entry`, replacing the shipped definition with the stub. The op count is unchanged either way, so nothing looks wrong; the entry simply stops matching every filter downstream. #1350's containment audit lost `git-diff` — the path-naming op it was written about — out of its own population and printed a pass. The merge rule is now one function the loader calls, the loader stamps each op's source during the same walk, and `registry` renders what the loader produced rather than recomputing it; `registry:OP` attributes every key of one entry. A population that could not be fully enumerated prints `INCOMPLETE` in its own body, naming the preset that failed to load, instead of a shorter list — stderr is somewhere else in a batched call, and a short listing and a complete one are otherwise identical.
