- **`slack_publish`'s TEXT slot no longer resolves a bare path -- a breaking change to its documented syntax** ([#2039](https://github.com/Digital-Process-Tools/claude-supertool/issues/2039)). Untrusted Slack message text reaching TEXT could name a file that happened to sit inside the publish-body allowlist -- `.max/`, the maintainer's own private drafts, among them -- and its contents would post to the channel with no marker in the call that a file was ever involved. Only the explicit `file://` prefix now triggers a read; a bare path, however real, posts as the literal string it is. The withdrawn arm was published as part of the syntax (`docs/presets/slack.md`), so an existing call relying on the bare-path form now posts the literal path string instead of the file's contents and needs `file://` added -- see `docs/presets/slack.md` for the exact wording. The other four publish/comment presets sharing this shape (`bluesky`, `devto`, `hashnode`) were left as-is: their TEXT is maintainer-typed rather than forwarded from a poller, so they are not reachable the same way, and narrowing them -- also a breaking change to each of their own documented syntaxes -- is a separate, unfiled question.
  - compatibility: breaking -- the bare-path arm of `slack_publish`'s TEXT argument, documented at `docs/presets/slack.md:14` prior to this change, is withdrawn; an existing call relying on it now posts a literal path string instead of file contents.
