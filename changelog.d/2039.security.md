- **`slack_publish`'s TEXT slot no longer resolves a bare path** ([#2039](https://github.com/Digital-Process-Tools/claude-supertool/issues/2039)). Untrusted Slack message text reaching TEXT could name a file that happened to sit inside the publish-body allowlist -- `.max/`, the maintainer's own private drafts, among them -- and its contents would post to the channel with no marker in the call that a file was ever involved. Only the explicit `file://` prefix now triggers a read; a bare path, however real, posts as the literal string it is. The other four publish/comment presets sharing this shape (`bluesky`, `devto`, `hashnode`) were left as-is: their TEXT is maintainer-typed rather than forwarded from a poller, so they are not reachable the same way, and narrowing them is a separate, unfiled question.
