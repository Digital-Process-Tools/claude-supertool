- **The GitLab radar tier tells its failure kinds apart by class, and the two tiers now share one set of classes** ([#1847](https://github.com/Digital-Process-Tools/claude-supertool/issues/1847)). `gh-prs` has raised `RadarUnreachable` for "the request never landed" and `RadarUnconfigured` for "no credential is configured" since #1568. `gl-mrs` had neither: a `glab` that was never spawned, one killed by the OOM killer, and a JSON body that arrived and was wrong all raised the same `RadarError` with different prose, so a caller could only tell them apart by matching on the message — and a caller that matches on a message is what #1823 had just finished removing. A loop told the credential is gone stops, where a loop told the tier could not answer retries.

  Both tiers now raise the same three classes out of `presets/watch/tiers/_radar_errors.py`, and `gh_prs.RadarError` **is** `gl_mrs.RadarError` — that identity is the part that was easy to get wrong invisibly. Each tier resolves helpers through its own `_load`, which builds a fresh module object per call, so lifting the classes the obvious way would have produced two unrelated classes with the same name, kept every per-tier test green, and left an `except` that silently never fires across the boundary. The shared module is reached by a plain `import` off `sys.path` instead, and the test pins the identity rather than the names.

  `gl-mrs` classifies on structure only — a spawn that never completed, a negative return code, `_auth_probe`'s answer — and deliberately raises no `RadarUnconfigured`: `glab` publishes no equivalent of `gh`'s exit 4, and the only thing left to split it on is prose. That gap is stated in `docs/presets/watch.md` rather than guessed at, and the class is exported anyway so a caller can write one `except` for the pair.
