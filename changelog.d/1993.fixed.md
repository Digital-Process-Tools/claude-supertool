- **An inherited pair of `repo:` markers can no longer survive into a call that never typed a `repo:` op, and a GitLab project id is now fully percent-encoded when it links issues** ([#1993](https://github.com/Digital-Process-Tools/claude-supertool/issues/1993)). `SUPERTOOL_REPO_FROM_OP` is a bare `os.environ.get(...) == "1"` with nothing binding it to the shape-checked pre-pass that is supposed to set it, and `main()` used to restore whatever value predated a call without ever denying it *during* the call — so an inherited pair (a parent shell's own export, or a value that outlived an earlier restore in a long-lived host process) could credit a `repo:` op nobody typed. `main()` now clears both variables on entry, before dispatch ever inspects the call's own argv, so either variable being set during a call means that call's own `repo:` op set it moments before. Separately, `presets/gitlab/issue_create.py` escaped only the slash in a linked issue's project id (`project.replace("/", "%2F")`), so a project carrying `?`, `#` or `%` reached the API path unencoded regardless of how the target arrived; it now uses the same `urllib.parse.quote(project, safe="")` path-segment encoding `_repo_target.gl_project()` already applies.
