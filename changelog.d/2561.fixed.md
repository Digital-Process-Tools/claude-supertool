- **A curate pass could never become due on its own** ([#2561](https://github.com/Digital-Process-Tools/claude-supertool/issues/2561)). `.oss.json` set no `curate_route_threshold`, so the curate route in the oss plugin's `workspace_routes.py` never evaluated as `over` -- an absent threshold silently skips the route rather than reporting it `not-due` for a reason, so it rendered exactly like a route that ran and found nothing. `trap.d/` had accumulated 48 fragments, oldest from issue #227, with nothing able to route a curate pass to drain them. `.oss.json` now sets `curate_route_threshold: 2`, the same value #2557/#2558 used for `triage_route_threshold` (a deliberate judgement rather than a measurement). Setting it low now, rather than draining the backlog by hand first, does not cause a repeated partial-drain: `commands/run/curate.md` states a curate pass takes its whole waiting backlog uncapped in one run ("One pass takes the whole backlog, uncapped"), so the very next curate pass drains all 48 fragments in `trap.d/` in one pull request, and the threshold then stays low so the directory never re-accumulates. A new guard, `tests/test_curate_route_threshold_configured_2561.py`, pins the key present and sane so this repo's own config cannot silently drop back into the dark state; the routing logic itself lives in the separate `claude-oss` repo and is outside this guard's reach.
