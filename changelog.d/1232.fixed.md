- **28 test call sites created a symlink with no privilege gate, and a register now stops the 29th** ([#1232](https://github.com/Digital-Process-Tools/claude-supertool/issues/1232)). On a runner without `SeCreateSymbolicLinkPrivilege` those raised `OSError` and the leg reported a defect in product code that was fine — this repo's own absence-read-as-a-verdict class, relocated into the harness meant to detect it. Four of the eighteen files were the containment suites (`test_security_safe_path`, `test_edge_cases_at_file_security`, `test_edge_cases_paste_security`, `test_security_xml`), so the leg would have said the containment tests were broken rather than unrun.

  `tests/test_symlink_gating_register_1232.py` keys all 71 symlink-creating call sites in `tests/` by `path::enclosing def` and records which of five mechanisms stands between each one and a privilege-less runner. The label is **re-derived from the AST on every run**, not trusted: a site that keeps its register entry and loses its `@requires_symlink` goes red, which is the failure a prose table cannot see. The derivation is about calls and about order, not text — a `require_symlink()` mentioned only in a docstring, or written below the `symlink_to` it claims to guard, is refused, and both shapes are pinned by a test of the classifier itself. A new ungated site is a red build naming the file, the function and the fix.

  **The count in the issue was low, and the sweep was not blanket.** An AST walk — a docstring naming `symlink_to` is not a call site — found 28 uncertified sites across 18 files, not ~19 across 13. It also found 43 sites that needed nothing: a `posix_only` class or an `O_NOFOLLOW` mark already keeps them off Windows entirely, and gating those would have been motion. One test went the other way: `test_an_in_tree_file_named_like_a_sentinel_still_works` merely borrowed a symlinked fixture, so it was given a symlink-free one instead of a gate — it asserts the guard's false-positive arm, and a blanket skip would have taken that off exactly the platform where nobody is watching it.

  **Measured, not reasoned:** GitHub Actions `windows-latest` has the privilege today — job 93605739570 on run 31434590388 printed `symlink-capability(#1143): available`. None of the 28 were red on this repo's CI, and the gate is for the runner that is not that one. Under a forced-absent privilege, before this change `conftest`'s summary read `0 symlink-dependent tests did NOT run` while four tests failed for precisely that reason; that line is now pinned to the true count.
