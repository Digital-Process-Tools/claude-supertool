- **The rule that blocks `Read`/`Edit`/`Write`/`Glob`/`Grep` is pinned as not shipping** ([#1791](https://github.com/Digital-Process-Tools/claude-supertool/issues/1791)). Reported as blocking every file operation in every repository the plugin is installed in, for contributors who never installed supertool. Measured and it does not: there is no `supertool-required.md` in the tree, the rule that matches the description is `harness-tools-blocked.md`, and it has been a recorded absence in `shipped_rules.NOT_SHIPPED` since [#1698](https://github.com/Digital-Process-Tools/claude-supertool/issues/1698) — `hooks/hooks.json` registers the hook on `Bash|PowerShell`, so no harness file tool reaches it. Fed one directly anyway from a foreign project directory, the hook allows it. Nothing asserted any of that, so `tests/test_harness_tools_do_not_ship_1791.py` now does, each row named with the mutation that reddens it. Shipping that rule would cost more than the report says: its index pattern is `~.`, so it would deny every Bash command in somebody else's repository, not only the file tools.
