- **`git-commit`'s unknown-payload-key refusal already names the accepted keys — pinned by a regression test** ([#2204](https://github.com/Digital-Process-Tools/claude-supertool/issues/2204)). Reported from a lane that guessed `files` instead of `paths` on the `@payload` route and asked that the refusal, if it didn't already, name the accepted key set. It already does: `_payload_unknown_fields`/`_payload_accepted_fields` (#1551) is generic across every op's `@payload` route, not specific to `git-commit`, and the refusal already reads `... has unknown field(s) files — accepted: message, paths, no_verify`. No behavior changed for this half of the issue — a regression test now pins it so a future refactor of the payload route cannot silently drop the accepted-keys clause for this op. (Part 1 of #2204, `edit`'s backslash guard on an escaped-newline literal, is a separate defect and untouched here.)
