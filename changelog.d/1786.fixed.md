- **`read:PATH` no longer hands a caller `rtk`'s garbled compressed render unchanged** ([#1786](https://github.com/Digital-Process-Tools/claude-supertool/issues/1786)). Reproduced directly against the real `rtk` binary (github.com/reachingforthejack/rtk, 0.35.0): `rtk read -n --max-lines N FILE` on a file over its window renders the file's real last line sandwiched between two contradicting elision-style footers (`// ... 362 lines omitted` above it, `// ... 361 more lines (total: 512)` below it, counts that do not sum to the file's own line count) -- a bug in `rtk`'s own compression, not in anything this repo computes. `render_file`'s RTK-delegation branch trusted that render wholesale and returned it unchanged, so a third party's corruption became supertool's own answer with no way for a caller who does not already know the file to tell a garbled compression from a correct one. `_rtk_output_looks_malformed` now detects the double-elision-marker signature and falls back to the native renderer, disclosing the fallback rather than silently swapping it in. `read:PATH:START-END` was never affected -- it bypasses RTK delegation by construction, which is why it read clean on the same file in the original report. Filed against `rtk` itself as the root cause; this fragment covers only the fallback added here.
