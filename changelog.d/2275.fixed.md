- **A separator fused with no space against a redirect operator, with no digit anywhere involved, still bypassed the raw-command guard** ([#2275](https://github.com/Digital-Process-Tools/claude-supertool/issues/2275)). #2267 closed this class only for the sub-case where a numbered fd redirect's dropped digit was the sole thing keeping a preceding separator and the redirect apart (`|2>&1` -> `|>&1`); the underlying gap in `_guard_raw_segment_spans`/`_guard_tokenize_prepared` — deciding a whole punctuation run was "one redirect, don't split" by asking only whether `<`/`>` appeared anywhere in it — predated #2267 and fired with no digit at all: `true;>out git commit -m x`, `true|>out ...`, `true&&>out ...`, `true&>out ...`, `true;>>out ...` and `true;<in ...` all read as one command, `true`, with `git commit -m x` silently swallowed as extra words rather than checked as a second command. A new `_guard_classify_separator_run` reads a mixed punctuation run character by character instead of asking only whether it contains a redirect char, and both functions now split at the boundary it finds inside the run rather than only at the run's own ends; `&` is the one ambiguous character, read as a separator except immediately after `<`/`>` (`<&`, `>&` — the fd-duplication operators #1684/#2195 already depend on staying fused).
