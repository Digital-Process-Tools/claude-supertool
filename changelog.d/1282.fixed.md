- **`git-worktrees:PATH` exited `0` — the `idle` code — whenever the path matched more than one worktree, while its own board printed `0 idle`** ([#1282](https://github.com/Digital-Process-Tools/claude-supertool/issues/1282)). The path filter is ancestor-or-descendant, so a nested layout pulls in the trees above and below the named one; three occupied worktrees rendered as three occupied worktrees and exited as though the named one were free.
- The exit logic was unchanged since v0.32.0. What changed is that it became an **authorization**: `gh-pr-merge`'s new `cleanup` arm read that exit code as permission to remove a directory. A latent disagreement between two renders became a delete gate without anyone deciding it should be one.
- Both halves are fixed. `git-worktrees:PATH` now exits `2` (`cannot tell`) when the path matches more than one worktree — the only honest answer for a board that is not about the tree that was asked for, and what the render already said.
- And `gh-pr-merge` stopped consuming an exit code as an authorization at all. It reads the board's own `[result] N occupied, N idle, N cannot tell` line and treats **only** `0 occupied, 1 idle, 0 cannot tell` as `idle`; a board with no tally line is `cannot tell`. An exit code is one integer standing in for a render with three states, and the collapse is where the meaning went. This is not a second occupancy heuristic — nothing is re-derived, the op's own verdict is simply read at full width instead of through a lossy channel.
