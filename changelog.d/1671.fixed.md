Same file, same edit, opposite verdicts, and nothing in the successful call said it had bypassed the gate that had just refused. Three surfaces now state the scope rather than implying a wider one: the SessionStart roster gains one line (+170 bytes of a ~7,168-byte budget, measured — the listing is the only account of file routes a session is given, and it read as complete), the refusal trailer gains one clause where it already names the op and the off switch, and `README.md`'s hard-block recipe — the thing an operator reaches for to close the other door — now denies `Edit`, `Write`, `MultiEdit` and `NotebookEdit`, which it had omitted while claiming to block the competing tools. `Write`/`Edit` are deliberately **not** blocked by the plugin: it has no hook that can see them. What is fixed is a boundary reported wider than it is — a refusal naming a path reads as *this file is protected* when what is true is *this route is protected*, which is this repository's own three-states defect arriving in the thing that enforces boundaries. The description now says what the plugin ships, and a test derives the check from `hooks/hooks.json`'s matchers rather than from the sentence, so the claim cannot be reintroduced without the hook that would make it true.
