- **The changelog fragment guard is a CommonMark parser now, not a scanner we wrote** ([#936](https://github.com/Digital-Process-Tools/claude-supertool/issues/936)). Three rounds of hand-written Markdown scanning produced three rounds of bypasses, and each fix opened the next hole: [#927](https://github.com/Digital-Process-Tools/claude-supertool/pull/927) anchored its patterns at column 0 and [#930](https://github.com/Digital-Process-Tools/claude-supertool/issues/930) found three ways past; [#932](https://github.com/Digital-Process-Tools/claude-supertool/pull/932) widened them and the next audit found six more; [#934](https://github.com/Digital-Process-Tools/claude-supertool/issues/934) inverted to a whitelist with its own fence state machine, and #936 walked through the fence.

  Every one of those is one shape: our scanner disagreed with CommonMark. So `.github/scripts/assemble_changelog.py` no longer has an opinion about Markdown — it parses each fragment with `markdown-it-py` and refuses a heading, a link-reference definition or raw HTML at any depth, a fence that does not close inside the fragment, and a top level that is not one `-` bullet list. The guard and the reader are the same parser, which closes the class rather than the instance.

  **The vector, verbatim.** A code block takes no lazy continuation, so a column-0 line inside a fence inside a bullet ends the list, the item and the fence — and both of these landed at column 0 of the released file under a receipt that said `ok`:

  ```
  # INJECTED HEADING
  [Unreleased]: https://evil.example/pwned
  ```

  Two more from the same audit are pinned as well: a release heading quoted inside a fence, which became the insertion anchor for the *next* cut, and a backtick inside a backtick fence's info string — CommonMark forbids it, so the line was a paragraph to the reader and an open fence to the guard, which then stopped checking anything after it.

- **Two entries the fragment guard used to refuse are entries again** ([#936](https://github.com/Digital-Process-Tools/claude-supertool/issues/936)). A bullet opening with an inline link, and a hard-wrapped continuation line doing the same:

  ```
  - [#123](https://x/y) fixed the thing.
  ```

  The old rule refused a bare `[` anywhere on the line, on the reasoning that a link-reference definition's label may run onto the next one. An inline link can never be a definition. The 360-entry corpus pin passed through all three rounds without catching it, because the shipped file happens to contain no entry of that shape — a corpus does not vindicate a rule it never exercises.

- **The release re-parses the file it is about to write, and refuses if the file gained anything it did not write** ([#936](https://github.com/Digital-Process-Tools/claude-supertool/issues/936)). A second layer, independent of the fragment guard: the assembled document's heading table has to be the old one plus exactly the headings the assembler reports emitting, its link-reference table the old one plus exactly the definitions it reports writing, and it may gain no raw HTML. One guard over this file has now been wrong three times running, so the write no longer rests on it being right the fourth time.

  This also catches a corruption no fragment causes. A `[Unreleased]:` definition anywhere above the block at the bottom wins, because the first definition of a label is the one that resolves — so a release could rewrite the bottom block, report `links [Unreleased] → compare/vX...HEAD`, and ship a document where that link goes somewhere else. It is now a finding that names both URLs and says whether a fragment introduced it.

- **`_anchor`, `_unreleased_span` and the link-ref block are read off the parse, not off line prefixes** ([#936](https://github.com/Digital-Process-Tools/claude-supertool/issues/936)). The insertion point was the first line starting `## [`, which a fenced example of a release heading satisfied — and `changelog.d/README.md` prescribes exactly that fence as the way to quote a heading in an entry, so the file acquires such lines by design rather than by attack. A release cut against one inserted itself between the opening fence and the heading it was quoting. The trailing link-ref block used to stop its backward walk on a closing fence, find nothing, and advance no link at all while reporting that it had left them alone.

- **`--check` and the release say `skipped` when they cannot validate, and never `ok`** ([#936](https://github.com/Digital-Process-Tools/claude-supertool/issues/936)). `markdown-it-py` is the guard, so without it the assembler has established nothing about a fragment — it reports `skipped`, names what is missing, exits non-zero and writes nothing. There is deliberately no text-scanning fallback; three of those shipped and all three were bypassed within one audit. `.github/workflows/changelog.yml` now installs the parser, which it did not: that job was a checkout and a bare `python3`, so the premise that the PR-time gate runs where dev dependencies are present was not true.
