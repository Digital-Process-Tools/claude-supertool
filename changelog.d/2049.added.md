- **Wire `classify` (#2046) into the tracker read path**: `gh-issue`, `gh-pr`, `gl-issue` and `gl-mr` now print a `classify:` verdict beside each description's and each comment's fence ([#2049](https://github.com/Digital-Process-Tools/claude-supertool/issues/2049)). A labeller, not a gatekeeper — nothing is dropped, filtered or refused on the strength of a verdict; the reporter's suggested fix remains a hint with no authority regardless of what it says. Classified per unit of authorship, not per issue, so a comment from a stranger on a trusted filer's issue gets its own verdict. Default is `full` (scanner + model spawn) uniformly on both forges — a claim about one deployment ("our GitLab is closed and trusted") is not baked into the shipped default; a `classify` config key per op (`full`/`scanner`/`off`, reaching the subprocess as `SUPERTOOL_CLASSIFY`) narrows it where the operator has standing to. `scanner`-only never renders as `safe` — a fourth state, `classify: scanner-clean`, keeps "we chose not to run the model stage" distinct from `could-not-classify`'s "it tried and failed". A per-call `Budget` (`presets/_classify_render.py`) caps model-stage spawns at 6 per call, since the model stage's own 45s timeout is per unit and a `:full` issue thread can carry many.
