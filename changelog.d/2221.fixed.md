- **A fresh clone no longer defaults to two channel MCP servers racing one socket** ([#2221](https://github.com/Digital-Process-Tools/claude-supertool/issues/2221)). `.mcp.json` declares `claude-channel` unconditionally (#1541) and `bin/oss-workspace` (the `oss` plugin) registers a second server, `oss-channel`, at local scope, both resolving to `notifiers/claude-channel/channel.ts` on the identical Unix socket -- the guaranteed-collision shape #2051's own static check already detects and reports as `CANNOT DETERMINE`, correctly, but never resolves. What stopped it on the maintainer's own machine was `disabledMcpjsonServers: ["claude-channel"]` in the gitignored `.claude/settings.local.json`, which does not travel to a fresh clone. The same disable is now tracked in `.claude/settings.json`, so every developer working on this repository gets one registered channel server from the checkout instead of re-deriving the workaround by hand. Deleting `claude-channel` from `.mcp.json` outright was considered and declined: that file also ships with the plugin and is the only registration path for a user who never runs `oss-workspace`, so removing it would drop channel support for them entirely. Reproduced against an actual fresh `git clone` on this machine (`claude mcp get claude-channel` read `Pending approval` before the fix and `Rejected (see disabledMcpjsonServers in settings)` after), not only inferred from the tracked/gitignored asymmetry.
