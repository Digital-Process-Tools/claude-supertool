- **Every `gh`/`glab` not-found and permission classifier now matches a status rather than the bare digits `404`/`403`, so a server error whose URL carries a run, job or project id ending in those digits stops classifying as "not found" or "permission denied"** ([#1864](https://github.com/Digital-Process-Tools/claude-supertool/issues/1864)). #1846 fixed the identical shape for the credential reading (`"401" in err`); this closes the not-found/forbidden half it filed and stopped at the boundary of.

  **The reported population was derived, not quoted, per the issue's own warning: #1846's filed list said ~17 sites and the tree held 23.** A sweep of `presets/github/`, `presets/gitlab/` and `presets/_declared_workflows.py` found **32 bare `"404" in` / `"403" in` sites across 18 files** — `gh-run`, `gh-pr`, `gh-issue`, `gh-labels`, `gh-branch`, `gh-check`, `gh-job`, `gh-follow`, `gh-star`, `gh-batch-follow`, `gh-batch-star`, all seven `gl-*` classifiers, `gl-runners`' own `radar_report` guard, and `_declared_workflows._api`'s not-found sentinel.

  **`gh` renders a run's own API path into its stderr** (`.../actions/runs/12404999`), and go-gitlab's mechanism is the one #1846 already established for the auth reading — it echoes the request URL into every error string, so any project, job or pipeline id carrying `404` or `403` made a server error classify as missing or forbidden, with no exotic input required.

  **`presets/_status_probe.py` is the new shared predicate, one copy, not folded into `_auth_probe.py`.** `says_not_found` and `says_forbidden` match a status — `could not resolve`, `not found`, `http 404` for the first; `forbidden`, `permission denied`, `http 403` for the second — never a bare digit, with the same structural test `_auth_probe.py`'s markers carry refusing one. Auth is a different question with its own per-platform vocabulary (`extra` for GitLab); not-found and forbidden are not, so a second predicate rather than a second tuple.

  **The positive controls are the test, and there is a population pin.** Every "must not read as X" case is paired at the same site with a "must still read as X" case using a genuine 404 or 403, run through the real functions with `subprocess`/the API call faked. A sweep test refuses any `"404" in` / `"403" in` under the same two directories plus `_declared_workflows.py`, so a nineteenth file growing its own copy is caught the way the seventeenth was for auth.

  **Two follow-on fixes the population sweep forced, both pre-existing tests whose own AST-derivation or taint-model no longer saw what changed underneath them.** `tests/test_repo_target_marker_vocabulary_1807.py`'s call-site derivation resolved only a literal `"x" in s`, so it went blind at every site now routed through `says_not_found`/`says_forbidden` — it now also resolves those two calls into the marker tuple they test, and the call site's own `"404"` marker becomes exactly `_repo_target._ABSENT_TARGET`'s existing `"http 404"` spelling rather than a superstring of it. `tests/test_forged_child_stream_line_1475.py`'s child-stream census flagged all 30 new predicate calls as an untracked escape, the same shape #1846 already fixed for `says_not_authenticated`; `says_not_found` and `says_forbidden` join it in `NOT_TEXT` for the same reason — both return `bool`, so the taint provably stops at the call.
