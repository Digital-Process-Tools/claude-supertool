- **A hung pytest test now dumps its thread stack instead of running silently until the job's hard timeout kills it with no diagnostic** ([#1889](https://github.com/Digital-Process-Tools/claude-supertool/issues/1889)). `faulthandler_timeout = 300` in `pyproject.toml` turns on pytest's built-in faulthandler plugin (stdlib, no new dependency) repo-wide: a single test item that has not returned after 300 seconds -- 30x+ the slowest real test ever observed here, comfortably under every job's 20-30 minute ceiling -- gets its stack traced to stderr. Previously the only signal a stuck run gave was GitHub Actions reporting the job "cancelled".
