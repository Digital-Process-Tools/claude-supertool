- **Four radar tests asserted on a board that may never have been printed** ([#800](https://github.com/Digital-Process-Tools/claude-supertool/issues/800)). `test_no_drift_when_event_and_source_agree`, `test_pruned_state_file_does_not_report_drift`, `test_a_healthy_feed_produces_no_warning` and `test_no_other_scope_note_when_the_only_live_feed_is_this_one` each carried exactly one assertion, and each of those was an absence — no drift mark, no `WARNING`, no other-scope note. Stubbing `render` to return nothing at all left all four green, which is the same shape as the filter that did nothing behind 3758 passing tests: an absence the tool produced, read as an absence in the world.

  Each site now pins the board before reading its content. The pruning case takes two, because its absence had two innocent explanations — a board that never rendered, and a state file that was never read — and only the second is what the test claims, so `1 pruned` is asserted alongside the row.

  No blanket skip, deliberately. A test that declines whenever the board is missing also declines when radar is genuinely broken and prints nothing, which trades the loud failure for the quiet one.
