- **`changelog.d/` — one fragment file per change, assembled at release** ([#906](https://github.com/Digital-Process-Tools/claude-supertool/issues/906)). 55 of the last 60 merged PRs touched `CHANGELOG.md`, every one of them appending to the top of the same 2,670-line file. That makes conflicts quadratic rather than occasional: with N open PRs, each merge re-conflicts the other N-1, and `oss_train` exists to automate exactly that churn — a tool built to survive the problem rather than remove it. A PR now adds `changelog.d/<issue>.<section>[.<slug>].md` and never opens `CHANGELOG.md` at all, so two PRs never touch the same path and the conflict class disappears instead of being merged around. `python3 .github/scripts/assemble_changelog.py --version x.y.z` folds the fragments into a new release section at release time and deletes them.

  **`merge=union` was the one-line alternative and this repo already proved it wrong.** `tests/test_git_resolve_heading_dup_839.py` exists because a line-level union on a document whose meaning comes from structure emits a duplicated `## [x.y.z]` heading and silently reparents every unreleased line between the two copies under a tagged release. A correctness bug in the changelog dressed as a convenience.

  **Three states, never two.** The assembler reports `ok`, a finding, or `skipped`, every run. Zero fragments is `skipped` with a stated reason and a non-zero exit rather than an empty release section and a green exit — the defect class this tracker is fullest of is an absence produced by a tool being read as an absence in the world. A filename that does not parse is **refused by name**, not skipped, because a file the release tool passed over quietly is an entry that never ships and nobody is told. Findings are gathered before refusing, so one bad name does not turn a release cut into a queue.

  **The existing `## [Unreleased]` section is not migrated**, deliberately: the mechanism starts at the next release boundary and history is left alone. The assembler inserts the new version above the newest existing release and below `## [Unreleased]`, so pre-existing entries stay exactly where they are — and the receipt says how many were left behind, because that seam needs a human hand exactly once. It also rewrites the `[Unreleased]` compare link and adds the new tag's link ref, which removes one step from a release checklist that already edits four files.

  **The CI check is its own workflow** (`.github/workflows/changelog.yml`), not a job in `tests.yml`: "did this PR add a fragment" is a policy read of a diff, not a test. It validates every fragment name repo-wide, then requires a fragment from any PR touching `supertool.py`, `presets/`, `validators/`, `formatters/`, `notifiers/` or the plugin manifest. Docs- and tests-only PRs are exempt, and a `no-changelog` label is the stated way out — requiring a fragment for a typo fix is how the discipline decays into a reflex-added empty file.

  **No new dependency.** `towncrier` and `scriv` both solve this and both are dependencies; the assembler is 250 lines of stdlib in `.github/scripts/`.
