    **The audit found a second structural parse, in a different op.** `gl-mr`'s conflict-hunk reader splits `git merge-tree` output, which is not porcelain — it is the two branches' conflicted file content, verbatim. `_MERGE_TREE_HEADER_RE` matches `changed in both` at column 0 and its match calls `_flush()`, so a conflicted line carrying U+2028 before that text **ended the file's hunk early and dropped every line after it**. The render then printed a conflict preview with the conflict missing, under a heading naming the file — an absence produced by the tool, read as an absence in the world. Reproduced against real `git merge-tree` output before it was fixed, not reasoned about.
