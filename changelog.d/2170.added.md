- **A macOS desktop ping can now be turned off without also cutting the wire events that feed the `claude-channel` MCP server** ([#2170](https://github.com/Digital-Process-Tools/claude-supertool/issues/2170)). `desktop_notify` used to fire unconditionally on darwin whenever a source supplied `notify_title`/`notify_message`, and the existing `only=event1,event2` knob was the wrong tool for silencing it: it filters what a poller emits at all, socket included, so narrowing it to quiet the desktop equally starves the socket a maintainer loop's channel server depends on. `SUPERTOOL_WATCH_NO_DESKTOP=1` (or the equivalent `.supertool.json` op-config key, `watch_no_desktop: true` under `ops.watch`/`ops.radar` — any non-reserved key already reaches its op's subprocess as a `SUPERTOOL_`-prefixed variable, and a JSON boolean arrives stringified lowercase by the existing generic export) is read once in `desktop_notify`, before the `shutil.which` probe, and stops only the macOS notification — the UDS socket and the status file are unaffected. `watches` and `radar` now say so through `channel_disclosure()` rather than going quiet: a silenced desktop is a stated configuration, not an absence a reader has to explain for themselves.
