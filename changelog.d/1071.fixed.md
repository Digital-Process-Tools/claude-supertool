- `gh-prs` no longer states an absence it did not establish. The `author=@me` default is kept — `gh-prs` means "my PRs" — but it is now **disclosed** on every board, and an empty one names how many rows the filter excluded and how to see them, instead of printing `No PRs match.` / `0 PR(s)` over an outside contributor's open PR. Four states, never two: rows found, rows excluded by the filter (with the count), genuinely nothing open, and `UNKNOWN` when the check itself could not run — a probe that failed to spawn is never rendered as `excluded none`. The excluded count costs one extra `gh pr list`, fired only when the board came back empty under the *implicit* default.
- **New flag `gh-prs:anyauthor`** — every author's open PRs. Before it there was no spelling of that question at all: `author=` is refused for carrying no value and `label=`/`state=` are not role keys, so the default survived every attempt to widen it. Combining `anyauthor` with an explicit `author=`/`assignee=`/`reviewer=` is refused rather than resolved by precedence.
- `gh-prs` gained the `capped at --limit N — more may exist, raise with per=N` disclosure that `gh-issues` has had since birth, measured against the fetch rather than against what survived `failed`; and an empty `failed` board now says how many not-failing rows it dropped.
