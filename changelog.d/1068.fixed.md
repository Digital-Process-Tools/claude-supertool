- `gh-pr:N:diff:PATH` now serves the **net** diff for the path instead of the first commit that touched it. The fetch asked `gh pr diff N --patch`, which is format-patch — one section per commit — so a file touched by three commits arrived three times and the hunks route rendered the first and stopped, with no truncation notice of any kind. The file list one level up was built from the same records and printed one file as several rows. On PR #1057 (five commits) the op showed `op_replace`'s first-pass `newline=""` addition as the current code and a test assertion that a later commit had already replaced; a review agent produced two confident findings about code that did not exist. Output was 14429 bytes against a 65536-byte cap, so no cap was involved. `gh pr diff N` with no flag is the merge-base-to-head diff GitHub already computes, which is the thing being merged and therefore the thing under review — nothing is reassembled here (#1068).
- `gh-pr:N:diff` records are now coalesced per path before either render, so serving a first-of-N is structurally impossible rather than merely unlikely. A path that still arrives more than once — any future source that replays a file per commit — has **all** its entries shown, oldest first, under `Assembled from N entries for this path in the fetched diff … the LAST occurrence is the current one`. The file list sums such entries into one row rather than counting one file as `2 files`.
