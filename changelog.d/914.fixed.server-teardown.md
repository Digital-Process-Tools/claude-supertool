- **A test server the suite believed it had killed was still listening, and the client that dialled it waited out the full request timeout every run** ([#914](https://github.com/Digital-Process-Tools/claude-supertool/issues/914)). `tests/test_image_fetch_ssrf_817.py` stopped its fixture servers with `srv.shutdown()` and a comment reading `# nothing is listening now`. That comment was false. `shutdown()` ends the `serve_forever` loop and nothing else — the listening socket stays bound, so the kernel goes on completing handshakes into a backlog no one accepts from. `test_a_network_failure_is_not_reported_as_a_refusal` therefore never exercised a refused connection at all: it connected successfully, sent its request, and sat there until `IMAGE_TIMEOUT` expired. Measured cost **20.53s**, on every platform, every run — the third most expensive test in the suite ([#891](https://github.com/Digital-Process-Tools/claude-supertool/issues/891)) and one of the four that own its tail. It is now **0.52s**.

  **The bug is the unbounded half, not the twenty seconds.** A connect that lands in an unattended backlog is only bounded by whatever timeout the *client* happens to carry, and by how the platform's TCP stack behaves when a listener never accepts. This one had a 20-second budget and Linux to run on. Anything dialling that port without a timeout — or on a stack that retries rather than refuses — waits forever, in a test whose own assertion is that the connection fails fast. That is the shape of a suite that stalls in its last few percent and never names a test.

  **`_stop` replaces nine hand-written teardowns**, and does `shutdown()` **and** `server_close()`. `test_a_stopped_test_server_leaves_nothing_listening` asserts the post-condition rather than the call: it stops a server through the same helper every test uses and requires the port to answer `ConnectionRefusedError`. Verified red first — against the old teardown it reports `DID NOT RAISE ConnectionRefusedError`, which is the defect stated as an assertion.

  **The same shape is still live in three other modules** — `tests/test_http_bounds.py`, `tests/test_mcp_routing.py`, `tests/test_mcp_workspace.py` — where the leaked listener costs a file descriptor per test rather than a stall, because none of them assert that a port is dead. `tests/test_security_redirect.py` was already doing both calls. Left as-is here so the change stays the one defect it was verified against, and recorded so the next reader does not have to find it twice.
