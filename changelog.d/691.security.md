- **Wired the #2100 forge disclosure marker and #149 confirmation gate onto the eight publish-family siblings the 2026-07-31 security review's T4 theme named** ([#691](https://github.com/Digital-Process-Tools/claude-supertool/issues/691)). `require_confirm` -- the LLM single-shot publish gate -- already existed on `devto_publish`, `bluesky_publish` and `gh-pr-merge`; it was missing on `devto_comment`, `bluesky_follow`, `bluesky_like`, `hashnode_publish`, `hashnode_comment`, `hashnode_react`, and `bluesky_repost`, each of which could act once with no confirmation and no opt-out set. Separately, `apply_forge_disclosure` -- the #2100 AI-authorship marker -- already ran on `gh-pr-create`, `gh-pr-edit` and `gh-issue-create`; `gh-issue-comment` (added later by #2078) never got it. All eight now carry the same guard their siblings already had; `bluesky_repost` also gained the `|force` opt-out its own siblings expose. Not fixed here: the confirmation gate's own error text names every bypass (`|force`, the env var, the config key) to whatever called it, which lets an unsupervised LLM caller retry past its own block without a human ever seeing the prompt -- reported to the maintainer as a design decision rather than fixed inline.
