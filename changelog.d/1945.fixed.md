- **`presets/git`: no more stranded `.git/index.lock` on a timed-out call** ([#1945](https://github.com/Digital-Process-Tools/claude-supertool/issues/1945)). `_git_common._git`/`_git_verbatim` (the chokepoint for most of `presets/git`), and the standalone `_git` wrappers in `presets/dashboard/dashboard.py` and `presets/github/pr_merge.py`, ran a `git diff`/`status`/`stash list` under `subprocess.run(timeout=)` -- whose `TimeoutExpired` arm is `process.kill()`, SIGKILL with no grace, so git never got the chance to unlink the `.git/index.lock` it held while refreshing the index. Worse than the sibling instance in the `git-status` validator ([#1944](https://github.com/Digital-Process-Tools/claude-supertool/issues/1944)), which at least sends SIGTERM first. All three chokepoints now pass `--no-optional-locks` (a git global flag, so it precedes the subcommand): git treats the call as read-only and skips the index writeback, so killing the process at any point leaves nothing behind. Applied at each chokepoint rather than per call site, so a future read-only call inherits the protection -- verified harmless on the write commands (`commit`, `checkout`, `stash push`, `branch -d`, `worktree remove`, ...) the same chokepoints also run, since the flag suppresses *optional* locks only.
