- **`git-status` validator: no more stranded `.git/index.lock`** ([#1944](https://github.com/Digital-Process-Tools/claude-supertool/issues/1944)). `git diff`/`git status` refresh the on-disk index and take `.git/index.lock` to do it; a child killed mid-refresh -- past `_stop()`'s SIGTERM grace, or on Windows where terminate/kill are the same call -- could leave a stale 0-byte lock behind, wedging every later `git add`/`git commit`/`git stash` in that repository until a human deleted the file. `validators/git-status/git-status.py`'s `run()` now passes `--no-optional-locks` (a git global flag, so it precedes the subcommand) on every call, telling git the invocation is read-only: it skips the index writeback and never creates the lock at all, rather than relying on cleanup running.
