- **`check_meta_guards.py` no longer collapses "guard convention not adopted" and "adopted guard module failed to import" into the same signal, and stops printing a hardcoded "3 guards checked" when fewer than three actually ran** ([#2439](https://github.com/Digital-Process-Tools/claude-supertool/issues/2439)). `_load_module_from` used to return a bare `None` for both a missing file and a file that raised during `exec_module`, so a genuinely broken, adopted guard module printed the exact same "not adopted here (no tests/test_encoding_seam.py)" line as a project that never adopted the convention at all -- silently letting a broken guard through as `RC_OK`. It now returns a `LoadResult`/`GuardResult` with three explicit states (`ok`/`adopted`, `absent`, `load_error`/`failed`), and a load error is reported as `RC_COULD_NOT_CHECK`, never folded into a clean pass. Separately, the closing summary's guard count and name list were a literal string regardless of how many guards were actually adopted; `checked_names` is now a real tally, so one guard adopted out of three prints "1 guard(s) checked (env-scrub)" rather than naming guards that never ran. `tests/test_meta_guards_preflight_2263.py` gained load-error-vs-absent tests for all three guards plus a positive control (`test_main_load_error_is_not_silently_ok`) proving the RC_COULD_NOT_CHECK case is caused by the broken import and not by the sandbox shape.
