- **`op_vim`'s `:r` failure receipt now names which of two shapes an ENOENT is** ([#1763](https://github.com/Digital-Process-Tools/claude-supertool/issues/1763)). `test_log_pattern_Nr_read_file_after_line` went red once on `windows-latest 3.9` with `[Errno 2] No such file or directory` on a path `tempfile.mkstemp` had created three statements earlier -- other interpreters green on the same commit, a rerun passed, never reproduced. Bare ENOENT could not tell "the path never resolved" from "something was there and is now gone", so the next occurrence would have cost the same log read and status calls this one did. The receipt on a missing-file `:r` now appends whether the parent directory exists: `(parent directory does not exist)` when the path never resolved at all, `(parent directory exists; the file itself does not)` when it did and no longer does -- the shape a reap-after-close would leave. Fires only for `FileNotFoundError`; a permission error or `:r`-ing a directory keeps its old one-line message, so the ordinary typo'd-path case does not grow a diagnostic block it has no use for.
