- **A pyright that hung was a finding about your file, and could roll your edit back** ([#1464](https://github.com/Digital-Process-Tools/claude-supertool/issues/1464)). The adapter's `TimeoutExpired` arm emitted `code: "timeout"`. `adapter` is the one word the core routes to the third state — it is the only member of `_NONDETERMINISTIC_ERROR_CODES` an adapter may use, and the only code `_validator_not_checked` accepts — so a stall was read as one error on the file: cached until the file's hash changed, subtracted from a baseline as if it were real, and counted as a new finding by `rollback_on_fail`, which reverts the edit with nothing to restore it from. `validators/SCHEMA.md` already reserved `adapter` for "a binary that is absent, a timeout, output that would not parse", so this was a violated contract rather than a design gap.

  The failure is silent by construction — the payload is well-formed, nothing warns, and the only symptom is a fault presenting as a finding — so the class is pinned rather than the instance: a sweep now parses every adapter's `except subprocess.TimeoutExpired` arm and refuses any literal error code other than `adapter`. 26 such arms across the 36 adapters, 18 of which name a code literally rather than through a helper; exactly one of the 18 was wrong.
