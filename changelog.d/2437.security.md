- **Closed a free `note` forgery in the raw-command guard's ladder wrapper** ([#2437](https://github.com/Digital-Process-Tools/claude-supertool/issues/2437)). `#1686` removed `silent` from the vocabulary a rung on `hooks/python-ladder.sh` may assert because it was bit-identical to the wrapper's own genuine no-op, so a rung that never ran `hooks/pre_bash_guard.py` at all could claim it for free. A bare, bodyless `note` turned out to be the same free win wearing a real verb's name: `$(...)` strips a trailing newline, so a forger printing `supertool-guard-v1 note` and exiting 0 reached the exact bytes the wrapper's own genuine "nothing to say" wrote. `hooks/pre-bash-guard.sh`'s `attempt` now discards a bare `note` the same way it discards `silent`, and `hooks/pre_bash_guard.py`'s own "nothing to say" moved to a dedicated third verb, `clean`, whose `additionalContext` the wrapper hardcodes as empty regardless of what a rung appends. This does not authenticate the channel — no secret on it is unreadable to the rung itself — it only removes the zero-knowledge guess; exploiting it at all still requires an adversary who can already write a fake rung on `PATH`, which is pre-existing local code execution.
