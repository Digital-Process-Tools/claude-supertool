- **Three `gh-run` / `gh-pr` test fixtures stubbed `subprocess.run` for every call, so a run's JSON payload was fed to commands nobody modelled** ([#1488](https://github.com/Digital-Process-Tools/claude-supertool/issues/1488)). `monkeypatch.setattr(run.subprocess, "run", ...)` sets the attribute on the shared `subprocess` module, so it replaces every spawn in the process rather than the preset's own. With a fall-through, an unmodelled command was answered with the payload — a fixture that answers every spawn cannot tell "the product rendered this" from "my stub echoed this", and the bar this repo applies, *would this still pass if the code did nothing?*, cannot be evaluated at all while it is that wide. Each fixture now models the commands it stubs and raises `unstubbed command` on anything else.

  Narrowing found a live instance rather than only a latent one. `presets/_declared_legs.py` reads `gh api .../jobs?filter=all` as the **second** leg source, and the fall-through handed it the run payload — which carries its own `jobs` list, so it parsed. The second source was silently the first source: [#804](https://github.com/Digital-Process-Tools/claude-supertool/issues/804)'s own defect ("a second source read through the first one is not a second source") reproduced inside #804's fixtures.

  One of the two suites the issue names as unfixed, `tests/test_gh_run_matrix_reconcile_804.py`, had already been narrowed under [#850](https://github.com/Digital-Process-Tools/claude-supertool/issues/850); `tests/test_gh_pr_run_coverage_804.py` had not, and its fall-through also recorded the unmodelled command as the `gh pr view` argv it reported having fetched.
