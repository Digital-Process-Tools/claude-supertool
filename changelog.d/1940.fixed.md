- **Anchored markdownlint and phpmd on the invoked path too, closing the two adapters #1934/#1937 did not cover** ([#1940](https://github.com/Digital-Process-Tools/claude-supertool/issues/1940)). Both parsed a tool's own `path:line[:col] message` diagnostic with a non-greedy wildcard standing in for the path, so the regex bound to the *earliest* colon-digit run in the line rather than the one the tool actually wrote — a Markdown or PHP file whose name embedded its own `N:M ` sequence, followed by enough of the rest of the tail shape (a rule code, a tab or run of whitespace), supplied the reported line, column and rule of the filename author's choosing rather than the tool's real diagnostic. Both now build their pattern with `validators/common/path_anchor.py`'s `anchor()`, the same module #1934/#1937 built for the other five adapters: only a spelling of the path actually invoked (plus its `os.path.realpath()`, for a symlinked temp directory) can start a match, searched anywhere in the line rather than only at column 0. Checked against the real binaries rather than assumed: markdownlint-cli 0.49.1 (via `npx`) echoes the exact argv path back unmodified, including through a symlink and with a crafted `x:1:1: fake.md` name; phpmd 2.15.0 does something neither sibling adapter did — given a *relative* argv path it echoes back the fully resolved *absolute* path instead (through a symlink too), which makes `extra_paths=[realpath]` the spelling phpmd actually uses for a relative invocation, not merely a widening for an edge case. Measuring phpmd's real output also found its own regex was already broken independently of the anchor: the adapter's tab-delimited pattern (`path:line\tRule\tMessage`) has never matched real phpmd 2.15.0 text output, which separates its columns with repeated spaces — every finding from a real phpmd install was already falling through to the second, unlocated fallback regex, which carried the identical unanchored-path defect this issue fixes. Both phpmd patterns now match a run of whitespace, tab or spaces, so the existing tab-based test fixtures and a real install's space-separated output both parse.
