- **`pyright.py` no longer hands a flag-shaped filename (e.g. `--outputjson`) to pyright as a bare argument, where pyright's own CLI misparses it as an unknown option and never type-checks the file** ([#2379](https://github.com/Digital-Process-Tools/claude-supertool/issues/2379)). Same missing-boundary shape #2375 fixed in `mypy.py`, but the same fix does not work here: pyright does not honor `--` as an end-of-options marker at all (`pyright --outputjson -- --outputjson` still errors `Unexpected option outputjson.`, exit 4, measured on real pyright 1.1.409). `pyright.py` instead uses `tsc-check.py`'s own containment (#1519): a relative, flag-shaped target is prefixed with `os.curdir` via `os.path.join` before it reaches pyright's argv, so pyright's own parser never sees a string starting with `-`. `docs/validators.md` documents the limitation explicitly, the way it already does for `tsc`, and `mypy.py`'s docstring is corrected — it no longer claims to mirror `pyright.py`'s shape on this one point, since the two adapters now use genuinely different containments for the same problem.
