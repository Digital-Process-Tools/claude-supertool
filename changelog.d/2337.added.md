- **`gh-pr-merge:N:...|cleanup` now names which same-repo issues it verified `CLOSED`, so a caller with its own per-issue lane bookkeeping can release it in the same call** ([#2337](https://github.com/Digital-Process-Tools/claude-supertool/issues/2337)). `cleanup` already reaped the merged branch's worktree and remote branch, but had no way to tell a caller-side release hook which issues the merge closed -- `claude-oss`'s own `.oss-lanes/<issue>.json` per-issue lane records were left behind after every such merge, silently narrowing what a later dispatch-selection pass could see as free until that caller's own TTL expired. The `## Cleanup` section now carries a `[release] N, M` (or `[release] none`) line built from the exact `verdicts` list already computed for `## Linked issues` -- nothing is re-derived, and a cross-repo ref (`owner/repo#N`) is excluded, since it never names an issue in the caller's own tracker. This is an explicit list, not a callback: the op stores nothing and calls nothing on a caller's behalf, matching the issue's own steer away from growing a dependency on any one caller's lane registry.
