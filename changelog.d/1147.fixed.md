- **The rollback and the writer no longer resolve a symlinked write target independently** ([#1147](https://github.com/Digital-Process-Tools/claude-supertool/issues/1147)). [#1136](https://github.com/Digital-Process-Tools/claude-supertool/issues/1136) made `_run_with_validators`'s rollback arms and `_atomic_write` agree on which object a write touched, both via `_write_target`, but `_atomic_write` still re-derived its own answer at write time instead of reusing the one `_run_with_validators` had already sampled before the op ran -- a narrower version of the identical disagreement #1136 closed, open only if the target were retargeted in the window between the sample and the write. `_run_with_validators` now pins the sampled target for the duration of its `do_op()` call, and `_atomic_write` consults that pin before asking `_write_target` again; a caller with no pin for its path (an internal write, `op_replace`'s own per-file loop) resolves exactly as before. Hardening: no reproduction exists without an external process racing a single-user CLI.
