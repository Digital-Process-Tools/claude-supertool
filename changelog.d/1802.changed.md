- **The pre-push hook stops running the suite for a caller that is not git, and keeps running it for a push to `master`** ([#1802](https://github.com/Digital-Process-Tools/claude-supertool/issues/1802)). The issue proposed removing the suite run entirely, resting on the claim that "almost nothing reaches master by direct push". That claim was checked rather than taken, and it does not hold: measured 2026-08-20 over the last 400 commits on `origin/master`, **30 arrived by direct push and 15 of those touch `.py` or `presets/`**, the most recent two days before the issue was worked. The squash-merge path commits as `GitHub <noreply@github.com>`, so the two are separable without guessing. Thirteen of the fifteen are release commits — the one path that never passes through a PR, and the one where the four tested version sites are all that stands between a typo and a published artifact. So the master arm is live rather than vestigial and keeps its job; the smaller half of the issue was taken instead.

  **The arm that went is the not-git fallback, and its reasoning had the odds backwards.** It ran the suite whenever the hook was invoked with no ref lines *and* no argv, on the stated trade "being wrong that way costs three minutes and being wrong the other way costs master". But it fires exactly when the destination is **unknown**, and a push in this repo is overwhelmingly to a feature branch — which the hook has declined to gate since #893. It was therefore buying a macOS-only verdict, serially, on the author's machine, in a suite that rewrites the index of the live worktree it runs in, for a push it had no reason to believe was going anywhere shared. CI gates the commit on all three platforms either way.

  **Four states still, and they are still told apart.** Only the verdict of the fourth moved: it now skips and says *the destination was never established*, which is neither "there is nothing to push" nor "this is a feature branch". #1242 split those apart and that split stands. `PREPUSH_FULL=1` still forces the run in every skipping state, and the override is asked **inside** each state rather than ahead of all of them — hoisting it would print one banner for two states and rebuild #1242's conflation one layer up. That was caught in review of this change's own first draft, which had hoisted it.

  **The git env scrub stays, and that was a decision rather than an omission.** The scrub exists because the suite runs inside the hook, so the issue put its fate in scope. The suite still runs inside the hook on the master arm, so the scrub still has a reason to exist and `tests/test_git_env_scrub_692.py` is untouched.

  **The retired arm turned out to be load-bearing for eleven tests that were not about it.** `tests/test_pre_push_interpreter_572.py` and `tests/test_git_env_leak_416.py` both invoke the hook with no argv and no stdin, and reached pytest through the fallback — an incidental dependency that made interpreter-resolution and env-scrub tests fail on a change to a question neither asks. Both now pass `PREPUSH_FULL=1`, stating the dependency instead of inheriting whatever the zero-ref default happens to be.
