- **`channel:health` — whether the watch bridge is delivering, in three states rather than two** ([#554](https://github.com/Digital-Process-Tools/claude-supertool/issues/554)). Process-alive, socket-held and write-succeeds all read identically whether events reach a Claude session or not, and on 2026-07-29 that ambiguity produced a confidently wrong diagnosis in both directions inside twenty minutes. Delivery into a session turns out to be unobservable from outside it — the bridge sends a JSON-RPC notification, which has no id and no response, and `channel.ts` never writes back to the producer connection — so the answer cannot honestly be a boolean. `NOT DELIVERING` is the one definite state and it is a negative: nothing is listening, every event a poller emits right now is lost at the source, and the report names the watchers whose own last emit already found nobody home. `FORWARDING` reads the consumer's newly published counters — lines read, forwarded, dropped, last forwarded — re-stamped on a 10s heartbeat so an idle consumer and a wedged one are distinguishable. Everything else is `CANNOT DETERMINE`, which is the state the old tooling reported as green. The word is `forwarded` and never `delivered`: it counts events handed to the MCP transport, which is the last thing any process outside the session observes about them.
