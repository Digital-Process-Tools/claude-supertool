- **`gh-pr-merge`'s worktree cleanup no longer reads a failed `git worktree list --porcelain` as an empty listing** ([#1947](https://github.com/Digital-Process-Tools/claude-supertool/issues/1947)). `_worktrees_for_branch` collapsed both "nobody has this branch checked out" and "the read itself failed" into the same `[]`, so `_cleanup_worktree` printed the identical `no worktree of this checkout has <branch> checked out` for a cleanup that looked and found nothing and one that never established anything. It now returns `(paths, error)`, matching `_worktree_dirt`'s idiom in the same module, and a non-empty error routes the item to `CLEAN_REFUSED` rather than `CLEAN_SKIPPED` — a cleanup that could not look has not skipped anything. A genuinely empty listing is unaffected and still `CLEAN_SKIPPED`.
