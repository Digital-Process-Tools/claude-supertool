- **`doctor:probe`'s validator target could leave the repository, and a C-quoted filename read as "not applicable"** ([#2022](https://github.com/Digital-Process-Tools/claude-supertool/issues/2022)). `_doctor_tracked_files` read `git ls-files` and split it with `str.splitlines()`, which folds on ten separators the listing never delimits on (U+2028 among them) -- a tracked path containing one became two list entries, and the fragment after the separator reached `_validator_run_one`'s target argument, a path handed straight to a subprocess. The default rendering also C-quotes an unusual filename (a backslash, for instance), which `_match_glob` could never match, so an in-scope validator rendered as "not applicable" under stock git config. Both close with `git ls-files -z`, NUL-delimited, which removes the separator ambiguity and disables the quoting in one change. A third, narrower finding folded in: `_doctor_classify_probe`'s rendered `target` and `detail` reached the `doctor` output with no `_flat_field`, so an adapter `skipped` reason carrying a newline could forge an extra row under the real tally -- both are flattened now.
