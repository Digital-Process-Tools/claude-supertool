- **`git-worktrees` names each tree's open PR, in four states** ([#941](https://github.com/Digital-Process-Tools/claude-supertool/issues/941)). The board answered *is anyone working in this tree* and never *is that tree's work published, and is it green* — so choosing where to act next meant running `git-worktrees`, then `gh-prs`, then `gh-pr:N:status` per PR, and joining branch → path → PR number → check tally by hand. Both halves of that join were already held by the tool. Each row now ends in a tracker token and carries its reasoning as one more evidence line.

  **Four answers, and they do not collapse.** `PR #N` with the check tally summed by `_checks.summarize()` — the same arithmetic `gh-pr:N:status` prints, so a `CANCELLED` leg is a named term rather than a silent zero. `no open PR` when GitHub answered and nothing tracks a branch that is pushed. `no remote ref` when there is no remote-tracking ref here. And `PR unknown` when the lookup did not run — offline, unauthenticated, rate-limited, a non-GitHub remote — which is the pair that matters: `unknown` and `no open PR` are the tool's absence and the world's absence, and merged into one they read *this work is unpublished, take the tree*, in the op whose whole job is deciding which tree to take, at exactly the moment you are least able to check. The failed lookup is therefore consulted before any local fact, and it names which failure it was.

  **One call for N worktrees — and a full page is `unknown`, not `no PR`.** A single `gh pr list --limit 100`, keyed by head branch, serves every row. But a page that comes back *at* its cap is authoritative only for the branches it named; a branch missing from it is `PR unknown`, because a partially-answered batch is the same defect wearing state 2's clothes.

  **"Never pushed" is not claimed, because it cannot be observed.** The first live run called four `[merged]` worktrees "never pushed"; all four had been pushed, merged and deleted on the remote. A deleted remote branch and an unpublished one leave an identical local trace, and `branch.<name>.merge` does not separate them either — `git worktree add -b X … master` writes an upstream of `origin/master` for a branch that has never left the machine. The row reports what it saw and names both histories.

  **On by default, which is a cost this op did not previously carry.** It made no network call at all before; it now makes exactly one, on an 8s budget, adding about a second. Opt-in behind a suffix was the alternative and was rejected: the friction being fixed is a join done in the reader's head, and a suffix only helps a reader who already knows it exists. `nopr`, or `SUPERTOOL_WORKTREE_PR=0`, restores the fully offline op. The `[result]` line counts the rows whose tracker did not answer, so a missing answer survives `| tail -1`, and the exit code stays a statement about occupancy alone — a tracker nobody could read says nothing about whether a tree is safe to enter.
