- A worktree's `.git` is a gitfile naming the real git directory, so a `cp -a` copy of one shares it: every git command in the copy reads and writes the *original* worktree's index, HEAD and refs, and nothing said so. `git-status` and `git-worktrees` now lead with `⚠ COPIED WORKTREE` naming the tree the writes reach, and the `Repo:` line on `git-commit` and `git-push` — which exists to say where a write landed — carries it too, instead of naming the copy, which is the one directory the write does not reach (#1536).
- `git-status` used to render a staged revert written by a process in another directory as ordinary staged work. It cannot tell who staged something, so it now names what it could not determine: a staged path whose file on disk still matches HEAD is disclosed as `⚠ STAGED CONTENT NOT IN THIS TREE` — content no file here has, the shape a stray `git checkout <sha> -- <path>` leaves and equally that of a stage undone by hand — and the list is disclosed, never suppressed. A `git diff --name-only -z HEAD` that does not answer prints `⚠ Staged provenance UNKNOWN` rather than the silence that reads as clean — except in a repository with no commits, where there is no HEAD for the index to revert and the question is meaningless rather than unanswered (#1536).
