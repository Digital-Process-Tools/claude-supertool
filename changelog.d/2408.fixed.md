- **`gh-issue-create`, `gh-pr-create` and `gl-issue-create`'s `@file`/`@-` payload route refused every real payload** ([#2408](https://github.com/Digital-Process-Tools/claude-supertool/issues/2408)) -- a regression from the generic preset `args`-list route #1165 added (dc431bc9, #2403), which could not distinguish these three ops' own named-field payload (`title`, `body`, `labels`, ...) from a genuine `args`-only preset op like `gh-job`, and refused every call with `unknown field(s) title -- accepted: args` before the op's own script ever ran. The generic route now excludes any op whose `repo_target` mode starts with `"payload"` -- the codebase's existing signal for "this op parses its own named-field payload" -- restoring `gh-issue-create:@-`, `gh-pr-create:@-` and `gl-issue-create:@-` to how they worked before #2403. `gh-issue-comment:ID:@file` and `gh-pr-edit:ID:@file` carry the same `repo_target` signal and are excluded too, though neither was actually reachable by the buggy route in the first place -- their leading ID argument means the payload reference is never the token immediately after the op name, which is what the generic route required.
