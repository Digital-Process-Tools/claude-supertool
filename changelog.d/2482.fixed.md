- **`gh-mirror`'s manifest lock now waits on Windows instead of failing outright** ([#2482](https://github.com/Digital-Process-Tools/claude-supertool/issues/2482)). `_manifest_lock` retried a contended exclusive create on `FileExistsError`, which is the POSIX spelling: Windows raises `PermissionError` (EACCES) when another process holds the path open, so the second writer never entered the wait loop at all. It escaped, `write_issue` returned an error, and its update was dropped -- the lost update the lock exists to close. Observed on master `de25091`, `pytest (windows-latest, 3.12)`, job #102540129404, as a red on the concurrent-writers test; load-dependent, so it had passed on the same leg minutes earlier. A genuine permission failure raises the identical exception and is not contention, and the two are not distinguishable at that call, so neither is guessed at: both wait, and the timeout now reports the refusal it actually last saw rather than asserting a crashed holder it never measured.
