- **The tracked `.claude/settings.json` is guarded by an allowlist of top-level keys, so a harness write cannot ride into a commit** ([#1747](https://github.com/Digital-Process-Tools/claude-supertool/issues/1747)). On 2026-08-15 six lines nobody typed appeared in that file during a session in which `/reload-plugins` was run — an `enabledPlugins` block naming one machine's plugin roster, the same block deleted a day earlier as local state and the same class #1726 closed for four `$HOME`-rooted hook registrations. Both of those fixed the file's *content*; neither stopped it being re-added, because the writer is not a person. `supertool 'grep:enabledPlugins:tests/:8:1'` returned 0 results across 794 files, so a commit carrying the block went green.

  `tests/test_settings_no_machine_state_1747.py` names the keys this repository intends to ship — today `{"hooks"}` — and fails CI on any other. The direction is the decision, not a detail: a denylist of keys the harness is known to write is green the first time it invents one, which is failing open silently, this repository's own defect class. **The cost of the allowlist is that somebody adding a legitimate setting is interrupted by a red leg**, and that is the intended trade: the failure asks whether a human typed the key or the harness wrote it, so widening the set is a line in a pull request rather than a shrug. It reads the top-level surface only — machine state nested inside an allowed key is not caught, and the docstring says so rather than leaving the gap to be inferred.

  `.gitignore` now names `.claude/settings.local.json`, where the per-machine copy belongs. It had been ignored on the maintainer's disk only through `~/.config/git/ignore`, a file no other clone has, so everywhere else it sat untracked and one `git add -A` from committing the same roster under a different filename.

  Untracking `.claude/settings.json` was considered and declined: it is what carries the `pre-bash-guard.sh` registration to every clone, which is exactly what #1698 argues must not wait on a plugin release. Untracking trades a drift `git status` renders for an absence that renders as nothing.
