- **`git-worktrees` no longer calls a branch with unpushed commits `published`, and every exit code now names itself in the body** ([#1496](https://github.com/Digital-Process-Tools/claude-supertool/issues/1496)).

  The row read `the branch is pushed and no open PR tracks it - the work is published but unproposed` off the *existence* of a remote-tracking ref alone. Hit live on the default branch: the clone was one commit ahead of `origin/master` and the row said `published`. Existence of `refs/remotes/origin/<branch>` and being in sync with it are different questions, and read in the direction that matters - somebody deciding whether a tree can be discarded - `published` reads as `safe to remove`.

  So the count is taken, with three answers and no fourth silent one: in sync (published, unproposed), `N commit(s) here are NOT on it` (not published, and the row line itself carries `N unpushed, no open PR` so a scan that never reaches the evidence still sees it), or the count could not be taken - which renders `UNKNOWN` with the reason and never as `0`. It is measured against the ref the row is about rather than `@{upstream}`, because `git worktree add -b X ... master` writes an upstream of `origin/master` for a branch that has never left the machine. One local `rev-list` per pushed branch; no extra network call.

  The second half: the same call exited `1` with no line in the body naming a failure, because nothing had failed - the `1` was the occupancy verdict. A caller gating on the status and a caller reading the render disagreed about the same call. Every return now prints an `[exit N]` line saying which verdict or which refusal produced it, and whether the op itself failed. It sits **above** `[result]`, not below: that line is what `gh-pr-merge` and every `| tail -1` reader take the tally off.
