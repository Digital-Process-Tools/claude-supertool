- `channel:health`'s subscription probe could not fit inside its own op timeout, so the one case where `CANNOT DETERMINE` is the right answer was the one case it could never give: the probe spends `PS_TIMEOUT * 2` plus a `claude mcp get` per channel tag, the op was declared at 15s, and because the report is one string printed at the end there was nothing to emit — the reader got a bare `TIMEOUT` with an empty body. The lookups now share a declared 12s budget, a tag the budget did not reach is named as unasked rather than as unconfigured, and a test pins the arithmetic (the declared op timeout must exceed the probe's worst case) rather than either number (#1558).
- `channel` is no longer declared `read-only`. `claude mcp get` health-checks by spawning the named server, and the name is parsed out of another process's argv, so a blind probe of this op starts whatever the harness has configured under that name — `acts`, by consequence rather than by mechanism (#1558).
