- **The watch board says which project the channel name belongs to, so a shared fleet stops rendering as a private one** ([#1732](https://github.com/Digital-Process-Tools/claude-supertool/issues/1732)). `SUPERTOOL_WATCH_NAME` derives one socket and one poller-slot directory, so two projects exporting the same name are one fleet: events from one project's pollers arrive on the other's channel, and each board reports a population that is not its own. `watches`, `radar` and `channel:health` rendered that identically to a correct single-project fleet — the name, the two paths, and no field naming an owner. Reported after four repositories ended up sharing one hand-copied `"SUPERTOOL_WATCH_NAME": "oss-supertool"` in one machine's `.claude/settings.local.json`.

  `naming.declared_names()` reads the `.supertool.json` at or above the cwd and answers in four states, so a look that did not happen can never render as an absence in the world: `found` (an op block declares a `watch_name`), `silent` (a config is there and declares none, so what is in force arrived from an environment this project never asked for), `no-config` (nothing above the cwd claims anything) and `unreadable` — a config that could not be parsed, or a directory in the upward walk this uid cannot traverse, stated as *unknown, not unclaimed*. That last half came out of review: `os.path.isfile` is an `os.stat` inside `except OSError: return False`, so the first version of the walk answered "no config here" for a directory it could not enter and reported an absence in the world off a look that failed. Every render then names the owner: `name X is declared by <path> (ops: …)` for the ordinary case, and the loud form when the name in force is not one this project declares, or when the project's own op blocks disagree. Nothing is printed on the default channel: those paths are shared by construction and have no owner to dispute.

  It also names the watch ops that declare nothing. A `watch_name` in an op block reaches only *that* op's subprocess, and `watch` and `unwatch` are the two that spawn and kill pollers — so declaring the name on `watches` alone reads a private board over a default-channel fleet, which is [#1309](https://github.com/Digital-Process-Tools/claude-supertool/issues/1309)'s half-configured state arriving through the config door instead of the environment one. This repository declared exactly that shape and now declares all five.

  Precedence is unchanged and deliberately so. An exported `SUPERTOOL_WATCH_NAME` is still authoritative, because it is the value a running poller already captured and a file that outranked it would move the socket and the slot directory underneath a live fleet ([#1477](https://github.com/Digital-Process-Tools/claude-supertool/issues/1477)). Nothing here changes what is in force; what changes is that a reader can tell whose it is.
