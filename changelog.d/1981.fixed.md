- **Fixed a race where the syntax-floor walk could compile a throwaway probe file mid-delete, reporting a bogus `SyntaxError` for a file in no commit** ([#1981](https://github.com/Digital-Process-Tools/claude-supertool/issues/1981)). `tests/test_gl_repo_target_676.py`'s env-leak probe wrote its real, throwaway `.py` inside `tests/` -- inside `repo_python_files()`'s walk root -- and held it there for up to 60s while a child pytest ran. Under `-n auto` a concurrent worker running `test_syntax_floor_478.py::test_every_repo_py_file_compiles_at_the_floor` could enumerate the probe between the write and the `finally: unlink()`, then fail to open it after the delete -- coded as `unreadable`, which reads exactly like a real `SyntaxError` (`line: None, col: None`) naming a file that was never committed. The probe now writes under pytest's own `tmp_path`, which is never inside the repository, so no repo-wide walk can ever enumerate it regardless of how the two race. `tests/test_repo_walk_probe_location_1981.py` pins the walk root and the fixed probe location as genuinely disjoint, with a positive control proving the walk would have caught the old location.
