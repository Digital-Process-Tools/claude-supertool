- **A child process's stdout reached a receipt at column 0 in seven more places, and nothing detected the eighth** ([#1475](https://github.com/Digital-Process-Tools/claude-supertool/issues/1475)). The class behind #1470, which closed it for `git-push` alone. `gh` echoes the GitHub API's own error body on its stderr and a commit hook writes whatever it likes, and both reached a line the tool owns with no `_untrusted` call in between. `_untrusted.split_lines` cuts on LF / CR / CRLF only, by design (#1081), so a U+2028 survives *inside* a relayed line and puts everything after it back at column 0 for any consumer that splits the way `str.splitlines()` does.

  **The fix is at the seam, not at the sites**, which is the whole argument: seven named sites is what a per-site fix earns, one re-filing per call site. `_git_common._first_error_line` now flattens what it returns, so `git-commit`, `git-push` and whatever is written next are covered at once — `_untrusted.flat` is idempotent, so the callers that already flattened pay a no-op rather than a second substitution. It also parses with `_untrusted.split_lines` instead of `str.splitlines()`: a writer who put a U+2028 in a line was choosing which line the error scan returned, and the tail it hid was dropped from the receipt rather than disclosed. `pr._format_error` is the single sink both `gh-pr` error prints share and flattens there; `gh-pr`'s diff header and diff-failure reason go the same way. `git-commit`'s whole refused-commit render moved into `_failure_receipt`, which relays the hook's transcript exactly as `git-push` relays its own — `split_lines`, then `visible(keep=tab)` per line, so tabs survive and separators are shown rather than dropped.

  **The detector is the part worth more than the seven, and it is a ratchet rather than a gate — deliberately.** An AST scan for "a child stream reaches `print` or a `return` without a marker" reports **174 candidates in 36 files** across `presets/git`, `presets/github` and `presets/gitlab`. Not every one is a defect (`push._local_head` returns `r.stdout.strip()`, and that is a SHA), and closing them is four lanes of work. So `tests/test_forged_child_stream_line_1475.py` records a **count per file that may only fall**: a new relay anywhere in those trees raises a number and fails, a fixed one lowers it and fails with the message telling you to write the smaller number down. It is not an allowlist — there is nothing to add a site to, and both directions are one visible line in a diff. What it does not catch is stated in the test: a relay added to `push.py` in the same commit that fixes another one nets out. That is the price of a ratchet, and the gate costs 174 fixes first.
