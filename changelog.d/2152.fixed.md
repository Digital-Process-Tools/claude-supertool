- **A new seam guard refuses a test fixture that writes a `tmp_path`-derived value straight into a TOML basic string** ([#2152](https://github.com/Digital-Process-Tools/claude-supertool/issues/2152)). A Windows `tmp_path` is all backslashes, and a TOML basic string (`"..."`) processes backslash escapes, so an f-string that interpolates `tmp_path` into one is unparseable on Windows only -- exactly what took out 7 tests on PR #2148, in the suite that tests backslash handling in payloads. `tests/test_toml_basic_string_seam_2152.py` walks every test file for the shape and is exempt-free by construction: it keys on the payload-writing shape (an f-string's double-quoted field interpolating an expression naming `tmp_path`) rather than on a field name or a bare "could hold a backslash" scan, so the existing `_toml_path()`/`_toml_str()` escaping helpers, and literal (single- or triple-quoted) TOML strings, are unaffected.
