- **`worktree:teardown` now says explicitly that it leaves `extensions.worktreeConfig` enabled, instead of leaving that repo-wide flag unmentioned** ([#2419](https://github.com/Digital-Process-Tools/claude-supertool/issues/2419)). `worktree:setup`'s `exclude` handling enables this git extension with a plain `git config extensions.worktreeConfig true` -- no `--worktree` flag -- so it lands in the **shared** `.git/config`, not a file scoped to the one worktree being provisioned. Teardown was already correct to leave it alone (unsetting a repository-wide flag from one worktree's teardown would silently stop every OTHER worktree, including ones added later, from having its own `--worktree`-scoped config -- e.g. a sibling's own `core.excludesFile` -- read at all), but said nothing about it, so the receipt read like the mechanism had simply been forgotten. The receipt now names the flag, says it was left enabled, and why.
