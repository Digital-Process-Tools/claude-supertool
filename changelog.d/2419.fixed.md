- **`worktree:teardown` now reports what the shared `extensions.worktreeConfig` flag actually is, instead of leaving that repo-wide flag unmentioned** ([#2419](https://github.com/Digital-Process-Tools/claude-supertool/issues/2419)). `worktree:setup`'s `exclude` handling enables this git extension with a plain `git config extensions.worktreeConfig true` -- no `--worktree` flag -- so it lands in the **shared** `.git/config`, not a file scoped to the one worktree being provisioned. Teardown was already correct to leave it alone (unsetting a repository-wide flag from one worktree's teardown would silently stop every OTHER worktree, including ones added later, from having its own `--worktree`-scoped config -- e.g. a sibling's own `core.excludesFile` -- read at all), but said nothing about it, so the receipt read like the mechanism had simply been forgotten. The receipt now names the flag and reports its actual current state (self-review caught the first cut of this fix always claiming "left enabled" even if the flag had been changed out-of-band since `setup` ran -- it now queries `git config` fresh at teardown time rather than assuming).
