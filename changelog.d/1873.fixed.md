- **A refused compound Bash call now names the earlier command(s) it also discards** ([#1873](https://github.com/Digital-Process-Tools/claude-supertool/issues/1873)). A `PreToolUse` decision covers the whole call, so a refusal on `B` in `A && B` never let `A` run either -- and said nothing about it, which read as "the guard stopped me from running `B`" rather than "... and also discarded `A`". `guard_command` now tracks which top-level shell segment each replaced invocation came from and, on a `blocked` verdict, names every segment before the earliest one that matched: `git commit --allow-empty -m "wip" && git push` now tells you the commit will not run either, not only that the push is replaced by `git-push`. Covers the `replaces` registry route only -- the hand-written regex rules under `.claude/jit-context/tools/00-manual/` (and their shipped subset in `hooks/shipped_rules.py`) match the raw command string directly and are deliberately checked before `_supertool` is imported, so they do not see this fix; #1873 stays open for that half.
