- **A shipped regex rule now names the earlier command it discards too** ([#1873](https://github.com/Digital-Process-Tools/claude-supertool/issues/1873)). A `PreToolUse` block is all-or-nothing across a whole Bash call, so a compound call whose first half is a write and whose second half trips a shipped rule (`supertool-no-cut.md`, the one rule that ships today) used to refuse silently about the write: the refusal spoke only about the piped command, and the earlier write never ran with nothing on the receipt to say so. The registry route (`_supertool.guard_command`) already disclosed this since [#2010](https://github.com/Digital-Process-Tools/claude-supertool/issues/2010); the hand-written regex rules under `.claude/jit-context/tools/00-manual/` now do too, naming every earlier top-level segment a `deny` verdict discards alongside it.
