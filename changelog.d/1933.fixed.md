- **`git-status`'s MR/PR diff line no longer collapses a `git diff --shortstat` timeout, an unfetched target ref, an unreported target branch, or any other local git failure into the same silent render as a genuinely empty diff** ([#1933](https://github.com/Digital-Process-Tools/claude-supertool/issues/1933)). The line's `changes_count` guard already proves the diff is non-empty before the local shortstat runs, so a bare `Diff: N files` inside that branch could only mean the call did not answer — never that there was nothing to count. A clean result still prints `(+a -d)`; a failed one now prints `` (+? -? — `git diff --shortstat` did not answer: <reason>) `` right on the same line. An unfetched target ref stays out of the `INCOMPLETE` footer deliberately — it is the ordinary case on a shallow or partial checkout — while a genuine timeout still reaches the footer, unchanged, because `_git` itself records that unconditionally.

  `tests/test_forged_child_stream_line_1475.py`'s `UNRESOLVED` moved 109 -> 111 for this change. Both new sites are `shortstat.returncode` and `shortstat.stderr`, the two arguments of one `_reason(shortstat.returncode, shortstat.stderr)` call in the new failure branch above. Neither is a new class of risk: `_reason` already flattens `stderr` through `_untrusted.flat` before returning, and this is the sixth call to that same helper in `status.py` — the other five (`_divergence_line`, `_note_failed`, `_hosted_request`, and `main`'s not-a-repository arm) never moved this number only because each embeds the call directly inside an f-string that is itself a sink's argument, which the census already models; this one reaches `_reason` through `diff_line += (…)`, an `AugAssign` the census does not track as taint-carrying, so it lands in the disclosed-but-unmodelled bucket instead of the modelled one. See `UNRESOLVED`'s own comment in that test file for the full account.
