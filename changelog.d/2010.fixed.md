- **The discard line #1873 shipped now names a command a caller can actually re-send** ([#2010](https://github.com/Digital-Process-Tools/claude-supertool/issues/2010)). `GuardVerdict.discarded` (#2009) rendered each earlier segment by re-joining its already-tokenised words, after `shlex` had consumed any quotes and after the redirect-drop loop had thrown the operator and its target away entirely -- so the line's own trailing instruction, re-send it separately, handed back `echo hello   world` for a segment that actually read `echo "hello   world" > /tmp/x.txt`, three words with no quoting standing in for one three-space argument, and the redirect gone outright. `_guard_segments_with_origins` now derives each segment's raw text as a character slice of the prepared command, via a new `_guard_raw_segment_spans`, rather than a token re-join -- so quoting and redirections survive. It falls back to the previous word-rejoin only for the segments actually affected by a handful of shell idioms that split on an all-punctuation WORD rather than a real operator (a bare `find` placeholder clause) -- scoped per segment rather than to the whole command, after a spawned auditor's own review of this fix caught the first cut degrading an unrelated, well-formed earlier segment in the same call.
