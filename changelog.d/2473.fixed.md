- **`_mini_toml_loads` (the fallback TOML parser for @file/@- payloads on Python <3.11, i.e. CI's 3.9/3.10 legs) now supports a single `[table]` header, not only `[[table]]` array-of-tables** ([#2473](https://github.com/Digital-Process-Tools/claude-supertool/issues/2473)). It used to raise `single [table] header at offset N is not supported`, blocking any op that accepts a nested-object payload field on Python <3.11 -- not only `json-set` (#1822, where it was first found), every op taking a table-shaped `@file`/`@-` field. It parsed clean on 3.11+ (stdlib `tomllib`) and only failed on the older two legs of the matrix, the "reasoned, not observed" gap `CLAUDE.md`'s Python-3.9-floor section warns about. `[table]` uses the same bare-name grammar `[[table]]` already validates against (alnum, `_`, `-`; no dots) rather than inventing a second, dotted-header convention -- a dotted header (`[a.b]`) still raises, by name. Inline-table syntax (`{ "a" = "b" }`) stays out of scope, per the issue's own split.
