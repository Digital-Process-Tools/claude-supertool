- ([#1681](https://github.com/Digital-Process-Tools/claude-supertool/issues/1681))
  Eleven renders under `presets/git/` split a log stream with `str.splitlines()`
  and printed **every** line, counted — so a U+2028 in a commit subject, an
  author name, a refname or a stash message added a row nobody committed and
  chose the number beside it. `core.quotePath` quotes pathnames; measured again
  on git 2.46.2, `log --format=%s` hands the separator back raw. The sites are
  `git-checkout`'s last-3-commits list, `git-diverge`'s commit list,
  `git-push`'s force-discard and incoming-commit lists, `git-status`'s other-branches,
  last-5-commits and stash sections, and all three of `git-trail`'s.
- **`_untrusted.split_lines` alone would have been the wrong fix, and that is
  the whole finding.** Everywhere else in this tree the site *selects* one line,
  where consuming the separator is right. These render all of them, so narrowing
  the split alone keeps the count honest and hands the separator to the terminal
  live, inside a row the tool presents as its own output — an inflated count
  traded for a cursor command. Every one of the eleven gets `split_lines` **and**
  `visible()` per rendered line, with `keep` set to the TAB only where the line
  is parsed on a TAB field (`for-each-ref`) or is indented source (`git show`
  hunks).
- **One of them was never a forged row at all.** `git-trail`'s pickaxe render
  feeds each line's first token back to `git show` as argv, and `git show
  --output=<file>` writes that file — verified on git 2.46.2. So a commit
  subject ending `<U+2028>--output=/path` became a *line* whose first token was
  that option, and a commit message chose a path on the reader's disk. That is
  `splices`, not `forges`, and `split_lines` is what closes it.
- `git-status` lost a real branch rather than gaining a fake one, which is why
  the register had ruled it survivable. `check-ref-format` accepts U+2028 in a
  refname, so `feat<U+2028>ure` split into a head fragment with no TAB — dropped
  by the `"ahead" in track` test — and a surviving row rendered under the name
  `ure`, which no branch in the repository has. The reader was told about
  unpushed work on a branch they cannot check out, and the real one was named
  nowhere.
- The `presets/git/` `str.splitlines()` register is down to 27 call sites in 24
  functions across 9 files, from 38 / 27 / 11. Three entries are gone entirely
  and three are now `QUOTED PATH`, each down to its one `--porcelain` /
  `--name-status` read. `git-status`'s dead `branch -vv` split — assigning a
  `current_branch` nothing ever read — is deleted rather than re-registered.
