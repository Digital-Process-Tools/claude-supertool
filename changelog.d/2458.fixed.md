- **`php-cs-fixer`, `prettier-write` and `phpcbf` now report `metrics.first_changed_line` / `last_changed_line`, matching `ruff-format`** ([#2458](https://github.com/Digital-Process-Tools/claude-supertool/issues/2458)). #2405 gave `ruff-format` a `SequenceMatcher`-based diff so a caller can tell *where* a post-write reformat touched lines a triggering edit never asked it to, not merely *how many* — but the other three SCHEMA-adapter formatters kept the older unified-diff counts-only shape, so the same class of stale-read failure #2405 fixed for Python files was still live for PHP, JS/TS/CSS/JSON/YAML/Markdown files. The diff logic moved out of `ruff-format.py` into a shared `validators/common/line_diff.py::line_diff()` so the four adapters share one implementation instead of `ruff-format`'s bugfixes drifting away from three copies; all four now emit the identical `(lines_added, lines_removed, (first_changed_line, last_changed_line))` shape, including both #2405 edge cases (no fabricated `(1, 1)` for an insertion into an empty file; disjoint hunks reported as one merged span).
