- **`new-file-lint` and `changelog-fragment` no longer trust a conventionally-named script found inside whatever repo happens to contain the edited file** ([#2228](https://github.com/Digital-Process-Tools/claude-supertool/issues/2228)). Both adapters import (and thereby execute) the project's own `.github/scripts/lint_new_files.py` / `assemble_changelog.py`, found by walking up from the edited file to its own git root. That walk was already bounded at the repo root (#2178), which stops an escape ABOVE the repo, but said nothing about whether the repo ITSELF should be trusted: a maintainer whose own `.supertool.json` sits above a directory of clones, editing a `.py` file inside any one of them, had that clone's own innocuous, conventionally-named CI helper imported and executed with the maintainer's privileges — before either adapter's new-file-only check even ran. Supertool's validator runner now stamps `SUPERTOOL_CONFIG_DIR` (the directory holding the `.supertool.json` that wired the run) into every validator adapter's environment, and both adapters refuse the convention-based location unless that directory is the edited file's own repo root or somewhere inside it. `SUPERTOOL_NEW_FILE_LINT_SCRIPT` / `SUPERTOOL_CHANGELOG_ASSEMBLER`, an operator's own explicit path, still bypass the check.
