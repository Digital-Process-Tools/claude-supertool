- **A re-exec'd poller never re-verified its state directory, because the path it inherited looked operator-supplied ([#1534](https://github.com/Digital-Process-Tools/claude-supertool/issues/1534)).** `transport.poller_env` pins the resolved state directory into the child's environment (#1477), so the child's `naming.resolve` saw an explicit `SUPERTOOL_WATCH_STATE_DIR` and set `state_dir_is_derived` to `False` — the flag every establishment guard is behind. `naming.ensure_state_dir` returned `""` without asking anything, so `claim_pidfile` and, since #1540, every `write_state` in a poller skipped the check entirely. The parent verified once before the spawn and nothing re-established it after: a race window on the public, committed leaf `/tmp/supertool-watch-<name>`, not an open door.

  **The flag conflated two facts and is now only one of them.** *The operator supplied this path* is theirs, and manufacturing it would trade a loud refusal for a poller spawned into a directory nobody asked for (#693). *This is the path the name derives* is ours. `state_dir_is_derived` is now equality with `state_dir_for(name)` — a question about the **value**, not about which variable delivered it. That needs no marker to survive the exec and adds nothing new to forge: an environment naming a *different* directory is the operator-supplied case it always was, and one naming the derivation is asking for the directory this code already owns.

  `state_dir_env_set` carries the other half, and only `state_dir_provenance` reads it. That function feeds the operator-facing refusal in `dispatcher.py`, which under the old flag sent a re-exec'd poller's operator to `SUPERTOOL_WATCH_STATE_DIR`, and under the new flag alone would have told them the variable is unset inside a process whose own environment sets it.

  **Two more things the same equality removes.** Both precedence notes read `... is set and overrides the name: poller slots are in /tmp/supertool-watch-oss, not /tmp/supertool-watch-oss` — and the same for the socket — in every re-exec'd poller, because `poller_env` pins both halves. An override notice for an override that did not happen, on the one surface this module exists to keep trustworthy. Each note is now gated on the value actually differing. And the establishment is re-asked per write in the child exactly as #1540 specified for the parent, rather than memoized by accident of the exec.

  **Windows.** No platform-specific code and no path literal: the comparison is against `state_dir_for(name)`, the same f-string that produced the value. `_image_root.ensure` is unchanged and keeps its own documented Windows split — `lstat` in place of `O_NOFOLLOW`, ownership and mode declined rather than faked. Pinned everywhere by `tests/test_watch_poller_state_dir_reverify_1534.py`, whose one subprocess spawns `sys.executable` and does not shell out.
