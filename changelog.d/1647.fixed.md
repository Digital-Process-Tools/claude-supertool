- **`git-push`'s option-shaped-remote guard now really does run before anything spends the value** ([#1647](https://github.com/Digital-Process-Tools/claude-supertool/issues/1647)). The #1617 chokepoint comment stated that `reject_fetch_option` is called "before the argv is built rather than inside each arm, so a future arm cannot reintroduce the hole by forgetting". It was not: `_remote_sha(upstream)` ran `git rev-parse --short <upstream>` 33 lines above the guard, spending the same `@{upstream}`-derived value the guard exists to refuse.

  Not exploitable on today's code — `rev-parse` spawns no helper, so a leading-dash upstream dies as an unknown option — and that is the whole severity. What was wrong is the invariant, not the argv. The sentence is the thing the next contributor relies on when adding an arm without re-reading the function, and any git call placed above the old guard silently inherited a pre-guard slot the comment said could not exist.

  Fixed by moving the guard above its first consumer rather than by editing the sentence down to something weaker but true. Editing it would have been honest and would have preserved a gap for no reason. The pre-push remote SHA is now read after the refusal, and a test asserts that no git call at all spends an option-shaped upstream before the guard — the existing #1617 spy watched `push`, `fetch` and `rebase` only, which is why a `rev-parse` above the guard went unseen by the tests written to pin it.
