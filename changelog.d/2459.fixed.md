- **Documented the `.py` shape of the `edit:@-` doubled-backslash refusal that costs the most round-trips in practice** ([#2459](https://github.com/Digital-Process-Tools/claude-supertool/issues/2459)). The refusal and its per-extension hint (#1794) were already correct, but a test fixture that builds a stub script as a string and has that stub write a further file needs one backslash level per file boundary crossed — `'<?php\n$x = 1;\n'` in the outer `.py` source is a *correct*, already-committed doubled `\n`, not a mistake, and rewriting or repasting such a file whole re-triggers the scan over content that was already fine. `docs/input-forms.md` now names this shape explicitly, beside the existing `literal_backslashes` guidance, so `literal_backslashes = true` is the first move for it rather than the third.
