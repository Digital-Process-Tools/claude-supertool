- **`html-check` is now registered, so it actually runs** ([#833](https://github.com/Digital-Process-Tools/claude-supertool/issues/833)). The adapter shipped in `validators/html-check/` with no entry in any config, which meant `validate:` on a page containing `<script>const a = ;</script>` ran only `git-status` and reported `0 with findings`. A checker nobody had wired up is indistinguishable, from the outside, from the gap it was written to close.

  It is registered in two places now: this repo's own `.supertool.json`, so the project that ships it runs on it, and `.supertool.example.json`, which `docs/validators.md` tells users of other projects to copy from — the table already listed `html-check` and the file it pointed at had no such block.

  `rollback_on_fail: true`, matching `node-check` for `*.js`: same tool, same question, same consequence. Rollback is regression-gated, so an edit to a page whose inline JS is already broken is not reverted — only one that introduces a new syntax error. `timeout: 60` sits above the adapter's own 30s per-block budget on purpose, so a hung `node --check` is reported by the adapter naming the block rather than by the core's blunter timeout naming nothing.
