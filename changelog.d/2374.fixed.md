- **The `worktree` op was classed `*` ("writes files in this tree") even though `worktree:teardown[:PATH]`/`worktree:setup[:PATH]` can write and delete at a PATH that resolves to a sibling worktree entirely outside cwd** ([#2374](https://github.com/Digital-Process-Tools/claude-supertool/issues/2374)). PATH is deliberately exempt from the generic cwd/repo containment gate (`presets/worktree.json`'s `"paths": {"args": []}`) because pointing outside cwd is the documented use case, and `presets/worktree/teardown_op.py` then runs `dest.unlink()`/`shutil.rmtree(dest)` against that target -- so `ops:roster`'s `*` marker told an agent this op was confined to the tree it was called from when it is not. Reclassified to `"acts"` (marker `!`, "reaches outside this tree, or outlives the call"), matching `git-push` and every other op here whose effect can land outside the caller's own tree. Not a containment-gate bypass -- `SUPERTOOL_READ_ONLY=1` already refused both classes alike -- this only fixes what the roster's own legend claims about the op's reach.
