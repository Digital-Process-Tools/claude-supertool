- **YouTube preset no longer leaks the API key to stderr on a same-origin redirect** ([#2533](https://github.com/Digital-Process-Tools/claude-supertool/issues/2533)). `presets/youtube/_yt.py::get()` is the first `presets/_http.py::urlopen()` caller to put its credential in the request URL's query string (`query["key"] = api_key`) rather than in a header; every other credentialed client (bluesky, devto, hashnode) sends its secret as a header instead. `urlopen()`'s same-origin redirect disclosure prints both the requested and the answering URL to stderr on every followed hop — deliberately, so a silently-followed redirect is never mistaken for the call the caller actually asked for — but that NOTE fires on the success path, before any caller-level exception handler (`_yt._scrub`, which only runs from `RedirectRefused`/`ResponseTooLarge`/`DeadlineExceeded`/`HTTPError` handlers) ever gets a turn, so the key rode straight through it in plain text. `presets/_http.py` now scrubs known credential-shaped query parameters (`key`, `api_key`, `apikey`, `access_token`, `token`, `secret`, `client_secret`, `password`, `auth`) out of both URLs before they are printed, generically at the one shared call site rather than per-caller, so a future integration that repeats youtube's URL-embedded-credential shape is covered without knowing this exists.
