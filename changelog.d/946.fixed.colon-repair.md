- **A `git-commit` refusal no longer suggests a repair that corrupts the message it is repairing** ([#946](https://github.com/Digital-Process-Tools/claude-supertool/issues/946)). `git-commit:::MSG:::PATH` splits on `:::`, so a `:::` inside MSG makes the tail of the message arrive as a PATH — which the op correctly refuses. The suggested repair then rebuilt the message by rejoining on a single `:`, whatever had actually split it, so the `:::` came back as a `:` with nothing saying so. Both offered routes carried the rewrite; pasting either committed bytes the caller never wrote, under a refusal that was otherwise right.

  The refusal now leads with the `@-` payload route carrying the message byte for byte, and offers the single-colon reading below it, stating that the separator changes. Both readings are named; neither is guessed at.

  On the payload route the same check can fire, and there the refusal no longer claims the message "was split on ':'" — nothing was split, the fields arrived structured. It names the entries that are not paths, leaves the message intact, and declines to guess where the stray text belongs.
