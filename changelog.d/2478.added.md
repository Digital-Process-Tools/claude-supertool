- **`channel:stranded` — a session armed for a watch channel with no consumer now gets told so unasked, at session start** ([#2478](https://github.com/Digital-Process-Tools/claude-supertool/issues/2478)). This repo's own checkout was the reproduction: `channel:health` correctly reports `NOT DELIVERING`, but a session has to think to run it, and a session that does not know its channel is dead has no reason to. Measured 2026-09-09: a session started with `--dangerously-load-development-channels` got no consumer for 32 minutes, and four pollers emitted into nothing, one of them a `checks_failed` event on an open pull request -- every instrument was right and none was asked. `channel:stranded` is deliberately not `channel:health` run early: `health` is `acts`-classed because its bound path spawns `claude mcp get` (#1558's own shape, one layer worse inside a SessionStart hook), and it answers about the socket *right now*, when at session start the consumer may not have bound yet. `stranded` instead reads only what the pollers' own state files already recorded -- `last_emit.state == "no-listener"` -- needing no socket, no network and no subprocess, and is silent whenever there is nothing to say (a delivering channel and a channel nobody watches both print nothing), since this runs on every session of every user of this plugin. Wired into `hooks/session-start.sh`'s existing `onboard()` call. Scoped narrower than the issue's own three suggested remedies (un-disable `.mcp.json`, re-register `oss-channel`, fix the `--dangerously-load-development-channels` flag's name) -- those are about the actual MCP wiring, which is outside this repository's control; this closes the "nobody notices" half instead, which is.
