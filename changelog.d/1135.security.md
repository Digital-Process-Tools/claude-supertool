- **`around`'s colon route no longer reads a file outside cwd through its pattern slot** ([#1135](https://github.com/Digital-Process-Tools/claude-supertool/issues/1135)). `_PATH_ARG_POSITIONS["around"]` is `(2,)` because parts[1] is a PATTERN and parts[2] is the path, and dispatch checks containment from that table. The `around_line` delegation added in 0.29.0 re-reads parts[1] as a filename and runs *after* that check, so the same file got two answers: `around:localhost:/etc/hosts:1` was refused and `around:/etc/hosts:3` was read. LINE is free and N is caller-chosen up to the 16 KB cap, so the window walked the whole file. Relative traversal behaved identically.

  **The check went in at the moment of promotion, not into the table.** parts[1] is a pattern in every other reading, and adding slot 1 to `_PATH_ARG_POSITIONS` would refuse `around:/etc/passwd:code.py` — searching a repo for an absolute path string, which is not reading one. The slot only becomes a path conditionally, so the guard is conditional too, and it uses the same `_containment_error` every other route calls rather than a second copy of the rule. `around` was checked against the rest of dispatch and is the only op that promotes an argument to a filename after the gate; `between`'s numeric hint probes parts[1] with `os.path.isfile` but only to choose error text, and is filed separately.
