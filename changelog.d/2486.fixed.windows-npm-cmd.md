- **The channel's auto-install now spawns npm through a shell, so a fresh Windows plugin install can start it** ([#2486](https://github.com/Digital-Process-Tools/claude-supertool/issues/2486)). `start.mjs` called `spawnSync("npm", ...)` with no shell. The executable on `PATH` on Windows is `npm.cmd`, and `CreateProcess` cannot execute a `.cmd` whatever `PATH` holds -- naming `npm.cmd` explicitly raises `EINVAL` rather than fixing it. So the auto-install that closed #2486 everywhere else failed on every fresh Windows install, and the channel never started: the exact failure #2486 set out to close, still open on one platform. The args are a fixed, static list with no metacharacters, so `shell: true` adds no quoting surface here. `tests/test_channel_dependency_2486.py` gains the positive control it was missing -- it asserted only that a failed install names its remedy, which an install that never spawned npm also satisfies, so on Windows it had been passing through the unreached arm.
