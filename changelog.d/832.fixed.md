- **A baseline nothing measured is no longer printed as a baseline that measured zero.** `phpunit-mcp` reported `0 → 7  (+7) ✗` after an edit that introduced nothing — all seven tests were already failing because the local test database was missing a table — and the reporter nearly reverted a correct fix on the strength of that `0 →`. The mechanism is not phpunit's: `_drain_validator_queue` calls `_validator_render_diff(None, data)`, because the **slow tier by design runs no baseline pass at all**, and `before.get("count", 0) if before else 0` turned that `None` into a literal zero. So every `"tier": "slow"` validator reported every pre-existing failure in the repo as a regression the current edit had caused, on every run. Same arithmetic as [#969](https://github.com/Digital-Process-Tools/claude-supertool/issues/969), one caller over: an absence given a number and subtracted as though it were a measurement.
- **The row now reads `? → 7   ✗ (baseline not measured)`.** Three states on the left of the arrow, not two: measured, measured-and-non-zero, and not measured.
- **The delta and the `+` prefix went with it, because they are the same subtraction in two more columns.** Seven minus an unmeasured baseline is not `+7`, so no `(+N)` is printed; and the per-error `+ ` prefix means "introduced by this op", which every finding qualifies for when the set it is diffed against is empty. Fixing only the arrow would have moved the false number rather than removed it.
- **The quiet half: a clean slow-tier run claimed `(no new errors)`.** Zero equalled the fabricated zero, so it took the equal-counts branch and asserted a comparison that never happened. It reads `? → 0` too. This is the one that would have survived a fix aimed only at the loud case.
- **The marker is deliberately unchanged.** The file does have those errors now, and nothing measured whether it did before — so the row states what it knows and softens nothing. Turning `✗` into a shrug because the baseline is unknown would trade this bug for the one where a real regression reads as pre-existing, which is the trade the whole "three states" rule exists to refuse. Rollback semantics are untouched; the slow tier does not roll back at all.
- **A measured baseline still gets real arithmetic.** The fast tier runs a genuine pre-op pass, and `0 → 7`, `(pre-existing — not from this edit)` and `(no new errors)` all still mean exactly what they say there.
