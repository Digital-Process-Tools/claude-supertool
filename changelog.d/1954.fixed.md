- **`map` now shows a class's parent and interfaces instead of dropping them** ([#1954](https://github.com/Digital-Process-Tools/claude-supertool/issues/1954)). A subclass with two methods of its own and a parent supplying the rest used to render as a small standalone class -- nothing in the output said otherwise, and the trait/`use` list already shown made it worse by looking complete. `class Foo < Base, IA, IB  [42-73]` now appends the hierarchy to the class's own line, one neutral `<` for every language rather than a language-shaped `extends`/`implements`, so a mixed-language map reads consistently. Covers both tiers that carry the gap: tree-sitter (PHP `base_clause`/`class_interface_clause`, Python's `class_definition` argument list minus `metaclass=`, TS/JS `class_heritage`, Java `superclass`/`super_interfaces`, Ruby `superclass`) and the regex tier that runs whenever tree-sitter is unavailable. A wide interface list is capped at 4 names with `, +N more` said rather than a shorter list that silently claims completeness. The ctags tier carries the same gap and is not addressed here -- see the PR for why.
