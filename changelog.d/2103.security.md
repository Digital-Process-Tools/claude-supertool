- **`gl-pipeline:ID:traces` handed `write_traces` a job id validated only with a display neutraliser, not a path check** ([#2103](https://github.com/Digital-Process-Tools/claude-supertool/issues/2103)): `write_traces` (`presets/gitlab/job.py`) builds `job-<id>.log` and joins it onto the traces directory with no check of its own; `gl-job:ID:trace` already validated its ids through `_job_argv.refuse_job_ids` before reaching that writer, but `gl-pipeline:ID:traces` (`presets/gitlab/pipeline.py`) only ran ids through `_untrusted.flat`, which leaves a traversal string like `../../../../tmp/pwned` byte-for-byte unchanged. The always-present `job-` filename prefix means the specific traversal string this issue named does not, in practice, resolve to a path outside the traces directory -- the OS requires the intermediate `job-..` segment it produces to already exist as a real directory, and `open()` fails with `ENOENT` rather than escaping -- so this closes an exposure that could not be demonstrated to succeed with that shape of id, verified by attempting the write directly with the guard removed. `write_traces` now refuses any non-digit id before building a path or fetching anything, for every current and future caller, rather than depending on that filename-prefix accident to keep holding.
