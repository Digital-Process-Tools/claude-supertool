- Four of the git ops declare what raw `git` invocation they supersede, so the shipped `PreToolUse` guard covers `git` as well as `gh` and `glab` ([#1384](https://github.com/Digital-Process-Tools/claude-supertool/issues/1384)). `git status`, `git commit`, `git push` and `git worktree list` are refused in favour of the op that answers them, with `--force-with-lease`, `--no-verify` and `-u` selecting which spelling of `git-push` the refusal names. Two of the three commands #1384 measured as allowed-and-silent are now blocked.
- The shapes of those commands that no op answers are left running on purpose, because the only way past a wrong block is `raw_command_guard: false`, which disarms every mapping in the repository: `git push --tags` / `--follow-tags` / `--delete` / `--force`, `git commit --amend` / `--fixup` / `--squash`, and the machine-readable `--porcelain`, `-s`, `-z` forms of `git status` and `git worktree list`.
- Two limits of the mapping schema are documented rather than papered over. `git push origin <tagname>` **is** blocked: it is discriminated by the value of a positional, which no `unless_flag` can express, and `--tags` is the flag-shaped route past it. `git -C <path> <subcommand>` reaches no mapping at all, because `argv` matches a contiguous token prefix and `-C`'s value sits inside it; `cwd:PATH` is the op-side answer. Nine git ops declare nothing, each for a reason recorded in `docs/presets/git.md`.
