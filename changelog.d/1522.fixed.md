- **Three renders put somebody else's text at column 0 — a watch note, a job step name and a verbose validator message** ([#1522](https://github.com/Digital-Process-Tools/claude-supertool/issues/1522)). A value from outside supertool was interpolated into a render without `_untrusted.flat`, so an embedded separator wrote a whole line where the tool's own structural lines live. `presets/_untrusted.split_lines` was not the seam for any of them: it splits on LF/CR/CRLF *by design*, because it is the parser-side helper (#1081), and U+2028/U+2029/U+0085/VT/FF are exactly what walked through in #1470. It is unchanged. The fix is flattening at each render.

  The reproduction: a newline in `SUPERTOOL_WATCH_SOCK` forged a second `watches: ...` row claiming everything was fine. The sweep found the class was wider than the three instances filed — the same two environment variables reach nineteen interpolations across `naming`, `channel`, `transport`, `dispatcher` and the `gh-prs` tier — so `naming.flat_path` is one seam all of them now use. It takes `disclose_newline=True` (#1557): a path can contain a newline and rendering it as a space names a directory that is not on disk. The values used to `connect()` and to `listdir()` are untouched — flattening a path before *using* it would be a different defect.

  `presets/github/run.py` flattened a failed job's name cell and not the step names printed under it, which are whatever the branch's own CI config called them. `op_format(verbose=True)` rendered an adapter's `msg` with `.strip().replace(newline, " ")` — one separator out of the ten `str.splitlines()` breaks on, and a lone carriage return returns the cursor to column 0 without making a line at all — where every sibling render already used `_flat_cell`.

  Found while testing that last one and fixed with it: `_formatter_render_row` interpolated the adapter's `name`, `raw` and `msg` into its own row with no flattening whatsoever, and cut `msg` at 120 characters with no marker, so a message that ended there and one that was truncated read alike. The validator twin has routed all three through `_flat_cell` since #895. `raw` keeps its lines — it is a block, and the reader asked for the tool's output verbatim — but every line after the first is now indented under the row.
