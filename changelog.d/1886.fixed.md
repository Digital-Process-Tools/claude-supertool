- **`docs/validators.md` and `validators/git-status/README.md` documented `SUPERTOOL_GIT_TIMEOUT` as if it had one default; it has three** ([#1886](https://github.com/Digital-Process-Tools/claude-supertool/issues/1886)). The same env var is read at `presets/git/status.py` (5s, courtesy calls that write nothing), `presets/git/_git_common.py` (10s, six other presets), and the `git-status` validator (15s, has to survive four sequential calls on a cold repository). Exporting the variable moves all three together, which is intended, but the docs stated one of the three as *the* default. Both files now name all three and why they differ.
- **Unifying the three was considered and deliberately deferred** ([#1886](https://github.com/Digital-Process-Tools/claude-supertool/issues/1886)). Each default is already justified inline at its own call site by the engineer who chose it, and each budget answers a different question — interactive latency for a courtesy line versus surviving a cold repository for a validator that blocks an edit. The prerequisite for collapsing them into one number is a cost nobody has measured yet: what a `git status` actually costs on a large cold repository, beyond the single >15s data point [#1882](https://github.com/Digital-Process-Tools/claude-supertool/issues/1882) reported. Correcting the docs to state the three real defaults is this change; picking one number for all three is not.
