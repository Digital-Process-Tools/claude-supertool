- **`git-commit` gained a hook-bypass route: `:::--no-verify` / `no_verify = true`** ([#2205](https://github.com/Digital-Process-Tools/claude-supertool/issues/2205)). A 3700-file merge commit died on the op's 30s hook-timeout cap, and the failure receipt's own advice — `git commit --no-verify -m '...'` — was exactly what the raw-command guard refuses, with no route through supertool to the bypass it was itself recommending. `--no-verify` is now a token in the PATHS position on the colon route (`git-commit:::MESSAGE:::--no-verify`, alone or beside real paths / `--all`) and its own field on the @payload route (`no_verify = true`) — refused by being absent, same posture as `git-push:no-verify`. When it fires the receipt's header prints `HOOKS SKIPPED` before anything is staged, so a skipped commit can never be mistaken for a checked one; an ordinary commit's receipt is unchanged. The failure receipt's bypass line now names this route instead of the raw `git commit` command the guard refuses.
