- `gh-branch`'s verdict sentence now agrees with the number of workflows it is talking about ([#841](https://github.com/Digital-Process-Tools/claude-supertool/issues/841)). It read "nothing has failed, but CodeQL, tests **has** not concluded on d6cf7a4, so **they are** neither a pass nor a fail" — a singular verb and a plural pronoun over one subject, in the line a maintainer reads at every merge gate. The pronoun half was already count-aware and the verb half was left hardcoded, so the two disagreed on every commit with more than one workflow moving.

- The sibling sentences #841 asked to be checked were wrong the same way, and are fixed with it: "the job list for A, B did not come back" is now "the job lists", and "A, B ran on the previous head and has no run" is now "have no run". Every count-dependent word in the verdict now comes from one helper instead of its own inline conditional — two independent conditionals over one count is a disagreement waiting to be written.
- Found while reviewing the above, in the clause appended onto that same rendered line: `scope_clause`'s UNESTABLISHED arm read "so whether these 1 are all of them is UNKNOWN" whenever a single workflow had produced a run on the commit, which is an ordinary case rather than an edge one. It now names the noun as well as the count — "whether this 1 workflow is all of them" — because fixing the agreement alone would still have left the reader guessing what was being counted.
