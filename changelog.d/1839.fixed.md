- **`literal_backslashes` accepts a per-field list, so one payload can write fields that disagree about escapes** ([#1839](https://github.com/Digital-Process-Tools/claude-supertool/issues/1839)). The flag was payload-wide only: `= true` exempted every field, and the one caller who wanted a doubled run taken literally in `new` while a `content` field in the same batch still meant a doubled backslash had no way to say so short of splitting the payload. #1096's own docstring argued against a per-field key, but the argument was about a key placed INSIDE an `[[ops]]` table, scoped by op *position* — which the doubled-backslash scanner genuinely cannot verify, since op boundaries are a line-counting heuristic over the raw source rather than a fact. `literal_backslashes = ["new"]` is a different shape: a top-level list matched against the bare field NAME the scanner already carries on every finding (`new`, `content`, ...), with no op-boundary heuristic involved at all, so the earlier objection does not apply to it. It still does not solve two OPS that both carry a `new` field and disagree with each other about that field's own intent — that payload is still two payloads, exactly as #1096 said.

  The refusal message now builds its suggested `literal_backslashes = [...]` from the fields it actually flagged, in the order it found them, so the way out is something to paste rather than to adapt. `docs/input-forms.md` and `docs/operations/edits.md` are updated with the list form and a refreshed refusal transcript.
