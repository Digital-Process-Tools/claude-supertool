- **`cargo-check` asks cargo which file a diagnostic names instead of guessing from the path's tail** ([#1045](https://github.com/Digital-Process-Tools/claude-supertool/issues/1045)). A package at the workspace root is printed by cargo as `src/lib.rs`, and every workspace member's absolute path ends with those same two segments — so the root package's pre-existing error was charged to the member file under validation, keeping its real rustc code, and `rollback_on_fail` reverted a correct edit over it. Raising the two-segment floor from [#1037](https://github.com/Digital-Process-Tools/claude-supertool/issues/1037) again could not have fixed it: the two strings are identical and what tells them apart is the workspace layout, not the path.

  So the layout is read rather than inferred. Cargo prints a relative diagnostic path relative to the **workspace root** — to that root whichever directory it was invoked from — and prints anything outside that root as an absolute path; `cargo metadata --no-deps` reports the root without resolving the dependency graph, so it touches no network and pays for no build, and it is only called when a run has diagnostics to attribute. Anchoring the relative case to that root resolves every diagnostic path to exactly one absolute file and the comparison becomes equality, with no suffix, no floor, and no tie to break. The two-segment floor's accepted cost goes with it: `build.rs` and other files at a crate root were always non-verdicts and are now simply decidable.

  Attribution has three outcomes, and the new one is the point. "This file" is a finding; "another file" is reported in full by its own path, unplaced, as before; and **"the workspace root could not be read" is now a distinct non-verdict that says so** — naming the path cargo gave and why the root is missing, rather than claiming the diagnostic belongs to some other file. A relative path with no root under it is a real path in every package in the tree, so declining to name one is the only honest answer. Every way the lookup can fail is a reason rather than a crash, including a spawn failure that only Windows raises.
