- **`git-commit`'s no-PATHS refusal now names the cause, not the index** ([#1155](https://github.com/Digital-Process-Tools/claude-supertool/issues/1155)). `ERROR: nothing staged.` is a true statement about the index and a useless one about the call: what the caller did was leave out the argument that fills it. Three people hit it in one day, all concluded the `@payload` route's `paths` key was the missing ingredient, and all three were wrong — the colon route stages identically, multi-line message included.

  The opening line is now one of four, and which one you get says which mistake was made: `no PATHS were given — git-commit never stages for you, so nothing staged`; `nothing staged — the N path(s) you named held no changes to stage`; `nothing staged — the working tree is clean, so there is nothing to commit`; or `nothing staged, and what is unstaged is UNKNOWN` when `git status` did not answer. Everything below it — the dirty listing and the pasteable remedies — is unchanged.

  It has to be the *first* line rather than merely present. supertool's `--- op ---` header replays the whole op string, so on a commit message of the length this repo writes, every line after the first sits below a wall of the caller's own prose. Suppressing that echo is [#946](https://github.com/Digital-Process-Tools/claude-supertool/issues/946) and lives in the core dispatcher, not in this preset.
