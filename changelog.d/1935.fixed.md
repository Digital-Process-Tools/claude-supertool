- **The four warm MCP adapters now send an unpredictable per-call request id, and `ndjson_scan.py`'s docstring no longer overstates the gap that leaves open** ([#1935](https://github.com/Digital-Process-Tools/claude-supertool/issues/1935)). `phpunit-mcp`, `phpstan-mcp`, `phpmd-mcp` and `rector-mcp` all awaited the literal `id: 2` on every call — a value fixed and identical across every invocation, so a process able to write noise onto the daemon's stdout could forge a matching frame without observing a single byte of real traffic. Each adapter now sends `random.randrange(2, 2**32)` per call and awaits that value instead — excluding `1`, the `initialize` frame's own fixed id sent first on the same connection, since a collision there would have made `find_response` (first match wins) silently return the `initialize` result instead of the real one. The module docstring's claim that "nothing short of an authenticated transport closes that gap" was true of the old fixed id and is no longer the honest description of the residual: what remains is narrower — a forger that can *observe* the id off the wire (a process sharing the daemon's stdout, a debugger, a log line) can still match it, since nothing here authenticates the transport itself.
