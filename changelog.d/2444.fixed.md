- **`help:gh-issue-comment` no longer tells a caller to send an `args` payload the op refuses outright** ([#2444](https://github.com/Digital-Process-Tools/claude-supertool/issues/2444)). `gh-issue-comment` takes a named-field payload (`body`/`body_file`/`repo`) it parses itself, one of the ops `repo_target: "payload"` already marks as owning its own shape — but `_at_file_payload_hint`, the function that renders `help:OP`'s `Payload route --` block, had no branch for that population and fell through to the generic args-list hint #1165 added for a different one, printing `args = [...]` for an op whose own loader answers `ERROR: gh-issue-comment payload carries unrecognised key 'args'` for exactly that shape. A new registry, `_PRESET_NAMED_PAYLOAD_FIELDS`, is checked first and renders the op's real keys; `tests/test_gh_issue_comment_help_text_2444.py` pins the shipped help text and pins the registry against the op's own `ACCEPTED_KEYS` so the two cannot drift apart the same way again.
