- **Four refusals held the answer to the round-trip they cost** ([#1334](https://github.com/Digital-Process-Tools/claude-supertool/issues/1334), [#1372](https://github.com/Digital-Process-Tools/claude-supertool/issues/1372)). A receipt owes `what happened / proof / what is next`, and these dropped the third column while already holding it. `edit`, `replace_lines`, `vim` and `replace` on a path that is not there now name the two ops that create one; `grep`'s LIMIT-0 refusal names a spelling for each of the two readings it declines to guess between; the `edit:@-` payload route says the file is missing rather than naming a field no value of which could have worked.

  **`edit` never reached the shared not-found helper at all.** #1372 designed its suggestion around the `tried:` line #1300 added, on the premise that it was already printing. It was not: `op_edit`, `op_replace_lines` and `_op_vim_impl` each returned a bare `f"ERROR: file not found: {path}"`, so three of this repo's mutating ops had neither the absolute path that separates a typo from a drifted cwd nor the `exists at <root> — prefix with cwd:` branch. They route through `_path_not_found` now, which is what makes naming a creating op safe rather than a guess.

  **The clause fires on one arm and is suppressed on the rest.** `file not found` from a write op has two causes and only one wants `paste`: a caller who meant to create, and a caller who typo'd a path to a file that does exist — for whom taking the suggestion writes a second file and leaves the real one unedited, which is [#1424](https://github.com/Digital-Process-Tools/claude-supertool/issues/1424)'s `misdirects` class and strictly worse than the refusal. So it renders only on the generic `wrong CWD?` fallback, never where the helper has positively identified a different mistake (cwd drift, `around`'s digit-path heuristic, a comma or whitespace path list, an unexpandable `~user`), and both readings are stated rather than one chosen. Read ops never pass it: nothing was to be written, so there is no next step to name.

  **`grep:PATTERN:PATH:0` said it would not guess between "unlimited" and "the default" — and gave a spelling for neither, while the op accepts both.** `all` has been the unlimited token since [#1328](https://github.com/Digital-Process-Tools/claude-supertool/issues/1328) and went unnamed by the one message whose reader is asking for it. The default is now printed as a number, resolved at call time from `grep.max_results` rather than frozen at import, so a project that overrode the cap is told its own cap instead of the shipped constant.

  **Adjacent, found while writing the clause: a directory was reported as a missing file.** `edit:::a:::b:::docs` answered `ERROR: file not found: docs` about a directory sitting right there, and every line after it — the cwd-drift hint, and the new create clause, which would have offered to `paste` a whole file over it — was advice about a path that is not the problem. `_path_not_found` had two states where it needed three; exists-but-wrong-kind is neither `ok` nor gone. It now says so and points at `ls:` / `tree:`. Every op that shares the helper gains it, `read` included, whose own test had been pinning the wrong sentence.

  **The payload clause stats behind the containment gate, which the first commit did not.** `_missing_field_create_clause` is reached from `_at_file_to_parts`, which runs *before* dispatch applies `_op_path_gate` — so "there is no file at X" would have differed by whether an out-of-boundary file exists, for exactly the paths every other route refuses to answer about. Raised by an independent review of the committed diff and fixed through `_containment_error` rather than a second copy of the rule ([#882](https://github.com/Digital-Process-Tools/claude-supertool/issues/882) is the filing about what a second copy costs). The test drops the suite-wide `SUPERTOOL_ALLOW_OUTSIDE_CWD=1` and asserts the two receipts are byte-identical.

  **There is no registry-derived route to these names, and the honest answer was a hand-written table with a test.** `replaces` — the registry key the raw-command guard quotes so its advice cannot go stale ([#1376](https://github.com/Digital-Process-Tools/claude-supertool/issues/1376)) — maps a raw *shell command* onto an op, and only preset and project ops carry one. Every substitute named here is a built-in, and a built-in has no registry entry: `registry:paste` says so in as many words, and `help:paste` reads `.supertool.json` and returns nothing outside a project. So `_CREATING_OPS` is written by hand beside `_OP_SYNONYMS`, and one test enumerates both against `_valid_op_names()` and fails the day a named target is renamed or dropped.
