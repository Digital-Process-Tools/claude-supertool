- **A changelog fragment's own content could forge a release heading and hijack the link refs of the file it was assembled into** ([#923](https://github.com/Digital-Process-Tools/claude-supertool/issues/923)). `assemble_changelog.py` inserted `frag.path.read_text().strip()` verbatim and validated filenames only, so a line at column 0 in a fragment became that line in the published `CHANGELOG.md`. A `## [x.y.z]` line became a real release heading — reparenting every entry below it, and becoming what `_anchor()` finds on the *next* cut, past a duplicate-heading guard that runs before insertion and so cannot see it. Separately, `_rewrite_links()` returned on its first `[Unreleased]: .../compare/v...HEAD` match anywhere in the document; fragment bodies land near the top and the genuine link refs are at the bottom, so a fragment carrying that line was matched first and the shipped tag ref was written against a base URL the fragment chose while the real compare link never advanced. The receipt printed `ok` for both, and the damage was durable: the injected line survives into the released file and matches again next time.

  **The trigger that mattered was not the hostile one.** A fragment whose prose contains a fenced code block with an unindented heading does this by accident, and entries here quote headings constantly — [#839](https://github.com/Digital-Process-Tools/claude-supertool/issues/839) and [#887](https://github.com/Digital-Process-Tools/claude-supertool/issues/887) both do. The three fragments live at the time carried none, so nothing shipped corrupted; the hazard was the next fragment anyone wrote.

  **Two fixes, at two layers.** `collect()` now reads every fragment body and refuses one carrying a column-0 Markdown heading, `[Unreleased]:` or `[x.y.z]:` line, naming the file, the line number and the line — in `--check`, so it fails on the PR where the author is standing, and in `--count` and the release path, which share the same function. And `_rewrite_links()` is scoped to the trailing block of link-reference definitions rather than the first match anywhere, which fixes the second half on its own merits: a document that already carries a stray compare-link line above that block, from a bad cut or a quoted example, no longer steers the rewrite.

  **The rule is positional, not fence-aware, deliberately.** Nothing downstream understands fences — not `_anchor`, not `_unreleased_span`, not git's merge driver — so a fence parser here would bless exactly the lines that still corrupt the file for every other reader, and would have to get nested and tilde fences right to do it. Column 0 belongs to the assembler; a fragment's own lines are indented. That is what the fragment format already asked for — one bullet plus its indented paragraphs — so the escape hatch for quoting a heading in prose is to indent it, and an indented line is genuinely inert to every one of those readers rather than merely permitted.
