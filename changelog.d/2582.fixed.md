- **A pinned `xfail(strict=True)` XPASSed on every CI leg, reddening master** ([#2582](https://github.com/Digital-Process-Tools/claude-supertool/issues/2582)). `tests/test_changelog_fragment_self_reference_1251.py::test_a_fragment_that_never_names_its_own_issue_is_refused` documented that the upstream `oss` plugin's `.oss/assemble_changelog.py` (`self_reference_finding()`) did not name issue #1251 the way this repo's own copy did (#2489). Commit `f0323829`'s `/oss:scaffold` refresh pulled in an updated copy that now embeds the literal URL `.../issues/1251` in the finding text, so the loose `assert "1251" in message` started passing -- an unexpected pass that `strict=True` turned into a hard failure on 4 of 16 `tests` legs. The `xfail` marker is removed and the assertion tightened to a digit-bounded regex (`re.search(r"(?<!\d)1251(?!\d)", message)`), the same shape `test_a_longer_number_containing_this_one_is_not_a_reference` already uses to guard #1192, so a future regression to a merely-coincidental digit run would fail again rather than pass silently.
