- `presets/oss/shim.py` and `presets/oss/tick.py` now carry the exception's own reason through the three except-arms that previously discarded it: `_load_record`'s `except (OSError, ValueError): return {}`, `_install_roots`'s `except OSError: return []`, and `tick.state_file`'s `except OSError: return None, "{} not found"`. A genuine read/parse failure -- an unreadable or corrupt install record, a permission-denied cache root, a `.oss.local.json` that exists but cannot be read -- rendered identically to "legitimately not installed"/"legitimately not resolved"/"legitimately not found", which sent a maintainer whose plugin *is* correctly installed down `tick.py`'s reinstall-it `NEXT:` line ([#2638](https://github.com/Digital-Process-Tools/claude-supertool/issues/2638)).
