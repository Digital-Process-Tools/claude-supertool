- **Three CI tests stopped paying for a clock they never needed to wait on** ([#2227](https://github.com/Digital-Process-Tools/claude-supertool/issues/2227)). None were slow because they tested something big:

  - `test_loopback_is_still_open_on_the_widened_routes[<lambda>2]` called `socket.getnameinfo(("127.0.0.1", 80), 0)`, which on a GitHub runner spent 35s on a reverse DNS lookup the test was already prepared to ignore (`except OSError: pass`). It now passes `socket.NI_NUMERICHOST`, which proves the same thing — the netblock guard does not refuse loopback — with no resolver round trip.
  - The four slowest tests in `test_git_timeout_disclosure_650.py` set a 1s git budget and drove a real stalled `git` through a PATH shim. The shim ran `sleep 300` as a foreground child of its own `/bin/sh` script rather than `exec`ing it, so killing the script left the `sleep` running, holding the inherited pipes open, and `_stop()`'s SIGTERM-then-SIGKILL grace both blocked for their full 2s each — nearly 5s of dead weight per stalled call, on top of the 1s budget, paid again for every subcommand the fixture shares the stall with. The shim now `exec`s the stall directly, so the process `subprocess.Popen` is watching is the one that dies on signal, the same as a real, well-behaved `git`.
  - `test_no_file_in_this_checkout_names_a_pending_fragment` matched every line of every tracked file against one compiled pattern per pending changelog fragment. A single combined pattern now checks a file's whole text once before the untouched per-line/per-pattern pass runs, so a file matching none of the pending fragments — nearly all of them — is skipped without a per-line scan.

  All three keep exactly what they were guarding against — a stalled git call rendered as success, the egress guard closing a hermetic test server, a changelog fragment referenced by a file the next tag deletes — verified by reintroducing each underlying defect and confirming the test still catches it. Measured on this checkout: the four `test_git_timeout_disclosure_650.py` tests fell from ~46s combined to ~10s, and the changelog scan from 7.7s to 1.3s.
