- **`supertool-no-cut` stopped firing on the commonest pipe there is** ([#1426](https://github.com/Digital-Process-Tools/claude-supertool/issues/1426)). Anchoring the pattern to command position also started requiring whitespace before the bar, so `supertool 'grep:x' | head` matched and `supertool 'grep:x'|head` did not — blocked before, silent after. That narrowing is disclosed nowhere: the fragment claimed three and named a different one, so read it as unintentional. The bar may now sit against whitespace **or** a closing quote, which is what a shell leaves there; a bar inside the op's own argument (`gh-job:9:grep:head|tail`) still has a bare letter to its left and is still ignored.

  The suite could not see it. `tests/test_jit_block_match_anchored_1415.py` defines `PIPE = " | "` and all ten fire cases used it, so nothing in 8,400 tests discriminated the space. Four cases now put the bar hard against the quote.
