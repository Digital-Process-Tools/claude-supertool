- **The core's own 36 `str.isdigit()` sites, which #1727's sweep never reached — two classes of character, and the quiet one was writing to files** ([#1748](https://github.com/Digital-Process-Tools/claude-supertool/issues/1748)). [#1727](https://github.com/Digital-Process-Tools/claude-supertool/issues/1727) replaced the test at 11 sites under `presets/`; `_supertool.py` was outside that lane and held 36 more, every one of them reachable from a plain op string.

  The loud half is the one the issue names. `str.isdigit()` is True for `²` (U+00B2) where `str.isdecimal()` is False, so `int()` raises — `around:PAT:F:²`, `around:PAT:²`, `grep:PAT:F:²`, `between:F:²:3`, `vim:F:²j` and `vim:F:>²j` all came back as `ERROR: argument parsing: invalid literal for int() with base 10: '²'`. That is a refusal, but only by accident of a catch-all two thousand lines away, and it names an interpreter builtin instead of the argument slot.

  The quiet half is worse and was not filed. `٢` (U+0662 ARABIC-INDIC DIGIT TWO) is `isdecimal()` too, so `int()` converted it and every one of those ops ran — `around:PAT:F:٢` rendered a 2-line window, `grep:PAT:F:٢` capped at 2 results, and `vim:F:٢jx` **edited the file** and printed `1. 2j` back in its receipt, a number the caller can neither match to what they typed nor find in their own command. A crash test cannot see that class: the two runs were byte-identical.

  All 36 now go through `_is_ascii_int`, an anchored `^[0-9]+\Z` beside `VERSION` in the core, and a non-ASCII digit is refused exactly like any other non-number — `around:PAT:F:²` and `around:PAT:F:x` produce the same message. The count is what makes this a sweep rather than a gesture, and the 36 partition exhaustively — 36 lines, 37 occurrences, one line carrying two. **10 lines / 8 sites** are the unguarded `isdigit()`-then-`int()` shape the issue names, and 8 is the issue's own figure re-derived: the `between` hint spends two lines on one guard and the vim count parser two more. **18** are index scans that walk a count character by character; they reach no `int()` themselves, but they feed the parsers that do, and one of them is not a parser at all — `<C-a>` scanned the *file's* text, so incrementing a line whose only digit was `٢` overwrote it with `3`. **5** reached `int()` inside a `try`, which closes the raise and not the conversion: they refused `²` with a message about the wrong thing and honoured `٢` in silence. **3** were routing or message-shaping tests that would have disagreed with the parsers once the parsers changed.

  `tests/test_core_ascii_digit_guards_1748.py` guards the file the way `tests/test_ascii_digit_guards_1727.py` guards its eleven — a scan for `.isdigit(`/`.isnumeric(` on code lines, with a positive control for the scanner itself and an assertion that the core actually arrived, because a negative assertion over an empty read passes. The behavioural cases are triples, not pairs: the `²` call must not reach `int()`, the `٢` call must not produce the same output as the `2` call, and the `2` call must work. The first draft compared full stdout and the `--- OP ---` header echoes the op string, so the middle assertion passed against unfixed code — caught by running it red first, which is the only thing that catches it.

  Two things reported rather than done. #1727's own entry above says **"31 code sites remain"** and enumerates eight directories, all of them under `presets/`; it reads as a claim about the whole repository and is what sent a reader past the core. It was folded into this file at v0.45.0, so the published record is left alone — the population it describes is `presets/` only, and this entry is the correction. And `presets/_digits.py` is deliberately not imported here: presets run as standalone subprocesses with only `presets/` on their path, so one shared module would mean either the core importing out of the tree it dispatches into, or every preset paying the core compile cost [#931](https://github.com/Digital-Process-Tools/claude-supertool/issues/931) exists to avoid. Two four-line predicates and a recurrence test over each file was the cheaper duplication.
