- **A live containment check took its exemption list from a documentation table** ([#1277](https://github.com/Digital-Process-Tools/claude-supertool/issues/1277)). `test_every_core_only_key_read_by_a_decision_is_stripped` fails when one of the core's own decisions consults a result key an adapter is free to write. It needs a list of keys that are legitimately adapter-owned, and it used this repo's transcription of `validators/SCHEMA.md`'s adapter table — so the boundary moved whenever that table did.

  Emitting a field and consulting a field are two permissions and only the second is a containment property. They are now two lists: `SCHEMA_ADAPTER_KEYS` stays the doc transcription, pinned to `SCHEMA.md` by #1042's drift guard, and `DECISION_READABLE_KEYS` is what a core decision may read. The relation asserted between them is containment, not equality — deliberately narrower is the legitimate state, and it is the state that was already true.

  The count is the finding: **four** of the nine documented adapter fields — `diff`, `duration_ms`, `file`, `metrics` — were exempt from the check and are consulted by nothing, so the exemption ran four keys wider than the property it stood for. Two guards keep it that way: one fails on any key exempted that no decision reads, one pins the withheld set so that adding a row to `SCHEMA.md` reddens the test instead of silently pre-authorising the next key a decision starts reading.
