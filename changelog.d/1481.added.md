- **CI now lints the files a pull request adds, copies or renames — and nothing else** ([#1481](https://github.com/Digital-Process-Tools/claude-supertool/issues/1481)). An error that arrives already dead was invisible to both existing gates at once. The pytest matrix runs no `ruff check .` step, deliberately: a tree-wide gate reds an unrelated contributor's PR the day the linter ships a new rule, and that cost is paid by whoever pushes next. The post-edit `ruff` validator covers the other side, but only for what an edit newly *introduces* — and a file split, a rename or a new module arrives whole, introducing nothing relative to a baseline it does not have. PR #1473 merged 22/22 green with three unreachable imports in a file it created, every edit to which truthfully reported `ruff : ok (no new errors)`.

  The new `lint-new` job scopes to the diff rather than the tree, so "pre-existing" is not a category the checked paths can be in and a new ruff rule only reds a PR already touching the file. Neither existing gate is reversed.

  **Two things the issue's own body had wrong, re-derived before building.** It states that `F401` is enforced repo-wide; `pyproject.toml` in fact carries a global `ignore = ["F401", "F841", "F541"]` from [#797](https://github.com/Digital-Process-Tools/claude-supertool/issues/797), so a plain `ruff check` of the offending file at `ffe47ed` returns `All checks passed!` — the gate as described would have reproduced the green it was filed against. That ignore was bought against 263 pre-existing findings in files that have a history, so the three rules are re-enabled for paths that do not, and the debt stops growing without anybody paying it down. And the offending file is `R065` in `git diff --name-status -M`, not `A`: a gate scoped to additions alone would have missed the instance it exists for, which is why copies and renames are in the filter. Measured cost of that, rather than assumed: 141 of 902 tracked `.py` files carry one of the three today, so renaming one reds until its author deletes the dead line — on the person moving the file, which is the test `tests.yml` sets.

  **Three states on every run, and the third is the point.** `ok`, a `finding`, and `declined` — an unresolvable base ref, no ruff, a checker that could not start or timed out. An unresolvable base yields an empty file list, an empty file list is one branch from "nothing to check", and "nothing to check" prints exactly like "I checked and it was clean". That equivalence is the whole of #1481 and must not be reproduced by the fix for it, so those arms exit 2 rather than 0. A push, which has no PR scope at all, is named `skipped` rather than left silent.
