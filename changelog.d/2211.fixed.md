- **`jit-index` now accepts the 3-column vocabulary row `claude-jit-context` 0.7.1 actually writes, and the committed `vocabulary/00-manual/00-index.tsv` carries that shape** ([#2211](https://github.com/Digital-Process-Tools/claude-supertool/issues/2211)). `rebuild-tsv.sh`'s vocabulary builder writes `keyword<TAB>file<TAB>verdict` — `verdict` is empty or the literal word `generic`, from the deferred generic-word classifier (#232/#255) that downgrades an entry to its summary when every keyword that matched it is generic. This tree's committed index carried two columns, so regenerating it for an unrelated reason silently widened every row by a trailing tab (the #1992 drift, one dimension over) — a short field reads as an empty one in the consuming awk, so nothing broke, but the diff arrived as noise in whoever's pull request happened to trigger the regeneration. `validators/jit-index/jit-index.py` previously classified any row that was not 6/7 fields (tools) or 2 fields (paths) as a shape error, so a real 3-column vocabulary row could never land through it either. The new branch is keyed on the file's own path (a `vocabulary/` layer, never on row shape alone): a 3-field row is read as vocabulary only under a `vocabulary/` directory, because a hand-truncated tools row missing its last three columns collapses to the identical 3-field shape, and unlike a vocabulary keyword — which is deliberately never handed to awk — a tools row's `match` column is supposed to be checked. Scoped to `vocabulary/00-manual/` only — `vocabulary/01-oss/` is `/oss:scaffold`-owned and replaced wholesale on every scaffold run, so pinning its shape here would fight that tool rather than this one; that loop is a separate, larger decision the issue explicitly defers. `tests/test_jit_vocabulary_index_three_columns_2211.py` pins the committed index's column count going forward, and `tests/test_jit_index_vocab_row_shape_2211.py` pins the validator's new vocabulary-row branch, including that a vocabulary keyword is never fed through the awk pattern checks a paths row's first column goes through (it is matched by a literal `index()`, never `match()`). The documentation for the 3rd column lives in a new, narrowly-scoped `paths/00-manual/vocabulary-index.md` rule (`match: \.claude/jit-context/vocabulary/`) rather than appended to the shared `jit-context.md`, which every session pays for regardless of task and had no headroom left under its own 6000-byte per-session budget (`tests/test_jit_rule_body_budget_1433.py`).
