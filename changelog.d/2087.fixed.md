- **`lsp-diag` no longer reports a hung `supertool diag:FILE` child as a finding about the file** ([#2087](https://github.com/Digital-Process-Tools/claude-supertool/issues/2087)). The MCP layer's own infra messages ("no result from get_diagnostics", "MCP server unavailable") were already correctly `skipped`; the child process itself timing out -- a stuck daemon, a socket that never closes -- was not, and rendered as `{"ok": false, "errors": [{"code": "adapter", "msg": "timeout"}]}`, a definite failing finding from an adapter that never looked at the file. It is `skipped` now, on the same reasoning as the infra messages beside it. The wall is configurable via `SUPERTOOL_LSP_DIAG_TIMEOUT` (default unchanged at 30s). Investigation did not find evidence of an unbounded hang in the reported case -- a direct repro of the reported file answered in ~31s, under this repo's own 60s `py-lsp` MCP timeout -- so the original report's specific shape (get_diagnostics answering nothing after 21s) looks like slow-but-eventually-successful analysis inside `cclsp`/`pyright` rather than a request that never returns; that is upstream of this repo and not something this fix changes.
