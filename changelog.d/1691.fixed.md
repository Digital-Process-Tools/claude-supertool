- **`git-push`'s unattributed-stall receipt no longer leaves a dangling sentence, and the test for it stops colliding with the commit sha** ([#1691](https://github.com/Digital-Process-Tools/claude-supertool/issues/1691)). `test_the_unattributed_recovery_stall_names_no_budget_at_all` asserted `str(push._RECOVER_TIMEOUT) not in out` — the characters `120` absent from a receipt that carries the upstream line — so it reddened whenever the fixture sha contained them, observed on `feature @ 120cb6a`. Roughly a one-in-a-few-hundred red on a suite that runs a 12-leg matrix per PR, and its failure mode reads as a real regression in the budget wording the test names. It could never have meant "no budget figure anywhere" in any case: the receipt's own header prints `Push budget: 600s (:budget — default is 300s)` on every run.

  The assertion now matches the three places `_report_recovery_timeout` actually attributes a stall to a numbered clock, which widens it rather than merely de-flaking it — any number fails it, not just whatever `_RECOVER_TIMEOUT` is this release. Its must-fire pair lives in the neighbouring test, where all three shapes have to be seen, so the empty list means "none quoted" and not "none looked for".

  Writing that pin surfaced a real defect on the arm it covers: with no figure to quote, `allowed is None` dropped the number and nothing else, printing `Retry. If this repo genuinely needs more than to rebase recovery, the budget is ...` to the caller. The unknown clock is a third state, and a third state is a phrase, not an empty string — it now reads `more than the clock it got`.
