- **`between` opened a file the containment gate never saw** ([#1163](https://github.com/Digital-Process-Tools/claude-supertool/issues/1163)). `_PATH_ARG_POSITIONS` gates fixed argument slots, but neither reading of `between` keeps its path in one: symbol mode takes `parts[-1]`, so a symbol carrying a `:` pushed the path to a slot nothing checked, and `between:Foo:barbaz:../outside.py` opened and parsed a file that `between:secret_fn:../outside.py` — the same file, one slot over — refuses. `re:` mode joins `parts[4:]`, so only the fragment before the first `:` was gated; with a directory whose name contains a `:`, that route printed the *body* of a file outside the boundary, not just its existence. Both branches now run containment on the path they computed, at the point they computed it, ahead of the two hints that stat the path to decide whether to fire.

- **A `between:re:` START regex that looked like a path refused a legitimate local slice** ([#1164](https://github.com/Digital-Process-Tools/claude-supertool/issues/1164)). The same table entry from the other side: slot 2 is a path in `between:SYMBOL:PATH` and the START *regex* in `between:re:START:END:PATH`, and one position cannot be right for both — `between:re:/etc/passwd:b:local.py` was refused with a containment error naming a file the caller never asked to open, while `local.py`, the only path in the call, was inside the boundary. `between` is out of the positional table entirely now, so the table describes only slots that are always paths.

- **The `::` claim in the ops listing was not true** ([#1163](https://github.com/Digital-Process-Tools/claude-supertool/issues/1163)). Both operations pages said symbols with `::` "like PHP `Foo::bar`" work. Measured, they do not resolve in PHP, C++ or Ruby: the query is compared literally against a definition's own name node, which is `bar`. Joining the middle parts on `:` still matters — it keeps the call in symbol mode instead of re-reading it as `re:` — and the pages now say that instead.
