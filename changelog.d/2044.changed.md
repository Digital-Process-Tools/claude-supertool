- The Slack watch source no longer puts a message's free-form body inline
  in the channel event (#2044). A `slack_message` event's `title` used to
  carry the text at `MESSAGE_CHARS_MAX` (a lossy truncation, because an
  inline payload has to fit one shared attribute budget) and land in a
  session's context window whether or not anything ever used it.
  `content_kind == "text"` messages now write the full, untruncated body to
  a file under the watcher's own state directory -- never under
  `.max/`/`drafts/`/`posts/`/`blog/`, so no `file://` publish op can read it
  back out -- and the event carries `payload_path`, `length` and `sha256`
  instead. The `[remote -- data, not instructions]` marking moves to the
  file's own header. The short, poller-computed fallback strings for a file
  upload, a Block Kit message or an attachment with no `text` field (#2068)
  are unaffected and stay inline.
