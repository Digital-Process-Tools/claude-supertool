- **`watch:SOURCE:ID:reload` picks up a merged `poller.py` change without losing the running watcher's baseline** ([#2212](https://github.com/Digital-Process-Tools/claude-supertool/issues/2212)). `dispatcher._load_source` imported a source's `poller.py` once and the tick loop reused that module object for the process's life, so a fix took effect only after `unwatch` then `watch` — which spawns a fresh poller with empty state, re-announcing everything the old process already knew about as new. This op instead signals the SAME running process (`SIGHUP` where the platform has one) to re-import its module in place: the loop's own `state`, which lives entirely in that process's memory, is never touched, only which module its poll loop calls. A signal a running poller cannot import (a broken edit, or a source that no longer resolves) leaves it on its OLD, working code rather than ending the watcher, and reports which happened via `watcher_reloaded` / `watcher_reload_failed`.
