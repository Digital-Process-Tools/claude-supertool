- **`gh-prs` and `gl-mrs` discarded a token they could not apply, so a typo returned the whole board as if it were the filtered subset** ([#939](https://github.com/Digital-Process-Tools/claude-supertool/issues/939)). Reproduced live against this repo before anything was changed: `gh-prs:milestone=nonexistent` and `gh-prs:onlygreen` each printed all five open PRs, exit 0, with no warning anywhere in the render. `milestone=` is not even a typo — `gh pr list` has no milestone flag, so the parser accepted the key and the argv builder dropped it. Both ops now refuse: exit 1, no board, every unapplied token named, and the accepted filters and flags listed.

  This is the repo's usual defect class with the sign flipped — not an absence produced by the tool read as an absence in the world, but a *failure to narrow* read as a property of the world. It is the more dangerous direction, because an empty result invites suspicion and a full, plausible board does not. `gh-prs:state=open` is the maintainer tick's own board call, so a dropped filter there is wrong at the exact moment a merge decision is being made.

  **The asymmetry was the argument for the priority.** [#864](https://github.com/Digital-Process-Tools/claude-supertool/issues/864) fixed exactly this for `gh-issues` one release earlier, so two sibling ops in one preset family disagreed about whether a mistyped token was an error or a silent full board — and a reader who learned the refusing behaviour from one would reasonably assume the other shared it.

  **A second silent drop was found on the same lines, on keys that are known.** `state=mergd` failed the `val in _STATES` test, emitted no `--state` flag, and the *open* board rendered as the merged one; `per=abc` reverted to the default page size without saying so. Both now refuse and name the accepted values. `gh-issues` had this half too and #864 did not close it, so `gh-issues:state=opne` returned the open board — fixed here as well.

  **Three answers, not two, and the third one is deliberate.** A token the op has never heard of is refused. A known key whose value the op has no mapping for is refused. A key the op *forwards* — `label=nosuchlabel` — is not: GitHub or GitLab answers it, and an empty board there is the truth. Pre-judging that case would invent a client-side vocabulary that drifts from the server's and would turn a real empty result into an error.

  **One tokenizer, not three.** The parser, the vocabulary check and the wording of both refusals moved to `presets/_filter_tokens.py`, shared by all three boards, rather than being re-derived per op — two independently written refusal paths in one family is how they drifted apart in the first place ([#628](https://github.com/Digital-Process-Tools/claude-supertool/issues/628)). The accepted keys stay per op, because the filter surfaces genuinely differ: `glab mr list` has `milestone`, `source-branch` and `target-branch` flags that `gh pr list` does not, and its states are `opened`/`merged`/`closed`/`all`, so `gl-mrs:state=open` is now refused and told to say `opened`.

  **The radar `gh-prs` tier's own refusal was disarmed by this fix and had to be rewired.** [#859](https://github.com/Digital-Process-Tools/claude-supertool/issues/859) landed a tier that re-derived the same check by hand, over `set(filters) - KNOWN_FILTERS`. Once the op stops putting an unrecognised key into `filters` at all, that subtraction is empty and the tier goes quiet — a fix in one place silently removing the guard in another. It parses through the shared tokenizer now, against its own deliberately narrower vocabulary (`iids` and `failed` are board shapes a radar board must not silently take), and both halves are pinned.

  Both manifests now advertise the full vocabulary, which matters more than it did: with an unrecognised token fatal, the `syntax` string is the only place a caller learns that `assignee=`, `label=` and `per=` were always accepted.

  **The GitLab half is stubbed, not verified.** `glab` was unauthenticated in the environment this was written in, so `gl-mrs` is covered by tests against a stubbed `glab mr list` only. The GitHub half was reproduced live and re-checked live after the fix.
