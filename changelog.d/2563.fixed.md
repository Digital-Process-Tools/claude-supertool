- **`_lock_dir_usable`'s write probe no longer falls back with no lock held on a one-off, transient failure** (#2563). Its own docstring named a transient Windows AV scan on the just-created probe file as a case it could hit, but the function had only one failure path -- any `OSError` on the probe returned `False` immediately, and `serialize_once` treated that the same as `lock_dir` being genuinely, permanently unusable, running `fn()` with no lock held. The probe filename is unique per call (`uuid4`), so contention can never trigger this; only a one-off hiccup or a genuinely broken directory can. It now retries the probe once, against a fresh probe name, after a brief pause before concluding `lock_dir` is unusable -- negligible against the multi-minute `timeout_s` this whole probe exists to avoid spending on a false positive.
