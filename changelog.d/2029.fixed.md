- **The hook-output cap is Claude Code's own constant now, not a guessed midpoint** ([#2029](https://github.com/Digital-Process-Tools/claude-supertool/issues/2029)). `_HOOK_OUTPUT_CAP_BYTES` was 7168, picked as the middle of an empirical bracket its own comment printed — "6.6KB landed full, 11KB+ got truncated". The real value is in the shipped bundle: `k0u = 1e4`, used as the default argument of the function that persists over-cap hook stdout, compared with `<=` so exactly the cap passes. Both original observations bracket it; the midpoint drawn between them was **40% low**. That number is the premise of what every fresh session is shown (`hooks/session-start.sh`) and of the truncation warning `op_ops(compact=True)` prepends, which between 7,168 and 10,000 was warning about a truncation that would not have happened. The comment now carries the source — the constant's name, the enclosing function, the inclusive boundary, the separate 2,000-character preview constant, and the evidence that this is the hook path rather than the far larger `CKr = 50000` tool-result cap.
- **Recorded next to it: the cap is a character count and supertool measures bytes.** `e.length` is UTF-16 code units, and a listing full of `—`, `→`, `⚠` and `✓` spends three bytes per one of those characters, so the byte count over-reports. That is the safe direction — it can only warn or refuse earlier than the harness would — and it stays a byte count deliberately, because a conservative bound survives the harness changing its own unit and a tight one does not. A new `_over_hook_cap()` helper owns the comparison so the inclusive boundary is written once rather than at each call site.
- `tests/test_meta_ops.py::test_ops_compact_warning_when_over_cap` built 40 synthetic ops, a count calibrated by hand against 7168. Correcting the constant left the fixture under the new cap, so the test failed for a reason unrelated to the behaviour it guards. It now derives its op count from the constant and asserts the body really is over the cap before asserting the warning — a fixture calibrated to a constant has to read that constant.
