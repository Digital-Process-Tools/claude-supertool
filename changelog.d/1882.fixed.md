- **A `git-status` validator whose git stalled reported the file as clean** ([#1882](https://github.com/Digital-Process-Tools/claude-supertool/issues/1882)). The adapter wrapped each of its four git calls in a hard-coded `timeout=5` and returned `""` on `TimeoutExpired`; its own parsers read `""` as an answer — `_parse_state("")` is `"clean"`, `_parse_numstat("")` is `(0, 0)` — so a large, cold or network-mounted repository published `ok: true` with a zeroed `metrics` block reading `state: "clean"`, a measurement of a working tree nothing had measured. That is the shape #1202 removed from this adapter's *absent-git* arm; the timeout arm was left behind on the adjacent line, and it fires on every edit rather than only where git is missing. It now declines with `code: "adapter"` — rendered `NOT CHECKED`, never cached, never able to roll an edit back. **`SUPERTOOL_GIT_TIMEOUT` now reaches it** (default **15s**, raised from an unreachable literal `5`), it is one deadline for the whole adapter rather than four in a row, and the registered validator `timeout` moved 5 → 30 so the adapter can state its own decline instead of being killed mid-git by the core — the two were tied at 5, and a tie is a race.
- **A stalled `git-status` validator no longer strands `.git/index.lock`** ([#1882](https://github.com/Digital-Process-Tools/claude-supertool/issues/1882)). `subprocess.run(timeout=)` calls `Popen.kill()` — SIGKILL on POSIX, no grace — so git never ran its own cleanup and the lock it was holding survived it, failing every later `git add`, `commit` and `checkout` in that repository until somebody deleted the file by hand. The stalled child now gets `SIGTERM` and a 2s grace period first, which is long enough for git to unlink its own lockfile, and is killed anyway if it does not go. **The adapter still never deletes a lock itself**, deliberately: it cannot tell a lock it orphaned from one a concurrent `git commit` legitimately holds, and deleting the second corrupts that commit. Windows gets the same grace period and gains nothing from it — `terminate()` and `kill()` are both `TerminateProcess` there — which is a property of the platform rather than a reason to branch on it.
- **That budget is interactive latency, and it is now argued rather than assumed** ([#1882](https://github.com/Digital-Process-Tools/claude-supertool/issues/1882)). Every mutating op blocks on its slowest validator, so raising this adapter's budget from an unreachable 5s to 15s means an edit to a file in a repository whose git does not answer blocks **19s measured** before the decline prints, against roughly 5s before — 5s and a fabricated `state: "clean"`. Roughly 3.4x worse interactive latency on exactly the cold or network-mounted repository the report cites, and it is the direct cost of not lying. `docs/validators.md`, `validators/git-status/README.md` and the `.supertool.example.json` `_doc` now carry the number and the remedy: because a stall is now an honest `NOT CHECKED`, `SUPERTOOL_GIT_TIMEOUT=3` is a legitimate setting for anyone who would rather have a fast decline than a slow measurement — a choice nobody had while the fast answer was a lie.
- **The lock-deletion guard covered four spellings and read as if it covered the class** ([#1882](https://github.com/Digital-Process-Tools/claude-supertool/issues/1882)). The test pinning "this adapter never deletes a lock" walked for attribute calls named `unlink`/`remove`/`rmtree`/`rmdir`, so `os.system("rm -f " + lock)`, `subprocess.run(["rm", p])` and every `from os import remove` spelling walked straight through — 5 of 7 realistic shapes, measured. A green guard read as *cannot delete a lock* while proving *not via four attribute spellings*: this repository's own defect class, inside the test written to prevent exactly that drift. It now resolves from-import aliases, refuses `os.system`/`os.popen` and `shell=True`, and requires every spawn's `argv[0]` to be git. Ten must-fire and six must-not-fire controls pin the branches — two of which exist because those controls failed on the first draft of the widening — and the docstring states the shapes no AST walk can reach rather than implying completeness.
