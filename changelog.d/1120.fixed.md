- **`grep` and `around` refuse a pattern that matches every line** instead of reporting it as a successful search ([#1120](https://github.com/Digital-Process-Tools/claude-supertool/issues/1120)). `grep:\| \{:PATH` returned `1000+ matches` — every line of the file — because supertool's unconditional rewrite of bash-grep BRE alternation turns the escaped literal `\|` into a bare `|`, leaving an empty left alternation branch that matches the empty string. The `:`-tokenizer, the suspected cause, was not involved. The refusal names the pattern that actually ran and the character-class spelling that works (`[|] \{`), and the rewrite is now disclosed on every call where it fires, not only where it saturates. An empty branch nested inside a group (`colo(u|)r`) or a `|` inside a character class is untouched — only a top-level empty branch saturates.
