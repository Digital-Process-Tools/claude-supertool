- **Three registry claims the dispatcher contradicted, and a guard so the next one reddens a test** ([#1245](https://github.com/Digital-Process-Tools/claude-supertool/issues/1245)). `.supertool.json`'s `builtin-ops` is what a machine reads to learn what this binary accepts, and it carried `read-grep` and `grep-count` — documentation for *forms* of `read` and `grep` (`read:PATH:::grep=PATTERN`, `grep:P:PATH:L:C:count`), neither of which dispatches. `.supertool.example.json`, the template users copy, carried a third the issue had not counted: `grep-no-exclude`. Enumerating from the two files rather than from the issue body is what found it.

  All three are kept, because each carries `"hint": true` and its example is what survives `ops-compact` into the SessionStart listing — the one place a non-obvious payload shape gets discovered. They now **declare** what they are: `"form": "grep"` names the op the entry is a spelling of. `_configured_op_names` skips a form entry, and `_build_at_file_registry` no longer derives a `@payload` route from one — `read-grep` had been sitting in `_AT_FILE_DROPPED_ROUTES`, the #770 diagnostic that says "a route was intended here and discarded", reporting about a name that is not an op. `tests/test_registry_matches_dispatcher_1245.py` holds both directions across both shipped configs: a `builtin-ops` key either dispatches or declares a `form` whose parent dispatches and whose `syntax` starts with it.

  **`status` was documented as informational and is not.** `docs/contributing.md`'s op-config schema called it `"experimental"` / `"stable"`, informational only. The code reads it as **truthy**, and a falsy value suppresses the op from `ops`, `ops-compact` and `ops:roster` while it still dispatches — an op that ships, dispatches, and cannot be found. Both documented spellings are non-empty strings, which is why a wrong claim survived. `docs/configuration.md` had it right all along, so the two pages disagreed. The row now describes the gate, and the behaviour is pinned in both directions.

  **The "~40 ops across five categories" claim was already fixed and is already guarded** — no change was needed. `docs/operations/index.md` opens with the real count, and `tests/test_ops_index_complete_1371.py` holds it there along with a phantom-name check on that page.
