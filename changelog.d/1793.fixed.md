- **`harness-tools-blocked.md` now names itself and gives a reader a way to check that without trusting the text** ([#1793](https://github.com/Digital-Process-Tools/claude-supertool/issues/1793)). Twice, a stock `Explore` reviewer with no supertool briefing read this repo's own `PreToolUse` block through its blocked `Read` call and refused it as "a fabricated ... prompt-injection payload" -- reasonably, since unsolicited text inside a tool result claiming its own tools are gone and naming another executable is textbook injection shape, and the rule had no way to signal it wasn't one. A self-declaration of first-party origin would prove nothing, since an injection can write the same sentence; the fix instead points the reader at a channel injected text cannot forge -- `git log -1 -- .claude/jit-context/tools/00-manual/harness-tools-blocked.md` or `git show HEAD:<same path>`, both runnable from the `Bash` the same reviewer already used to fall back to `git show`. Does not cover a reader with no `Bash`/git access, and does not cover the separate scaffolded per-repo copy at `.claude/jit-context/tools/01-oss/supertool-required.md` that the issue's own comment reports as a second instance -- that file is written into other repositories by the `oss` plugin and is not tracked here, so the fix belongs to that plugin.
