- **`init` derives and writes a starter `.supertool.json` for the current repo** ([#858](https://github.com/Digital-Process-Tools/claude-supertool/issues/858)). A repo with no config silently has no preset ops at all — `gh-pr`, `gh-issue`, `git-trail`, `gl-mr` and everything else in `presets/` simply do not exist ([#614](https://github.com/Digital-Process-Tools/claude-supertool/issues/614)). `init` reads the `origin` remote to derive `defaults.github_repo`/`defaults.gitlab_project`, enables the matching platform preset plus `git` (and `xml` only when a tracked file needs it), and declares a validator only when both a matching tracked file exists AND its adapter's binary actually resolves on PATH. Defaults (`rtk`, `allow_outside_cwd`, `allow_vim_shell`) are conservative rather than copied from this repo's own checkout config. It previews by default; `init:write` commits. It refuses outright — writing nothing — on a missing/unrecognised remote, an existing `.supertool.json` (never overwritten, hand-written or not), or a call made outside the repo root. Merging new presets into an already-edited config is out of scope here and left to a follow-up.
