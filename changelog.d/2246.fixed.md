- **GitLab/GitHub job artifact printers now flatten the forge-supplied expiry timestamp through `_untrusted.flat()`, matching the artifact `name` field beside it** ([#2246](https://github.com/Digital-Process-Tools/claude-supertool/issues/2246)). `presets/gitlab/job.py`'s and `presets/github/job.py`'s `print_artifacts` already flattened `name` before printing it, but printed `artifacts_expire_at` / `expires_at` unflattened in the same function. Checked against GitLab's Jobs API docs and CI YAML `artifacts:expire_in` docs, and GitHub's Artifact REST schema (`expires_at`: `string or null, format: date-time`) and `retention-days` input: both fields are documented as computed, typed datetimes derived from a bounded duration/integer, with no documented route for a pipeline author's free text to reach them — so this is hardening for consistency with every other remote-sourced field in these functions, not a fix for a proven injection route.
