- `git-worktrees` decided `[merged]` with `git for-each-ref --merged`, which is an **ancestry** test and cannot see a squash merge ([#1229](https://github.com/Digital-Process-Tools/claude-supertool/issues/1229)). Measured on the live fleet 2026-08-10: of 24 worktree branches, 8 carried the tag and 16 had a merged PR. Worse than a wrong flag — there was no `not merged` column, so a row simply carried nothing, and plain absence reads as unmerged work in the op a maintainer uses to decide which trees are safe to reap.
- The column now has three states per row, each naming the method it was decided by: `merged` (an ancestor of the base, or a merged PR with this head), `not merged` (both consulted, neither said yes), and `merge unknown` with its reason — offline, `nopr`, the lookup failed, or the merged-PR page hit its cap. Rows whose merge state is unknown are counted on the `[result]` line, so the count survives `| tail -1`.
- Ancestry is kept as a **positive only**: an ancestor of the base is merged for certain with no network, which is what keeps `nopr` able to answer `merged` at all. It is never read as a `no`, because that reading is the defect.
