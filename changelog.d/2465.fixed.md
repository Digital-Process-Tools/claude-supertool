- **`tests/test_meta_doc_figures_1783.py` and `tests/test_render_size_claims_1877.py` were already the "derived, not literal" fix #2465 asked for — a regression test now pins that, so the next audit does not have to re-read both files by hand** ([#2465](https://github.com/Digital-Process-Tools/claude-supertool/issues/2465)). The issue's own evidence was four CI-only breaks (#2415, #1822, #1955, and a splitlines-registry hit) where an unrelated op-description change broke these guards, and its preferred fix was to make their pinned figures derive from the live render rather than a literal, "the same fix #1783 already applied to three other stale-figure instances in the same file." Reading both files end to end shows that fix already landed in full: every figure `test_meta_doc_figures_1783.py` checks is computed from `supertool.op_ops()`/`op_ops(full=True)` at assertion time, and `test_render_size_claims_1877.py`'s whole `SITES`/`RENDERS` registry (added by #1877, after #2465 was filed) grades every documented byte/KB figure the same way, normalising away the checkout-path-dependent disclosure rather than hiding drift behind a wide tolerance. What actually broke CI in all four cited instances was never a stale number *in the test* — it was the hand-written prose in `docs/operations/index.md`, `docs/contributing.md`, `docs/operations/meta.md` and `hooks/session-start.sh` going stale, which these already-derived guards correctly caught; no test edit was needed in any of the four, only a doc edit. `test_a_changed_op_description_moves_the_derived_size_without_touching_this_file` (in `test_render_size_claims_1877.py`) manufactures that exact scenario on a private config copy — appends 500 bytes to one op's description, shows the graded `ops:full` size moves by exactly 500 bytes with no change to `SITES`/`RENDERS`/`TOLERANCE_KB`, and shows `_grade` then reports the resulting doc mismatch honestly. `tests/test_preset_twin_splitlines_register_1119.py`, the issue's second named instance, is a structurally different class — an AST register keyed on `path::function`, not a rendered figure — and is not a literal-pin defect: it requires a human judgment call for each new `str.splitlines()` call site by design, which is the point of the gate, so it is left unchanged. The issue's other suggested fix, guard-detection in `lane_setup.py` recognizing "an op description changed" as its own cross-cutting concern, lives in the `oss` plugin and is out of scope here.
