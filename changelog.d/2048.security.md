- **`gh-job`/`gl-job` scrubbed job-log bodies but never fenced them, the one remote-text surface in this repo that carried no boundary** (#2048). `_log_lines` disclosed control characters with `_untrusted.visible()` but every printed excerpt of a CI job's own log — raw, grep hits, the grep no-match fallback, the `:fail`/`:errors` dump, the error-context-plus-tail block, the plain tail, the unmatched-failure tail, and GitLab's `:trace` writer — went to the terminal or to disk with no `_untrusted.open_marker()`/`close_marker()` around it, so a step that echoed a line shaped like this tool's own verdict landed unmarked and indistinguishable from supertool's own output. Every such block in both files is now fenced, with `_untrusted.banner()` printed once ahead of the first one per render, and `_log_lines` now routes each line through `_untrusted.scrub()` instead of `visible()` so a line shaped like the fence markers themselves is neutralised rather than able to forge a close from inside the fence it sits in.
