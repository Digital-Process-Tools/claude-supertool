- **`repo:` reaches `gh-issue-create`, `gh-pr-create`, `gh-pr-edit` and `gl-issue-create`** ([#1909](https://github.com/Digital-Process-Tools/claude-supertool/issues/1909)). These payload-mode write ops used to refuse the whole call outright when a `repo:` op named a target, on the theory that "one place the target comes from" meant one route. It now means one *resolved value*: `repo:` supplies the op's own payload field (`repo`, or `project` for `gl-issue-create`) when the payload is silent, and the op refuses on its own — naming both values and which op each came from — when the two are set and disagree. A single call can now `repo:`-target a sibling repo's board for the reads and file on it in the same batch.
