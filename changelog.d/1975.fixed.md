- **`markdownlint` is registered in this repo's own `.supertool.json`, not just the example config** ([#1975](https://github.com/Digital-Process-Tools/claude-supertool/issues/1975)). Same class as #1795 (`yaml-check`, `actionlint`): the adapter shipped, was tested, matched 82 real `.md` files here, and had never fired on a single edit in this checkout because only `.supertool.example.json` — the template users copy — listed it.

  `rollback_on_fail: false`, deliberately: markdownlint is a style linter over a large body of prose-heavy Markdown here, and its default rule set flags nearly every long paragraph (`MD013`) and every pipe table (`MD060`) in this repo's own house style. A new `.markdownlint.json` at the repo root disables both; the remaining default rules stayed on and found 17 real, specific issues in `docs/validators.md` on the first edit through it (unlabeled fenced code blocks, a stray table column, spaces inside code spans) — left in place rather than fixed here, since the finding is advisory and does not block the write.
