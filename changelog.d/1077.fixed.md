- **`branch.verdict()` can no longer be called without a scope, and radar's default-branch row states the scope it cannot account for** ([#1077](https://github.com/Digital-Process-Tools/claude-supertool/issues/1077)). [#846](https://github.com/Digital-Process-Tools/claude-supertool/issues/846) built `scope_for` as a seam and said why in its own docstring — `presets/dashboard/dashboard.py` and `presets/watch/tiers/gh_prs.py` both call `verdict()` directly, and "a caller that has to remember to compute this will not". The dashboard was wired; the radar tier was not, by the same change. So the disclosure that exists because v0.27.0 was tagged on a commit whose declared workflows had not all run was unreachable from the board that reports the default branch on every tick.

  `scope` is now a keyword-only argument with **no default**. A caller that omits it raises rather than publishing an unscoped green — a default is a reminder, a required argument is a mechanism, and the difference is the whole content of this issue.

  The tier's blank-on-GREEN is where the disclosure was actually being dropped, and it was not simply removed. `scope_for` now returns a third value saying whether the green is bounded, and the tier speaks on a green only when it is not: a declared workflow set that could not be read, or a workflow declaring a **push** trigger that produced no run on the head commit. A `schedule`- or `pull_request`-only workflow producing no run on a push is expected, and on this repo `slow tests` and `changelog` are permanently in that state — so a board that spoke whenever the clause was non-empty would print the same two lines on every tick forever, which is precisely the habituation `scope_clause`'s own docstring says this repo has already paid for twice. The loud/quiet split reuses `_declared_workflows.is_push_triggered`, the predicate the named block already renders on, so the two cannot drift, and an `on:` block that could not be read counts as loud on both sides.

  The tier's `could_tell` moves with it, and that is the part that makes the lines reachable at all: radar's `quiet_when_healthy` discards a healthy tier's entire output, so un-blanking the lines while still reporting healthy would have looked fixed and disclosed nothing to an operator running quiet. It is dropped only against the green — every other state here is a finding, and a finding is something the tier could tell; a green is a clearance, and a clearance over a set of unknown size is not one.

  `gh-branch` itself and the dashboard section are unchanged in behaviour: both still print the full clause and the named block unconditionally, the dashboard being the board a human reads immediately before tagging.
