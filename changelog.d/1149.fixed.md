- **A test drew its subject out of a set by hash order, so about 39% of CI runs went red for a reason unrelated to the branch on them** — `test_help_known_builtin_without_docs` picked `next(iter(_BUILTIN_OPS))`, and one member of that set is a guaranteed loss: `_BUILTIN_OPS` is a shadowing blocklist rather than a capability list, so it still carries `vi` from before the op was renamed `vim`, and `no help for op: vi` is the *correct* answer there ([#1149](https://github.com/Digital-Process-Tools/claude-supertool/issues/1149)). `vi` was drawn in 8 of 200 measured seeds; twelve legs per run, one independent draw each. Nothing about it was platform-specific — it landed on Windows twice by coincidence and reproduces on macOS at `PYTHONHASHSEED=11`, which matters because a single-platform red on this repo is usually genuine and this one had been quietly polluting that signal. The test now sweeps `_valid_op_names()`, which is deterministic and strictly stronger: it fails if the "valid operation here" arm stops covering any single op, which a one-element sample could only catch by lottery.
