- **`grep`, `around` and `grep_around` accept `path=VALUE` / `file=VALUE` as an explicit keyword token, in any position** ([#1690](https://github.com/Digital-Process-Tools/claude-supertool/issues/1690)). The read family disagrees about which positional slot the path goes in -- `read:PATH:...` takes it first, `grep:PATTERN:PATH` and `around:PATTERN:PATH[:N]` take it second -- and each op's own signature is internally consistent and documented, so the disagreement is only visible from a call that uses more than one. Rather than converging the four onto one order (a breaking change for every existing caller and every jit-context note that teaches the current spelling), this ships the cheaper of the three directions the issue ranked: a caller who does not want to remember the order can name the path explicitly -- `grep:needle:path=src/app.py` and `grep:file=src/app.py:needle` answer identically. Purely additive: a call with no `path=`/`file=` token parses exactly as before, and a call with two or more such tokens is left for the existing positional parser to answer (and fail) rather than silently picking one. `between` and `read` are untouched -- `read`'s path already leads, and `between`'s two modes (symbol / `re:START:END`) are a separate parsing shape better left to its own change.
