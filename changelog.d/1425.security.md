- **`git push --dry-run` was blocked, and the refusal named the op that performs the real push** ([#1425](https://github.com/Digital-Process-Tools/claude-supertool/issues/1425)). `git push --dry-run` and `git push -n` were not on the bare `git push` entry's `unless_flag` list in `presets/git.json`, so the raw-command guard blocked them and pointed at `git-push`, which has no dry-run route and pushes. Every other way this guard has been wrong costs a *missed block* — a raw read an op could have answered. This one costs the opposite, on the one op here that can destroy someone else's commits.

  It is worse on a refspec. `git push --dry-run origin feature:refs/heads/other` previews pushing a named branch onto a named ref; a caller obeying the refusal and running `git-push` pushes **the current branch to its own upstream** — a ref nobody in that exchange named. `git commit --dry-run` was the same shape and is excluded with it. `-n` is excluded on `git push` and deliberately not on `git commit`, where it is `--no-verify` and commits.

- **A clustered short flag now reaches `unless_flag`** ([#1425](https://github.com/Digital-Process-Tools/claude-supertool/issues/1425)). `_guard_excluded` compared whole tokens, so an entry excluding `-s` did not exclude `-sb` — the ordinary spelling of the intent `-s` was excluded for — and `git status -sb` was blocked while `git status -s` was not. The gap existed for every short flag on every entry, present and future, so it is fixed in the matcher rather than enumerated per entry: a single-dash token is read as a cluster of single-letter flags.

  Only exclusions, never the positive `flag` matcher. Widening an exclusion makes the guard block *less*, which is the direction it is allowed to be wrong in — a wrong block has no per-command escape short of `raw_command_guard: false`, which disarms every mapping in the repository — while widening the matcher would block more. A `--` token is never expanded, or every long flag containing an `f` would un-claim an entry excluding `-f`.

  The cost is stated rather than hidden: a short flag carrying a clustered **value** is expanded regardless of what the value spells, so `git push -oci.skip` now reads as carrying `-f` and is no longer claimed. Telling that from `-sb` needs per-flag arity the schema does not carry, and it errs toward allowing.
