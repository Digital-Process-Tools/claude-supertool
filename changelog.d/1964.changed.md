- **`.claude/settings.json` now wires the status line, reversing the opt-in decision recorded in [#1964](https://github.com/Digital-Process-Tools/claude-supertool/issues/1964).** The original reading was that a status line is cosmetic, so a tracked `statusLine` key imposes one maintainer's display choice on everybody who clones. What it missed is what the untracked alternative costs: `.claude/settings.local.json` is per-*machine* state, so routing the key there makes every developer working on the repository derive the same wiring by hand, with no way to see that the others did. The command resolves through `$CLAUDE_PROJECT_DIR`, so it names nothing outside the checkout and carries none of the machine state #1747 exists to keep out. `tests/test_statusline_wiring_documented_1964.py` now pins the key, the doc section and the `$CLAUDE_PROJECT_DIR` spelling — that last one is the interior guard `tests/test_settings_no_machine_state_1747.py` says it does not provide, since its allowlist reads top-level keys and not their contents, and an absolute `/Users/someone/...` command would otherwise ship one machine's disk to every clone.
