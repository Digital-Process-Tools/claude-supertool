- **`paste`/`edit`'s shell single-quote-escape idiom (close-quote, backslash- or double-quote-escaped-quote, reopen -- `'\''` / `'"'"'`) now refuses the write instead of only warning** ([#2243](https://github.com/Digital-Process-Tools/claude-supertool/issues/2243)). Inside a TOML triple-single-quoted literal the idiom is not unescaped -- it lands on disk as the literal 4-character sequence, not the single apostrophe a payload author usually meant -- and the prior warning (#2114) let the write proceed either way, so it was easy to read past. The sibling even-backslash-run case (`_payload_double_backslash_refusal`, #1087) already refused; this idiom now does too, reusing the same `literal_backslashes` escape key rather than adding a second one, and reports the payload line number of the first occurrence the same way the sibling refusal does.
