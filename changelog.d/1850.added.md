- **New op: `statusline`** ([#1850](https://github.com/Digital-Process-Tools/claude-supertool/issues/1850)) — renders a bar for Claude Code's `statusLine` hook from `ops.statusline.groups` in `.supertool.json` (nested groups/items, joined with `item_sep`/`group_sep`, never literal separator entries). The render path never makes a network call: local segments (`session`, `git-status`) compute live under a sub-second budget, and `gh-pr` publishes its own check tally — the same reconciliation `presets/_checks.py` already performs, never a second verdict path that could disagree with it — as a side effect of running normally; the statusline op only ever reads that fragment, atomically and keyed by worktree, rendering `checks: unknown (not run this session)` when nothing has been published yet in this session. That is the normal, expected state, not an error. Unconfigured refuses rather than inventing a default, and a segment name this op does not know how to render is refused by name rather than silently blank. Multi-line output and further segments (`radar`, `gl-mr`) are deferred — see `docs/presets/statusline.md`.
