- **`source_fingerprint` no longer silently drops a file it cannot `stat()`** ([#2237](https://github.com/Digital-Process-Tools/claude-supertool/issues/2237)). The per-entry loop caught `OSError` and `continue`d, dropping the one file and reporting a fingerprint that quietly omitted it -- unlike the `rglob` walk failure a few lines above, which already poisons the fingerprint to `None` with a reason. If the dropped file happened to be the newest one, the resulting fingerprint could equal a poller's fork-time value and `version_state_of` would report `VERSION_CURRENT` for a poller that is actually stale, the exact false positive #2179 exists to prevent. A per-file `stat()` failure now poisons the whole fingerprint the same way the walk failure does.
