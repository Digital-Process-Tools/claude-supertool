- **`gh-branch`'s `NO RUN` now escalates into its own finding, `NO RUN — STALE`, when a commit has genuinely gone past the point where "still expected" is a plausible reading** ([#2362](https://github.com/Digital-Process-Tools/claude-supertool/issues/2362)). A squash merge into `master` produced a commit for which zero workflow runs of any status ever existed, verified ~20 minutes after the merge with path filters, the cancel-in-progress trade-off and rate limiting all ruled out — and the existing ~15min creation-window reading (`_GRACE`, #585) declined the same way at 20 minutes as it would have at 20 hours, so a listing that had not caught up and a commit that would never see a run read identically forever. A second, longer threshold (`NO_RUN_STALE_SECS`, ~45min) now escalates to a distinct state token rather than repeating the same declined sentence — `gh-pr-merge`'s post-merge report picks it up for free via the `Branch <ref>: <STATE>` line it already quotes verbatim, and `presets/watch/sources/gh-branch/poller.py` gives it its own event key, `no_run_stale`, while still treating it as the same raw-empty reading `NO_RUN` is for its own direction-guard bookkeeping (#2333).
