- **A numbered fd redirect fused with no space against a preceding `|`/`;`/`&`/`&&` bypassed the raw-command guard** ([#2267](https://github.com/Digital-Process-Tools/claude-supertool/issues/2267)). `_guard_drop_io_numbers` strips the leading digit off a numbered redirect (`2>&1` becomes `>&1`), which is fine when whitespace already separates it from a preceding operator -- but when it does not (`true|2>&1 gh pr view 1`), the digit was the only thing keeping the `|` and the `>&` apart, and dropping it fused them into one adjacent run (`|>&1`) that `_guard_raw_segment_spans`/`_guard_tokenize_prepared` then read as a single redirect rather than a separator followed by one, collapsing two top-level shell segments into one and losing the split -- a blocked command placed after the fused separator read as `clean`. `_guard_drop_io_numbers` now inserts a single space between a separator it is about to fuse and the redirect operator, matching the (already-correct) spaced idiom byte for byte in every other respect; `origin_texts` keeps rendering the caller's undropped text (#2195), so nothing shown back to a caller changes. A 200k-string fuzz sweep that found 9,622 span-count mismatches on `master` finds zero after this fix.
