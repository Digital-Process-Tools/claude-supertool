- **15 of 19 validator adapters now separate the target filename from the tool's own flags** ([#2412](https://github.com/Digital-Process-Tools/claude-supertool/issues/2412), closes [#2418](https://github.com/Digital-Process-Tools/claude-supertool/issues/2418)). `bash-check`, `ci-lint`, `eslint`, `gofmt-check`, `hadolint`, `markdownlint`, `phplint`, `phpstan`, `node-check`, `prettier-check`, `shellcheck`, `ruby-check`, `stylelint`, `terraform-check` and `xmllint` passed `file` to `subprocess.run` with nothing between the tool's own flags and the target -- a contributor adding a file named `-o=payload` or `--eval=x` to a pull request could change what the validator does rather than what file it lints, the same class [#1040](https://github.com/Digital-Process-Tools/claude-supertool/issues/1040) tracks for `repo:` reaching `gh repo view`. Each of the 15 was checked against its own real CLI behaviour before being fixed, never assumed: 10 (plus `prettier-check`'s `--check` call) now get a `--` immediately before the target, confirmed against a real installed binary to be honoured as an end-of-options marker; `eslint`, `hadolint`, `stylelint` and `terraform-check` (no binary available to test against) and `xmllint` and `prettier-check`'s own `--file-info` call (both measured NOT to honour `--`) instead route through the same containment `validators/pyright/pyright.py` (#2379) already uses -- a relative target starting with `-` is prefixed with `os.curdir`, which does not depend on the tool understanding `--` at all. `tests/test_validator_dash_filename_2412.py` is the shared, table-driven regression test #2412 asked for, so a 20th adapter reusing the same argv shape is one new row rather than a new test file.
