- **markdownlint no longer flags a `changelog.d/*.md` fragment for the project's own no-heading, no-wrap convention** ([#2338](https://github.com/Digital-Process-Tools/claude-supertool/issues/2338)). The generic ruleset applied uniformly before, so a fragment in a consuming project with no local `.markdownlint.json` override (this repo's own config already disables MD013/MD041, which is why the noise never showed up here) cost a review-and-confirm step on every changelog write in a repo like `claude-oss`. The fix is scoped, not a blanket relaxation: a path matching the same `*changelog.d/*.md` glob `changelog-fragment` is already wired to is `skipped` here -- a scope decline, not `ok: true` -- and only when the project's own assembler script (`.github/scripts/assemble_changelog.py`, `.oss/assemble_changelog.py` or `scripts/assemble_changelog.py`) is discoverable above the file, bounded at the repo root. A `changelog.d/` directory in a project that never adopted the convention still gets ordinary markdownlint coverage.
