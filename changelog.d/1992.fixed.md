- **This repo's jit-context tools index now carries the same 7 columns claude-jit-context 0.6.0's `rebuild-tsv.sh` derives** ([#1992](https://github.com/Digital-Process-Tools/claude-supertool/issues/1992)). `rebuild-tsv.sh:308` had grown a 7th tools column, `requires` (`claude-jit-context` #203) -- a binary name whose absence from PATH degrades that row's `block`/`require`/`forbid` to advisory -- while this repo's committed `.claude/jit-context/tools/00-manual/00-index.tsv` still carried 6, so `CLAUDE.md`'s promise that regenerating the index is a no-op was false: running the real generator against this tree would have silently widened every row by one column instead of leaving it unchanged. A short field reads as empty in the awk that consumes it, so nothing was broken in the meantime, only unregeneratable without a hand-edit. The index now carries the 7th column (empty on every row -- no rule here declares `requires:` today), `tests/test_jit_tools_index_seven_columns_1992.py` pins the column count so the next such drift is a red here rather than a silent rewrite, and `CLAUDE.md` states the true history instead of an unconditional no-op claim.
