- **A failing op whose argument contained a newline exited 0** ([#1235](https://github.com/Digital-Process-Tools/claude-supertool/issues/1235)). The marker that turns a `FAIL`/`ERROR:` receipt into a non-zero process exit was anchored to the line immediately after the `--- op ---` header, and matched with `[^\n]*` — which cannot cross a newline. The header is `--- <the argument you sent> ---`, so any argument holding a newline made the header multi-line and the marker never matched.

  Measured: `git-commit:::subject` refused and exited 1; the identical refusal with one body line added exited 0. That is a refused commit which a git hook, a `&&` chain or a CI step reads as a success, firing on exactly the multi-line commit messages this project's conventions ask for — and it applies to every op, not just `git-commit`. The marker now spans to the header's closing ` ---`.
