- **A custom op's `{file}`/`{arg}` got only the first `:`-token and the rest was discarded in silence** ([#873](https://github.com/Digital-Process-Tools/claude-supertool/issues/873)). `{file}`, `{dir}` and `{arg}` substitute `parts[1]` — the first argument and nothing after it — so an op registered as `"cmd": "tool.py {arg}"` and called as `op:all:dry` ran with `argv == ["all"]`. No warning, no error, no mention in the receipt. In the filed case that token was a safety flag: the op ran in live mode and force-pushed two branches while its caller read the receipt as a dry run, and two "fixes" to the script's own flag parsing passed their unit tests because they were written against an argv shape the tool never produces.

  Refused now, above the subprocess, naming the text it will not pass and pointing at the placeholder that would have carried it. Not passed through: widening a single-token placeholder to the whole remainder would interpolate `parts[2:]` into `{file}`, whose `"paths"` declaration gates index 1 only — a second path-shaped token arriving downstream of the containment check, which is the failure [#1135](https://github.com/Digital-Process-Tools/claude-supertool/issues/1135) was filed about — and it would change what all 24 `{arg}` ops shipping at the time receive, several of which index their `|`-separated fields positionally. The refusal sits after `_preset_path_containment`, so it adds no path slot, moves none, and a call that both escapes the boundary and drops a token still reports the escape.

  **Preset ops take the same route** — one `_resolve_custom_op`, one substitution pass. The difference was never the kind of op, only which placeholder its author picked: zero shipped presets write `{file}`, 58 wrote `{args}`/`{argjoin}` and got every token, 24 wrote `{arg}` and got one — 61 and 21 after the three repairs below. So the trap was undocumented and invisible, and it had already fired inside the shipped set: `hashnode_list`, `devto_list` and `hashnode_search` each documented a second `[:N]` token and each split its one argument on `:` for a field discarded upstream — the documented limit was never honoured and the default was used in silence. All three now take `{args}` and rejoin. A test walks every manifest, so an op documenting a token its `cmd` cannot reach is red at write time.

  The issue proposed exit 2 for this, citing #647. There is no exit-2 route in this core — a refusal is an `ERROR:` line and the run exits 1 — so it follows the house shape instead.
