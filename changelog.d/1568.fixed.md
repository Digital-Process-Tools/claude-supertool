- **A live `gh` API call sat in the default test selection, so a network hiccup reddened runs that said nothing about the change under test** ([#1568](https://github.com/Digital-Process-Tools/claude-supertool/issues/1568)). `tests/test_watch_radar_gh_prs_859.py::test_live_board_over_this_repo` shells out to real GitHub inside a ~12,000-test xdist run. On 2026-08-12 it was the single failure of a full suite whose diff touched only `hooks/`, and it passed in isolation eight seconds later — a red that is a verdict about the socket, triaged by somebody asking what their diff broke.

  **The test stays in the default selection.** Marking it out costs the coverage it exists for: the fixtures in that module cannot produce the shapes real GitHub does, which is why the live case is there at all. What changed is that the tier now separates the two facts it was collapsing. `presets/watch/tiers/gh_prs.py` raises `RadarUnreachable` — a `RadarError` subclass, so radar's own handling is untouched — from every arm that means the request never landed: a spawn that failed or timed out, `gh` killed by a signal, no credentials, throttled, or the socket. Everything else stays a plain `RadarError`: a malformed argv, a reply that is not a PR list, a filter the tier refuses. An unrecognised failure is red, deliberately, because the alternative swallows a product bug wearing a flake's clothes.

  **The skip is countable, which is the half that keeps it honest.** `tests/_live_gh.py::reachable` skips on the subclass and re-raises everything else, and `conftest` prints `live-gh(#1568): N of M skipped tests did NOT reach the live GitHub API` on every run including when N is zero — beside the two counters #1143 and #1360 already built, now sharing one reader instead of three copies of the same `longrepr` walk. A silently-skipped live test is this repo's own defect class relocated into the thing meant to detect it.
