- **A live `gh` API call ran on the per-push critical path, so a network hiccup — or a runner with no credentials — reddened legs that said nothing about the change under test** ([#1568](https://github.com/Digital-Process-Tools/claude-supertool/issues/1568)). `tests/test_watch_radar_gh_prs_859.py::test_live_board_over_this_repo` shells out to real GitHub. It exists because the fixtures in that module cannot produce the shapes real GitHub does.

  **It is now `slow`, which in this repo means it runs on a schedule rather than nowhere.** `.github/workflows/slow-tests.yml` selects that marker daily on one ubuntu leg and its header exists to make exactly this distinction; the job now carries `GH_TOKEN: ${{ github.token }}` and `pull-requests: read`, so the test genuinely reaches the API there. Measured: it ran nowhere in CI before this. The `gh auth status` probe that used to guard it exits non-zero on a runner with no credentials, so it skipped on all twelve legs of every run since it was written — the marker moves it from nowhere to somewhere, and takes it off the path where a rate limit can red an unrelated diff.

  The token is deliberately **not** set on the twelve pytest legs. That would put a live call back on the per-push path, hand a credential to the environment of ~12,400 tests and the ~900 subprocesses they spawn, and buy nothing — the response is a JSON payload, identical on all three platforms, so twelve legs answer one question twelve times. It also sits against [#1341](https://github.com/Digital-Process-Tools/claude-supertool/issues/1341), whose autouse fixture refuses non-loopback sockets for every test and which `conftest` documents a subprocess as *escaping* rather than as being permitted.

  **Wherever it runs, the tier now tells "the API did not answer" apart from "the board says X".** `presets/watch/tiers/gh_prs.py` raises `RadarUnreachable` — a `RadarError` subclass, so radar is untouched — from every arm where the request never landed: spawn failure, timeout, a signal kill, a rejected token, throttling, or the socket. `RadarUnconfigured` narrows that to the standing case, keyed on `gh`'s own exit code 4 rather than on its prose: measured on gh 2.50.0, both spellings of "no credentials" exit 4 and nothing else does, while a *rejected* token exits 1 with `HTTP 401` and every product failure exits 1. That distinction is exact — a rejected token means the request landed. Everything unrecognised stays a plain `RadarError` and stays red, because the alternative swallows a product bug wearing a flake's clothes.

  **The skip is countable, and the two states are counted apart.** `tests/_live_gh.py::reachable` skips on those classes and re-raises everything else; `conftest` prints `live-gh(#1568): N of M skipped tests did NOT reach the live GitHub API` every run including at zero, breaking out how many of the N were the unconfigured kind. One number would make the second unreadable: after a token is set its expected value is 0, so a non-zero one is a finding about the workflow — but only if it is not summed with a transient blip whose expected value is not 0 ([#1274](https://github.com/Digital-Process-Tools/claude-supertool/issues/1274)'s argument, one level over). The three counters `conftest` now prints share one reader instead of three copies of the same `longrepr` walk.
