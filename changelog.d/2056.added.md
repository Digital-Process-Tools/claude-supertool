- **Wire `classify` (#2046) into the slack watch source**: `slack_message` events now carry a `classify` payload field, on the same footing as `author_is_viewer` — never something a message author can set ([#2056](https://github.com/Digital-Process-Tools/claude-supertool/issues/2056)). Scanner-only, always: a `claude -p` spawn is 45s against this poller's own 30s tick, so the model stage never runs here regardless of the configured level, and `SUPERTOOL_CLASSIFY=full` collapses to the scanner-only rendering rather than being silently ignored. A clean scan renders `classify: scanner-clean`, never `classify: safe` — the model stage that could say `safe` never ran. `SUPERTOOL_CLASSIFY=off` disables even the scanner. Named `classify`, not `ts`: #2052 already found the envelope silently dropping a payload key literally named `ts`.
