- **`doctor` also reports which of the project's validators actually resolve here** ([#1950](https://github.com/Digital-Process-Tools/claude-supertool/issues/1950)). `validators/` adapters are 39-deep in this tree, and nothing previously enumerated which of them can run on a given machine — a gap you found out one edit at a time, months after a checkout stopped being able to lint something. Bare `doctor` reports, for every configured validator, whether any tracked file even matches its scope (free — one pass over `git ls-files`), so an absent tool for a language this project does not use renders as furniture rather than a finding. `doctor:probe` additionally invokes each in-scope validator's own resolution path — never a `shutil.which()` sweep, which reports green where the tool the adapter actually shells out to (e.g. through `npx`) is the one that is missing — against a real matching file, and sorts the result into three states: **resolves**, **absent** (with the adapter's own `INSTALL_HINT`, verbatim), or **could not tell** (a crash, a timeout, or an ambiguous decline — never folded into either of the other two). Because probing runs the real adapter against a real file in this tree, it surfaces a missing or unreachable *configuration* for free too — `eslint.py`'s `_NO_CONFIG` decline and `stylelint`'s ignore-marker skip are ordinary `skipped()` results the invocation already produces. Probing costs one subprocess per in-scope validator, so it is opt-in rather than the default.
