- **`read` no longer spawns a `git status` per file outside any repository** ([#1397](https://github.com/Digital-Process-Tools/claude-supertool/issues/1397)). `_path_meta_suffix` used to run a per-path `git status` even when `_path_meta_repo_root`'s own walk had already climbed from the file's directory to the filesystem root and found no `.git` -- a spawn that could only ever answer "not a git repository" or fail, paid on every `read` of a `/tmp` scratch file, a fixture path, or a `tmp_path`-built test tree. That case is now skipped outright and renders a new, distinct token, `no-git` -- "the walk found no repository; git was never asked" -- rather than silently rendering as clean, which would have papered over the walk's own known gaps (an unreadable `.git`, a `GIT_DIR` that escaped the #714 scrub). Distinct from the existing `git?` decline (git *was* asked and failed to answer, unchanged by this fix, see #1596) and from a genuinely clean answer (no marker at all).
