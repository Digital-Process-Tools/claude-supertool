- **Two HTTP test fixtures paid a ~35s resolver stall in setup, on every CI leg** ([#928](https://github.com/Digital-Process-Tools/claude-supertool/issues/928)). `tests/test_http_bounds.py` and `tests/test_security_redirect.py` each built a stdlib `HTTPServer`/`ThreadingHTTPServer` bound to `127.0.0.1`, and `HTTPServer.server_bind()` calls `socket.getfqdn(host)` -- a reverse DNS lookup nobody needs, since every fixture in this suite addresses its server by `127.0.0.1:port`. On a runner with no reverse zone the call blocks until the resolver gives up; locally it returns in 0.01s, which is why nobody saw it.

  A third construction site, `tests/test_image_fetch_ssrf_817.py`, had the same shape and was fixed alongside the two the issue named. All three now use `NoFqdnHTTPServer`/`NoFqdnThreadingHTTPServer` from `tests/_no_fqdn_server.py`, which override `server_bind` to skip only the `getfqdn` call.

  The pin (`tests/test_no_getfqdn_928.py`) asserts the property that actually matters -- nothing on this path calls `socket.getfqdn` -- by patching it to raise and proving it never fires. A wall-clock threshold was rejected: it is a flake generator on a loaded runner and would not catch a regression on the one machine (a dev laptop) where the stall is invisible by construction.
