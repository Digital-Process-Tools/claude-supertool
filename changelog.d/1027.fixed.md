- **A payload whose ''' literal block carries `\\` is now named before the ops run, instead of landing bytes nobody wrote and reporting `edited`** ([#1027](https://github.com/Digital-Process-Tools/claude-supertool/issues/1027)). TOML triple-single-quoted literals process no escapes, so `\\d` in a payload is backslash-backslash-d. When the doubling is in `old` the anchor cannot match and the runner reports the skip — that half was already safe. When it is in `new`, the anchor matches, the write lands, the receipt says `edited`, and every validator agrees, because two backslashes are legal in nearly every language this tool edits. The wrong bytes reached disk and nothing anywhere said so.

  ```text
  ⚠ payload: a ''' literal block carries `\\`. A literal block processes NO escapes, so each pair reaches the file as TWO backslashes -- if you meant one, write one.
    ↳ `new` (1 occurrence): PAT = re.compile("\\d+")
  ```

  **It warns and never rewrites.** Collapsing `\\` to `\` would guess at intent, and some payloads want two characters; a wrong guess in the write path is worse than the bug, because the caller loses even the ability to read the bytes back and see what they asked for. The message says so in as many words, so the receipt cannot be read as a correction.

  **It warns rather than refusing**, which is where it parts from #834 and #835. Those fire at a fixed position — immediately before the closing quotes, at the end of a shell line — and there every reading has a second spelling, so a refusal strands nothing. This pattern has no position at all: a payload that legitimately writes a pair does so at an arbitrary offset, and refusing would make that unwritable everywhere.

  The line between signal and noise sits at exactly two places. A `"""basic"""` block is never flagged, because there `\\` *is* one backslash and is the correct spelling — a guard that fired on it would fire on its own remedy. A run of three or more is never flagged, because it was counted rather than produced by reflex. It is deliberately **not** narrowed to escape-looking sequences: the reported cases were `\\d`, `\\302` and `\\n`, and `\d` and `\302` are not TOML escapes, so the reflex is generic rather than TOML-specific and any escape set narrow enough to filter would miss the report it was written for. Measured instead — 710 of 208854 lines in this repository carry a `\\`, 0.34%, in the pathological corpus whose densest files are tests about backslash handling.

- **`batch:` now prints its `[result]` count above the first op as well as below the validators** ([#1027](https://github.com/Digital-Process-Tools/claude-supertool/issues/1027)). The footer is separated from the per-op results by a validators block long enough that `| tail` ends on `git-status : ok`, which reads as success — so a non-zero `K skipped` was the one number a reader was most likely to miss. The footer is unchanged and `[branch: X]` still ends the output; the leading copy costs one line and makes the count visible with no filter. Scoped to `batch:`, because a single op's receipt is three lines with the footer already adjacent to them. This is the half of #984 that #1018 marked `Part of` and left unbuilt; #1018 itself shipped the rollback wording and the already-applied hint, both verified against the tracker before this was written.
