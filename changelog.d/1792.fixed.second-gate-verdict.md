- **`gh-pr-merge` refused any pull request carrying a failed superseded leg, and printed no reason** ([#1792](https://github.com/Digital-Process-Tools/claude-supertool/issues/1792)). A regression in that issue's own fix, found by the v0.48.0 release audit. `gate()` returned `(not lines, lines)` and the superseded disclosure was appended to that same list on the **passing** path — so a line whose entire purpose is to say these legs are *not* counted red decided the merge was refused. The maintainer read the note, then `[result] REFUSED`, with **zero `REFUSED:` lines** to act on, and was then offered the raw `gh pr merge` escape hatch: routed onto the path with no leg reconciliation and no post-merge read-back, for no valid reason.

  **Why it was invisible.** `named_disclosure` skips the passed and pending buckets, so a superseded *pass* — the ordinary re-push case — emits no lines and flipped nothing. Only a superseded *failure* emits, and that is precisely the reported case the fix existed for. Four pull requests merged cleanly the afternoon it shipped, every one of them with a superseded pass.

  `lines` now holds two kinds and only one decides. The invariant is one sentence: **`allowed is False` if and only if at least one line says `REFUSED`** — asserted as a property over several rollups rather than as one more example, because the defect was not in any branch, it was in the return contract where every branch meets. A note that spells `REFUSED` anyway is treated as a refusal and said out loud rather than trusted for the list it arrived in; the merge is irreversible, so the classification fails closed. `gh-pr-merge` prints the disclosure on the passing path too, where it was previously discarded along with the rest of the gate's output.

  The misfiled check is **anchored at line start**. Written as an unanchored substring it read over lines that render check-run names verbatim, and a check-run name is written by whoever writes the repo's workflow files — a job called `connection REFUSED` would then have blocked every merge of every pull request carrying it. Same defect class one layer further in, caught by self-review before it shipped.

  The test that let this through asserted that a *phrase* was absent from the findings text — true of a gate refusing for a different reason, and true of a gate refusing while naming nothing. Compounding it, every gate test passed `declared=None`, so the reconciliation declined on all of them and the genuinely-clean passing path was never exercised. Both are fixed: the tests assert the boolean, and pass a reconciled `declared`.
