- **`replace` re-terminated your line endings and never said so** ([#1049](https://github.com/Digital-Process-Tools/claude-supertool/issues/1049)). `_newline_note` states the invariant in its own docstring — *"re-writing the caller's own endings is always disclosed"* — and `edit` and `replace_lines` call it. `replace` did the same `_newline_variants` re-termination and called nothing: a multi-line `replace` against a CRLF file rewrote the block you typed from LF to CRLF, correctly, under a receipt that mentioned only a count. The bytes were right; the invariant was stated and not held, which is the same absence-read-as-presence shape the rest of this issue is about, pointed at the receipt instead of at the write.

  The disclosure is not `edit`'s line copied across. `replace` is multi-file and the answer differs per file — one CRLF file re-terminated and one LF file matched literally, in the same call — so a single summary sentence would be true of the run and false of every file it did not apply to. The convention is marked on each file's own line (`src/win.rs (1) [CRLF]`) and the explanation is said once beneath the list. A file that matched byte for byte carries no marker, and a call where nothing was re-terminated prints no line at all: the narrowing that removed this note from every clean edit of a uniform CRLF file is preserved, because on Windows every file is CRLF and a disclosure that fires on every call is noise before it is information.
