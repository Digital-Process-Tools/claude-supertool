- Two whitespace-separated paths in the one PATH slot are now named as such. `grep:PATTERN:a.py b.py` used to fail with `path not found` and blame the `:` split, then prescribe a payload — where `path` is a scalar too, so the prescribed repair reproduced the failure one form further along.
- The refusal now says the value looks like N paths, that the op takes one, and prints the batched repair: one op per file, all in a single call, which is the round-trip the caller was reaching for.
- Three states, so the disclosure only fires when every whitespace-split part exists. A partial match is a genuinely missing path and keeps the previous message; stacking a second guess on the first would trade one misreport for another.
- It is derived in `_path_not_found` rather than per-op, so `read`, `map`, `around_line` and `replace` get it as well — those four also inherited the comma-list disclosure from #921, which until now only `grep` had been wired to.
- No new syntax. A whitespace-separated list would make a filename containing a space unrepresentable in the one slot that must be able to name any file, and the ops that do take lists already use a comma.
- Fixed alongside: the comma-list disclosure stat'd every entry without a containment check, while dispatch had only ever gated the comma-joined string. `a.py,/etc/shadow` resolves under the cwd because its first character does, so the tally leaked whether the second entry existed.
