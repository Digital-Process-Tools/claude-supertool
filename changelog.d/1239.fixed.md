- **`gh-issues` declared neither `per=` nor `assignee=`, and both have always worked** ([#1239](https://github.com/Digital-Process-Tools/claude-supertool/issues/1239)). The op prints `raise with per=N` in its own footer while the `syntax` string in `presets/github.json` did not list the key, so anything validating a documented invocation against the registry reported `gh-issues:per=100` as wrong — four documents, all of them correct, flagged by `claims` on its first run over this repo's docs.
- The `syntax` field is parsed and not merely displayed: for any op whose string carries `:::` it derives the `@file` payload field names. An omission there is the registry disagreeing with the code about what an op accepts, not a typo.
- **A new test compares every op's accepted vocabulary against its declared syntax** — `tests/test_registry_syntax_drift_1239.py` walks `presets/*.json`, imports each op's script, and asserts that every `_FILTER_KEYS` key and `_FLAGS` flag appears in that op's `syntax`. Swept over the whole registry it found exactly one drifted op and two undeclared keys, both on `gh-issues`; `gh-prs`, `gl-mrs` and `git-worktrees` were already in step. Second instance for this op — [#864](https://github.com/Digital-Process-Tools/claude-supertool/issues/864) was `milestone=`, also accepted, also unadvertised.
