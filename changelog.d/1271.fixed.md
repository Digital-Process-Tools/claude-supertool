- **A Windows absolute path split off its own drive letter by a preceding space is now recognised once it fails to resolve, instead of mis-tokenizing silently** ([#1271](https://github.com/Digital-Process-Tools/claude-supertool/issues/1271)). `_split_arg` rejoins a drive letter that sits after a `,` or `|`, but never one that sits after whitespace -- `grep:pattern:file.py C:\Users\x.py` tokenized to pattern=`'pattern:file.py C'` + path=`'\Users\x.py'`, and #1261's own multi-path disclosure could never fire on it because the path never reached that check as one string.

  Deliberately not fixed in `_split_arg` itself: widening the rejoin to look across whitespace would change tokenization for a call that works today -- a pattern containing a space followed by an absolute path currently parses as pattern-with-space plus path on POSIX, and would silently become one token. The repair instead runs once a path has already failed to resolve (`_colon_split_hint`'s new `_drive_letter_swap_suggest`), which cannot break a call that currently succeeds, because it only ever runs after a failure.
