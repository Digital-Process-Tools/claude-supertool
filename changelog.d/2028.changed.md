- **A session now starts with every op's signature, not just its name** ([#2028](https://github.com/Digital-Process-Tools/claude-supertool/issues/2028)). `hooks/session-start.sh` asks for `ops:session`, a new form that prints the signature listing when it fits the hook cap and falls back to `ops:roster` when it does not, saying what it measured and which listing it withheld. The roster answers "does this op exist" ([#614](https://github.com/Digital-Process-Tools/claude-supertool/issues/614)) but not "is this op the answer": an op's own error teaches its signature only *after* the decision to call has been made, so a name a reader cannot interpret is a capability never reached for — and nothing fails when that happens, which is why the cost went unmeasured for fifteen releases. `between` is a word; `between:SYMBOL:PATH` is a call. Measured here: the whole hook payload goes from ~2.9KB to ~5.1KB against a 10,000-byte cap, so it uses half the allowance instead of a fifth and withholds no signature.
- **`ops` carries the safety class the roster was carrying alone.** Unmarked is read-only and a positive claim, `*` writes in this tree, `!` reaches outside it or outlives the call, and an undeclared class renders `!` so a gap is never the quiet answer. Both listings render it from `_roster_classes()` and share one legend constant, so the two cannot drift into describing the same three markers differently. A `form` entry inherits its parent op's class rather than falling to `acts`, so `read:PATH:::grep=PATTERN` is not marked as if it acted.
- **The comment that chose the roster had three wrong numbers, and they were the whole argument.** It read "`ops` is 47,254 bytes and `ops-compact` 9,067 against a ~7,168-byte SessionStart cap, so the startup listing is truncated *today*". Measured: `ops` 4,126, `ops-compact` 16,486, cap 10,000. The `ops` figure was **12.6x high** — it predated [#1774](https://github.com/Digital-Process-Tools/claude-supertool/issues/1774) moving descriptions out of `ops`, and 47,254 is roughly what `ops:full` costs now. So "signatures cannot fit" was false the whole time. [#1877](https://github.com/Digital-Process-Tools/claude-supertool/issues/1877) corrected this same pair where it appears in `hooks/session-start.sh` and left the copy in `_supertool.py`, which is the one a reader reaches from the code; the first is graded by a test and the second was prose beside a constant that nothing re-ran.
