- **`slack_publish`'s `force`-recognition docstring undersold what the code accepts, and the `THREAD_TS` hijack it did document is now spelled out beside it** ([#2040](https://github.com/Digital-Process-Tools/claude-supertool/issues/2040)). The code was and remains deliberate -- `FORCE`, ` force `, and a tab-padded `force` all set the flag, case-insensitively and after stripping whitespace -- but the docstring described only a bare `force`. It now says so. The second half, a message whose own last field happens to look like a Slack `ts` and so gets read as THREAD_TS, was already documented and is left open on purpose: `require_confirm`'s preview still shows the resolved `(thread ...)` before anything posts.
