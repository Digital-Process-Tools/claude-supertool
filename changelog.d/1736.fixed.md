- **Five tests that asserted a bare digit substring was absent from a whole receipt now assert on the field the receipt attributes to the thing under test, each paired with a must-fire control** ([#1736](https://github.com/Digital-Process-Tools/claude-supertool/issues/1736)). The census #1691 asked for found sixteen sites; five were fixed in #1731 and six were already defended. These are the six that remained. `"30" not in head` over a grep receipt that prints a results count, a scanned-files count, a `limit`, a `context` and a cap figure became `f"{seen}+ matches total"` and `f"count capped at {seen}"`, both built from the same renderer the assertion is about, so a renamed field reddens rather than making the guard vacuous. `"774" not in out` became `"#774"`, the spelling the listing actually uses for a linked PR. `"33698" not in out` became a row whose SOURCE and ID cells are the slot — the board renders those two as separate fixed-width columns, so the id never appears beside its source and five bare digits matched a PID, a timestamp or a path just as readily.

- **One of the six was not merely loose, it was the one spelling that could not arrive** ([#1736](https://github.com/Digital-Process-Tools/claude-supertool/issues/1736)). `tests/test_forged_child_stream_line_1475.py` guarded the commit relay's kept tab with `"0009" not in body`. A tab is in C0 and therefore has a Control Picture, so `_untrusted.visible` spells it `[U+0009]` only on a stream that will not name an encoding; under pytest `sys.stdout` names utf-8 and a re-flattened tab spells `␉`. Measured against a deliberately re-flattening `_git_common.relayed_lines`: the receipt read `> PASS␉tests/test_a.py`, and `"0009" not in body` was `True` — green on exactly the regression it was written for. Both spellings are now named, in that file and in `tests/test_git_push_relays_hook_output_1448.py`, whose harness redirects into a `StringIO` and therefore hits the other one.

- **Each rewritten absence is now paired with a must-fire case in the same fixture** ([#1736](https://github.com/Digital-Process-Tools/claude-supertool/issues/1736)). A must-not-appear is satisfied just as well by a render that printed nothing, and two of these were: with `cmd_list` reduced to printing no rows the pre-change watch-board test passed, and with the linked-PR renderer dropping every node the pre-change `#774` test passed. Both are red now. The eleven-digit `"30993457393" not in out` in `tests/test_gh_pr_names_check_run_id_827.py` is left as written: it already carries its positive control on the line above (`"job #92264786336" in out`), and at eleven digits in a receipt that never prints the details URL there is no path by which it passes for a second reason.
