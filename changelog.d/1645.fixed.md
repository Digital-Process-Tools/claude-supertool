- **Four GitLab error classifiers matched `glpat_`; GitLab mints `glpat-`** ([#1645](https://github.com/Digital-Process-Tools/claude-supertool/issues/1645)). `gl-issue`, `gl-mr`, `gl-pipeline` and `gl-job` each tested `glab`'s stderr for `glpat_` before taking the "not authenticated. Run: glab auth login" arm. Underscore, where every one of GitLab's thirteen documented token prefixes is hyphenated. So an error naming a real token missed that arm and took the generic relay — the wrong advice, and the branch that echoes the remote's text back to stdout and, since [#1602](https://github.com/Digital-Process-Tools/claude-supertool/issues/1602), to a desktop notification.

  **The test was written to the typo.** `tests/test_security_glab.py`'s `FAKE_TOKEN` used `glpat_` too, so the one check over these classifiers agreed with the thing it was checking and would have passed against a build that matched nothing at all. Correcting both literals reproduces that structure exactly, so the prefix list now lives once — `presets/_secrets.GITLAB_TOKEN_PREFIXES`, read by the redaction rule and by the four classifiers through `mentions_gitlab_token()` — and `tests/test_glab_token_prefix_1645.py` holds GitLab's own documented list, cited to `https://docs.gitlab.com/security/tokens/` and dated, asserting the shared tuple against it. A literal is unavoidable (nothing in CI can reach that page, and no test can mint a token); it is now singular, cited, and load-bearing for two subsystems rather than five copies agreeing with each other.

  **Seven prefixes the redactor did not know.** The same list widened `_secrets`' `gitlab-token` rule from six prefixes to the documented thirteen — `glrtr-`, `gloas-`, `glft-`, `glimt-`, `glagent-`, `glwt-` and `glffct-` were minted by GitLab and unrecognised, so a transcript carrying one was relayed whole by `claude-log` and `git-resolve`.
