- **`main()` restores `SUPERTOOL_REPO` after the call that exported it** ([#1962](https://github.com/Digital-Process-Tools/claude-supertool/issues/1962)). The `repo:` pre-pass wrote `os.environ["SUPERTOOL_REPO"]` directly, with nothing to restore it — a process-global mutation `monkeypatch` never performed and so cannot undo. A test driving `main()` in-process left the variable live for every test after it in the same pytest worker: `presets/watch/transport.repo_slug()` and any other `_repo_target` consumer then answered about whichever repository leaked in, silently, in a file that never mentioned `repo:` at all — eleven CI legs went red on PR #1961 this way. `main()` now snapshots both `SUPERTOOL_REPO` and its #1986 from-op marker before dispatching, and restores the prior value (or clears it, if there was none) in its own `finally` — so an outer ambient export survives a call that names its own `repo:` op, and neither variable outlives the call that set it.
