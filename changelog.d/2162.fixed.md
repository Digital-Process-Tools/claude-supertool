- **`ruff-format`, `php-cs-fixer`, `prettier-write` and `phpcbf` now say when they could not verify their own result, instead of silently reporting "no changes"** ([#2162](https://github.com/Digital-Process-Tools/claude-supertool/issues/2162)). Each computes `metrics.lines_added`/`lines_removed` by re-reading the file after the tool exits; an `OSError` on that re-read (the file deleted or its permissions changed mid-run) used to fall back to `after = before`, publishing `ok: true` with `metrics: {lines_added: 0, lines_removed: 0}` -- byte-identical to the receipt for a file the tool genuinely left untouched. The payload now carries `verify_failed: "<reason>"` in that case, and `_formatter_render_row` reads it before the silent-no-op check, so the row always renders (`formatted, but could not verify what changed: ...`) instead of disappearing into the quiet-clean-run path every genuine no-op takes.
