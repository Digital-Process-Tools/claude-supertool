- **A wall-clock assertion in `edit`'s minified-file test measured the runner, not the product, and blocked the v0.41.0 release push** ([#1623](https://github.com/Digital-Process-Tools/claude-supertool/issues/1623)). `test_a_minified_file_does_not_hang_the_diagnostic` asserted `elapsed < 15`. The bound it guards is real — `_EDIT_NEAR_BUDGET` caps `_edit_nearest_hint`'s scan in cells — but the assertion measured how loaded the machine was: it went red three times in one hour on 2026-08-13, on a laptop running five suites, while the same commit was green on all 18 CI legs. One of those reds was the pre-push hook on the release commit, where the correct reading of a red ("do not ship") is the reading it made wrong. A test harness rendering an environment limit as a product verdict is this repo's own defect class ([#1143](https://github.com/Digital-Process-Tools/claude-supertool/issues/1143)) relocated into the thing meant to detect it.

  **It now counts the cells handed to `difflib` instead**, against `_EDIT_NEAR_BUDGET` and the `_EDIT_NEAR_MAX_CHARS` per-comparison clip, and requires the decline to be the *budget* one by its wording. Both halves were load-bearing: with the budget lifted, this same input still declines — for a tie, at 100% across 60 places — so the old `cannot suggest` assertion passed against an unbounded scan and only the clock was holding the line. Nothing about the product changed.
