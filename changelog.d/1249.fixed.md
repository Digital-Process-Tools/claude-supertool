- **`git-commit:@-`'s `message` field is now write-bound for the doubled-backslash guard, closing the last gap #1249 recorded** ([#1249](https://github.com/Digital-Process-Tools/claude-supertool/issues/1249)). An even backslash run in a payload `message` used to warn and let the commit proceed, because the refusal machinery scoped "write-bound" to a *file* and a commit message is not one -- the recorded consequence was a commit message about backslash misreporting that itself misreported backslashes, corrected afterwards with a raw `git` amend outside the payload route entirely. `message` now shares `_PAYLOAD_DBS_WRITE_KEYS` with `new`/`content`: an even run is refused before the commit runs, suppressible with `literal_backslashes` exactly as any other write-bound field, since a commit message has no `old`-shaped anchor reading to keep a note-only case for.
