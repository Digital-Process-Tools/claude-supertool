- **Added `github-pr-feed`, a discovery watch source for GitHub pull requests** ([#1780](https://github.com/Digital-Process-Tools/claude-supertool/issues/1780)). GitHub could watch one PR by number (`github-pr`) and GitLab could watch its whole open-MR feed (`gitlab-mr-feed`); the missing combination was watching GitHub's own open-PR board. `github-pr-feed` polls the population instead of one member of it — a new PR is discovered and its own `watch:github-pr:<n>` poller spawned with no one typing anything, and a PR that vanishes is reported as merged, closed, or having left the filter, never as an unexplained silence. `presets/watch/tiers/gh_prs.py` now spawns and keeps this feed alive as a first-class part of `radar`'s reconcile, exactly as `gl_mrs.py` already does with `gitlab-mr-feed` — one poller per resolved filter, healed on every tick, its own scope reported by `watches` and `radar --state`.
