- `gh-prs` gained `merged-since=<ISO date|instant>`, the boundary filter it had no vocabulary for — "what merged since Friday" had no op at all. It takes instants only, never a tag name: resolving a tag has three outcomes and a listing filter has two, and this op follows a `repo:` target while a tag is a read of the local clone. Beside `state=open` (the default) it is refused rather than answered, because `--search merged:>X` cannot match an open PR and the empty board would be a fact about the query, not about the repo ([#1411](https://github.com/Digital-Process-Tools/claude-supertool/issues/1411)).
- `gh-since-tag` no longer builds its own `gh pr list` argv. It was a third caller of the listing `prs._build_list_cmd` owns — the one that drifted in #1207 and again in #1230, each fix paid for twice — and now calls it with `state=merged,merged-since=INSTANT` and its own field set. The boundary's three states, the local-history reconcile and the `changelog.d` cross-check stay where they are: what must not be duplicated is the judgement, not the render ([#1411](https://github.com/Digital-Process-Tools/claude-supertool/issues/1411)).
- Every `gh pr list --search` qualifier now composes into one flag. gh binds `--search` to a single string, so `reviewer=@me,merged-since=...` would have emitted two and silently answered half the question — unreachable until this release added the second search key ([#1411](https://github.com/Digital-Process-Tools/claude-supertool/issues/1411)).
- `gh-prs`'s scope footer names the state it is about. It read "every author's **open** PRs" whatever `state=` asked for, so `gh-prs:state=merged` labelled a merged board as the open one — on the one line whose job is naming the population ([#1411](https://github.com/Digital-Process-Tools/claude-supertool/issues/1411)).
