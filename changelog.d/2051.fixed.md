- `channel:health`/`radar` said `subscribed` for a session that could not
  possibly receive anything: this repository's own `.mcp.json` declares
  `claude-channel` unconditionally, and any session also carrying a
  `--dangerously-load-development-channels server:NAME` tag spawns two
  channel-capable servers over the identical socket. One binds; the harness's
  connection to the other closes. #2133/#2136 already catch this reactively,
  off a marker the losing process writes beside the socket -- but that marker
  is only readable in the window between the loss and the winner's next
  (re)bind, which clears it, and #2051 measured a session past that window
  where no marker was left and `subscription()` still read `subscribed`.
  `subscription()` now also checks the two config files directly -- no
  marker, no live process state needed -- and reports `CANNOT DETERMINE`
  naming both declared servers when they resolve to one socket.
