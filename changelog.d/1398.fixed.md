- **The `git status` budget behind the ` git?` marker is now a tunable config key, not a hardcoded `2`** ([#1398](https://github.com/Digital-Process-Tools/claude-supertool/issues/1398)). `_path_meta_suffix`'s two `git status` spawns -- the repo-wide bulk snapshot and its per-path fallback -- both read `builtin-ops.read.git_timeout_seconds` (env: `SUPERTOOL_READ_GIT_TIMEOUT_SECONDS`), defaulting to the historical `2` when unset. Parallel mode spawns several of these against the same fixed budget, so raising worker count used to strictly raise the rate of honest-but-noisy ` git?` declines regardless of a caller's own timeout tolerance; the budget stays flat rather than auto-scaling with concurrency (there is no shared coordination point between separate `supertool` invocations to read a worker count from), but a caller who knows their own parallelism can now raise it. Following #1332's lesson, an explicit `0` is refused loudly, with the default used and the substitution announced, rather than silently honoured as a stuck-at-0 budget.
