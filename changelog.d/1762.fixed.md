- The raw-command guard now reads a command substitution wrapped in double
  quotes -- `"$(gh run view 123)"`, the spelling shellcheck requires -- the
  same way it already read the bare `$(gh run view 123)` form. It used to
  decline the double-quoted shape outright (correctly disclosed as
  `undecided`, never a silent `clean`), which meant the safest shell idiom
  was the one spelling that went unchecked. `_guard_find_substitution_end`
  now balances the interior against nested parens and quotes and checks it
  through the same reader; what it genuinely cannot balance -- an
  unterminated substitution, a backtick's own delimiters, a further layer of
  indirection -- still takes the `undecided` arm rather than guessing (#1762).
