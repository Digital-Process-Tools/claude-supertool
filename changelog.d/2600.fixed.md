- **`youtube_comment` supports `:::` as an unambiguous field separator, alongside `|`.** `parse_args`'s trailing-field scan for `|force`/`|force-dup` cannot tell "the operator's last pipe-delimited segment is body text" from "the operator meant the flag" once both spell the same word -- `youtube_comment:VID|may the|force` silently dropped "force" from the body and forged the publish confirmation, on the one guard standing between a call and a public, un-deletable comment. `:::` is not a character ordinary prose would contain by accident, so opting into it (`VIDEO:::body ending in the word force:::force`) keeps a body's own trailing `force`/`force-dup`-looking text intact instead of guessing. Default `|` parsing is unchanged, since redefining it would silently reinterpret every already-shipped `|force` call site ([#2600](https://github.com/Digital-Process-Tools/claude-supertool/issues/2600)).
