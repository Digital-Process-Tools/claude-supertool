- **A test can no longer assert that its own `changelog.d` fragment exists** ([#1053](https://github.com/Digital-Process-Tools/claude-supertool/issues/1053)). The release *consumes* fragments, so `assert (root / "changelog.d" / "953.added.md").is_file()` passes for as long as no release happens and then reddens every platform at once, on the one event it should be indifferent to. It shipped three times — #941 took five legs on v0.26.0, #953 took thirteen of twenty on v0.27.0 — and both were fixed only where they were found. Two things now close the class instead of the instance: `assert_change_is_findable(<issue>)` in `tests/_changelog_findable.py` implements the fragment-or-CHANGELOG rule once, so the correct form is a single call; and a sweep of the suite parses every test module and refuses any `assert` that tests a `changelog.d` path's existence, naming the file, the line and the accepted form. #941 and #953 are the first two callers.
