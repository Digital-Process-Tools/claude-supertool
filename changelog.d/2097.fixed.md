- **`presets/_classify_render.py` now wires the verdict cache from #2054 into its own `Budget`** ([#2097](https://github.com/Digital-Process-Tools/claude-supertool/issues/2097)): `gh-issue`, `gh-pr`, `gl-issue` and `gl-mr` no longer spawn `claude -p` a second time for a body or comment they have already classified. #2054 shipped the cache, but `presets/_classify_render.py` -- the caller its own body named as the actual fix -- was never wired to it; every read still paid a fresh spawn per unit, repeats included. `Budget()` now builds one `presets/classify/cache.py` `Cache` per op call by default (`cache=None` still means "no caching" for a caller reaching `verdict_line` directly, matching `model.classify`'s own convention), so every real call site gets caching with no change of its own. A cache hit no longer spends the call's spawn budget either -- checking the cache before decrementing `Budget.remaining`, rather than only inside the spawn path, is what stops a run of nothing but repeats from exhausting the cap on units that never actually spawn. The cache's `expired`/`unreadable` statuses are not surfaced as a new rendered state: `could-not-classify` still covers every way the model stage produced no verdict, and a cache malfunction is a fact about this machine rather than about the text. `CLASSIFY_BUDGET` (6) is left unchanged -- no measurement backs a different number yet.
