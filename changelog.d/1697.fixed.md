- **Every validator adapter now publishes a verdict when it crashes, and a crashed checker exits 1 instead of 0** ([#1697](https://github.com/Digital-Process-Tools/claude-supertool/issues/1697)). An exception escaping an adapter's `main` writes **nothing** to stdout. `validators/common/refusal.guard_main(TOOL, main)` wraps the call in every one of the 36 adapters and publishes `refusal.crashed()` — `ok: false, count: 1`, one `code: "adapter"` row naming the exception class, its message and the last three traceback lines, with a measured `duration_ms`. Measured end to end on a `.json` file holding invalid UTF-8, which makes `jsonlint`'s `open(..., encoding="utf-8")` raise `UnicodeDecodeError` before any handler it owns: `validate:` printed `skipped — jsonlint adapter produced no output` and **exited 0**, so `supertool 'edit:x.json' && git commit` committed on a checker that had died. It now prints `NOT CHECKED — adapter jsonlint adapter crashed and did NOT check this file: UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff in position 7` and **exits 1**.

  **Two things the issue reported are corrected here, and the second changes the count.** It says callers `json.loads()` the empty stdout as a clean run; the core does not, and has not since [#634](https://github.com/Digital-Process-Tools/claude-supertool/issues/634) — `_validator_run_one` tests `if not out` before parsing. The cost was never a false clean. It was a **discarded diagnosis** (the traceback goes to a stderr the core captures and never reads) and a **lowered alarm** (a core-produced skip escalates only for a validator named in `$SUPERTOOL_REQUIRE_VALIDATORS`, while an adapter's own `code: "adapter"` row escalates unconditionally). And the population is **35 of 36, not 31**: the four MCP adapters do have an `except Exception`, but it wraps `ensure_daemon` + `ndjson_call` only, leaving their own `print(json.dumps(format_response(...)))` outside every handler they had. A handler that exists is not a handler that covers, which is why the net goes at the call site rather than inside `main`.

  **Not `skipped()`, and the reason is mechanical rather than stylistic.** An adapter cannot set `no_verdict` — a core-only key, stripped on the way in — and `_validator_no_verdict` returns `None` the instant `skipped` is a key, so a crash spelled `skipped` would reach neither `_note_not_checked` nor `_NOT_CHECKED` and would exit **0**: quieter than the bare crash it replaced. `refusal.tool_fault()` already said it in prose — "a fault routed to `skipped` is a validator quietly reporting clean" — and `tests/test_adapter_crash_net_1697.py` now asserts both directions on one fixture rather than leaving it to prose.

  Five spellings became one. `ruby-check`'s hand-rolled module-level net published `str(exc)` alone, so a `KeyError()` or a `RecursionError` — both of which stringify to nothing — rendered a row with a blank reason; its `_STARTED` shim from [#1683](https://github.com/Digital-Process-Tools/claude-supertool/issues/1683) is gone, because `guard_main` measures its own elapsed. The four MCP copies of the same nine-line handler, differing only in the name each wrote into its payload, are gone too. The guard drives all 36 adapters as `__main__` in a subprocess with a failure injected into their publish path, pairs every must-not-be-silent case with a must-fire one, and requires the shared helper by name so a thirty-seventh adapter cannot arrive without a net.

  Documented in `docs/validators.md` §"Declining instead of guessing", which gains a fourth escalation row; `validators/SCHEMA.md` and `docs/contributing.md` both described a crash as something the *core* observes and are corrected. `docs/contributing.md` also carried the issue's own two wrong claims verbatim ("every caller `json.loads()` that", "surfaces as a `JSONDecodeError`") and now says why neither is true.
