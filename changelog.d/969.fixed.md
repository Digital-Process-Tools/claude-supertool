- **A `rollback_on_fail` validator that could not run reverted a good edit** ([#969](https://github.com/Digital-Process-Tools/claude-supertool/issues/969)). `_validator_regressed` compares an error count before an edit with the count after it, and an absence of information carries `count: 1` — that is the only channel `SCHEMA.md` gives it. So a checker that answered before the edit and could not answer after it scored `0 → 1`, read as a regression, and rewrote the file with its pre-edit bytes. The edit was fine, nothing had checked it, and the work was gone. Every other open finding misinforms; this one destroyed.

  **#967 had already won this argument one commit earlier and the rollback path did not hear it.** It established that a result whose errors are all `code: "adapter"` is a non-verdict rather than a finding, and taught the renderer, the `[result]` line and the exit code to say so. `_validator_regressed`'s own docstring promises that "the red the caller sees and the revert it triggers can never disagree" — after #967 they disagreed exactly: the row printed `NOT CHECKED` while the file was reverted underneath it.

  **The core's own timeout was the same absence and the likelier trigger.** `code: "orchestrator"`, `ok: false`, `count: 1`, from the `TimeoutExpired` arm — reachable with no exotic configuration at all, just a loaded machine and `jsonlint`'s 10s budget, on a validator this repo ships with `rollback_on_fail: true`. It now renders `NOT CHECKED (timed out — no verdict about this file)` instead of `1 err (timeout)`, is excluded from the delta, and exits non-zero. A count about a file the checker never finished reading is a measurement nobody took.

  **The `before` side was the same defect pointing the other way, and it was the quiet one.** A baseline that produced no verdict also carries `count: 1`, so a real finding introduced by the edit cancelled against it: the row read `1 err (pre-existing — not from this edit)` about an error that edit had just created, no rollback fired, and the call exited 0. A baseline nothing measured is not a clean baseline and is not a zero — it is the absence of a baseline, now folded into the case that already existed for one. Those rows show `? → 1`, never `0 → 1`.

  **The judgment, stated so it can be argued with: keep the edit, disclose loudly, exit non-zero.** The alternative was to refuse the write so nothing lands unverified, which is defensible for a gate whose point is that the file must not change unchecked — and it is the trade #665 already declined, for a reason that is stronger here. The pre-edit bytes a revert restores were never checked either. Reverting buys no safety over disclosing; it only deletes.

  **A core timeout now escalates with `$SUPERTOOL_REQUIRE_VALIDATORS` unset, which narrows #975.** That release grouped the timeout with four adapter breakdowns and pinned all five to a quiet exit 0 when the variable is unset, on #665's rationale: an optional checker nobody installed must not redden unrelated edits. The rationale covers the four — they become a `skipped`, which is what a missing tool produces — and cannot produce the fifth, because reaching a timeout needs the adapter present, spawned, and still running when the budget expired. So the checker that could not be vouched for is one the operator configured and expects. Its parametrized case is now asserted separately, in the opposite direction, with that reason written next to it; the other four are untouched, and `skipped` is still deliberately not folded in. The two rendering paths were also spelling one failure two ways — a required timeout read `(no verdict about this file)` and an unrequired one `(timed out — …)` — so they now agree; the variable changes the exit code, not what went wrong.

  **`validate:` gained the `[result]` footer it never had.** It mutates nothing, so the footer was gated out entirely and its non-verdict reached the reader in the row and the exit code but not in the summary line the docs tell them to trust. The line now appears for a read-only op precisely when a checker declined, naming it, and carries no op or write counts — there was no op to count.
