- **`str.isdigit()` is gone from every preset guard that reads a number, and the strict test lives in one place** ([#1727](https://github.com/Digital-Process-Tools/claude-supertool/issues/1727)). The issue was filed on `pr_create.py`'s PR-number read-back, where the value is parsed out of `gh`'s own stdout and the blast radius is low. The sweep it asked for is the change: `str.isdigit()` is True for two classes of character, and only the first was known here. Unicode decimals — `٢`, `۲`, `২` — convert through `int()`, so an op proceeded against a number nobody typed. **Superscripts — `²`, `³` — do not**: `str.isdecimal()` is False for them and `int()` raises, so every `isdigit()`-then-`int()` site was an uncaught `ValueError` reachable from a plain op string. `supertool 'gh-issues:per=²'`, `'gh-prs:per=²'`, `'gh-following:²'` and `'gh-starred:²'` all died with `invalid literal for int() with base 10` before anything was fetched. The worst of those is `presets/_filter_tokens.py`, whose `bad_values` is the function that exists to name a filter value the op cannot honour and which crashed on the value it was asked to refuse — shared by `gh-issues`, `gh-prs` and `gl-mrs`.

  The test now lives once, in `presets/_digits.py`, as `is_ascii_int` over an anchored `^[0-9]+\Z` — the `\Z` for [#1188](https://github.com/Digital-Process-Tools/claude-supertool/issues/1188)'s trailing newline. `presets/_job_argv.py` and `presets/github/run.py` had it right already and each carried a private copy plus its own paragraph of rationale; they now import it, which is the point — the loose spelling next to the strict one is what the next reader copied, nine times. Rewired with it: `gh-check` (both ids, straight off the caller's op string and interpolated into a `gh api` path), `gh-pr-merge`'s number, `gh-pr`'s number-or-branch argument, `gh-pr-create`'s read-back gate, `gh-following`, `gh-starred`, `gh-find-starable`, `gh-find-followable`, and `_filter_tokens`' positive-integer and ISO-date-prefix checks. `tests/test_ascii_digit_guards_1727.py` pairs every "must refuse" case with an ASCII control in the same fixture, and its recurrence scan carries a live positive control so it cannot pass by finding nothing.

  Not covered, and reported rather than fixed, because they are outside this change's lane: the same `isdigit()`-then-`int()` shape survives in `presets/devto/`, `presets/hashnode/`, `presets/bluesky/`, `presets/claude-log/`, `presets/gitlab/` and `presets/git/`.
