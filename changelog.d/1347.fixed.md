- **Two JIT rules hard-blocked commands the shipped guard allows** ([#1347](https://github.com/Digital-Process-Tools/claude-supertool/issues/1347)). `git-push-has-an-op.md` and `gh-pr-view-merge-have-ops.md` predate the registry guard and cover the same two commands with one awk regex, which cannot express *except with these flags* — one-true-awk has no negation. So they refused `git push --dry-run`, `git push -n`, `gh pr create --dry-run` and every `--help`, and the body they injected named `git-push` / `gh-pr-create` as the remedy. Worse than the guard defect of the same shape: the guard prints a suggestion, a `block` prevents the call outright.

  Both drop to `mode: remind`. Enforcement stays with the one gate that honours `unless_flag`, and the reference material the guard's refusal does not carry — the tag route, `git worktree add -b` leaving the branch tracking its base, "a zero exit is not a push" — stays where it was. A new test also pins the `.md` frontmatter `mode:` against the `00-index.tsv` column that actually runs it: they disagree silently everywhere else, which is the same "reads as enforced, never fires" shape #1254 closed for the regex column.
