- **Two of #1708's three flattening sites had no positive control** ([#1766](https://github.com/Digital-Process-Tools/claude-supertool/issues/1766)). `_list_conflicts` has read `-z` since #1708, so a conflicted path arrives as its real bytes and can carry LF, CR or U+2028 into the `## ...` heading `git-conflicts` and `git-merge` print at column 0 — both already flatten it with `_untrusted.flat(path, disclose_newline=True)`, but nothing noticed if that stopped: restoring the pre-#1708 raw interpolation at both sites and running the full suite twice, mutated and restored, produced the identical `21 failed, 13934 passed, 56 skipped`. `resolve.py`'s third flattening site already had one (`tests/test_list_conflicts_quotepath_1708.py`); `tests/test_conflict_merge_heading_flatten_1766_positive_control.py` adds the same shape for the other two, mutation-tested — both assertions go red against the restored raw interpolation and green against the shipped flattening. Per-site rather than a register: `_list_conflicts` has exactly three callers, and the one register precedent in this tree for "survives a fourth site" (`tests/test_preset_git_splitlines_register_1130.py`) answers a different, static question, whose own published deciding rule #1654 measured as correct for only 3 of its 27 entries — a warning against forcing an AST-verified shape onto a question that only running the render actually answers.
