- **A new file's unused import is now caught locally, not only by CI's added-path lint leg.** `pyproject.toml` ignores F401/F841/F541 tree-wide for 263 pre-existing findings (#797); `.github/scripts/lint_new_files.py` re-enables them for the files a PR adds, copies or renames, but only in CI, against a PR base ref no local route has. Measured cost: three separate lanes shipped a new test file with a dead import in one session, each green on every local check and red on the CI leg after a full push-and-wait round trip. `.github/scripts/new_file_ruff_gate.py`, wired into `.supertool.json` as the `new-file-lint` validator (imports `EXTRA_RULES` from `lint_new_files.py` rather than copying it), asks the one question a local, PR-less check actually can answer -- does this path have a blob at `HEAD` -- and re-enables the three rules for any file that does not, on every mutating op. A file that already has history is left to the shared `ruff` validator and the CI leg's own merge-base diff, which this gate has no PR base ref to reproduce.
