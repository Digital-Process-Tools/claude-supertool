- **The `gh-branch` watcher no longer regresses a confirmed GREEN commit to `no_run` on a transient empty run listing** ([#2333](https://github.com/Digital-Process-Tools/claude-supertool/issues/2333)). Observed live on this repository's own `v0.57.0` release commit: `went_green` -> `no_run` -> `went_green`, all on the same SHA, 36 seconds apart, while `gh-branch` run cold in between showed four concluded, all-passing runs on that exact commit -- the poller's own absence, rendered as an absence in the world. Runs on a concluded commit do not disappear, only the read of them can fail, so a poll of a SHA this poller already confirmed runs on that comes back with zero runs is now read as `unknown` rather than trusted at face value; a fresh SHA that genuinely has zero runs still fires `no_run`, unchanged.
