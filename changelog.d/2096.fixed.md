- **A test reaching a preset auth reader (`presets/{slack,bluesky,devto,hashnode}/_auth.py`) without stubbing it could resolve the maintainer's own on-disk credential** ([#2096](https://github.com/Digital-Process-Tools/claude-supertool/issues/2096)): each reader falls through, in order, to its env var, then `~/.config/<preset>/<name>`, then a `.{preset}-...` file in the cwd, and the second and third arms are machine-local rather than CI-local -- `tests/test_watch_slack_ts_guard_2063.py` passed locally against a real `~/.config/slack/bot_token` and failed on every CI runner, on an assertion that named neither credentials nor the environment. A new autouse fixture in `tests/conftest.py` clears the six env vars the four readers check and redirects `HOME`/`USERPROFILE` to an empty directory for every test, so the disk fallback cannot resolve a real credential regardless of what is configured on the machine running the suite; `tests/test_preset_auth_env_isolation_2096.py` proves the leak was real (a positive control, gated on this machine actually carrying a token) and that the new fixture closes it. The cwd arm is guarded separately, by asserting no stray `.{preset}-...` file sits at the process cwd during a test run, rather than by chdir'ing every test file. Redirecting `HOME` also broke `cargo-check`'s real-crate CI tests ([#2112](https://github.com/Digital-Process-Tools/claude-supertool/issues/2112)): rustup resolves its default toolchain from `RUSTUP_HOME`/`CARGO_HOME`, defaulting to `$HOME/.rustup` and `$HOME/.cargo`, so a redirected `HOME` left it with no default toolchain to choose. The fixture now preserves both from the real home before redirecting, a named allowlist rather than a general fix -- the next external tool that resolves a default the same way will need its own entry.
