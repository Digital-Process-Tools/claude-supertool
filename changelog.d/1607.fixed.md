- **`gl-mr:N:status` named no approval state at all, and `gl-issue` could not answer "which MR will close this"** ([#1607](https://github.com/Digital-Process-Tools/claude-supertool/issues/1607) items 2 and 3 of the original 4; item 1, the pipeline leg tally, shipped in #1755). `:status` now buys one extra `glab api` approvals request unconditionally — the same #815 "state it, don't smuggle it" argument the leg tally already makes — and prints `approved_by: ...` reusing `_approvals_line`'s existing three-state contract (approved/none/UNKNOWN with a reason), so "no approvals" can never render for "did not ask"; the `gitlab-mr` watch poller does not call `:status` at all, so this cost is paid only by an ad-hoc maintainer call. `gl-issue`'s `Related MRs:` (`related_merge_requests`) answers "does anything reference this issue", not "will this close it" — GitHub's `Linked PRs:` answers the narrower question, settled in #780. `gl-issue` now also queries GitLab's `/issues/:iid/closed_by` and prints a second `Closing MRs:` section carrying the same cap/`:full`/three-state disclosure as `Related MRs:`, rather than switching the existing heading onto data it was never asked for. Item 4 (`gl-issues`, a listing op the size of `gh-issues`' 1439 lines) is a new op rather than a field tweak and was not taken in this change — left tracked under #1607.
