- **Two more core-only registry keys leaked into an op's own subprocess, and three shipped config defaults did nothing** ([#1757](https://github.com/Digital-Process-Tools/claude-supertool/issues/1757)). `_OP_CONFIG_RESERVED_KEYS` was a denylist written as an allowlist: `replaces` (#1347), `paths` (#1357) and `exitStatus` (#1672) were each reserved one issue at a time, and the mechanism re-opens the moment a new metadata key is added. `safety` and `repo_target` -- both read only by the core off the merged registry entry, never by the op's own subprocess -- now join the reserved set. Separately, `.supertool.json`'s `default_status_posts` / `default_status_comments` / `default_status_limit` for `devto_status_since`, `hashnode_status_since` and `bluesky_status_since` were stamped as `SUPERTOOL_DEFAULT_STATUS_*`, while every reader asks for the un-prefixed `SUPERTOOL_STATUS_*` -- a user setting one of these got the hardcoded fallback silently. The three config keys are renamed to `status_posts` / `status_comments` / `status_limit` so the shipped defaults now actually take effect.
