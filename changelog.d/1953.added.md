- **`watch:gh-branch:<ref>` -- a branch tier, so the default branch can be watched instead of only reported** ([#1953](https://github.com/Digital-Process-Tools/claude-supertool/issues/1953)). No tier watched a branch: `presets/watch/tiers/` held `gh_prs.py` and `gl_mrs.py`, both keyed on a forge review object, so a consumer that recorded "wait until the default branch is green" had written a condition nothing on the channel could ever satisfy -- `radar`'s own default-branch member row *pulls* that answer at report time and never *pushes* one, and a tier that does not exist and a branch with nothing to report are the same silence. The new source reuses the exact composition `gh-branch:<ref>` and the member row already use (`_head_commit`, `_run_list`, `runs_on_sha`, `verdict` from `presets/github/branch.py`) and emits once per **state transition**, polling every 30 seconds like `gh-run`/`github-pr`. The event vocabulary is `gh-branch`'s own four states, unfolded rather than collapsed into a green/red pair: `went_green`, `went_not_green` (covers both "a leg failed" and "nothing failed but nothing has concluded either" -- the sentence in the payload carries which), `no_run` (zero runs on the head commit -- the ordinary state for the first seconds after a squash, never a false red), and `unknown` (a job list that did not come back). A lookup that cannot resolve the ref or list runs at all fires `branch_unreachable` once per outage, the same edge-triggered shape every other source's `*_unreachable` event already has. `<ref>` names the branch explicitly (`watch:gh-branch:main`) rather than resolving "the repository's default branch" itself, since a poller has no per-tick moment to re-derive that the way `radar`'s member row does.
