- **`tests/test_parallel.py` no longer flakes on the read freshness note** ([#2347](https://github.com/Digital-Process-Tools/claude-supertool/issues/2347)). `test_parallel_preserves_input_order` compares a sequential and a parallel `read` batch byte-for-byte, but #1379 added `, modified Ns ago` to `read`'s own header, computed from wall-clock time at the instant each of the two `subprocess.run` calls runs -- enough elapsed time on a loaded runner (`modified 2s ago` vs `modified 0s ago`) turned a correct receipt into a failing assertion, reddening `pytest (windows-latest, 3.10)` on master. The comparison now normalizes the freshness note out of both sides the same way it already normalizes the `git?` decline token (#1364) out of both sides, leaving order, content and every other formatting detail exactly as byte-exact as before. A new deterministic test backdates the files with `os.utime` between the two runs so the race reproduces on any machine, not just a slow one.
