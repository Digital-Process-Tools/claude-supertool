- `phpstan` exiting 0 with nothing on stdout is now `skipped`, not a clean pass. The adapter synthesised `{"totals": {"file_errors": 0}}` for that case, which is `ok: true` about a file nothing opened. Measured against phpstan 2.1.55, a clean run under `--error-format=json` always writes its object — `{"totals":{"errors":0,"file_errors":0},"files":{},"errors":[]}` — so silence there is a run that produced no report, not a file with no findings (#1547).
- `phpmd-mcp` no longer throws away a report it was handed. The `structuredContent["error"]` branch returned before `structuredContent["output"]` was read, so a run that set both published a message about the analysis in place of the analysis. The report is parsed first now and its violations always survive: a genuine runtime error is one additional error beside them, and a scope refusal is dropped rather than counted, because a declination and a report are two mutually exclusive claims and only one of them carries evidence — the same rule #1527 applied to the cold phpstan adapter. Whether the `mcp-phpmd-warm` server can set both keys is not answerable from this repository, so the adapter no longer depends on the answer (#1547).
