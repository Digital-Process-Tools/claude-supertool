- **Every publish op now appends a short marker disclosing machine authorship, on by default** ([#2042](https://github.com/Digital-Process-Tools/claude-supertool/issues/2042)). `slack_publish`, `bluesky_publish`, `devto_comment`, `hashnode_comment` and `hashnode_reply` posted bodies exactly as composed, with nothing distinguishing them from a human's own words -- under a Slack user token in particular, the posted message carries no badge of any kind. `presets/_publish_safety.py`'s new `apply_disclosure`, on the same shared path `publish_body_allowlist` already lives on, appends `[AI-generated]` to the body before it is sent and before any confirmation preview is shown, so a human confirming a publish sees the disclaimer that will actually be attached. Silence about authorship is a decision that must be findable, never a side effect of the body being long: suppress it with `SUPERTOOL_NO_PUBLISH_DISCLOSURE=1` or `"no_publish_disclosure": true` in `.supertool.json` (both reported on the receipt as `(disclosure: suppressed)`), override the text with `"publish_disclosure_text"`, or -- for Bluesky's 300-character cap -- the marker is dropped rather than truncating the body, reported as `(disclosure: dropped)`.
  - Compatibility: breaking - every published body now carries extra text by default; a caller matching an exact posted body, or a downstream consumer parsing one, must account for the appended marker or opt out via `.supertool.json`/env.
