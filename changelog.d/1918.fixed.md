- **`#1475`'s census scored a whole sink node clean when any one value in it carried a mark, discarding every other raw stream on the same line** ([#1918](https://github.com/Digital-Process-Tools/claude-supertool/issues/1918)). `_unmarked` used to gate on `MARKS & _call_names(node)` — `_call_names` walking the whole subtree — so one `_untrusted.flat(...)` anywhere inside a `print(...)`, including inlined into an f-string, cleared the node entirely. PR #1913 inlined `flat()` into one value of a print that also carried `mr_state` and `pipe_status` raw; both vanished from the census with nothing fixed, the file's count read as a repair, and the ratchet's own failure text told the reader to write the smaller number down.

  **Per-value marking, not per-node.** `_unmarked` now walks the AST directly and stops descending only at a `MARKS` (or `NOT_TEXT`) call's own arguments — the same boundary `_walk_text` already draws for `NOT_TEXT` — so a mark clears the value it wraps and nothing beside it. Two node shapes needed their own rule rather than a blind walk, because a blind walk over them would have turned this fix into the census-inflating one the issue explicitly warned against: `IfExp.test` (a ternary's condition, never its value — five of the sites this fix first surfaced were `_untrusted.flat(tail[-1]) if tail else "…"` guards, where the old walk read `tail` a second time as the boolean test) and a comprehension's `iter`/`ifs` (which decide what is bound and what is kept, never what is produced — `_comprehension_keys` reads a comprehension's value off its `elt`, tainting a loop target only when its own `iter` was tainted, the same rule an ordinary assignment already gets).

  **The real count moved, in both directions, and both are shown rather than adjusted until green.** Measured on this tree: 145 -> 139 sites in 32 files, `UNRESOLVED` 113 -> 109. All of the movement is a correction of pre-existing imprecision in `_streams_in`'s blind subtree walk (ternary-test and comprehension-iter false positives that predate this issue and were not specific to a MARKS site), not a new defect surfacing — no file's count rose. Every changed line is traced and reasoned about in `CENSUS`'s own comments.

  **What per-value marking still cannot see, stated rather than silently assumed**, per two fixture pairs added alongside the fix (`test_a_mark_on_one_value_does_not_clear_its_siblings` / `test_the_same_sink_with_only_the_marked_value_counts_zero`): a mark applied to one name and the same raw value read again under a second, untracked alias — not a new gap, the same blind spot `_streams_in` already had; and a comprehension whose loop target is a tuple (`[a for a, _w in cut]`) — unlike a top-level tuple-unpacking assignment, there is no `ast.Call` node for `_escapes_from` to hang an `UNRESOLVED` disclosure on, so a raw value reaching a sink this way would leave silently. Both live instances of that shape (`status.py`'s `known`, `pipeline.py`'s `summary`) were checked by hand and are genuinely safe; a comprehension shaped this way earns its own disclosure mechanism if one is ever found to matter.
