- **The changelog fragment guard reported `ok` while the released file carried the injected lines it was built to refuse** ([#930](https://github.com/Digital-Process-Tools/claude-supertool/issues/930)). [#927](https://github.com/Digital-Process-Tools/claude-supertool/pull/927) closed [#923](https://github.com/Digital-Process-Tools/claude-supertool/issues/923) by refusing a fragment line that would become a heading or a link-reference definition of `CHANGELOG.md`, and anchored every pattern at column 0. CommonMark does not: it allows **0-3 leading spaces** before both constructs, link **labels are case-insensitive**, and *any* `[label]:` line is a definition rather than the two the pattern enumerated. Three bypasses followed from that one anchor — a heading indented by one to three spaces, a lowercase `[unreleased]:`, and a definition of any other label — and each produced `ok` on both `--check` and the release write while `CHANGELOG.md` gained the line. Fragment bodies are inserted near the top of the file and the genuine link refs are at the bottom, so a planted definition is the *first* one for its label, which is the one a reader's Markdown resolves.

  **The receipt was the other half of the defect.** `no body writes at column 0` stayed literally true through all three, because it named where the pattern was anchored rather than what a reader was trusting the gate for. It now states the property: no body line would become a heading or a link ref of `CHANGELOG.md`. The refusal's prescribed remedy was wrong in the same way — it told the author to indent by two spaces, which is a live heading and a live link ref, walking them into the bypass. It now says four.

  **Four spaces is the boundary, and a tab is deliberately not in the pattern.** At four columns CommonMark reads an indented code block, and `_anchor`, `_unreleased_span` and `_link_ref_block` each read something that is neither a heading nor a link ref, so the rule and the safety property remain the same line — which is why, as in [#927](https://github.com/Digital-Process-Tools/claude-supertool/pull/927), no fence parser is needed and none was added: nothing downstream understands fences either, git's merge driver included. A leading tab advances to the next four-column tab stop, so a tab-indented line is already at or past the boundary; refusing it would cost an author a safe line and buy nothing, and every character class added to a guard is one someone trips over writing an ordinary entry.

  **The same column-0 assumption was one layer down, and it failed closed rather than open.** The pattern that finds the trailing link-ref block stopped its backward walk at a definition written with one to three spaces, truncating the block or missing it entirely — so the release advanced no link at all and shipped a `## [x.y.z]` heading whose link resolves to nothing, under a receipt stating only that no compare line was found. That pattern now allows the same 0-3 spaces. Recognising an indented line as part of the block is not permission to write it: the rewrite target stays anchored at column 0, where the assembler's own line is, so an indented look-alike inside the block cannot capture it.
