- **`presets/slack/_authorization.py::load_project_config` now carries the same #695 trust boundary the other three walk-up loaders already carry, instead of being the fourth walker nobody hardened** ([#2416](https://github.com/Digital-Process-Tools/claude-supertool/issues/2416)). It walked from cwd all the way to `/` looking for `.supertool.json`, with no stop at the nearest `.git` ancestor and no ownership/group-world-writable check -- the exact class of bug #695 closed for `_supertool._load_config`, #2370 closed for `presets/worktree/_common.py::load_config`, and #2365 closed for `presets/gitlab/_maintenance.py::load_config`, all of which had to re-implement the same two limits because a preset cannot import the core module. The block this file reads can NARROW a Slack channel's authorization level (never widen it), so a `.supertool.json` sitting above the repository root, owned by another local account, or group/world-writable, could previously supply that narrowing decision. `load_project_config` now stops at the nearest `.git` ancestor and skips a candidate that fails `_config_trust_violation` (POSIX-only; trusted unconditionally on Windows, root treated as trusted) exactly like an absent one, so the walk can still find a further, trusted config higher up.
