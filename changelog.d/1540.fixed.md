- **A symlink planted on a watch state file's temporary name was written through by every reader, and only the poller path had ever checked ([#1540](https://github.com/Digital-Process-Tools/claude-supertool/issues/1540)).** #1518 established the derived state directory through `presets/_image_root.ensure` and wired it into `transport.claim_pidfile` -- the one path that spawns a poller, and the one path that was never the problem. `transport.write_state` opened `f"{state_path}.tmp"` with a plain `open(..., "w")`, and it is reached from `record_death` (`watches`, `unwatch`, the `radar` heal) and `clear_deaths` (`watch`, `unwatch`) in processes that never claim a slot. The channel name is public -- this repo commits `"watch_name": "oss-supertool"` to its own `.supertool.json` -- so a co-tenant creating `/tmp/supertool-watch-<name>/` first, with a stale pid file and a symlink at `supertool-watch-<src>__<id>.state.json.tmp`, got any file the victim can write truncated and refilled with state JSON whose `last_event.payload` is remote text. The `.tmp` is now opened `O_WRONLY|O_CREAT|O_TRUNC|O_NOFOLLOW`, the write mirror of the `O_RDONLY|O_NOFOLLOW` that `read_state_checked` and `read_pid_checked` have carried since #1197/#1200; and a *derived* directory is established through `ensure` once per process on the first write, so a reader refuses a squatted directory the same way a poller already did. `write_state` returns the refusal instead of swallowing it, and `record_death` and `clear_deaths` return `False` when nothing reached disk -- they used to report a death as recorded and a ledger as cleared after an `OSError` they discarded. **Not closed:** a co-tenant who takes `/tmp/supertool-watch-<name>` before you still owns it, and every write to that channel -- reader and poller alike -- now refuses until it is removed; and the unnamed default keeps its state files loose in world-writable `/tmp`, where there is no directory to establish and `O_NOFOLLOW` on each name is the whole boundary. On Windows `O_NOFOLLOW` does not exist and the flag is `0`, so that half declines rather than pretending, exactly as `_image_root` declines the `st_uid` and mode arms there.
