- **A symlink planted on a watch state file's temporary name was written through by every reader, and only the poller path had ever checked ([#1540](https://github.com/Digital-Process-Tools/claude-supertool/issues/1540)).** #1518 established the derived state directory through `presets/_image_root.ensure` and wired it into `transport.claim_pidfile` -- the one path that spawns a poller, and the one path that was never the problem. `transport.write_state` opened `f"{state_path}.tmp"` with a plain `open(..., "w")`, and it is reached from `record_death` (`watches`, `unwatch`, the `radar` heal) and `clear_deaths` (`watch`, `unwatch`) in processes that never claim a slot. The channel name is public -- this repo commits `"watch_name": "oss-supertool"` to its own `.supertool.json` -- so a co-tenant creating `/tmp/supertool-watch-<name>/` first, with a stale pid file and a symlink at `supertool-watch-<src>__<id>.state.json.tmp`, got any file the victim can write truncated and refilled with state JSON whose `last_event.payload` is remote text. The temporary is now created by `tempfile.mkstemp` -- a name carrying ~40 random bits that nobody can pre-take, opened `O_CREAT|O_EXCL` so it comes into existence with our create and there is no window to plant anything at it, with `O_NOFOLLOW` and `O_BINARY` added where the platform has them. The first cut of this fix instead opened the fixed `<path>.tmp` with `O_WRONLY|O_CREAT|O_TRUNC|O_NOFOLLOW`, the write mirror of the `O_RDONLY|O_NOFOLLOW` that `read_state_checked` and `read_pid_checked` have carried since #1197/#1200 -- and `O_NOFOLLOW` does not exist on Windows, where `getattr(os, "O_NOFOLLOW", 0)` is `0`, so the open followed the planted link in silence and three `windows-latest` legs overwrote the victim while ubuntu and macOS were green. A guard that cannot run on a platform rendering as a guard that passed, arriving inside the fix for exactly that. A *derived* directory is also established through `ensure` on every write -- not memoized, because `O_NOFOLLOW` guards the final component only and a cached "established" would report an old measurement of the parent as a current fact -- so a reader refuses a squatted directory the same way a poller already did. `write_state` returns the refusal instead of swallowing it, and `record_death` and `clear_deaths` return `False` when nothing reached disk -- they used to report a death as recorded and a ledger as cleared after an `OSError` they discarded. **Not closed:** a co-tenant who takes `/tmp/supertool-watch-<name>` before you still owns it, and every write to that channel -- reader and poller alike -- now refuses until it is removed; and the unnamed default keeps its state files loose in world-writable `/tmp`, where there is no directory to establish and the temporary's unpredictable name is the whole of the write-side boundary. `tiers/_snapshot.write` -- `radar`'s delta snapshot, in the same directory under a name of the same shape -- opened `f"{target}.tmp"` with a plain `open(..., "w")` and had no guard at all, so #1540's mechanism applied to it unchanged and on every platform; both writers now go through one `transport.write_json_contained`. The residual of the unpredictable name is litter rather than exposure: a hard kill between the create and the rename leaves one `<name>.state.json.<random>.tmp` that nothing collects, where a fixed name was reused by the next write. On Windows `_image_root` still declines the `st_uid` and mode arms on the *directory* rather than faking them; that `os.replace` replaces a link planted at the final state name rather than following it is observed on POSIX and only reasoned on Windows, and there is now a test whose Windows leg answers it.
