- `lsp-diag` read cclsp's `Found N diagnostic(s) for X:` header as framing, dropped it, and never compared `N` against the records its parser actually built — the one place the adapter could notice its own parse had lost something. It now reconciles the two and discloses a disagreement as a `code: "adapter"`, `severity: "warning"` record naming both numbers and the direction: fewer records than `N` means findings may be missing and the receipt's count is a floor, more means records were built that the server never framed. Agreement is silent, and so is output carrying no header at all — no number is a different fact from two numbers that match, and a disclosure firing on every run is one nobody reads. `N` is read only from the first framed line, the one position a file under validation cannot get in front of the server, so an echoed `Found 9 diagnostic(s)` in the source cannot choose the number being reconciled against (#1537).
- The same header is now the interlock on a clean verdict the file wrote for itself. `lsp-diag` matches `No diagnostics found` and `no errors, warnings, or hints` as substrings of the whole tool output, so a diagnostic *message* quoting either phrase returned an empty finding list for the entire file — a `.py` or `.php` comment erasing every real diagnostic on it, the #482 shape reached from the inside. Genuinely clean output carries no `Found N` header, so a header claiming entries alongside that phrase is now reported as a disagreement instead of rendering the file clean (#1537).
