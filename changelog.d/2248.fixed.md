- **`gh-job:ID:artifact:PATH` now discloses when its download cap could not be checked, instead of silently skipping it** ([#2248](https://github.com/Digital-Process-Tools/claude-supertool/issues/2248)). `print_artifact`'s `isinstance` guard on `artifact["size_in_bytes"]` short-circuited on a missing or non-numeric value, so `_fetch_artifact_zip` buffered the whole archive into memory with the `GH_JOB_ARTIFACT_DOWNLOAD_MAX_BYTES` cap never consulted and nothing in the receipt saying so — the same two-state defect this codebase keeps filing, one file over from `gitlab/job.py`'s own `_is_past` and its "unknown size" fallback, which already draw this line for their sibling fields. An unusable size now prints a `NOTE:` line naming the cap that could not be checked before the archive downloads; a genuine numeric pass under the cap renders no such line, and both are pinned by fixture.
