- **Four `claude-jit-context` hook registrations removed from the tracked `.claude/settings.json`** ([#1726](https://github.com/Digital-Process-Tools/claude-supertool/issues/1726)). They resolved through `$HOME/Documents/claude-jit-context/scripts/`, a clone on one maintainer's disk, behind `[ -f "$S" ] && bash "$S" || true` — so in every other clone all four ran and did nothing, which is indistinguishable from four rules that matched nothing. The `claude-jit-context` plugin registers the same four itself through `${CLAUDE_PLUGIN_ROOT}`, so on the one machine where both paths existed they fired twice; repointing at `$CLAUDE_PROJECT_DIR` was not available, because those scripts are in no checkout of this repository. `.claude/jit-context/` rules are unaffected — the plugin reads them. What stays hand-wired is the raw-command guard, whose script does ship here. `tests/test_settings_hooks_portable_1726.py` refuses a tracked hook command naming `$HOME`, and one that guards on a script's existence without announcing the absent branch.
