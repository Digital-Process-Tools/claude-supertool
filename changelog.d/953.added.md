- **`tick` — "what do I do next", in one read-only call** ([#953](https://github.com/Digital-Process-Tools/claude-supertool/issues/953)). Four reads used to answer the maintainer's standing question and none of them answered it: clone currency, the default branch's CI, the open-PR board and worktree occupancy, joined by hand six times in one session. `tick` performs the join and returns the two facts none of the four carried — which PRs are mergeable right now, and which lanes are free.

  The verdict column is the value and the risk, so `MERGE` is the last branch reached and the only one that asserts anything. It is derived from the shared `_checks` tally and from `gh-pr`'s own leg reconciliation, not a second copy of either: **a tally that does not sum to the legs the run declares renders `UNKNOWN`** — never `WAITING`, which would assert the missing legs are still coming, and never `MERGE`. `MERGE` requires every leg in the passed bucket rather than the absence of a failure, so `CANCELLED`, `SKIPPED`, `TIMED_OUT`, `NEUTRAL`, `ACTION_REQUIRED` and any state added after this shipped fall out as `UNKNOWN` by construction instead of by enumeration.

  Lane occupancy is inferred, and `git-worktrees`' three states are carried all the way up. An open PR or an `occupied` tree makes a lane `occupied`; a lane whose only signal is a tree the occupancy check could not decide is `unknown`, because `cannot tell` is not `idle` one layer up either; and `free` additionally requires that every live worktree in the repository was attributable to some lane, so one stray occupancy nobody could place degrades every otherwise-free lane to `unknown` and names it. Reporting a lane free while an agent works in it is how two agents end up editing one file. The labels themselves live on issues, not on PRs — measured on this repository, seven lanes existed, 54 of 65 open issues carried one, and no open PR carried one at all, so a lane board read off PR labels would have printed all seven free while six PRs and thirteen worktrees were live.

  A section that could not be fetched prints its heading, says `!! unread` with the reason and is counted in the footer, because a tick missing its board must not read as a tick with an empty board; `next:` declines outright rather than advising from data it never got. Read-only permanently — clone currency uses `git ls-remote`, which reads the remote's ref without writing yours, and every command `next:` can name is a read op. GitHub only; GitLab equivalence is stated as out of scope in `docs/presets/tick.md` rather than half-built.
