- **`repo:OWNER/NAME` was a shipped op that no registry admitted exists** ([#1240](https://github.com/Digital-Process-Tools/claude-supertool/issues/1240)). It has been implemented since [#673](https://github.com/Digital-Process-Tools/claude-supertool/issues/673) and is documented in prose in four places, but it was absent from `_MAIN_LEVEL_OPS`, from `_OP_SAFETY_BUILTIN` and from `.supertool.json` — so `ops` did not list it, `help:repo` denied it, the unknown-op message left it out of "Valid operations", and `claims` reported every document citing it as *unchecked* rather than holding. The op that exists to reach another repo could not be discovered from the tool.

  There was no new category to invent: `cwd` is the other leading pseudo-op, `_MAIN_LEVEL_OPS` exists for exactly that class, and its own comment already says they belong in any list a caller reads. `repo` was simply never added to it. Its safety class is declared `read-only` rather than left to the `acts` fallback, which renders `!`.

- **The maintainer skill cited `presets/_pr_board.py` as settled precedent for a module that does not exist** ([#1240](https://github.com/Digital-Process-Tools/claude-supertool/issues/1240)). It is the name [#958](https://github.com/Digital-Process-Tools/claude-supertool/issues/958) proposes and that issue is still open, so the line was quoted at an agent as an existing pattern to follow. It now reads as the work item it is, and names what *is* already shared for that argument — the judgement, `presets/github/pr.py`'s `_reconcile_checks`, which `dashboard` and radar's `gh_prs` tier both call rather than re-derive.
