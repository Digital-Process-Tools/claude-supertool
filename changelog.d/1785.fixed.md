- **Fixed the "may be another project's fleet" warning firing on every `radar`, `watches` and `channel:health` call in a correctly configured repository** ([#1785](https://github.com/Digital-Process-Tools/claude-supertool/issues/1785)). A `.supertool.json` that declares no `watch_name` in any op block is indistinguishable, by this warning alone, from a hand-copied `SUPERTOOL_WATCH_NAME` leaking in from an unrelated project's settings — but the first is a designed path some launchers take on purpose (the `oss` plugin's `bin/oss-workspace` derives the name from a repository's own slug precisely because nothing declares one, rather than binding the shared default socket unknowingly). A launcher that derives the name for a specific directory can now say so by also exporting `SUPERTOOL_WATCH_NAME_ROOT`; when it names the directory holding the (name-silent) `.supertool.json`, the board reports that instead of warning. Absent, or naming a different directory, every case the warning exists for still warns exactly as before.
