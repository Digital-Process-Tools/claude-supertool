Under `SUPERTOOL_PARALLEL`, a `validate:` op's `[result]` footer counted files that belonged to the other ops running alongside it — six single-file ops reported 1/2/3/4/5/6 files, and a single file's finding was claimed by five footers that never saw it ([#1109](https://github.com/Digital-Process-Tools/claude-supertool/issues/1109)). The footer's per-op counts were sliced out of a process-global list by an entry-time `len()` snapshot, which is only per-op while exactly one op is appending. Per-op rows now live on the dispatch frame, which is thread-local, and roll up into the process-global when the frame unwinds — so the whole-call scope the `$SUPERTOOL_REQUIRE_VALIDATORS` exit code reads is unchanged, and a batch's footer still counts its own sub-ops. Sequential runs, the default, were never affected.
