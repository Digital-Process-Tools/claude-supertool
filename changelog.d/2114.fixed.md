- **A write-bound payload field carrying the shell single-quote escape idiom now warns, naming the exact sequence it found** ([#2114](https://github.com/Digital-Process-Tools/claude-supertool/issues/2114)). `'"'"'` and `'\''` -- close a single-quoted string, emit a literal quote another way, reopen -- resolve to one apostrophe inside a shell's own quoting and to nothing inside a TOML literal block, which is what a `content =` / `new =` / `message =` payload field IS: the whole sequence lands on disk at its full length, the write reports success, and every validator agrees, because the sequence is legal text in nearly every language this repo edits. Reproduced for the first time (the reporting lane preserved none): a plain `paste:@` payload writing the idiom mid-word. This is a warning, not a refusal, because unlike #834's trailing-backslash case there is no unambiguous second spelling to offer -- a payload correctly documenting the idiom (this repository's own `CLAUDE.md` is one) writes the exact same bytes a payload that meant a plain apostrophe wrote by mistake, and refusing would strand the correct write with no way out. The write itself is never altered or rewritten either way.
