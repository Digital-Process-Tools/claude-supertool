- **Dropped the Bun requirement for the `claude-channel` MCP server and declared it in the plugin manifest** ([#520](https://github.com/Digital-Process-Tools/claude-supertool/issues/520)). `channel.ts` made zero `Bun.*` calls, so requiring it bought nothing but an install step whose three failure modes — no Bun, a wrong clone path, no watchers spawned — all produce the identical silent symptom: a radar that says nothing. `.mcp.json` now launches it under `node --experimental-strip-types` (the shipped floor is Node 22.6.0; the flag is a documented no-op on anything newer that strips types by default), and `install.sh` installs the one runtime dependency with plain `npm`, refusing loudly on a missing or too-old `node` instead of failing later. `plugin.json` now also declares `"channels": [{"server": "claude-channel"}]`, making the plugin structurally a channel provider. Checked against the current plugins/channels reference rather than assumed: this declaration does **not** exempt a user from `--dangerously-load-development-channels` — that flag is gated by allowlist membership (Anthropic's `claude-plugins-official`, or an org's own `allowedChannelPlugins`), never by the manifest, and the bypass it grants is per-entry, on every launch, until this plugin lands on that allowlist. `install.sh`, this repo's own `README.md`s and `docs/presets/watch.md` say so explicitly rather than implying the flag is now optional.

  Deliberately unchanged: `.github/workflows/tests.yml`'s `notifiers` job still exercises `channel.ts` under Bun, and `notifiers/claude-channel/bun.lock` stays. Both are relied on by that job's own frozen-lockfile install and cache key, and by several existing tests that assert on the job's literal structure (`tests/test_ci_non_python_coverage_557.py`, `tests/test_ci_pip_cache_890.py`) — removing Bun from CI's own contributor-facing toolchain is a separate, larger change than fixing the end-user-facing install path this issue is about, and is filed rather than folded in here.
