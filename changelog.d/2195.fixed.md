- **The guard's `origin_faithful`/`command_faithful` flags were falsely `True` for a command carrying a numbered fd redirect (`2>&1`)** ([#2195](https://github.com/Digital-Process-Tools/claude-supertool/issues/2195)). `_guard_drop_io_numbers` strips the leading digit off a numbered redirect (`2>&1` becomes `>&1`) before `_guard_segments_with_origins` sliced its render, so `git status 2>&1` refused with `command`/`discarded` rendered as `git status >&1` while the flag that exists to certify a faithful character-for-character render said `True`. The digit-drop stays -- it is still needed downstream so a stray `2` never lands in an argv as an extra positional (#1684) -- but `origin_texts`/`GuardMatch.command`/`GuardVerdict.discarded` now render an UNDROPPED slice of the same span, so the fidelity flag is genuinely true rather than falsely so.
