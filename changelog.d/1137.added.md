- **`git-commit:::MESSAGE:::--all` — an explicit way to accept the paths the refusal just counted** ([#1137](https://github.com/Digital-Process-Tools/claude-supertool/issues/1137)). The bare form still refuses, which is the point: committing whatever happens to be dirty is how an unrelated file rides into a release commit. But the refusal printed `24 paths in all, 20 shown and 4 not shown — name the ones you mean` and then offered no way to say "those ones", so satisfying it meant dropping to a raw `git status --porcelain` heredoc to rebuild the list the op had already computed.

  `--all` stages every modified-tracked and untracked path — ignored files excluded, since that is what `git status` reports — and the receipt then lists **all** of them, uncapped, rather than the usual first 20. The cap is right when the caller typed the list and already has it; under `--all` the caller typed nothing and the receipt is the only record of what was chosen, so a capped one would be a subset presented as the whole. `paths = ["--all"]` spells the same thing on the `@payload` route.

  Three ambiguities are refused rather than resolved: `--all` beside a named path (one of the two readings silently drops files under a green tick), a repository where git knows a file literally called `--all` (the remedy is `:::./--all`; the payload route reaches the same argument and is no escape hatch), and a `git status` that did not answer — which returns two empty lists, and staging those would be an empty commit dressed as a deliberate one.
