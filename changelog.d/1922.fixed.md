- **`gh-prs`' and `gl-mrs`' unwatched footer disagreed with `radar` and `watches` under a named watch channel** ([#1922](https://github.com/Digital-Process-Tools/claude-supertool/issues/1922)). Both boards hardcoded their own `STATE_DIR = "/tmp"` as the default poller-pidfile directory for `_watched_numbers`/`_watched_iids`, while `presets/watch/transport.py` resolves the actual directory (`transport.STATE_DIR`) — `/tmp/supertool-watch-<name>` under `SUPERTOOL_WATCH_NAME`, or wherever `SUPERTOOL_WATCH_STATE_DIR` points. `radar` and `watches` already read the resolved directory, so only the board's own footer looked in the wrong place and reported a PR/MR unwatched while a live, emitting poller held its slot — exactly the shape reported live, under `SUPERTOOL_WATCH_NAME=oss-supertool`. Both `main()`s now pass `transport.STATE_DIR` explicitly, the same value `radar`'s tier already passes. `tests/test_gh_prs_footer_state_dir_1922.py` pins the control pair the issue asked for — an armed poller under a non-default state dir reads as covered, a bare one still reads as unwatched — for both boards, plus a direct before/after comparison against the stale default that reproduces the reported mismatch.
