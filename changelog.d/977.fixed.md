- **`git-status` flattened an MR/MR target branch and then built a git ref from the flattened name** ([#977](https://github.com/Digital-Process-Tools/claude-supertool/issues/977)). `presets/git/status.py` ran `mr_target = _untrusted.flat(str(mr.get("target_branch", "?")))` and then built `f"origin/{mr_target}"` for `git diff --shortstat`. `flat()` folds U+2028/U+2029 to a space, and `git check-ref-format` accepts both in a refname (#1654), so a target branch carrying one built a ref that does not exist — the diff call failed silently and the `(+a -d)` figure vanished with no error shown anywhere. The fix keeps the raw name for the ref and flattens only at the print, the same split `presets/github/job.py` already uses for `pr_branch`/`_local_branch_check`. The GitHub sibling (`pr_target` in the same file) was checked and is display-only, so it needed no change.
- **`per=²` crashing the refusal instead of refusing it was already fixed** ([#977](https://github.com/Digital-Process-Tools/claude-supertool/issues/977)). The issue was filed against v0.26.0; #1727 (then #1748/#1764/#1765) replaced the `str.isdigit()`-then-`int()` shape across every preset guard, including `presets/_filter_tokens.py::bad_values`, with `presets/_digits.is_ascii_int` — an anchored ASCII-only `^[0-9]+\Z`. `²` and `٢` are both refused cleanly today; no code change was needed for this half.
