- **A state token from a remote check could add a line to the tally that reports it** ([#1453](https://github.com/Digital-Process-Tools/claude-supertool/issues/1453)). `_checks.normalize()` stripped only leading and trailing whitespace, so an internal newline in a job's `conclusion`, `status` or `state` survived into `summarize()`'s leftover term — and from there into `gh-branch`'s two-space-indented table and its `Legs:` line, the two lines [#1449](https://github.com/Digital-Process-Tools/claude-supertool/pull/1449) had just flattened four other fields on. The flatten now happens in `normalize()` itself rather than at either render, which also closes the five other places that print its return value unchanged: `gh-pr-merge`'s `mergeable` and `mergeStateStatus` lines, the dashboard's equivalents, and `gh-branch`'s run conclusion. Fixing the two lines the issue named would have left five open, which is the per-call-site failure #1449 rejected one file over.

  It cannot change a verdict: no member of `PASSED_STATES`, `FAILED_STATES`, `PENDING_STATES` or `BENIGN_STATES` contains whitespace, so a token that gains a space can neither enter a set nor leave one.

  `label()` additionally substitutes the comma, because that is a second forgery on the same line and flattening does not reach it. `summarize()` promises its output "can be audited by arithmetic instead of by trusting the labels" and its terms are comma-separated, so a state reading `x, 5 passed` rendered as `1 x, 5 passed` and forged a term inside the audited list. Only there — a comma is never legitimate in a state token, and routinely is in the matrix job names `shortfall()` renders.
