- **Split `gh-branch`'s poller `NOT_GREEN` into a pending state and a failed state, and made the transition test sha-aware** ([#2355](https://github.com/Digital-Process-Tools/claude-supertool/issues/2355)). `master` sat red for 3h33m on 2026-09-07 with a live `gh-branch` watcher, because a pending-to-failed transition on the same commit changed nothing the old `branch_state != prev_state` comparison could see -- `NOT_GREEN` folded "nothing has concluded yet" and "a leg failed" into one string, and the sentence that would have carried the distinction only ships on a transition. The poller now classifies `NOT_GREEN` into `NOT_GREEN_PENDING`/`NOT_GREEN_FAILED` structurally, off `branch._red_workflows(selected, legs)` -- the same data `branch.verdict()` reads before it ever renders a sentence, never the sentence itself. A first cut classified by scanning the rendered sentence for a marker substring; two reviewers spawned against the committed diff independently found the hole -- `verdict()`'s pending sentence interpolates a workflow's own GitHub `name:` field, which a repo author can spell however they like, so a workflow literally named after the marker text would have forged a false "failed" reading on a genuinely pending commit. `events.json` gains a `went_failed` event alongside the now-narrower `went_not_green` (pending only) -- a real behavior change for any consumer keyed on the old, coarser `went_not_green`. `presets/watch/tiers/gh_prs.py`'s `BRANCH_ONLY` event allowlist is updated to include it, or the new event would have been silently filtered out at the watch subscription layer.

  The transition test also now compares `sha`, not just the coarse state: a branch moving to a brand-new commit while remaining in the same category (e.g. still pending) now emits too, since a consumer holding the previous sentence had no way to learn the subject changed under it. This widens emission volume for every new commit on a watched branch -- decided deliberately here rather than inherited silently, per the issue's own request.

  `presets/github/branch.py`'s own four-state vocabulary (`GREEN`/`NOT_GREEN`/`NO_RUN`/`UNKNOWN`) is unchanged; `dashboard.py` and `presets/watch/tiers/gh_prs.py`'s `default_branch_report` keep rendering the coarse `NOT_GREEN` sentence as before. Only the poller (`presets/watch/sources/gh-branch/poller.py`) reads the finer split.
