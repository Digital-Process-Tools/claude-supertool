- **The trap.d/ population guard reddened master the moment a curate pass finally drained it** ([#2568](https://github.com/Digital-Process-Tools/claude-supertool/issues/2568)). `test_no_local_home_paths_in_trap_d` paired its local-path scan with a positive control -- "at least 5 files must be found, or the glob silently stopped working" -- pinned to the count present the day the guard was written (#2426). `curate_route_threshold` was only configured this week (#2561, #2565), so PR #2567, the first curate pass ever to run, drained all 52 fragments as designed and the fixed floor of 5 turned that success into a CI failure: `assert 1 >= 5` against a directory correctly holding only `trap.d/README.md`. The floor is now a discriminator instead of a count: `README.md` is tracked, never a fragment, and never removed by a curate pass, so its presence in the `trap.d/*.md` glob proves the scan mechanism still works, whatever it finds beside it. Missing `README.md` still fails loudly (a broken glob renders exactly like a legitimately-scanned zero otherwise); zero real fragments beside a found `README.md` now passes. `test_scan_fragments_detects_broken_glob`, `test_scan_fragments_passes_on_legitimately_drained_directory` and `test_scan_fragments_still_finds_real_fragments_beside_readme` pin the new three-way behaviour directly, and reproducing PR #2567's exact drained state (`README.md` only) against the old `>= 5` assertion confirms it was the guard's own floor that was wrong, not the diff it blocked.
