- **`read` and `git-status` now say how fresh their own answer is** ([#1379](https://github.com/Digital-Process-Tools/claude-supertool/issues/1379)). `[complete file — no more lines]` and `Working tree: clean` were both correct when printed and carried no instant with them, so a reader with no memory could not tell a fact read a minute ago from one read just now -- one session spent ~20 minutes reconciling a 17-line `[complete file]` read against a file that had grown to 35 lines a minute later. `read`'s header now carries the file's own freshness, `(N lines, N bytes, modified 2s ago)`, at the cost of one extra `os.stat` the header line was already about to pay for `_path_meta_suffix`. `git-status`'s `Working tree: clean` now carries HEAD's own commit age, `clean, HEAD 15s old`, reusing the same short-age vocabulary `git-worktrees` already renders as `newest write … ago`. Both decline rather than guess when the age cannot be determined.
