- **`worktree:setup` no longer overwrites a real provisioning manifest with an empty one when it cannot tell whether one already exists** ([#2386](https://github.com/Digital-Process-Tools/claude-supertool/issues/2386)). `read_manifest` reports a `read_manifest` failure -- a transient `git` error resolving the manifest path (#2371), or a manifest file that exists but fails to parse -- as `ConfigResult(None, error=...)`, an UNKNOWN rather than a genuine "setup never ran". `setup_op.py` used to treat that `.error` exactly like an empty manifest: it rebuilt an in-memory manifest from scratch and unconditionally `write_manifest`'d it over whatever was already on disk, silently discarding any `linked`/`copied`/`excluded` entries a PRIOR successful setup run had recorded that this run did not itself re-declare or re-create. Setup still proceeds with provisioning on a `.error` (its own docstring already treats a missing/unreadable *source* as a WARN, never a refusal, and config may have a legitimate reason to run even when the manifest can't be read), but the manifest WRITE step is now skipped whenever the read failed, leaving the on-disk manifest untouched instead of clobbering it with an incomplete record. A genuine first-ever setup (no `.error` at all) is unaffected and still writes a fresh manifest as before.
