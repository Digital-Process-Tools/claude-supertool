- **A warm MCP validator that times out now says what it received, not just that it waited** ([#1927](https://github.com/Digital-Process-Tools/claude-supertool/issues/1927), follow-up to [#1924](https://github.com/Digital-Process-Tools/claude-supertool/issues/1924)). `phpunit-mcp`, `phpstan-mcp`, `phpmd-mcp` and `rector-mcp` all read a JSON-RPC response through `validators/common/ndjson_scan.receive_until`, now with three changes: a short idle deadline (10s by default) after the *last* byte received, distinct from the overall call budget, so a server that has stopped talking is not waited out for the rest of the call's several minutes; the timeout message quotes the first bytes actually received rather than only counting them, so silence and garbage read as the different failures they are; and the daemon's own `<sock>.log` tail rides along in the message when it is there to read. The elapsed time is always stated, so `NOT CHECKED` no longer reads the same at 2s and at 300s.
