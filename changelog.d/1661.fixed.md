- **The `$1`-shim gate's dispatcher exemption now requires a `shift` that runs, not the letters `shift` somewhere in the loop** ([#1661](https://github.com/Digital-Process-Tools/claude-supertool/issues/1661)). The exemption shipped as `if "shift" in m.group(0)` over the loop body text, so any loop mentioning the word — in an `echo`, a comment, a variable name — was read as a dispatcher walking argv, and every `$1` subcommand decision inside it was exempted. A shim could opt itself out of the class by printing a message. The gate's live population was zero at the time, in the file whose entire subject is a detector whose zero meant "I did not look".

  **What counts now is command position, read off the literal with its quoted spans and comments blanked in place.** `shift` has to sit where the shell can start a command — at the beginning, after `;`, `&`, `|`, a brace, a paren or a newline, or after `do`, `then`, `else`, `elif` — with `shift=1` excluded as an assignment and `shiftcount` excluded by the word boundary. Blanking rather than deleting is the point: it preserves offsets, so the loop span and the `shift` inside it are found in the one reading that knows the `;` in `echo "trap: ; shift"` is part of an argument. The first cut of this fix checked for a `shift` per *literal* and then took its spans from the quote-stripped text, which rebuilt the same defect one level in — any real `shift` anywhere licensed a loop whose only `shift` was a quoted word. Review caught it; it is pinned.

  **The `$1` tests are counted in a second reading, and the two have to agree.** Blanking a quoted span would take `"$1"` with it, so the tests are located in a copy where only the quote characters became spaces. `[ x"$1" = x"status" ]` is one test to the quote-*deleting* reading and none to that one, because deletion joins `x` to `$1`. When the two counts differ the exemption is refused rather than aligned against a set of tests the code cannot count.

  **Every arm fails closed.** No `shift` that runs, no loop carrying one, no readable `$1` test — each returns "not exempt" rather than a guess, because an exemption that cannot be established is not an exemption. Measured over `tests/` after the change: 5 string literals test `$1`, exactly 1 is exempted by this rule and it is the real `while`/`shift` dispatcher in `tests/_gitshim.py`, the other 4 are exempted by the option rule from [#1412](https://github.com/Digital-Process-Tools/claude-supertool/issues/1412), and the gate still reports 0 hits — a zero the run now earns.
