- **An unreadable file rendered exactly like a file with no context to show** ([#1446](https://github.com/Digital-Process-Tools/claude-supertool/issues/1446)). `validators/common/source_context.py` swallowed `OSError` and returned `[]` — the same value a located finding gets when its window falls outside the file. Every receipt printed the two identically, and thirty adapters inherited it.

  The finding survives, because it does not depend on us: the tool said something is wrong at that line whether or not we can reprint the line. So only the illustration is qualified. The helper now returns *fields* rather than a list — `**context_fields(target, line)` — and a read that failed carries a `context_unavailable` reason beside the empty `source_context`, rendered in verbose mode as `[no source context: FileNotFoundError reading ...]`. Three states where there were two: lines, no lines, and could-not-look.

  Not theoretical, and not Windows-only the way the `pkg_paths` instance in #1443 was. Measured against `Path.read_text` on macOS: a directory raises `IsADirectoryError`, a `chmod 000` file `PermissionError`, a deleted target `FileNotFoundError`, a symlink loop `OSError` errno 62. `phpunit-mcp` renders context from a path taken out of the tool's own output, and a `slow`-tier validator runs at the end of the call, by which time the target may be gone.

  `source_context()` is removed rather than deprecated: left in place, the next adapter copies the call that was already in twenty-eight files. `phpstan-mcp` and `phpunit-mcp` carried private copies of the same swallow and now use the shared helper; a test refuses any new copy of either.
