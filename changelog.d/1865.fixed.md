- **`git-commit` with `--all` carries both halves of a staged rename** ([#1865](https://github.com/Digital-Process-Tools/claude-supertool/issues/1865)). `--all` resolves to the working tree's dirty paths plus everything in the index, and it read the index with `git diff --cached --name-only` — which has rename detection on by default, so a staged `git mv a b` printed `b` alone and the deletion of `a` never appeared. The commit was scoped to the new path, the deletion stayed staged, and half a rename landed: two copies of the moved file in one tree, compiling and passing any test that only touches the new path. The index reads now pass `--no-renames`, so `--all` means what its own contract already said. A call that NAMES its paths still leaves an unrelated staged path alone — "commit everything staged" remains the pathless spelling and a different op (#1228).
