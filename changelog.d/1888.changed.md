- **Census: no other `validators/*` adapter treats an `OSError` from `communicate()` as a dead child** ([#1888](https://github.com/Digital-Process-Tools/claude-supertool/issues/1888)). PR [#1883](https://github.com/Digital-Process-Tools/claude-supertool/pull/1883) fixed that shape in `git-status.py` — a broken pipe under a live child is not the same event as a dead one, and the first `_stop()` conflated them, leaking a process that could still hold `.git/index.lock`. Every other adapter that spawns a subprocess does so through a single `subprocess.run(..., timeout=...)` call rather than its own `Popen`/`communicate()`/kill path, so there is no site outside `git-status.py` where an adapter's own code makes that read. `tests/test_communicate_oserror_census_1888.py` pins the population so a future adapter growing its own manual teardown does not pass this census unexamined. A residual instance of the same shape was found inside `git-status.py` itself — its outer `run()` catches `TimeoutExpired` around its first `communicate()` call but not `OSError`, so that call can still leak a live child on a broken pipe outside the already-fixed `_stop()` path — and is filed rather than fixed here, since `git-status.py` is this issue's reference implementation, not a site this diff touches.
