- **`_merge_presets` now warns when a `builtin-ops` section, or a `builtin-ops.<op>` entry inside it, is not a table — instead of storing it silently, and the two runtime readers that used to crash on one now fall back to their default instead** ([#2308](https://github.com/Digital-Process-Tools/claude-supertool/issues/2308)). #2079 fixed this ONE layer above — `registry:OP` could not disclose a malformed `builtin-ops` entry byte-identically to no override at all — but every runtime reader downstream still fell back to its own default with nothing recorded, or so this fix originally claimed: self-review across two rounds (a spawned reviewer, and the oss:auditor across two runs) found three further instances of the same class in the immediate area. `_get_op_int` and `_grep_file_includes` actually raised `AttributeError` on a non-table entry rather than falling back, which is worse than the silent default the fix's own new warning text promised — only `_get_op_bool` already carried the needed `isinstance` guard; both readers now carry it too. A preset whose WHOLE `builtin-ops` section (not just one op's entry inside it) was not a table used to skip the merge branch entirely with nothing recorded, dropped exactly as if the preset had declared no `builtin-ops` at all — now recorded on the same `_preset_warnings` channel as the per-entry case. And the sibling gap one layer up was closed too: `_load_config()` used to coerce a `.supertool.json` that parses but is not a JSON object (an array, string, or number) to `{}` with nothing recorded, identically to no config file existing at all; it now records that in `_CONFIG_WARNINGS`, matching the policy chosen for #2306's own loader in the same commit.
