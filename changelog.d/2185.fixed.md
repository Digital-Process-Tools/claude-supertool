- **A `resolve`-class validator command that could not look (git absent, timed out, not a repo, unspawnable, or its own crash) is no longer invisible to `$SUPERTOOL_REQUIRE_VALIDATORS`** ([#2185](https://github.com/Digital-Process-Tools/claude-supertool/issues/2185)). Routed through the same `_validator_unusable_reply` seam the four other core-detected "this validator is too broken to answer for itself" cases already use, so it now sets the same `no_verdict` marker and escalates the exit code and the row the same way they do -- while staying a quiet `skipped` on an ordinary, unrequired edit, and deliberately short of the unconditional `NOT CHECKED` a self-reported adapter crash gets, for the same reason those four cases are gated rather than unconditional.
