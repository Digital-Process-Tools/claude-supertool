- **A malformed project `.supertool.json` no longer silently widens a Slack channel's authorization back to the machine-owner's base level** ([#2427](https://github.com/Digital-Process-Tools/claude-supertool/issues/2427)). `presets/slack/_authorization.py::load_project_config()` collapsed three distinct cases -- no project config, project config found but malformed (truncated write, merge marker), and walked to the repo root with nothing found -- into the same `{}`, and `resolve_channel` had no arm distinguishing "malformed" from "not found". A repo that had narrowed a channel to `off` via `.supertool.json`, whose config then became malformed, fell back to the wider out-of-repo level and rendered byte-identical to a repo that had never configured Slack at all.

  `load_project_config_result()` now returns the three-state result (`data`/`error`, following `presets/worktree/_common.py`'s `ConfigResult` pattern), and `resolve_channel` takes a `project_config_error` argument: a malformed, tracked project config now fails the channel closed to `off` rather than falling back to `project_config`'s absence-shaped default, and the two cases produce different `detail` strings. `load_project_config()` stays as a back-compat wrapper returning `{}` for both cases, unchanged for any existing caller.
