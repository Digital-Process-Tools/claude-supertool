- **`channel:health` no longer demotes itself over a channel server the harness rejected** ([#2208](https://github.com/Digital-Process-Tools/claude-supertool/issues/2208)). `claude mcp get` exits 0 for a server declared in `.mcp.json` and switched off by `disabledMcpjsonServers`, printing `Status: Rejected (see disabledMcpjsonServers in settings)`. `_configured` read the exit code only, so the #2182 standing-server gate opened and the dual-declaration branch reported a collision against a declaration the harness had already thrown away -- a permanent `CANNOT DETERMINE`, and a permanent `ch?` on the statusline, over a channel that was forwarding normally. Exit 0 is now two answers: a rejected server gates exactly like an absent one. `Status: Failed to connect` is untouched and still positive, because for our own consumer that is what healthy looks like (#550).
