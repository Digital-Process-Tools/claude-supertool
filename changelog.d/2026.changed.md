- **`vim`'s documentation moved into a `vim` preset** ([#2026](https://github.com/Digital-Process-Tools/claude-supertool/issues/2026)). The entry sits under `presets/vim.json`'s `builtin-ops` section, the doc-only shape [#2025](https://github.com/Digital-Process-Tools/claude-supertool/issues/2025) added. The op is untouched: it dispatches from core, and `vim:@-` derives `path` and `script` from `_AT_FILE_BUILTIN_DEFAULTS`, so the payload route works with no config at all — pinned against an empty config rather than against this repo's, because a route deleted by an edit to `syntax` is silent ([#770](https://github.com/Digital-Process-Tools/claude-supertool/issues/770)). Measured here, leaving the preset unlisted takes 1,478 bytes off `ops-compact` and `ops:full` and 19 off the default `ops` listing, which has been signatures-only since [#1774](https://github.com/Digital-Process-Tools/claude-supertool/issues/1774).
- Note what this costs, since the byte figure alone reads as free: `vim`'s description **is** the macro grammar — mode boundaries, the ex subset, the autocorrections — and a repo that does not list the preset loses `help:vim` along with the listing bytes. It carries `hint: true`, so that text is what renders in `ops-compact` in the first place. This repository lists the preset. A repo that uses the op should too; the alternative shape, a one-line `description` beside a `long` key only `help:OP` renders, reaches the same byte count without the loss and is still open for the five remaining `hint: true` entries — `guard` (2,166 bytes), `doctor` (1,341), `repo` (1,051), `registry` (583), `claims` (481).
