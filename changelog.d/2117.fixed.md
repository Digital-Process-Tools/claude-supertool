- **`gh-branch`'s declared-workflow-with-no-run reading had no first-run window, so a commit seconds old could report the one state a release gate treats as blocking** (#2117). GitHub creates workflow runs asynchronously after a push — the same latency `_checks.absence()` already accounts for on the check-run side — but `undispatched_lines`/`scope_for` said "a push trigger IS declared and this commit has no run from it ... UNKNOWN from here" regardless of the commit's age, reproducing #846's own "declared, should have run, and did not" wording on a run that GitHub simply had not created yet. Both functions now take `age_secs`/`grace` (default `_checks.CHECK_CREATION_GRACE_SECS`, the same ~15min window `verdict()`'s own `missing`-workflow branch already uses): a push-triggered workflow with no run on a commit still inside the window reads as "still expected", the same vocabulary as its sibling case, and is excluded from `scope_for`'s `unresolved` marker; past the window, or when a workflow's `on:` block could not be read at all, the wording is unchanged. Every caller of `scope_for` (`gh-branch`, the dashboard, radar's `gh-prs` tier, and the standing `gh-branch` poller) now passes the commit's age.
