- **An ambient `SUPERTOOL_REPO` reaches read ops again** ([#2001](https://github.com/Digital-Process-Tools/claude-supertool/issues/2001)). v0.51.0 shipped a regression: `main()` cleared both `SUPERTOOL_REPO` and its `#1986` from-op marker on entry, so `SUPERTOOL_REPO=owner/name supertool 'watch:...'` silently started a poller against the cwd's repository instead, with no error and no notice. `explicit_target()` — what every payload-mode write route and `gh-pr-merge` call — already gates on the marker alone, so clearing only `SUPERTOOL_REPO_FROM_OP` on entry closes the same hole `#1993` fixed without taking the read path down with it. `docs/presets/watch.md` and `presets/_repo_target.py`'s own docstrings already described the restored behavior and needed no change.
