- **`gh-prs` radar tier: `pr_exclude_events`, an event blacklist for the per-PR pollers it heals** ([claude-oss#1499](https://github.com/Digital-Process-Tools/claude-oss/issues/1499)). `heal()` forked every `github-pr` poller with `only=[]` — no filter, every declared event on every PR, and nothing an operator could set short of unwatching each poller by hand. The new tier option names the keys to drop; the poller's `only=` is every key `sources/github-pr/events.json` declares minus those, read off the source's own file rather than a retyped copy. Absent or empty keeps today's unfiltered spawn; a JSON-encoded string list is read like a list. An unknown key is refused with `RadarError` naming the key and the valid vocabulary, before the first `gh` call and with nothing healed — never dropped silently. The board footer states the one caveat while the option is on: a poller already alive keeps the filter it was forked with, so `unwatch:github-pr:N` then `radar` re-forks it with the new one. `radar:--state` shows the resolved exclusion on a `pr events` row.
