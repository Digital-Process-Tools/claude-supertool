- **Two wrong claims `presets/git` made about its own input, corrected and pinned** ([#1704](https://github.com/Digital-Process-Tools/claude-supertool/issues/1704)). `_untrusted.split_lines`'s CR/CRLF arms are dead code for every `presets/git` caller today: they all read through `_git` (`subprocess.run(text=True)`), which rewrites a lone CR to LF before the split ever runs. The docstring and the #1130 register now say so, and `test_split_lines_cr_arm_is_dead_for_every_git_ops_caller` pins it against `_git_verbatim`'s own two callers, which both already avoid `split_lines` for exactly that reason. Separately, `_looks_like_success` word-anchored its demotion keywords the same way #1669 word-anchored `_ERROR_WORD_RE`: `"fatal" in low` matched inside `"nonfatal"`, reading a genuine success line as not-success.
