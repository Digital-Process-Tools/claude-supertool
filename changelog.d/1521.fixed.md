- **Two counters in `gh-prs` rendered a measurement that never happened as one that found nothing** ([#1521](https://github.com/Digital-Process-Tools/claude-supertool/issues/1521)). The repo's house defect, on both halves of the same op.

  `merged-since=DATE` threw away `filter_merged`'s third return value. A row whose `mergedAt` will not parse has not been shown to be outside the window — it has not been placed at all — and the tag branch has always disclosed those as `UNPLACED: N`. On the date branch they vanished from the listing with nothing said and an exit of 0. Both branches now share one `unplaced_note`, so the same absence cannot be worded two ways again.

  `split_tagged_commit` returns `(rest, tagged, compared)` rather than two values. It returns early when the boundary carries no commit sha, and `tagged is None` there is identical to what a comparison that ran and matched nothing returns — so `assess` printed `boundary PR: none — no returned row's merge commit is the tagged commit` on a path where nothing had been compared to anything. That path now says `NOT COMPARED` and says what it rests on instead.
