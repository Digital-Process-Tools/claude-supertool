- **The PreToolUse guard imported 25,000 lines of `_supertool` and spawned two interpreters before deciding it had nothing to say about `ls`** ([#1377](https://github.com/Digital-Process-Tools/claude-supertool/issues/1377)). That is a tax on every Bash call of every plugin user, and it is now paid only by commands that could actually be replaced.

  **What the cost actually was, measured rather than assumed.** macOS, median of 15 runs of `hooks/pre-bash-guard.sh` on `ls -la /tmp`: whole wrapper 301ms, of which a bare `python3.13 -c pass` is 52ms and importing `_supertool` is 194ms. In-process after the import: `_load_config` 2.2ms, `_guard_replacements` 0.1ms, `guard_command` 0.1ms. The issue listed three costs and ranked them wrong — **the registry walk is not a cost**, three orders of magnitude below the term it was named beside, and the interpreter probe is 52ms of 301 rather than the largest. The import is the cost.

  **One interpreter spawn per call, not two.** A candidate used to be proved a Python 3 by a throwaway `-c` run and then spawned again for the real answer. The envelope the real run writes proves the same thing and more, so the wrapper now reads the first bytes of the answer instead. [#1402](https://github.com/Digital-Process-Tools/claude-supertool/issues/1402)'s protection against a launcher that prints a preamble survives as a prefix test rather than an equality test, and [#1390](https://github.com/Digital-Process-Tools/claude-supertool/issues/1390)'s "ran and said nothing" stays reachable — no envelope, no verdict, next rung. A rung that fails now advances instead of declining outright, so a host with a broken `python3.14` and a working `python3.12` keeps its guard.

  **`_supertool` is not imported at all when the command names nothing the registry replaces.** The word list is read straight off `presets/*.json` with a flat scan that returns "unknown" on anything unexpected, and a project `.supertool.json` — or a project `presets/` that is not the plugin's own — declaring any `replaces` of its own turns the fast path off wholesale rather than being parsed. Reproducing which words a project override contributes is `_op_registry`'s job ([#1356](https://github.com/Digital-Process-Tools/claude-supertool/issues/1356) says so), so nothing is cached and nothing is re-implemented: the check is cheap and the answer stays the real guard's. `tests/test_guard_hook_cost_1377.py` pins the containment against `guard_command_words` preset by preset, which is what keeps two readers of one registry from drifting apart silently.

  Interleaved A/B against `origin/master` on one host, 4x25 runs per arm, min of the two medians: `ls -la /tmp` 307.5ms to 114.4ms, `pytest tests -q` 307.9ms to 112.6ms, `git push` 305.8ms to 262.1ms, `echo $HOME` 301.5ms to 262.9ms. Output byte-identical on all four. A macOS number, and macOS is the platform whose spawn cost this project can see — where a spawn is 150-800ms the two removed interpreter startups are worth more than they are here.

  **What it costs, stated.** A command that names nothing replaced no longer gets the `undecided` note about a part of it that could not be read — `. ./script.sh` no longer says its argument went unread. That is the narrowing [#1413](https://github.com/Digital-Process-Tools/claude-supertool/issues/1413) already applied to the PowerShell disclosure, for the reason it gives there: a line under every command anyone writes is one nobody reads. A command containing `$` or a backtick is never fast-pathed, because expansion can produce a replaced word the text does not contain, so the DENY direction loses nothing.
