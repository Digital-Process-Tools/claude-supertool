- **`gh-pr-merge:N:squash|force|cleanup` now runs the cleanup it used to print for you to retype** ([#1256](https://github.com/Digital-Process-Tools/claude-supertool/issues/1256)). Measured on this repo: 96 of 99 remote branches were merged and undeleted, and 10 worktrees on merged branches survived one day. Cleanup was skipped because it was a second decision after the interesting one had ended.
- It runs **only** after `MERGED` is read back off the remote. The rule it replaces — cleanup is a separate command — was written when nothing verified the merge; the read-back gate is now exactly that verification, and it sits upstream of this arm. A merge that is not confirmed skips all three items and issues no command at all.
- Three items, three states each, never two: `done`, `refused: <reason>`, `skipped: <reason>`, with a `[cleanup] N done, N refused, N skipped` tally. A cleanup that could not run never renders as a cleanup that had nothing to do.
- The remote branch goes through `gh api -X DELETE`, never `git push --delete`: the pre-push hook runs the entire suite per deletion, so 96 branches that way is about three hours of pytest whose output looks like progress.
- A worktree is removed only when `git-worktrees` says `idle`, read off that op's own `[result]` tally rather than re-derived here; `cannot tell` is treated as occupied and refused by name. The tree is then read — by two commands with different failure modes, see #1290 — and refused if it holds anything git is not tracking — `--force` governs modified and untracked files only, never ignored ones ([#1280](https://github.com/Digital-Process-Tools/claude-supertool/issues/1280)). Immediately after your own merge the honest answer is usually `refused: cannot tell` — the litter this exists for is day-old trees, which are the ones that pass.
- The local branch is deleted with `git branch -d`, never `-D`. `-d` cannot confirm a squash merge and declines — observed on `fix/1207`, whose PR had merged — and that decline is printed as a finding rather than forced past or skipped in silence.
- Nothing is deleted until the head branch is established to be in **this** repository and the remote ref reads back at the PR's own `headRefOid` ([#1281](https://github.com/Digital-Process-Tools/claude-supertool/issues/1281)). A head that is cross-repository, unestablished, or named after the default branch refuses all three items.
- Local items are skipped outright when a `repo:OWNER/NAME` target is set: the checkout is then not that PR's repository, and a branch of the same name here is a different branch.
- The exit code stays a statement about the merge. A refused cleanup is not a failed merge.
