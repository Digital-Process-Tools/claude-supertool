- **`grep` declines an empty PATH slot instead of silently scanning the whole tree** ([#1417](https://github.com/Digital-Process-Tools/claude-supertool/issues/1417)). `grep:_FLAGS|def main:presets/github/issues.py:::40` rejoined to the pattern `_FLAGS|def main:presets/github/issues.py:` with the path `.`, scanned 934 files and returned hits — the house defect in a read op, where the wrong answer is well-formed. Two agents hit it in one day and one acted on the result before noticing. The `|` was incidental: `grep:PATTERN:PATH:` does the same with no alternation in it, because the trigger is the empty PATH token defaulting to the repo root while the real path stays inside the rejoined pattern.

  `_colon_split_hint` already produced the right refusal for this whole family, carrying the `grep:@-` escape that is the remedy — and its first line is `if not path or path == "." or os.path.exists(path): return ""`. Every arm below that keys off "the path does not exist", and `.` always exists, so the one reading in the family that does **not** fail loudly was the one reading the helper declined to diagnose. That line is unchanged — it is correct for the ops that never default a path — and grep's dispatch arm now runs a dedicated check ahead of it.

  It declines rather than auto-correcting, which is where it differs from `around:.supertool.json:232:12` — that one is redirected to `around_line` and disclosed, and is safe precisely because the reading it replaces is a hard failure with nothing to lose. Here the reading it would replace is a successful whole-tree sweep, so a silent redirect swaps one answer nobody typed for another. The gate is narrow: it fires only when the path resolved to `.` and a segment of the rejoined pattern names an existing file or directory, past the first segment. Measured over the 165 distinct `grep:` spellings written down in this repo, 39 hit the rejoin and none is declined. A segment failing cwd containment is skipped rather than named, so the refusal cannot be turned into an existence oracle for paths outside the boundary, and the pattern is re-segmented through `_split_arg` rather than a plain `split(":")` so a Windows drive letter is not torn in half on the only platform where it occurs.

  **`grep` only.** `around` and `between` share the error helper and not the defect: neither defaults a path to `.`, so a `.` there is a value the caller typed, and `between:re:START:END:PATH` carries three caller arguments ahead of the path — `between:re:START:code.py:.` is an ordinary tree-wide range search whose END names a file. Generalising the check to the family produced a false refusal on that call and a printed repair that dropped the `re:` marker selecting the mode.
