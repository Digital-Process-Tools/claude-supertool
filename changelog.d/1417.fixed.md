- **`grep` declines an empty PATH slot instead of silently scanning the whole tree** ([#1417](https://github.com/Digital-Process-Tools/claude-supertool/issues/1417)). `grep:_FLAGS|def main:presets/github/issues.py:::40` rejoined to the pattern `_FLAGS|def main:presets/github/issues.py:` with the path `.`, scanned 934 files and returned hits — the house defect in a read op, where the wrong answer is well-formed. Two agents hit it in one day and one acted on the result before noticing. The `|` was incidental: `grep:PATTERN:PATH:` does the same with no alternation in it, because the trigger is the empty PATH token defaulting to the repo root while the real path stays inside the rejoined pattern.

  `_colon_split_hint` already produced the right refusal for this whole family, carrying the `grep:@-` escape that is the remedy — and its first line was `if not path or path == "." or os.path.exists(path): return ""`. Every arm below that keys off "the path does not exist", and `.` always exists, so the one reading in the family that does **not** fail loudly was the one reading the helper declined to diagnose.

  It declines rather than auto-correcting, which is where it differs from `around:.supertool.json:232:12` — that one is redirected to `around_line` and disclosed, and is safe precisely because the reading it replaces is a hard failure with nothing to lose. Here the reading it would replace is a successful whole-tree sweep, so a silent redirect swaps one answer nobody typed for another. The gate is narrow: it fires only when the path resolved to `.` and a segment of the rejoined pattern names an existing file or directory, past the first segment. Measured over the 155 distinct `grep:` spellings written down in this repo, 33 hit the rejoin and none absorbs a real path. A segment failing cwd containment is skipped rather than named, so the refusal cannot be turned into an existence oracle for paths outside the boundary.
