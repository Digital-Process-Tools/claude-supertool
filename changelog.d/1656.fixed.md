- **The test suite no longer writes outside its own tree** ([#1656](https://github.com/Digital-Process-Tools/claude-supertool/issues/1656)). Three sites, measured: 52 files and 288 KB per full run landing in the developer's real `~/.cache/supertool/paste-backup/` (the store [#1650](https://github.com/Digital-Process-Tools/claude-supertool/issues/1650) added), a file named `@-` created and unlinked in the live checkout root — which is typically symlinked as the operator's `supertool` binary, and which two concurrent runs race on — and two `os.environ["XDG_CACHE_HOME"]` assignments popped rather than restored in their teardown.

  **`XDG_CACHE_HOME` is redirected for the whole session instead of a switch per store.** `_cache_root()` is the one place `~/.cache/supertool` is spelled, so one line covers the paste-backup store, the read-elide cache, the GC and the vim cursor/undo store — including whichever store is added next, which under the old convention would have needed a fourth switch nobody would remember to write. No product surface moves: the alternative was a `SUPERTOOL_PASTE_NO_BACKUP` knob that silently disables a data-loss net, which would then need a fourth `paste` receipt state to stay honest, and which fixes one instance of the three.

  **The pop had to go first, and that ordering is the whole reason instance 3 belongs here.** A `pop` is not a restore: with a session-wide redirect in place, the first test to pop it leaves every test after it in that worker writing to the operator's real cache — silently, and in the direction that reads as a pass.
