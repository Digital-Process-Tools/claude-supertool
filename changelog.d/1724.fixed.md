- `git-status` prints each untracked path's write time, so a file another process dropped in your tree stops rendering identically to one you made and forgot (#1724). A time, never an attribution — nothing on disk records who wrote a file. A write inside the activity window is tagged with the same 15 minutes and the same `SUPERTOOL_WORKTREE_ACTIVE_WINDOW` knob `git-worktrees` uses; an mtime that cannot be read says `mtime UNREADABLE` rather than going silent, since a row with no time under rows that have one reads as "this one is yours". The default view's `... (N more)` marker names the newest write among the rows it hid, so the cap cannot conceal the entry the field was added to surface — and it says `UNKNOWN`, or how many of the hidden mtimes it could not read, rather than letting a tail nobody could time render as a tail with nothing in it.
