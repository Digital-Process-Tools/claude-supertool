- **A failed validator's stderr reached the `git-resolve` receipt unredacted** ([#925](https://github.com/Digital-Process-Tools/claude-supertool/issues/925)). Validator adapters shell out, and a child dying on an auth error puts the credential it tried on stderr — a `user:token@host` clone URL, an `Authorization: Bearer …`, a `GITLAB_TOKEN=…` echoed by a wrapper. `_child_failed` put that line into a receipt people paste into issues. `presets/_secrets.redact` had existed since [#760](https://github.com/Digital-Process-Tools/claude-supertool/issues/760) and was wired into `claude-log`, `devto` and `bluesky` — named call sites rather than output boundaries — so validate and resolve bypassed it. Both places on that line now redact: the dead child's stderr, and the `(why)` of a validator that declined, which is the adapter's text too. Redaction runs *before* the 120-character cap, because cutting first leaves a token too short for its own rule to match and ships its head. It claims nothing about completeness — detection is by shape, so a credential `_secrets` does not recognise still passes through.
