- **A radar tier can live outside the plugin** ([#2165](https://github.com/Digital-Process-Tools/claude-supertool/issues/2165)). `radar._tier_module` resolved a registered tier two ways and both landed inside the installed plugin, so a project that declares its op in its own `.supertool.json` could poll a population with a private watch source ([#2135](https://github.com/Digital-Process-Tools/claude-supertool/issues/2135)) and then had no way to put a single line about it on the board. Measured on 0.53.0: `radar: WARNING — tier 'server-diag' is registered but exposes no radar_report()`, with nothing ever opened.

  A third route reads `SUPERTOOL_WATCH_SOURCES_PATH` and loads `<dir>/<name>/tier.py` — the directory the matching `poller.py` already lives in, because a tier and a source for one population are one concern and two knobs for it is one to forget. **It imports and executes Python from a caller-supplied path**, on the same terms the sources path states: anyone who can write to a directory on it, or to the `.supertool.json` naming it, runs code as you.

  Three things are said out loud rather than swallowed. A shipped tier still wins, and the external file it hides is named on the board. A tier nothing answers to now prints every directory that was searched, instead of `Check the name`. And a tier that raises while being *loaded* — newly possible, since route 3 imports somebody else's file — is one tier's failure, not radar's.
