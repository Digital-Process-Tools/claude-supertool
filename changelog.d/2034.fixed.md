- **A contended `.git/index.lock` now retries within a bounded budget instead of failing on the first attempt, and a lock that outlasts that budget is diagnosed rather than left as a bare `File exists`** ([#2034](https://github.com/Digital-Process-Tools/claude-supertool/issues/2034)). `_git`/`_git_verbatim` — the one chokepoint most of `presets/git` reaches git through — now retry a lock-contention failure with a short backoff, up to `SUPERTOOL_GIT_LOCK_WAIT` seconds (default 2, `0` opts out of the whole feature). Any other git failure is returned on the first attempt, unchanged. On exhausting the budget the lock itself is diagnosed: is a process still holding it open (checked directly, via `lsof`/`/proc/*/fd`, not inferred from a worktree's cwd), so the answer is `live`, `stale`, or `cannot tell` when the scan itself could not run -- never a guess, and never a suggestion to delete the lock.
