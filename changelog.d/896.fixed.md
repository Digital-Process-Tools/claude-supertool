- **Two low-severity containment edges documented as accepted risk; a real content-disclosure gap in F2's own "not a content-disclosure channel" claim, found via CI on Python 3.9/3.10, fixed; one docstring overclaim corrected** ([#896](https://github.com/Digital-Process-Tools/claude-supertool/issues/896)). F2: `_resolve_at_path` never containment-checks the `@file` reference itself, so `grep:@/tmp/outside.toml` loads and parses a file outside the project root. Judged low severity because a TOML/JSON parse error "reports only a line/column position, never the file's own text" -- true for stdlib `tomllib` (3.11+), and **false** for `_mini_toml_loads`, the only TOML reader on Python <3.11: a bare TOML key is any run of `[A-Za-z0-9_-]` characters, so ordinary file content commonly IS one, and the fallback parser's error messages echoed the parsed key (sometimes the whole malformed file) back verbatim. CI caught this deterministically on the ubuntu-latest 3.9 and 3.10 legs after this branch's own new test for the claim passed locally on 3.13 (tomllib only). Fixed by threading an integer offset through `_toml_decode_escape`/`_toml_parse_value`/`_toml_parse_array`/`_mini_toml_loads`'s error messages instead of the key/value text, matching `tomllib`'s own position-only behavior; a new test forces the <3.11 fallback path (`no_tomllib` fixture, matching #834's own pattern) so this is exercised on every interpreter rather than only the two CI happens to run without `tomllib`. F3: `_containment_error` realpaths each candidate once, and the op that follows re-resolves the same string independently -- a classic TOCTOU window that predates this diff and is the shape of every "check, then act" gate backed by two separate syscalls; documented on `_containment_error` rather than closed, since closing it for real means opening every op's own file through an `O_NOFOLLOW`-style handle rather than a path string, out of proportion to a narrow-window race needing a second local account. F4: `presets/_untrusted.py`'s docstring claimed `_is_control` covers "exactly, in both directions" the ten code points `str.splitlines()` breaks on; a full 0x0-0x10FFFF sweep shows it is a strict superset by 57 code points (the rest of C0, all of C1, DEL) -- the safe direction, no ordinary path affected, docstring corrected and pinned by a new test asserting both counts.
