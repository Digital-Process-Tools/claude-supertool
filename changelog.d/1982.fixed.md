- **A file the syntax floor could not open no longer renders as a syntax error in the code** ([#1982](https://github.com/Digital-Process-Tools/claude-supertool/issues/1982)). `_syntax_floor_check`'s child snippet already told the two cases apart -- a real `SyntaxError` versus a path that vanished mid-walk or could not be opened at all -- but the parent folded both arms into the same hard-coded `"code": "syntax"` literal, so a check that never ran on a file read exactly like a defect in it. The child now tags each arm, the parent honours the tag: an unreadable path goes to a new `skipped_paths` list and drops out of `checked`, mirroring the in-process `_builtin_syntax_run`'s existing three-state contract. A file that genuinely fails to compile is unaffected.
