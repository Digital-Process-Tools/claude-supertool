- **`op_between_pattern` compiled caller-supplied regexes with no gate, no length cap and no ReDoS backtracking guard** ([#2571](https://github.com/Digital-Process-Tools/claude-supertool/issues/2571)). `#2547` moved the #150 backtracking guard into `_pattern_gate` specifically so it would cover "every other route through this chokepoint", and `#2550` added the 1000-char length cap there too -- but `between`'s `start`/`end` patterns went straight to `re.compile` and `.search()` against real file content on both dispatch routes, unrefused. An adversarial pattern like `(x(a+)+y)` against a near-miss (non-matching) line hung the calling agent's turn indefinitely, with no per-call timeout -- the same nested-unbounded-quantifier shape backtracks in microseconds against a line it actually matches, so the danger is specifically a line that almost matches. Fixed by routing both `start` and `end` through `_pattern_gate` before either is compiled, the same chokepoint `op_around` and `read`'s `grep_filter` already use -- including the rewrite-disclosure `note` `_pattern_gate` returns, which `op_grep`/`op_around` already print and `between` now does too, so a caller whose `start`/`end` was silently BRE-rewritten (an escaped pipe becoming a plain one) can see it happened. `tests/test_pattern_gate_between_2571.py` pins the refusal for an adversarial and an overlong pattern on each of `start` and `end`, the rewrite disclosure, and a positive control that an ordinary slice still works.
