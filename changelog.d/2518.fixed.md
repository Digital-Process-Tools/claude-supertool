- **`watch:SOURCE:ID:reload`'s own receipt now says which file it does and does not reach** ([#2518](https://github.com/Digital-Process-Tools/claude-supertool/issues/2518)). `cmd_reload` signals SIGHUP to a live poller, and the running process's own next tick re-imports only that source's `poller.py` -- `dispatcher.py` itself (the shared back-off/retry/wait machinery every poller runs under: `_retry_after_seconds`, `_wait_interruptible`, `MAX_RETRY_AFTER_SECONDS`, the outer poll loop) is already imported by the running process and is never swapped by this signal. A maintainer reloaded three pollers expecting a `dispatcher.py`-level fix (#2515) to take effect, and it did not, because the fix lived in the wrong file for what `reload` actually swaps -- and nothing in the receipt said so.

  `cmd_reload` now prints an unconditional caveat on every successful reload naming both files by name and pointing at `unwatch` + `watch` as the path that reaches a `dispatcher.py`-level change. It is static rather than a diff of the two files -- the dispatcher has no way to know which file a pending fix actually lives in -- so it prints every time, not only when it would matter.
