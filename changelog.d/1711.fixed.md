- **`around`, `grep` and `between` (symbol mode) now name a PATTERN/PATH swap instead of blaming the cwd** ([#1711](https://github.com/Digital-Process-Tools/claude-supertool/issues/1711)). `around`'s "Read as pattern=X + path=Y — split on \':\'" diagnosis already existed but only fired when the leading argument carried a \':\' (`_colon_split_hint` declines otherwise) -- exactly the arity a plain swap does NOT have, since both values are ordinary tokens just in the wrong slots. `around:PATTERN:PATH` with the two swapped used to answer `ERROR: file not found: <pattern>` plus `wrong CWD? Prefix the call with cwd:PATH` -- a remedy that does not fix the problem, since the cwd was fine and the thing it called a file is a pattern. The new check (`_swap_suggest`) is generic and positive rather than shape-based: whenever the value in the OTHER slot resolves to a real file/dir and the missing one does not, that is checkable evidence of a swap, at any arity, and the refusal now says `Did you mean: around:PATH:PATTERN[:N]` instead. Checked per #1711\'s own "Check N": `grep` shares the same shape and gets the same fix; `between` symbol mode (`SYMBOL:PATH`) does too; `between:re:START:END:PATH` and `read` were checked and left alone -- `read`\'s path already leads (nothing to swap it with) and `between:re:` swapping START/END against PATH is a three-way ambiguity `_swap_suggest`\'s two-value shape does not fit, left for a follow-up rather than widening this fix. `_colon_split_hint`\'s own early-decline (the check that lets `_swap_suggest` run at all) only fired when the leading argument had no `:` anywhere -- true for a swap on POSIX, never true on Windows, where an absolute path always carries one from its own drive letter (`C:\Users\...`), so a genuine swap there kept getting the generic "split on :" message instead. Fixed the same way: "does the leading value resolve as a real file" settles it regardless of platform, so that check now runs ahead of the colon-count heuristic too (caught by CI\'s `windows-latest` leg).
