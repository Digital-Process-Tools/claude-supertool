- The coverage gate no longer keeps its scratch data at a fixed, world-guessable
  path in the system temp directory. `.github/scripts/coverage_gate.py` wrote
  `coverage_gate.ini` to `<tmp>/supertool-coverage-gate/` with
  `mkdir(exist_ok=True)` and no ownership, symlink or mode check, then ran
  `coverage run --rcfile=` against it and exported it as
  `COVERAGE_PROCESS_START` to every child process. A coverage rcfile can declare
  `plugins =`, which coverage imports — so on a shared-`/tmp` machine another
  local process could pre-create or symlink that path and have its own code run
  inside the gate that decides whether the release's coverage floors pass. The
  directory is now `<repo>/.coverage-gate/`, created at mode 0700 with the
  rcfile at 0600, which keeps `--report` working (the path is still stable) and
  makes it per-checkout rather than shared by every worktree on the machine. Not
  exploitable on the single-tenant GitHub runner; the gate is documented as
  locally runnable, which is where it mattered.
- The coverage gate refuses instead of degrading when it cannot write that
  config. A symlinked or uncreatable scratch directory, or a failed write, now
  prints `coverage gate: REFUSED` and exits 2 without reaching the report — a
  third state alongside pass (0) and floor-failure (1). With no config there is
  no coverage data, every bucket totals zero statements, and a zero prints the
  same as a directory that genuinely holds no code.
- `.github/workflows/tests.yml` declares `permissions: contents: read`. It
  checks out, installs and runs tests, and publishes nothing; with no block the
  token got whatever the repository default happened to be, and that default is
  a settings page that can widen without touching this file.
