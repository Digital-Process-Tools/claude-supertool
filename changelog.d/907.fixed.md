- **One implementation of "is this url on GitHub", parsed rather than counted, and a `None` that says which of four things it means** ([#907](https://github.com/Digital-Process-Tools/claude-supertool/issues/907)). The lookalike-host hole itself closed in [#1212](https://github.com/Digital-Process-Tools/claude-supertool/pull/1212), but it closed twice — `gh-issue` and `gh-issues` each grew their own hand-rolled check over `url.split("/")` — and the two disagreed. `gh-issues` stripped userinfo and port off the authority before comparing; `gh-issue` compared the whole thing, so `https://user@github.com/o/r` and `https://github.com:443/o/r`, both perfectly ordinary URLs, resolved on the board and were refused by the single-issue op. Both read `o#x` as the owner of `https://github.com/o#x/r`, because a `#` ends a path and slash-counting does not know that. There is now one predicate in `presets/_repo_target.py` — `is_github_host`, `url_host`, `github_owner_repo` — built on `urlsplit`, and both ops call it.

  GitHub Enterprise Server is now decided rather than assumed, which was the open question the issue left. It is **not** supported here, and the reason is written where the next reader will loosen the literal: a GHES install lives on an operator-chosen host and is not a subdomain of `github.com`, so the `.github.com` arm never reached it. That arm admits GitHub's own `www.`, `api.` and `gist.` subdomains — two comments and a test docstring called them "Enterprise" and were wrong. If GHES is ever wanted it belongs in configuration, next to `SUPERTOOL_IMAGE_HOSTS`, not in a widened constant.

  `gh-issues` no longer answers a bare `None` to four different questions. An empty listing, rows carrying no url, rows whose urls are on some other host, and a `github.com` url too short to hold an owner and a name were one answer, and that answer is rendered into the decline a reader is meant to act on. Each now names itself, by count — never by quoting a url back, because a row url is tracker content and the error line is ours.
