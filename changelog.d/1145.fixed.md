- **`gh-job` and `gl-job` answered questions nobody asked, three ways, and every one of them looked like a successful read** ([#1145](https://github.com/Digital-Process-Tools/claude-supertool/issues/1145)). Core splits an op string on every `:` and hands the pieces to these presets as argv. A MODE token neither preset recognised fell through to the default render — metadata, log tail, exit 0 — so a caller who asked for a slice read the tail as "the slice found nothing". A job id with trailing non-digits was rendered in the header as the job being read: `gh api repos/{o}/{r}/actions/jobs/93211401185ep` returns **200**, because GitHub coerces the trailing text away and answers for job 93211401185, so a corrupted identifier — the one tell that argv was mangled upstream — was published as a fact about the job. And a `:` inside `:grep:PATTERN` split the pattern in two, of which only the first piece was used, so `:grep:Error: not found` searched for `/Error/`.

  Both ops now refuse a non-numeric id and an unrecognised mode before anything is fetched, and rejoin a colon-split pattern rather than truncating it, echoing above the render how the pattern was read — core `grep`'s own resolution, and the note is silent when there was no colon. The parsing lives in one shared `presets/_job_argv.py`, so the two forges cannot drift into two answers.

  **`|` was never the bug.** The issue leaned toward refusing alternation; core `shlex.quote`s each part before substituting `{args}`, so a pipe has always reached the preset intact and `:grep:passed|failed` works — verified live. The reproduction that filed the issue had lost `:gr` from the op string somewhere upstream of supertool; what turned that into a confident wrong answer was the mode falling through and the id rendering, both of which are fixed here. Refusing the character would have removed the natural way to grep a job log and left the actual defect in place.

  Swept: `gh-run` 404s on a trailing-text id and `gh-check` validates one, so `gh-job` was the only op in the family handing a raw id into a REST path; and `:` is the only character that breaks this tokenizer — `$`, `;`, `&`, backtick, `*`, spaces, quotes and backslashes all survive shell-quoting, measured against a live job log.
