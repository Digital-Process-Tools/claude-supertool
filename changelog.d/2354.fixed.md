- **`tests/test_read_elide_unchanged_1329.py` no longer depends on real wall-clock timing between two back-to-back `op_read` calls** ([#2354](https://github.com/Digital-Process-Tools/claude-supertool/issues/2354)). `test_full_returns_content_and_rearms_the_window` and `test_the_config_switch_turns_it_off` each called `op_read` twice in a row and expected the second call to report `elided`, relying on real `time.time()` to keep the two calls inside `_read_elide`'s `now - prior[1] <= _read_elide_window()` gate -- correct product behaviour that a loaded/parallel CI runner (`pytest -n auto`) is not guaranteed to satisfy (2 of 18 cases failed on one CI run; a rerun with no code change passed all 21 legs; always green locally). Both tests now pin `supertool.time.time` to a fixed instant, the same technique `test_the_window_is_measured_from_the_last_content_not_the_last_elision` already uses, so the two calls always land at the same simulated moment regardless of real elapsed time. A new positive control, `test_a_loaded_runner_gap_still_correctly_refuses_to_elide`, confirms the frozen-time fix does not paper over the real gate: a genuinely exceeded window (simulated via the same mocked clock) still correctly withholds the elision.
