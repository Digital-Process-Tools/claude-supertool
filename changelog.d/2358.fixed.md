- **`vim`'s `:s` substitutions now disclose a silent second application** ([#2358](https://github.com/Digital-Process-Tools/claude-supertool/issues/2358)). `edit` and `replace` already gained a `K re-applied` footer for this shape (#938, #701); `vim`'s `:s` shared the same underlying bug and had none of it -- a `%s/pattern/repl/` where `repl` contains `pattern`, run twice, silently doubled the written text while both receipts read identically (`1 subs`, `[result] 1 op run, 1 write`).

  Detection is per MATCH rather than per pattern: the literal text a match actually consumed (`m.group(0)`) against the literal text it is about to become (`m.expand(repl)`, which resolves any backreference for that match), reduced to the same positional-containment test #938 already proved. So it is not limited to a backreference-free subset -- `:s/(a)-(b)/\1-\2-X/` run twice is caught the same way `:s/foo/foo-bar/` run twice is. It is disclosure, never refusal: a genuinely intended second application (the same substitution applied twice at different sites) still lands and is disclosed, not blocked.

  Best-effort, not exhaustive: a quantified group that re-matches its own PRIOR output as one larger capture (`:s/(\w+)/\1\1/` re-applied to already-doubled text) is not caught, because that match's own text no longer equals what any one run wrote. Documented in `op_vim`'s own help text.
