- **`gl-job:ID:fail` now consults a declared runner maintenance window before calling a container-level exit (`137`/`139`/`143`) unexplained** ([#645](https://github.com/Digital-Process-Tools/claude-supertool/issues/645)). Every DVSI runner host runs a cron cleanup+reboot at a known time, and a job still running then is killed by design — until now that read identically to genuine OOM, and cost real diagnostic time (a whole fleet wrongly declared "degrading under load" in one session). Declare a fleet default and per-runner overrides in `.supertool.json`'s `gl-runners.maintenance` / `gl-runners.runners.<description-or-id>.maintenance` (`null` opts a host out); a death inside the window gets a `RETRY — scheduled cleanup` verdict, a death outside it is named as outside rather than silently unexplained, and a malformed or absent declaration reads as "no window" and never as an error. Scope guard: only container-level exit codes qualify — a real test failure at the same second is never softened.
