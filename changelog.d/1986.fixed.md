- **An inherited `SUPERTOOL_REPO` with no `repo:` op in the call no longer directs a write** ([#1986](https://github.com/Digital-Process-Tools/claude-supertool/issues/1986)). `gh-issue-create`, `gh-pr-create`, `gh-pr-edit` and `gl-issue-create` resolved their target through a bare read of `SUPERTOOL_REPO`, which cannot tell a value THIS call's own `repo:` op exported from one merely sitting in the process environment — a caller's shell export, or a value #1962 could leave behind. An ambient value therefore filled a silent payload, unshape-checked, and directed the write at a repository nobody named in the call — the receipt even credited a `repo: op` that was never typed. Core now exports a second, call-scoped marker alongside the target, set only when this call's own `repo:` op ran and passed the shape check; the four write ops consult that marker (`presets/_repo_target.py::explicit_target`) before filling a silent payload, and fall back to the ordinary cwd-remote/config auto-detect exactly as if no target existed when it is absent.
