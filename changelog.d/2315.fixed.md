- **`gh-issue-create` refuses a `[[body]]` TOML table-array with a clear message instead of crashing three frames deep with a bare `TypeError`** ([#2315](https://github.com/Digital-Process-Tools/claude-supertool/issues/2315)). `presets/github/issue_create.py` read `content = body` with no type check, so a payload whose `body` key parsed as a TOML array-of-tables (a list of `{"value": ...}` dicts) reached `_publish_safety.apply_forge_disclosure(body: str)` as a `list`, raising `TypeError: can only concatenate list (not "str") to list`. `gh-issue-comment` accepts this same shape without crashing, but was found not to actually join it either -- its own `_body_text` stringifies the raw Python list (`str([{"value": "..."}])`), publishing the literal repr as the comment body rather than the intended prose (reported separately, not fixed here). Rather than copy that behaviour, `gh-issue-create`'s `_validate` now refuses any non-string `body` outright, naming the accepted shape and pointing at `body_file`. `help:gh-issue-create` documents the requirement.
