- **`json-set` — a structured field-set for JSON-shaped files** ([#1822](https://github.com/Digital-Process-Tools/claude-supertool/issues/1822)). `paste` is whole-file and `edit` needs an exact, unique `old` string — fine for a line of code, expensive for a JSON report with ~100 fields where only 8 changed: the measured case was a 22 KB re-send to change 300 bytes, which had already pushed one agent to a raw, unvalidated `python3 -c` transform. `json-set:@FILE`/`json-set:@-` takes a `path` plus a `set` table of dotted field paths to values (`"tests.green.result" = "..."`) and does the whole-file work internally — parse, set each leaf, re-serialize — refusing rather than guessing on a file that is not valid JSON or a dotted path through a segment that does not already exist. Routed through the same validator/rollback machinery as every other write op (`jsonlint`, `rollback_on_fail: true`), so a schema check this repo has not configured yet gets the identical safety net for free.
