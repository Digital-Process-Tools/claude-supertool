- **`git-status.py`'s outer `run()` no longer loses a live `git status` when its FIRST `communicate()` breaks** ([#1912](https://github.com/Digital-Process-Tools/claude-supertool/issues/1912)). PR #1883 taught `_settled`/`_stop` that a `communicate()` failure is a broken pipe, not a dead child — but only `_stop`'s own call site used them. `run()`'s own `communicate(timeout=remaining)`, the one every one of the four `git` calls this adapter makes goes through, still caught only `subprocess.TimeoutExpired`; an `OSError` there (reproduced against a real child: closing a live child's stdout fd under a running `sleep` raises `OSError(9, "Bad file descriptor")` with the child still alive) propagated past `main()`'s `except _NoAnswer`, so `_stop` was never called and a `git status` holding `.git/index.lock` was left running. `run()` now catches `OSError`/`ValueError` there too, falls back to `_settled` to ask the process directly, and only escalates to `_stop` when the process is still alive — an already-dead child is not sent a stop signal it never needed.
