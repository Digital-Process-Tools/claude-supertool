- **The self-hosting risk in the doubled-backslash payload scanner is now a documented trap, not a silent hazard** ([#1906](https://github.com/Digital-Process-Tools/claude-supertool/issues/1906)). `_load_at_file_raw` runs that scanner unconditionally on every `edit:@-`/`paste:@-`/`batch:@-` payload, before dispatch, so a mid-edit state that leaves the scanner itself transiently broken (the ordinary state between the two halves of a rename) locks every subsequent `edit:@-` call out -- including the one that would repair it. `docs/contributing.md` now names the recovery: do not retry `edit:@-`, write the fix directly outside the payload route, then verify with `python3 -c "import _supertool"` before resuming. No bypass mode was added -- any bypass narrow enough not to become a general escape hatch would need to inspect the payload using the same machinery that is currently broken, which is not a narrowing.
