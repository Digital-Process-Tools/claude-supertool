- **`git-worktrees`' description is the contract again, not the case history** ([#1774](https://github.com/Digital-Process-Tools/claude-supertool/issues/1774)). Documenting the two columns #1750 and #1751 added grew it from 4,832 to 7,021 characters, and #1774's ledger refused the growth. It now reads 2,383: every state of every column is still named, and the incident behind each — the `ps` grep that returned 0 for a live agent, the 24-branch ancestry measurement, the git 2.46.2 reflog result, why the dirty scan runs `--no-optional-locks` — moved to `docs/presets/git.md`, which is where the long form already was.

  The ledger row falls from 4,832 to 2,383 rather than being deleted. Under `MAX_DESCRIPTION` (2,000) it would leave the ledger, and the last 383 characters are reachable only by dropping a column's state list or the exit-code contract — and a reader who does not know that `PR unknown` is not `no open PR`, or that `dirty unknown` is not `clean`, misreads the board in the direction this op exists to prevent. The ratchet asks that the number fall, not that it hit a round one.

  Worth knowing for the next growth refused here: `help:OP` renders the **same** `description` field byte for byte, so there is no long form to move prose *into*. The cheaper home is `docs/presets/git.md`, the issue, or the test's own docstring.
