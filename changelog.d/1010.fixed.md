- **`git-push:watch` reported "Watching →" for a watcher that had refused to start** ([#1010](https://github.com/Digital-Process-Tools/claude-supertool/issues/1010)). `_spawn_watch` was fire-and-forget: `Popen` with stdout *and* stderr on `DEVNULL`, and `True` returned the instant the call did not raise. The `watch` op names its own refusals — an unknown source, a pid-file slot it could not claim, and on Windows an `os.fork` that does not exist — by exiting non-zero and saying so on stdout, and every one of those went into `DEVNULL` underneath a receipt line announcing coverage that had never been established. It now waits for the spawned op to exit (bounded, and cheap: the process being waited on is not the poller — `watch` claims the slot, detaches a grandchild and returns) and has **three outcomes, not two**: started, *not* started with the child's own reason quoted, or `UNKNOWN` when the op outlived the budget. The timed-out child is left running rather than killed, because it may already have detached a working poller, and the receipt says plainly that it is neither claiming one exists nor claiming one does not.

  **This is also the red Windows leg.** `test_watch_spawns_through_supertool_py_when_the_wrapper_is_missing` failed as `assert '' == 'watch:gitlab-mr:42'` on `windows-latest, 3.12` and nowhere else, on two open PRs that share no files. Neither branch caused it and neither did the entry-point shim: the test file and `presets/git/push.py` are byte-identical across commits where that leg is green and commits where it is red, and the shim is not an ancestor of either branch. The spawn was asynchronous, so the test waited for the sentinel file to *exist* and then read it — and on Windows a file exists from `CreateFile`, before a byte of its payload lands. The empty read was the tool's own race arriving as if it were the watcher's answer. With the spawn waiting for its child there is no window to lose, and the test now reads the sentinel with no polling at all, so a return to fire-and-forget fails it immediately on every platform.
