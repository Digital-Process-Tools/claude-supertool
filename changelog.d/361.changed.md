- **The canonical "push, then wait for the pipeline" path is now documented** ([#361](https://github.com/Digital-Process-Tools/claude-supertool/issues/361)) -- it did not need building. `git-push:watch` already pushes and spawns a detached poller against the branch's MR/PR, whose own head-pipeline events (`pipeline_succeeded`/`pipeline_failed`/`pipeline_canceled`) are the terminal verdict this loop needs; `watch:gl-pipeline:ID` / `watch:gh-run:ID` cover a pipeline with no MR/PR yet. README now spells out both forms and points a failure at the existing triage ops (`gl-pipeline:ID:failed`, `gh-job:N:fail`) for the failed-job list, so hand-rolling a `glab api .../pipelines/<id>` poll loop is no longer the only way to get this.
