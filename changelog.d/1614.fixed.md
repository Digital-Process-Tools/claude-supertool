- **`edit`'s tie disclosure was unreachable for any anchor over 20 lines, so the confidently-wrong line number came back for the case it was written about** ([#1614](https://github.com/Digital-Process-Tools/claude-supertool/issues/1614)). `_nearest_block_candidates` char-scores at most `_EDIT_NEAR_WINDOWS` (20) of the windows that tied on the line pass, and returns a `tie_floor` meaning *more places tied than were scored*. `_edit_nearest_hint` consulted that floor only inside `if rivals:`, where `rivals` first discards every candidate within the anchor's own height of the leader as one neighbourhood. For an anchor taller than 20 lines all 20 sampled starts sit inside one such neighbourhood by arithmetic, so `rivals` was always empty and the floor was dead code. A 30-line anchor over a file with 34 tied windows got `nearest match at lines 1-30 (98%)` — one sample of 20, named as a fact, roughly 470 lines from the block the caller wrote.

  **The floor is its own trigger now**, not a modifier on `rivals`: more tied than scored means the unscored ones were never located, so the hint declines with `at least 34 places score the same` rather than naming one. The "and N more" count is also taken against the lines actually listed rather than a hardcoded three — with `rivals` empty only the leader is named, and the old arithmetic under-reported the withheld places by two.
