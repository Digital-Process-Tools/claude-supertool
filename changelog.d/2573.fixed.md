- **`op_vim`'s search and substitute motions compiled caller-supplied regexes with no gate, no length cap and no ReDoS backtracking guard** ([#2573](https://github.com/Digital-Process-Tools/claude-supertool/issues/2573)). Filed as an unconfirmed `adjacent` finding off `#2571`'s own fix: `/`, `?`, `n`/`N`, the inline `o`/`O` search-then-open reflex, `:s`, `:g`/`:v`, the `:d /PAT/` line-address form, and the operator motion forms (`d/PAT`, `c/PAT`, `d?PAT`, `c?PAT`) all reached `re.compile`/`.search()` against real file content with a caller's pattern completely unrefused -- nine independent entry points sharing the exact shape `#2571` fixed for `op_between_pattern`, two of them (`:s`, `:g`/`:v`) write-class. Fixed by routing each entry point's raw pattern through `_pattern_gate` once, before the retry/autocorrect ladder that follows it (`_pattern_gate` already normalises and refuses in one place; re-checking on every retry would just re-run the same verdict against a pattern that has not changed). `_pattern_gate` gained a `check_saturation` parameter (default on, unchanged for every existing caller): `op_vim`'s search motions (`/`, `?`, `n`/`N`, the `o`/`O` reflex, the `:d /PAT/` address resolver, and the operator motion forms) are a single-match position search, not a filtered count, so the "matches every line" refusal that makes sense for `grep`/`around` broke five previously-passing tests that search for a literal `|` character -- an ordinary, common vim idiom, not an adversarial pattern. Those seven sites pass `check_saturation=False`; `:s` and `:g`/`:v` deliberately do NOT -- self-review caught that the first cut of this fix turned the check off uniformly for all nine sites, including these two write-class ones, where a saturating pattern is exactly as destructive as it is for `grep`/`around`: a bare `|` as `:s`'s PAT silently interleaved the replacement between every character of the buffer, and as `:g`'s PAT silently deleted the whole file. `trap.d/2571.between-saturating-refusal.md` had flagged the identical mismatch for `op_between_pattern` without needing the opt-out yet. The length cap and the backtracking guard still apply unconditionally at every one of the nine sites regardless of `check_saturation`. `tests/test_pattern_gate_vim_2573.py` pins the refusal for an adversarial and an overlong pattern across all nine entry points (including `n`/`N` and the `o`/`O` reflex, and correcting an earlier version of the operator-motion-backward test that exercised the wrong code path), the saturation refusal on `:s`/`:g`'s literal-`|` case, and positive controls that ordinary `/`, `:s` and `n` calls still work.
