- **`op_vim`'s search and substitute motions compiled caller-supplied regexes with no gate, no length cap and no ReDoS backtracking guard** ([#2573](https://github.com/Digital-Process-Tools/claude-supertool/issues/2573)). Filed as an unconfirmed `adjacent` finding off `#2571`'s own fix: `/`, `?`, `n`/`N`, the inline `o`/`O` search-then-open reflex, `:s`, `:g`/`:v`, the `:d /PAT/` line-address form, and the operator motion forms (`d/PAT`, `c/PAT`, `d?PAT`, `c?PAT`) all reached `re.compile`/`.search()` against real file content with a caller's pattern completely unrefused -- nine independent entry points sharing the exact shape `#2571` fixed for `op_between_pattern`, two of them (`:s`, `:g`/`:v`) write-class. Fixed by routing each entry point's raw pattern through `_pattern_gate` once, before the retry/autocorrect ladder that follows it (`_pattern_gate` already normalises and refuses in one place; re-checking on every retry would just re-run the same verdict against a pattern that has not changed). `_pattern_gate` gained a `check_saturation` parameter (default on, unchanged for every existing caller): `op_vim`'s search motions are a single-match position search, not a filtered count, so the "matches every line" refusal that makes sense for `grep`/`around` broke five previously-passing tests that search for a literal `|` character -- an ordinary, common vim idiom, not an adversarial pattern. `op_vim` is the first caller to pass `check_saturation=False`; `trap.d/2571.between-saturating-refusal.md` had flagged the identical mismatch for `op_between_pattern` without needing the opt-out yet. The length cap and the backtracking guard still apply unconditionally at every one of the nine sites. `tests/test_pattern_gate_vim_2573.py` pins the refusal for an adversarial and an overlong pattern across the forward/backward search, the operator motion forms, `:s`, `:g`, and the `:d` pattern-address form, plus positive controls that ordinary `/` and `:s` calls still work.
