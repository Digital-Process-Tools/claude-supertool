- **An operator's ambient `FORCE_COLOR` no longer reaches a spawned child, so a captured receipt (an error tail, a validator's stdout, `_mcp_stop_server`'s `detail`) never carries terminal control bytes** ([#1429](https://github.com/Digital-Process-Tools/claude-supertool/issues/1429)). CPython 3.13+ colourises its own tracebacks purely because `FORCE_COLOR` is set -- even when stderr is a pipe -- and this repo's own agent harness exports `FORCE_COLOR=3`, so any of the ~130 `subprocess.run`/`Popen` call sites across `_supertool.py` and the presets could hand back ANSI escapes baked into a rendered field. Fixed at the choke point that reaches all of them without an audit of each: `_disable_force_color_for_children()` pops `FORCE_COLOR` from `os.environ` once, at import, before anything can spawn a child. Every call site that inherits its child's environment (`env=None`, the default) sees the scrubbed value directly; every one that builds an explicit `env=` does so by copying/merging `os.environ` first (`{**os.environ, ...}` or `os.environ.copy()`), so the merge already excludes it. `presets/mcp/daemon.py` repeats the same pop, since its own docstring documents it as directly runnable outside this process (`python3 daemon.py SERVER_NAME`), where the import-time strip cannot reach it. `NO_COLOR` is deliberately left untouched, not forced to `"1"`: CPython's own colour check honours `NO_COLOR` before `FORCE_COLOR`, so forcing it would have silently defeated the one escape hatch this fix means to leave open -- a declared preset's own `.supertool.json` `env:` block, applied after the merge above, still wins for an operator who wants colour on one command (caught in self-review, pinned by `test_a_declared_env_override_still_wins`). `_mcp_stop_server`'s existing strip-on-ingest (#1333) is unaffected and stays as defence in depth for a child launched outside this process's own environ. No op deliberately requests colour today (`--color`/`FORCE_COLOR`/`NO_COLOR` do not appear in any op's own command construction), so nothing lost the option it was using.
