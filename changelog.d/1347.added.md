- **The raw-command block belongs to the op, and ships with the tool.** Each op may now declare `replaces` — the raw shell invocations it supersedes — and a `PreToolUse` hook installed with the plugin refuses those commands with **the op's own description** as the message. Before this, the enforcement was hand-written markdown rules living beside the ops they protected, and on 2026-08-11 three of them were failing in three different directions at once: one blocked and did not block the same `gh pr view` minutes apart and reached no subagent at all (20 unblocked raw calls in one triage run), one refused commands that carried the very flag it required whenever a quoted argument preceded it, and one fired on the substring `supertool` — which in this repo is the **directory name**, eight false positives in a day, none of them piping a supertool op. Every one of those is a regex reading a shell command as a string, so the matcher **parses**: the command is tokenised into argv the way a shell would, and the match is on the command word, its subcommands and its flags. A directory name is then not a command word and a heredoc body is not an argv, structurally rather than by another pattern. Flags select *which* op is named rather than whether to block — `gh pr view --json state` points at `gh-pr:N:status`, `--json files` at `gh-pr:N:diff`. The first cut maps `gh pr view`, `gh pr diff`, `gh pr merge`, `gh pr create` and `gh issue list`; a raw call no op supersedes has no entry and is never blocked, which is the whole escape hatch — there is deliberately no environment variable, since one that can be prepended to a command is not a block, and the gate is turned off with `"raw_command_guard": false` in `.supertool.json` where the decision shows up in a diff. A guard that could not answer — a command that did not tokenise, a registry that could not be enumerated — allows the command and **says so in the transcript**, because failing open silently reproduces the exact defect this closes: a gate that did not run is otherwise indistinguishable from a command that complied. `guard:SHELL COMMAND` asks the same question without running anything.
