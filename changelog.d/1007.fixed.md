- **`dashboard`'s lane board matched a prefix no label in this repository uses, so every lane was unplaced and the section was inert** ([#1007](https://github.com/Digital-Process-Tools/claude-supertool/issues/1007)). `LANE_PREFIX` was hardcoded to `lane:`, read out of the *title* of [#964](https://github.com/Digital-Process-Tools/claude-supertool/issues/964) — an issue whose entire subject is a colon that appears in no label name. The seven labels here are `lane-watch`, `lane-release`, … so the universe came back empty, every row rendered `lane ?`, and the footer read `0 lanes free, 0 occupied, 0 unknown` beside six open PRs and thirteen live worktrees.

  **The vocabulary is configuration now, and unconfigured refuses.** `ops.dashboard.lane_prefix` in `.supertool.json`, with no default and deliberately so — `claude-supertool` spells lanes `lane-watch` while `claude-remember` spells priorities `priority:high`, same organisation and opposite convention, so a literal that is right here is wrong one repository away. Absent, the lanes section prints `!! unread`, names the key, and the footer reads `lanes UNCONFIGURED`: the property `radar_tiers` was given in [#528](https://github.com/Digital-Process-Tools/claude-supertool/issues/528), because a prefix nobody chose selects zero labels and zero labels reads exactly like a repository with nothing in flight.

  **An empty lane universe is its own state, which is the part that would have caught this on the first run.** A configured prefix matching nothing and a repository that genuinely declares no lanes rendered identically as a tally of zeroes; the first is a defect and the second is fine. The section is now `!! degraded` and says `no label matches 'lane:', so the lane universe is empty and no lane can be reported free`, names the labels sharing its stem behind a different separator, and suggests the spelling — as a suggestion the reader applies, never a fallback the op applies for them, since silently retrying the other separator would rebuild the guess this removes. The footer has four shapes and none is `0, 0, 0`: a real tally, `lanes UNREAD`, `lanes UNCONFIGURED`, `lane universe EMPTY`.

  **What already worked was kept and is now pinned.** Under the total failure the op never reported a lane free: it said `unplaced`, printed `'unknown' is NOT 'free'`, and declined in `next:`. That is why this was a `priority-high` bug and not a two-agents-one-file incident, and a test now fails if it is traded away for a tidier board.

  **The false measurement is gone.** `dashboard.py` and `docs/presets/dashboard.md` both asserted "Measured on this repository on 2026-08-07: 7 `lane:*` labels exist". Seven lane labels do exist; not one is spelled that way. Both now cite the spelling the tracker actually returns, and a test fails on any re-appearance of `lane:*` in either file.
