- **Fixed `merged-is-not-ancestry` blocking commands that carry no `--merged` flag at all** ([#1977](https://github.com/Digital-Process-Tools/claude-supertool/issues/1977)). Two defects composed: `require: --merged` was a substring test that `--merged-prs` also satisfied, and the `match` regex's span stopped at `|` but not at `;` or `&&`, so a `--merged-prs` argument to a later, unrelated command in the same compound call still counted. Together they refused the maintainer loop's own `git branch -D NAME && python3 oss_state.py ... --merged-prs N` shape for a flag it never asked git about. The span now stops at `;` and `&&` the way `supertool-no-cut.md` already does, `--merged` itself must be followed by end-of-string or a non-identifier character, and `require` is dropped rather than patched -- the anchored `match` regex already demands the subcommand at command position on its own. `tests/test_jit_merged_prs_not_merged_1977.py` drives the live pattern through `awk`, the same way it is actually evaluated.
