- **`radar` and `watches` name the channel they are a board of, and any export overriding it** ([#1495](https://github.com/Digital-Process-Tools/claude-supertool/issues/1495)). Both printed the socket and the state directory as bare paths, and the override disclosure — *`SUPERTOOL_WATCH_SOCK` is set and overrides the name: the socket is X, not Y* — was computed on every run and printed by `channel:health` alone. So an operator running a named channel with a stale socket exported read two healthy boards, neither of which said the name was not in force: #1477's half-set knob relocated one surface over.

  One formatter in `naming`, reached through one `transport` accessor, so the three surfaces cannot disagree about the same resolution. Silent on the default paths with no override — a header printed on every board is one nobody reads — and the name is flattened before it reaches a fixed-width table, because it arrives from an op's config block rather than from this repo.

  The disclosure stays in the renders and out of `transport`, which the #1476 review argued for and this keeps: `transport` is imported by a detached poller whose stdout has no reader, so a print there writes into nothing.

- **`channel:health` says when it declined to ask who holds the socket** ([#1495](https://github.com/Digital-Process-Tools/claude-supertool/issues/1495)). The arm for a socket that could not be probed is right to make no claim about a holder — `peer_pid()` connects, and the connect is the one that just failed — but it omitted the line the other arms print, and an omitted line reads exactly like a *no holder* line to anyone scanning for one. It now states the skip and its reason, and still names no holder.
