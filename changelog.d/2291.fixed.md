- **`_expand_env` no longer nests a second quote pair inside a `$VAR` reference that already sits in the template's own single quotes** ([#2291](https://github.com/Digital-Process-Tools/claude-supertool/issues/2291)). #2290 fixed a Windows-only backslash-eating bug by wrapping every substituted value in `shlex.quote()`, but that quoting was blind to a template's own pre-existing quoting: the shipped `docs/notifiers.md` pattern (`bash -c '...$SLACK_WEBHOOK'`) got a nested quote pair spliced in whenever the substituted value held a shell-special character, and `shlex.split` has no notion of nested quoting, so the value split back apart into multiple argv tokens — or, for a value holding an odd number of special characters, raised `ValueError: No closing quotation` outright. `_expand_env` now tracks whether each match sits inside a single-quote span the template itself opened; inside one, the value is spliced directly with only its own `'` characters broken out, since nothing else is special there. A `$VAR` reference outside the template's own quoting keeps the unchanged #2290 behaviour. A `$VAR` inside the template's own DOUBLE quotes is unaffected by this fix and is a still-open, narrower pre-existing gap than the one this closes.
