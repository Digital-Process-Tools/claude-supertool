- **`argv0()`/`_spawnable()` no longer hand a refused cwd-only match to the OS's own search** ([#2578](https://github.com/Digital-Process-Tools/claude-supertool/issues/2578)). Both chokepoints ended `which_excluding_cwd(name) or name`: when a match existed only via the current directory, `which_excluding_cwd()` correctly refused it, but the fallback then handed `subprocess` the **bare name** -- and on Windows, `CreateProcess` performs its own PATH+cwd search, resolving the very match this module exists to refuse. A genuinely absent tool (no match anywhere, not even cwd) is unaffected and still returns the bare name unchanged. Also routes `hooks/guard-selftest.py`'s bash resolution through the same chokepoint ([#2610](https://github.com/Digital-Process-Tools/claude-supertool/issues/2610)), closing the same class in a pre-existing, out-of-band diagnostic that predates the audited range.
