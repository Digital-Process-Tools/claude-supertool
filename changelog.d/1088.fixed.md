- **A `paste` that creates a file now removes it when a rollback validator fails** ([#1088](https://github.com/Digital-Process-Tools/claude-supertool/issues/1088)). The rollback loop was gated on having pre-edit bytes to restore, and a created file has none — so it skipped the loop entirely and survived its own failed validation, red row printed above it. That inverts the contract the payload route is recommended for: the receipt said the write had not survived, the filesystem said it had, and the next `read` or `pytest` saw a file the caller believed did not exist.

  **Undoing a create is a delete, so it is decided on provenance, not on the absence of a baseline.** Three states now: restore the captured bytes; unlink a path this op brought into being; or **refuse**, loudly, for an existing file whose bytes could not be read — removing that one would destroy content this tool never wrote, which is the outcome ranked below misreporting. The retraction line says `the file was NOT created` rather than `NOT edited`, because a reader deciding what to do next needs to know the path is now absent rather than reverted. The same three states apply to the formatter rollback path, which had the identical gap.
