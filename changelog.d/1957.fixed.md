- **`gh-job` refused to read any job log containing terminal escape sequences, in all three modes** ([#1957](https://github.com/Digital-Process-Tools/claude-supertool/issues/1957)). `gh api .../logs` refuses to write a response with terminal control bytes to a non-TTY, which supertool always is when it captures output — so a job's log with ANSI colour codes (the CI norm, not the exception: pytest, npm, cargo and most action runners emit it by default) was unreadable through `:fail`, `:raw` and `:grep:PATTERN` alike, and `gh`'s own message named the remedy, `--allow-escape-sequences`, while no op string could pass it. The call site now passes the flag; the existing ANSI-strip already run on the log before it is parsed means the reader still never sees a raw control byte ([#1429](https://github.com/Digital-Process-Tools/claude-supertool/issues/1429)). An older `gh` predating the flag fails a different way — refusing the flag itself — and is now reported as itself rather than folded into the escape-sequence refusal or the generic "gh failed" catch-all.
