- **`validators/phpstan/phpstan.py` spawned the bare literal `"php"` as argv[0] despite gating `phpstan_bin`** ([#2605](https://github.com/Digital-Process-Tools/claude-supertool/issues/2605)). `phpstan_bin` was correctly resolved through the cwd-excluding chokepoint (`spawnable()`/`argv0()`, #2581) and placed at argv[2] -- but the program `subprocess.run()` actually executes, argv[0], was left as the untouched string `"php"`, resolved with no cwd-excluding lookup at all. Since the spawn passes no `cwd=`, the adapter inherits supertool's own cwd -- the repository under inspection -- so a repo-planted `php.exe` at the project root would have been executed in place of the real interpreter on Windows, with a maintainer's forge token in the environment (the identical outcome #2575/#2596/#2602 already exist to stop, reached here because the resolved binary landed in the wrong argv slot). Fixed by resolving `php` through the same `spawnable()`/`argv0()` chokepoint as `phpstan_bin`, declining with an `adapter` error when it cannot be resolved, the same as every other gate in this file. Neither of #2540's/#2579's own registers (`tests/test_spawnable_register_2540.py`, `tests/test_gate_matches_spawn_2579.py`) could see this shape -- the first only flags a bare literal the SAME file also proves with a raw `shutil.which()` call on that literal, and the second only inspects a gate/spawn mismatch, never argv construction itself. A new register, `tests/test_bare_argv0_construction_2605.py`, inspects the constructed argv list directly for a bare string literal at argv[0] with no corresponding `spawnable()`/`argv0()`/`which_excluding_cwd()`/`resolve_bin_cmd()` call anywhere in the file -- and, run once against the whole `validators/`+`formatters/` tree, confirmed the two sibling instances already named in the issue's own scope note (`validators/phplint`, `validators/xmllint`) and found seven further files carrying eight NEW unfixed call sites of the identical class (`validators/bash-check`, `validators/changelog-fragment`, `validators/common/ci_lint_resolve_root.py`, `validators/common/encoding_seam.py`, `validators/markdownlint`, `validators/new-file-lint` (two sites), `validators/node-check`), allowlisted in the new register as known, tracked separately, and reported to the maintainer rather than fixed in this change.
