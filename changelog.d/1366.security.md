- **`glob` was outside the cwd containment boundary entirely** ([#1366](https://github.com/Digital-Process-Tools/claude-supertool/issues/1366)). From a directory with no opt-out, `read:/tmp/x/f.txt` refused and `glob:/tmp/x/*.txt` answered — same target, same call, two verdicts. What crossed was not file contents but an **existence oracle**: directory layout, project names, file naming, whether a given path is there at all (same family as [#1135](https://github.com/Digital-Process-Tools/claude-supertool/issues/1135) and [#1142](https://github.com/Digital-Process-Tools/claude-supertool/issues/1142)). `glob` resolves its own pattern and was absent from `_PATH_ARG_POSITIONS` with no note beside it — the only unexplained absence in a table where `grep`, `around` and `between` each say why — so it reached neither the dispatch gate nor [#1287](https://github.com/Digital-Process-Tools/claude-supertool/issues/1287)'s declaration gate, which only ever sees preset ops. It was an oversight, not a decision, and the table now says so.

- **A glob pattern is not a path, so it is gated in two halves and neither one narrows a result.** The two obvious single answers both fail: the literal prefix before the first magic character is *empty* in `*/../../etc/*`, so a prefix gate clears it; and filtering the expanded matches turns a refusal into a shorter list, which is this repo's house defect wearing a clean receipt. Instead, before disk is touched the pattern's **reach** is checked — every magic component read as one ordinary name, which loses nothing, because no glob metacharacter can invent a `/` (`*`, `?` and `[...]` stay inside a component, `**` spans them but only downward), so the traversal is fully determined by the separators and `..` already written. Brace groups are expanded first and each branch checked on its own: `_expand_braces` runs *inside* `_glob_files`, so `{.,/etc}/host*` used to read as one contained component and fan out into a pattern the gate never saw. After expansion the matches are checked too, for the one escape a pattern cannot predict — a wildcard landing on a symlink pointing out of the tree — and that refuses the **whole call**, naming no file: dropping the entries would report a population it had silently narrowed, and printing them would disclose the very paths the refusal is about.

- **A refusal is never `(0 files)`.** Both halves say `path escapes cwd`, with the same opt-out sentence as every other containment refusal — now a single `_ALLOW_OUTSIDE_HINT` constant rather than a second copy of the remedy. A manufactured zero is indistinguishable from an empty directory, which is exactly what `glob` said about `~` until [#1300](https://github.com/Digital-Process-Tools/claude-supertool/issues/1300). `glob` still does not expand `~`, for the same reason as before: the gate here reads a pattern, not a path, so there is nothing for an expansion to sit behind.
