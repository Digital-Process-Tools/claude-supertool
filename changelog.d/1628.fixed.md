- **The cohort burn-down asked for the open column one search at a time, and by 16 cohorts that returned nothing at all** ([#1628](https://github.com/Digital-Process-Tools/claude-supertool/issues/1628)). `gh-labels:tally=PREFIX` cost `2N + 2` search calls per family against an API allowing 30 a minute. On 2026-08-13 it refused at 15 labels; on 2026-08-14, past `GH_LABELS_TALLY_MAX=16`, it answered **34 of 34 cells `?`** — where the day before the same escape hatch had dropped 2 of 32. The family grows by one label per release, so there was no future state of this repository in which the query plan started working again.

  **The open column never needed a search.** `fetch_open_issue_rows` was already reading the whole open set on every tally call, for the multi-label check — the run that returned 34 `?` still printed `Multi-label: none of all 74 open issues …` from the listing it was holding and then discarded. The per-label open counts are a client-side group-by over exactly that data, so `open` is now tallied from it and only `closed`, where enumerating would render a floor as a burn-down denominator, still costs a search per label. A family is `N + 1` calls, and `GH_LABELS_TALLY_MAX` rises from 14 to 24 on that arithmetic.

  Not to 29, which `N + 1 <= 30` alone would give. The old bound sat exactly on the limit — 14 labels, 30 calls — and did not hold: a whole board lost to a two-call overrun only happens if the minute's budget was already partly spent, which on a maintainer tick it always is. Five calls of headroom is the measurement, and the env var stays for a caller who knows their minute is quiet.

  **The two columns now fail independently and say so separately.** A rate-limited search costs the `closed` column and leaves `open` intact — which is the number the tick actually turns on — so the header carries an `Open:` sentence and a `Closed:` sentence instead of one covering both. The refusal is unchanged in kind: past the bound it still declines rather than rendering a half-read board, and it quotes the cost it now actually pays. The three states carry to the new source too: an unreadable listing leaves every open cell `?` and never `0`, and a listing that hit `GH_LABELS_ISSUE_CAP` makes each open cell a floor (`>=N`) that carries into `frozen` — an enumeration has a cap where a search did not, and that is the cost of the move, stated rather than absorbed.
