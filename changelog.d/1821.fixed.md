- **`around` says which pattern the colon split settled on** ([#1821](https://github.com/Digital-Process-Tools/claude-supertool/issues/1821)). `around:PATTERN:PATH[:N]` rejoins a colon-bearing pattern exactly as `grep` does, and where the PATH slot resolves it printed the answer and nothing else — so `around:mode:.*remind|title:DIR` searched for `mode:.*remind|title`, found two files, and named neither half of the split it had just guessed at. It now prints the same `(pattern read as …, path as …)` line `grep` has printed since #1065, with the escape hatch naming `around:@-` rather than `grep:@-`.

    #1821 was filed as an *ordering* defect on `grep` — the wrong answer printed above the note explaining why — and that half does not reproduce: `op_grep` has prepended the line since #1065 and the path since #1166. A test now pins the order rather than leaving it to the next refactor, and `op_around`'s docstring claim that it is "guarded and disclosed exactly as op_grep is" is true for the first time since it was written in #1120.
