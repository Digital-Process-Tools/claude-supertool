- **`classify`'s model spawn now pins a model instead of inheriting the host's configured default** ([#2055](https://github.com/Digital-Process-Tools/claude-supertool/issues/2055)). No `--model` was ever passed, so the spawn silently ran whatever the caller had configured — on one machine, a 1M-context Opus session, to emit a single line of `SAFE`, and with no way for two operators classifying the same text to know whether they got answers from the same model. `model.DEFAULT_MODEL` (`claude-haiku-4-5-20251001`) is now always passed explicitly, chosen because it clears `tests/test_classify_live_2046.py`'s two live verdict tests, and overridable per repo with a `model` key in the op's `.supertool.json` block, reaching the subprocess as `SUPERTOOL_MODEL`.
